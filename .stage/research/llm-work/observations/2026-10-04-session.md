# 이 대화에서 목적 해석이 어긋난 사례

날짜: 2026-10-04

이 기록은 현재 연구 대화의 사용자 발화와 assistant의 공개 답변을 분석합니다.
모델의 숨겨진 추론을 기록하거나 재구성하지 않습니다.
아래 발췌는 원래 순서를 따르며 전체 대화를 대신하지 않습니다.

## 관찰한 발화

| 순서 | 발화자 | 발췌 |
|---|---|---|
| 1 | 사용자 | “저는 AI 가 일하는 방식을 꼼꼼히 뜯어보고 Jev 같은 걸 한 번 만들어보고 싶어요.” |
| 2 | assistant | “이를 참고해 서비스를 만드는 방법과, 판단용 모델 자체를 학습하는 방법을 나눠 조사하겠습니다.” |
| 3 | 사용자 | “이건 좀 철학적 논의가 필요해요. LLM 이 일하는 방식에 대한 걸 좀 뜯어보자구요.” |
| 4 | 사용자 | “내가 하고 싶은 건 Jev 가 하는 디시전 API 를 만드는게 아니라 그걸 왜 만들었냐 라는 동기입니다.” |
| 5 | 사용자 | “지금 LLM 들이 일하는 방식을 뜯어보고 그걸 강화하는 방식을 찾는거에요.” |
| 6 | 사용자 | “더 쪼게봐야합니다.” |

## 관찰에서 말할 수 있는 것

- 첫 발화에는 새로운 것을 만들려는 의도와 기존 AI를 분석하려는 의도가 함께 있었습니다.
- assistant는 공개적으로 서비스 구현과 모델 학습으로 조사 범위를 좁혔습니다.
- 사용자는 그 방향을 바로잡고 원하는 분석 수준을 더 구체적으로 설명했습니다.
- 이 대화에서는 사용자가 목적을 다시 설명하는 수고를 했습니다.

## 관찰만으로 말할 수 없는 것

- assistant 내부에서 정확히 어떤 계산이 이 선택을 만들었는지
- 처음부터 의도가 하나로 명확했는데 무시한 것인지
- 같은 입력에서 항상 같은 일이 생기는지
- 목적을 요약하는 절차가 있었다면 반드시 막았을지
- Claude, Grok, Gemini도 같은 빈도로 실패하는지

## 동작 지도에 연결합니다

아래는 관찰을 설명하기 위한 해석입니다.

| 동작 | 의심되는 문제 | 가능한 다른 설명 |
|---|---|---|
| U02 원하는 변화를 뽑습니다 | Jev 같은 결과물을 만들고 싶다는 말을 특정 API를 만들겠다는 뜻으로 좁혔을 수 있습니다. | 첫 요청 자체에 여러 해석이 가능했습니다. |
| U05 추측을 표시합니다 | 제품 구현이라는 가정이 충분히 드러나지 않았을 수 있습니다. | 해석을 알렸지만 사용자와 뜻이 맞는지 확인할 기회가 짧았습니다. |
| U06 완료 조건을 정합니다 | 조사 결과를 구현 경로로 정했을 수 있습니다. | 사용자에게도 대화를 통해 목적을 구체화하는 과정이 필요했을 수 있습니다. |
| U03 이어지는 요청인지 가립니다 | 사용자의 수정이 들어왔을 때 원래 계획을 얼마나 바꿨는지 확인해야 합니다. | 구체적인 발화가 추가되면서 정상적으로 방향이 조정된 것일 수 있습니다. |

지도 원문: [요청에서 작업을 정합니다](../work-map.md).
