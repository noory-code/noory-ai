# LLM이 일하는 방식과 강화할 방법을 조사했습니다

**처음 읽으시면 [연구 종합 정리](synthesis.md)부터 보시면 됩니다.**
연구 목적, 세 가지 후보, 실험 결과, Stage·Distill·Avatar의 역할과 남은 검증을 한 문서로 정리했습니다.

**2026-10-06 후속 호출 48번을 마쳤습니다:** [검토할 함수를 AI가 고른 결과](findings/2026-10-06-auto-selected-review.md)에서는 판정 32개가 모두 기대 답과 일치했습니다.
그러나 함수를 고르는 비용까지 더하자 절약 효과가 사라졌습니다. 코드를 줄인 과제도 Claude 보고 금액은 12.1%, Codex 입력은 67.7% 늘었습니다.
이미 아는 범위와 코드로 확인할 수 있는 정보를 먼저 활용할 후보로 남겼습니다.

**자료를 골라 전달하는 비교 36번을 마쳤습니다:** [코드 리뷰 입력을 좁힌 결과](findings/2026-10-05-selected-review.md)에서 한 과제의 판정을 유지하며 입력과 Claude 보고 금액을 줄였습니다.
다른 과제는 전체 파일을 유지했습니다. 안정적인 속도 개선과 일반 업무의 절감률은 확인하지 못했습니다.

**비용을 다시 확인했습니다:** [원본 호출 125번의 재집계](findings/2026-10-05-cost-audit.md)에서 시간·토큰·캐시·보고 금액을 구별했습니다.
토큰이 가장 많은 조건이 보고 금액도 가장 크지는 않았습니다. 기준을 먼저 추출한 비용과 실패한 호출의 시간도 포함했습니다.

**상태: 2026-10-05에 Codex 업데이트 후 남은 비교 16번을 마쳤습니다. Stage 전체 운영 검증과 실무 재사용률 관측은 남아 있습니다.**

[최신 결과](findings/2026-10-05-stage-after-update.md): 기준 적용 24번은 모두 기대 답과 일치했고 실제 작업 인계 여덟 조건을 완료했습니다.
원문을 정리하거나 관찰 파일 링크를 추가하는 방식에서 뚜렷한 개선은 확인하지 못했습니다.

**중간 요청:** 파생 아이디어를 기록한 뒤 본래 연구를 계속했습니다. 당시에는 Avatar / Clone 구현을 보류했습니다.
이후 사용자가 Stage·Distill·Avatar 구현을 요청해 [별도 작업 묶음](../../work/current/W-00000272/_epic.md)을 등록했습니다.
연구 결과와 구현 진행 상태는 구별합니다.
본래 연구는 AI가 일하는 과정을 나눠 보고 개선할 방법을 찾는 일입니다.
적용 아이디어는 [Stage 개선](product-design.md)과 [개인의 판단 기준·메타인지를 다루는 Avatar / Clone](avatar.md)으로 구분했습니다.
이후 [세션 인계 때 읽는 자료](experiments/context-handoff/README.md)를 조사하고 Claude·Codex 비교 24번을 마쳤습니다.
[결과](findings/2026-10-05-context-handoff.md): 입력 토큰은 줄었고 작은 과제의 판정은 유지됐지만, 빨라졌다는 결과는 얻지 못했습니다.
그다음 과거 결함 두 개에서 [다른 AI가 실제 수정을 이어받는 비교](findings/2026-10-05-cross-session.md)를 여덟 번 수행했습니다.
현재 파일을 미리 넘기자 이어받기의 모델 호출은 13번에서 11번으로 줄었습니다. 전체 시간은 줄지 않았습니다.
전체 검사에 요청 범위 밖의 API 변경이 섞인 문제도 확인하고, 원래 판정과 후속 진단을 함께 남겼습니다.
이후 [목표와 검사를 맞춘 실제 CLI 시험](findings/2026-10-05-stage-followup.md)을 진행했습니다.
네 인계는 정상 완료했고 다섯 번째는 실제 파일 수정 뒤 Codex 서버 오류로 중단됐습니다.
Claude의 기준 적용과 관찰 시점 비교, 실제 로그 조사도 수행했습니다. 이때 Codex 쪽 미실행 항목이 남았습니다.
사용자가 요청한 [재시도](findings/2026-10-05-stage-retry.md)에서는 Codex의 기준 추출 응답을 받았지만 출처 형식 검사에 걸렸습니다.
다음 호출에서는 서버 혼잡 오류가 다시 나왔습니다. Claude의 남은 인계 두 조건은 모두 완료했고 각각 테스트 94개를 통과했습니다.
다시 이어간 [업데이트 전 시험](findings/2026-10-05-stage-criteria-resume.md)에서는 출처 단위를 명시한 Codex 추출이 검사를 통과했습니다.
두 상황을 두 조건에서 판단한 네 응답은 모두 맞았습니다. 간격을 두고 재시도해도 서버 혼잡이 반복돼 나머지 비교는 남았습니다.
[남은 연구를 판단하는 기준](followup-plan.md)에서 후속 범위를 확인할 수 있습니다.

요청하신 구조 조사, 실패 분석, 비교 실행, 가설별 판단과 개선 우선순위를 정리했습니다.
초기 조사와 탐색 실험의 결론은 [초기 보고서](final-report.md)에 남겼습니다.
조사 결과에서 도출한 [개선 아이디어 여섯 가지](ideas.md)도 정리했습니다.
이후 모두 작은 시제품으로 만들고 [Claude·Codex 비교 결과](findings/2026-10-05-ideas-lab.md)를 남겼습니다.
최근에는 실제 과거 결함 두 개를 복원해 [이전 판정을 다시 쓰는 효과](findings/2026-10-05-review-reuse.md)를 시험했습니다.
사용자가 새로 제안한 [사람의 판단 기준 수집과 적용](decision-criteria.md)은 별도 연구 후보로 기록했습니다.
이후 Distill의 초기 목적이 룰 생성이었다는 사용자 설명을 반영하고 [현재 코드와 대조](findings/2026-10-05-distill.md)했습니다.
현재 설계는 [궁극적 목적 → Distill → 사용자](decision-criteria.md#decision-order) 순서로 판단 근거를 찾습니다.
현재는 세 가지 개선을 [Stage가 제공할 능력으로 함께 검토](product-design.md)합니다.
AI가 목적을 붙잡고 자유롭게 일할 수 있는 무대라는 사용자 설명을 반영했습니다.
동시에 [한 사람의 기준을 프로젝트 밖에서 모으고 이어서 쓰는 방향](decision-criteria.md#person-across-projects)도 유지합니다.
기능별 효과를 검증하고, 별도 제품으로 나눌지는 독립적인 쓰임새가 확인된 뒤 검토합니다.
[여러 세션에서 같은 작업을 이어가는 설계](session-continuity.md)에서는 Stage의 작업·결정 기록을 활용하는 방법과 추가 검증 범위를 정리했습니다.
[플러그인·MCP 검토](integration-choice.md)에서는 세 후보 모두 MCP 없이 시작할 수 있다고 판단했습니다.
프로세스 종료 뒤 자동으로 이어갈 실행 주체와 MCP 연결은 별도로 설계해야 합니다.
제품에 적용한 효과까지 검증했다는 뜻은 아닙니다. 확인하지 못한 주장은 보류로 결론 내렸습니다.

사용자가 실제로 쓸 AI는 Claude와 Codex입니다.
후속 실험과 개선은 [이 두 환경으로 범위를 정했습니다](purpose.md#available-ai).
앞선 실행 280건은 Claude에서 수행했습니다.
시제품 후속 시험에서는 Claude와 Codex로 각각 48번 비교했고 연결 확인 두 번은 별도로 기록했습니다.
그다음 실제 코드 리뷰 시험에서는 요청 64번을 처리했습니다. 모델 호출 48번과 판정 재사용 16번을 구별했습니다.

AI가 요청을 받아 일을 끝낼 때까지 무엇을 수행하는지 분석합니다.
각 동작이 왜 필요한지 따지고, 우리가 바꿀 수 있는 지점을 찾습니다.
Jev는 새로운 기회를 발견한 사고방식을 살펴볼 사례로 다룹니다.

현재까지의 결론은 다음과 같습니다.

- 작업을 분석할 때 쓰는 단위와 실제 모델 호출은 일대일로 대응하지 않습니다.
- 모델이 무엇을 선택했는지와, 실행 뒤 무엇이 달라졌는지를 함께 봐야 합니다.
- 개선 효과는 작업 전체에서 확인해야 합니다. 한 단계의 점수만으로 판단하지 않습니다.

이 결론의 근거와 한계는 [첫 분석 결과](findings/2026-10-04.md)에 적었습니다.
초기 연구에서는 공개 출처 27개 항목을 정리하고 두 SDK의 소스를 분석했습니다.
초기 연구의 Claude CLI 실행은 예비 실험 10건, 후속 반복 174건, 문제를 보완한 96건으로 총 280건입니다.
추가로 모델 없이 로컬 규칙 18개 항목을 검사했습니다.
가설 6개의 근거와 적용 조건을 평가했습니다. 모델 간 성능 순위는 매기지 않았습니다.

## 기록 원칙

1. **출처에서 확인했습니다:** 공개 문서나 논문에서 확인한 내용을 출처와 함께 적습니다.
2. **관찰했습니다:** 실제 입력, 출력, 도구 결과에서 확인한 내용을 적습니다.
3. **해석했습니다:** 자료와 관찰에서 이끌어 낸 설명입니다. 다른 설명도 검토합니다.
4. **가설입니다:** 실험으로 확인할 예상입니다. 개선됐다고 보고하지 않습니다.
5. **아직 모릅니다:** 정보가 없거나 확인하지 못한 부분입니다.

출처 설명은 `sources.md`, 동작 정의는 `work-map.md`, 가설 상태는 `hypotheses.md`가 소유합니다.
다른 문서는 해당 위치로 연결합니다. 같은 정의를 여러 문서에서 따로 갱신하지 않습니다.
논문이나 웹페이지 전문을 복제하지 않습니다. 직접 확인한 부분을 짧게 정리하고 원문을 연결합니다.

## 연구 이후의 적용

어떤 제품을 만들거나 기존 플러그인을 바꿀지는 이번 연구와 별도로 결정합니다.
적용할 때 필요한 검증은 최종 보고서와 가설별 판단에 남겼습니다.
초기의 정식 비교 계획은 사람 검토와 전체 과제 실행을 전제로 했습니다.
그 계획을 완료했다고 표시하지 않습니다. 이번에는 더 좁은 탐색 실험으로 후보와 한계를 판단했습니다.
