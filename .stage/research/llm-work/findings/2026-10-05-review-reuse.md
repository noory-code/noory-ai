# 실제 코드 리뷰에서 이전 판정을 다시 쓴 결과

**같은 입력이 절반 반복되는 조건에서 모델 호출을 절반으로 줄였고, 요청별 평균 시간도 약 절반으로 줄었습니다.**
기본 조건과 재사용 조건 모두 정한 기준의 판정은 맞았습니다.
반복 비율은 실험자가 정했습니다. 실제 업무에서도 절반을 줄일 수 있다는 뜻은 아닙니다.

2026-10-05에 실제 과거 결함 두 개를 복원해 시험했습니다.
총 요청은 64번이며 실제 Claude·Codex 호출은 48번, 저장한 판정의 반환은 16번입니다.
합성 문제로 기능을 확인한 [앞선 시험](2026-10-05-ideas-lab.md)과 별도의 기록입니다.

## 실제로 무슨 일을 시켰나요

이 저장소에서 고친 결함 두 개의 코드를 읽고, 명시한 기준을 만족하는지 리뷰하게 했습니다.
수정 전후 대상 파일을 Git에서 그대로 꺼냈습니다.
기준과 코드만 모델에 전달했습니다. 커밋 메시지, 수정 전후 표시, 테스트 결과와 기대값은 전달하지 않았습니다.

| 실제 결함 | 판정할 기준 | 독립적으로 확인한 코드 동작 |
|---|---|---|
| 마일스톤의 완료 기준을 여러 개 주면 마지막 값만 남았습니다. | 전달한 기준 세 개가 순서대로 각각 저장돼야 합니다. | 수정 전 파일에서는 실패했고 수정 후 파일에서는 통과했습니다. |
| 회고 번호가 다른 작업과 충돌했는데 새 번호를 골라 넘어갔습니다. | 다른 번호를 만들지 않고 충돌한 번호와 작업을 알려야 합니다. | 수정 전 파일은 다른 번호를 반환해 실패했고 수정 후 파일은 충돌을 알려 통과했습니다. |

각 수정 커밋의 Stage 전체를 임시 폴더에 꺼내 기존 회귀 테스트를 실행했습니다.
수정 전 조건은 대상 파일 하나만 부모 커밋의 내용으로 바꿨습니다.
따라서 부모 커밋의 전체 환경을 재현했다고 주장하지 않습니다.
두 조건에 쓴 테스트 파일은 같고, 검사 전후 Stage 소스도 바뀌지 않았습니다.
[복원 방법과 Git 출처](../experiments/review-reuse/fixtures.md), [회귀 검사 네 번의 원본](../experiments/review-reuse/regression-results.json)

모델이 코드를 수정하거나 Stage의 전체 작업을 끝낸 시험은 아닙니다.
이번에 맡긴 일은 특정 기준에 대한 코드 리뷰이며, 그 결과를 파일로 남기는 과정까지 수행했습니다.

## 무엇을 바꿨나요

같은 사례에서 다음 네 요청을 순서대로 보냈습니다.

1. 수정 전 코드를 검토합니다.
2. 같은 자료의 판정을 다시 요청합니다.
3. 수정 후 코드를 검토합니다.
4. 같은 자료의 판정을 다시 요청합니다.

기본 조건은 네 번 모두 모델을 호출했습니다.
재사용 조건은 첫 번째와 세 번째에 호출하고, 두 번째와 네 번째에는 저장한 판정을 반환했습니다.
코드 내용·파일 경로·판정 기준·검토 정책·CLI 설정이 모두 같아야 재사용했습니다.
두 조건에서 모델에 전달한 입력은 같습니다. 각 CLI에서 두 번 반복했고 두 번째에는 조건 순서를 바꿨습니다.

이전 답이 맞는지 보고 저장 대상을 고르지 않았습니다.
형식이 맞고 확정한 판정이면 저장했습니다. 틀린 답도 그 조건을 만족하면 재사용될 수 있습니다.
이번 요청은 같은 판정의 조회이며, 새로운 독립 검토나 새로운 결함 탐색은 요구하지 않았습니다.

### 시간에 포함한 범위

입력 읽기, 해시 계산, 캐시 조회·저장, 필요한 CLI 호출과 응답 파일의 첫 저장까지 쟀습니다.
요청별 시간의 합은 Claude 기본 90.942초, 재사용 44.876초입니다.
Codex는 기본 121.177초, 재사용 62.656초입니다.
두 작업을 병렬로 진행했으므로 이 합은 실험 전체의 실제 경과 시간과 다릅니다.

Git 자료를 꺼내고 회귀 테스트로 기준을 확인한 공통 준비 작업은 별도로 기록했습니다.
시제품을 만드는 시간과 운영에 연결하는 비용은 포함하지 않았습니다.
서버 상태와 캐시를 모두 통제하지 못했습니다. 관찰한 시간 차이를 일반적인 개선율로 확대하지 않습니다.

### 비용과 사용량

이번 Claude 호출 24번의 보고 비용 합계는 0.933916달러입니다. 실제 청구액은 조회하지 않았습니다.
재사용 조건의 Claude 보고 비용은 기본 조건보다 적었습니다.
공급자 캐시와 첫 호출의 비용도 섞여 있으므로 모든 업무에서 같은 비율로 줄어든다고 주장하지 않습니다.

Claude 입력에는 새 입력과 캐시 생성·읽기 토큰을 합쳤습니다. 그 합이 같은 단가로 청구된다는 뜻은 아닙니다.

## 이번에 확인한 가치

**이미 한 판단을 다시 요청하는 경우, 그 판단을 새로 만들지 않아도 요구한 결과를 줄 수 있었습니다.**
이번에는 판단의 정확도를 높인 효과가 없었습니다. 기본 조건도 모두 맞혔습니다.
확인한 효과는 입력이 같은 요청의 반복 호출을 없앤 것입니다.

이는 새로운 캐시 원리를 발견했다는 뜻은 아닙니다.
제품으로 가치가 있으려면 실제 AI 업무에서 무엇을 같은 입력으로 볼지, 언제 재사용을 끝낼지 정하는 부담을 줄여야 합니다.
그 조건을 확인하는 데 더 많은 모델 호출이 필요하다면 절감 효과가 작아질 수 있습니다.

## 실무 효과는 아직 어디까지 모르나요

[리뷰 비용 관측](../../../state/observations/O-00000024.md)은 이 실험을 고른 계기입니다.
당시 계정 원본을 새로 집계하지 않았으며 기록에 적힌 한계도 함께 따릅니다.
최근 실제 로그 세 개를 읽었지만 입력 전체의 해시는 없었습니다.
완전히 같은 입력이 반복된 비율은 입증하지 못했습니다.

- W-00000249의 리뷰 제목 두 개만으로 별개 호출 두 번이라고 셀 수 없습니다.
- W-00000259에는 소스를 더 고치지 않았다는 기록이 있지만, 검증 결과와 판정 맥락이 달라졌습니다.
- W-00000166은 통과 판정과 함께 테스트 범위의 빈틈을 지적했습니다. 이후 테스트를 보강해 다시 검토했습니다.

따라서 이번에 정한 50% 반복 비율을 과거 작업에 적용할 수 없습니다.
독립 재검토를 원하는데 저장한 판정을 반환하면 필요한 작업을 생략한 것입니다.

### 입력의 범위를 빠뜨리면 재사용할 수 없습니다

키는 모델에 제공한 대상 파일을 확인합니다. 그 파일이 가져오는 모듈과 템플릿 전체는 추적하지 않습니다.
실제로 Claude는 수정 후 코드의 설명에서 제공되지 않은 템플릿을 가정했다고 밝혔습니다.
이번 판정 기준은 정상적인 Stage 프로젝트를 전제했고 회귀 검사도 그 환경에서 실행했습니다.
템플릿이나 외부 상태가 바뀌는 운영 환경까지 이 캐시가 안전하다고 판단할 수는 없습니다.

실제 적용 시에는 판단에 영향을 주는 파일·상태·현재 지시·권한·기준을 빠짐없이 확인해야 합니다.
확인하지 못한 조건이 있거나 새로운 독립 검토를 요청하면 다시 검토해야 합니다.
캐시 자체는 첫 판정이 옳은지 보증하지 않습니다.

## 실행 환경과 기록 확인

- Claude Code 2.1.289에서 `claude-sonnet-5-5`를 요청했습니다. 사용량에도 같은 이름이 기록됐습니다.
- Codex CLI 0.146.0에서 기본 모델과 낮은 reasoning effort를 요청했습니다. 실제 모델명은 공개 이벤트에서 확인하지 못했습니다.
- Python 3.14.6과 macOS에서 실행했습니다. Windows와 Linux에서는 직접 시험하지 않았습니다.
- 캐시 검사 17개와 입력·응답 형식 검사 2개가 통과했습니다. 캐시의 구현 전 실패와 구현 후 통과를 기록했습니다.
- 기존 회귀 테스트 네 번으로 결함과 수정 동작을 대조했습니다.

## 연구를 어떻게 이어갈까요

현재 제품 후보는 ‘같은 판단을 언제 다시 해야 하는지 관리한다’는 범위로 남깁니다.
다음 실무 검증에는 파일·기준·검토 목적이 같은 요청의 비율과, 이를 확인하는 관리 비용이 필요합니다.
단순한 호출 절감보다 잘못 재사용해 생기는 재작업까지 포함해 판단해야 합니다.

사용자가 새로 제안한 [사람의 판단 기준을 수집하고 적용하는 아이디어](../decision-criteria.md)는 별도로 기록했습니다.
이번 실험은 기존 답을 재사용했습니다. 새 후보는 기준을 새로운 상황에 적용하는 문제까지 연구합니다.
[AI에게 필요한 기능과 제품 후보](../essential-work.md)에서 두 방향이 어떻게 이어지는지 설명합니다.
