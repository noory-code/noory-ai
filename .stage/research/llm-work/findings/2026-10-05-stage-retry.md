# 중단된 비교를 다시 실행한 결과

이 문서는 첫 재시도 때의 기록입니다. 이후 [출처를 명시한 기준 추출과 판단 결과](2026-10-05-stage-criteria-resume.md)를 추가했습니다.

**Codex는 한 번 정상 응답한 뒤 다음 호출에서 다시 서버 혼잡 오류를 반환했습니다.**
정상 응답한 기준 추출에서도 출처 형식을 확인하는 검사에 걸렸습니다.
원래 결과를 보존하고 [별도 폴더](../experiments/stage-followup/retry-1/manifest.json)에 이번 기록을 남겼습니다.

## 1. Codex 응답은 돌아왔지만 비교를 끝내지는 못했습니다

먼저 실패했던 기준 추출과 같은 입력을 보냈습니다.
CLI는 19.2초 만에 정상 종료했습니다. 입력 토큰 7,464개와 출력 토큰 494개를 보고했습니다.
그러나 기준 한 개에 `source: "N2, N3"`를 적었습니다.
인용에도 두 원문의 일부를 `/`로 이어 넣었습니다.

기존 검사는 기준 하나를 원문 ID 하나와 대조합니다.
따라서 이 결과를 이후 판단에 넘기지 않았습니다. 연구자가 나누거나 고쳐 넣지도 않았습니다.
검사 프로그램이 저장한 오류 문구는 빈 문자열이었습니다. 원문 ID를 찾지 못한 예외에서 나왔습니다.
[이번 집계](../experiments/stage-followup/retry-1/summary.json)에는 실패한 항목과 이유를 다시 계산해 적었습니다.
[모델의 실제 답](../experiments/stage-followup/retry-1/criteria-runs/extract--codex.json)

요청문에도 부족한 점이 있었습니다. 필드와 원문 인용을 요구했지만 출처를 반드시 하나만 쓰라고 명시하지 않았습니다.
**검사에서 요구하는 출처 단위를 요청문에도 정확히 알려야 합니다.**
내용을 이해하는 능력과 정해 둔 저장 형식을 지키는 능력을 구별해서 봐야 합니다.
앞선 Claude 결과처럼 이번 Codex 결과도 프로젝트명이 없는 N4를 A로 분류했습니다.
미확인 추정으로 표시했지만, 출처 연결 검사만으로 이 분류까지 검증되지는 않습니다.

출처 하나와 연속된 원문 인용만 쓰도록 더 구체적인 요청을 준비했습니다.
원래 추출과 구별한 [추가 시험 계획](../experiments/stage-followup/retry-1/continuation-manifest.json)에 남겼습니다.
그 시험에 앞서 독립된 관찰 시점 비교를 시작했으나 첫 호출에서 다음 오류가 돌아왔습니다.

```text
Selected model is at capacity. Please try a different model.
```

이 호출은 6.6초 만에 끝났으며 응답과 사용량을 받지 못했습니다.
[서버 오류 기록](../experiments/stage-followup/retry-1/freshness-runs/codex--original--r2.json)
추가 Codex 호출은 중단했습니다. 더 구체적으로 쓴 추출 요청은 아직 실행하지 않았습니다.

## 2. Claude의 남은 인계 두 건은 완료했습니다

Codex 서버 상태에 영향을 받지 않는 인계 두 조건을 이어서 시험했습니다.
앞선 Codex가 남긴 회고 처리 코드를 Claude가 받아 실제 파일과 전체 테스트를 확인했습니다.
첫 AI의 수정은 보존된 원본을 그대로 사용했습니다.
[실행 계획](../experiments/stage-followup/retry-1/claude-continuation-manifest.json)

두 조건 모두 완료 응답을 받았고 독립 검사 94개를 통과했습니다.
대상 밖의 파일과 사람이 남긴 주석도 보존했습니다.

| Claude가 받은 자료 | 도구 사용 | 입력 토큰 | 준비부터 독립 검증까지 | CLI 보고 비용 |
|---|---:|---:|---:|---:|
| 작업 카드 | 5번 | 58,565개 | 138.5초 | $0.059219 |
| 카드와 관찰 파일 링크 | 8번 | 99,509개 | 142.3초 | $0.092157 |

이번에도 관찰 파일을 여는 호출은 없었습니다.
이전 실행까지 합쳐 관찰 파일을 제공한 세 번 모두 해당 파일을 여는 호출이 없었습니다.
링크를 제공하는 것만으로 자료가 전달되지는 않았습니다.
이번 조건에서는 입력과 도구 사용이 늘었지만, 한 번씩 수행한 비교이므로 안정적인 차이라고 단정할 수 없습니다.
관찰 내용을 읽지 않았으므로 그 내용이 성능을 바꿨다고 해석할 수도 없습니다.

실제 CLI 인계의 원래 여덟 조건 중 여섯 조건을 정상 완료했습니다.
한 조건은 앞선 Codex 서버 오류 뒤 파일 검사만 통과했습니다. 한 조건은 아직 실행하지 않았습니다.
실제 코드의 수정 완료와 Stage 드라이버·독립 리뷰·공식 종료까지의 검증은 계속 구별합니다.
Claude가 테스트 출력을 파이프로 처리한 경우가 있어 독립 검사는 실제 프로세스 종료 코드를 사용했습니다.

## 3. 이번 결과가 제안에 미치는 영향

- 기준을 저장할 때 원문과 연결하는 검사는 필요합니다. 이번에는 형식이 맞지 않은 기준이 판단에 들어가기 전에 멈췄습니다.
- 어떤 단위로 출처를 적을지 먼저 정해야 합니다. 여러 출처를 지원하려면 저장 형식과 검사도 함께 바꿔야 합니다.
- 확인하지 않은 범위를 AI가 채워 넣는지도 봐야 합니다. 인용이 실제로 존재하는지만 검사해서는 부족합니다.
- Codex 서버 오류가 반복돼 남은 비교를 마쳤다고 보고할 수 없습니다.

## 기록과 적용 범위

이번에 CLI를 네 번 호출했습니다. 세 번은 정상 종료했고 한 번은 서버 오류로 끝났습니다.
정상 종료한 세 번 중 기준 추출 한 번은 형식 검사를 통과하지 못했습니다.
이전 실행까지 합치면 29번을 호출했고, CLI 서버 오류는 세 번입니다.
Claude의 이번 보고 비용은 $0.151376이며 앞선 실행과의 합계는 $0.703585입니다.
실제 청구서는 확인하지 않았습니다. Codex 과금 금액과 서버 오류가 난 호출의 사용량은 알 수 없습니다.

CLI 버전과 호출 설정은 이전 실행과 같습니다. Codex는 이전과 같은 CLI 기본 모델 설정을 사용했습니다.
모델 ID를 명시적으로 고정한 실험은 아닙니다. 재시도 시각과 임시 경로도 달라집니다.
따라서 다른 시간에 얻은 기록을 같은 시점의 비교처럼 해석하지 않습니다.

이전 원본 JSON 38개가 바뀌지 않았음을 확인했습니다.
실행기·입력·이전 수정의 해시와 변경 경로·검사 결과를 대조했고 불일치는 없었습니다.

연구용 실행기와 기록만 추가했습니다. 제품 코드, 버전, 사용자 설정과 원래 작업 카드는 바꾸지 않았습니다.
전체 계획과 운영 검증의 경계는 [후속 연구 범위](../followup-plan.md)에 남아 있습니다.

## 남은 일

1. Codex가 회고 처리 코드를 이어받는 두 조건입니다. 하나는 앞선 오류의 재시도이고 하나는 미실행 조건입니다.
2. 출처 단위를 분명히 한 Codex 기준 추출과 이후 판단 12번입니다. 원래 조건의 추출 실패는 별도로 유지합니다.
3. Codex 관찰 시점 비교 여섯 번에서 정상 응답을 확보해야 합니다. 이번 첫 시도는 서버 오류로 끝났습니다.
4. Stage 전체 운영 과정과 실무에서 반복되는 판단 비율은 별도 검증이 남아 있습니다.

Codex 호출을 성공할 때까지 반복하거나 다른 모델로 바꾸지 않았습니다. 연구 전체를 완료했다고 표시하지 않습니다.
