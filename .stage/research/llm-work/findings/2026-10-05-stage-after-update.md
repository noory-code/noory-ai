# Codex 업데이트 후 이어간 비교

**업데이트 후 남아 있던 실험 16번을 모두 마쳤습니다. 새 실행 오류는 없었습니다.**
판단 여덟 번, 관찰 시점 비교 여섯 번과 실제 작업 인계 두 조건을 확인했습니다.
실험에 쓰는 Codex CLI는 `0.146.0`에서 `0.160.0`으로 바뀌었습니다.
기존에 성공한 추출과 판단은 보존하고, 남은 입력을 같은 실행기에 전달했습니다.
업데이트가 서버 오류를 해결한 원인인지까지 확인한 것은 아닙니다.

[원본과 대조한 집계](../experiments/stage-followup/after-update/summary.json)

## 1. 원문과 추출한 기준은 같은 판단을 만들었습니다

남아 있던 네 상황을 두 조건에서 각각 확인했습니다.

| 상황 | 원문 기록을 사용 | 추출한 기준을 사용 |
|---|---|---|
| A의 CSV에서만 허용한 예외를 PDF에도 적용하려 합니다. | 사용자에게 예외 허용을 물었습니다. | 같은 판단을 했습니다. |
| 현재 사용자가 A의 PDF에 Q를 쓰라고 지시합니다. | 현재 지시에 따라 Q를 선택했습니다. | 같은 판단을 했습니다. |
| C에서 구현을 고르는데 프로젝트의 우선순위가 없습니다. | 우선순위를 물었습니다. | 같은 판단을 했습니다. |
| AI의 미확인 추측과 A의 정확성 요구가 다릅니다. | 정확한 알고리즘을 선택했습니다. | 같은 판단을 했습니다. |

앞서 확보한 두 상황까지 합치면 Codex의 두 조건은 각각 여섯 번 모두 기대 답과 일치했습니다.
Claude도 앞선 동일한 상황 여섯 개에서 두 조건 모두 기대 답과 일치했습니다.
명시된 합성 기록을 적용한 결과입니다. 사용자의 실제 취향을 배웠다고 해석하지 않습니다.
Codex의 추출 요청에는 출처 단위를 더 명확히 한 설명이 들어갔으므로 두 호스트의 추출 성능 순위를 매기지 않습니다.

업데이트 후 실행한 네 상황만 비교하면 다음과 같습니다.

| 받은 자료 | 기대 답과 일치 | 입력 토큰 | 응답 시간 합계 |
|---|---:|---:|---:|
| 원문 | 4/4 | 32,741개 | 40.6초 |
| 추출한 기준 | 4/4 | 33,619개 | 34.5초 |

시간은 한 번씩 실행한 결과입니다. 안정적인 속도 개선이라고 단정하지 않습니다.
이 표에는 앞서 수행한 기준 추출과 실패한 호출, 요청 사이의 대기 시간을 넣지 않았습니다.
업데이트 전후 수치를 합쳐 같은 환경에서 반복한 값처럼 비교하지도 않습니다.
짧은 원문에서 기준을 따로 추출하면 판단 입력이 늘어난다는 관찰은 이번에도 유지됐습니다.

**현재 제안:** 짧은 기록에는 추출 단계를 일괄 추가하지 않습니다.
기준을 오래 재사용할 필요가 있을 때 출처·적용 범위·확인 여부를 함께 보존하는 방향을 검토합니다.
긴 기록에서 얻을 이득은 별도 측정이 필요합니다.

## 2. 관찰 시점을 설명해도 Codex의 다음 행동은 같았습니다

과거에 파일을 다시 읽었던 입력 한 개를 원본 그대로 세 번 실행했습니다.
같은 파일을 인계 직전의 관찰이라고 설명한 입력도 세 번 실행했습니다.
Codex는 두 조건에서 모두 완료를 선택했습니다.

| 다음 행동 | Claude 원본 | Claude 시점 명시 | Codex 원본 | Codex 시점 명시 |
|---|---:|---:|---:|---:|
| 다시 읽기 | 1번 | 0번 | 0번 | 0번 |
| 완료 | 2번 | 3번 | 3번 | 3번 |

Claude와 Codex는 다른 시점에 실행했습니다. 이 표로 호스트의 성능 순위를 매기지 않습니다.
앞선 결과를 보고 고른 입력 한 개를 반복한 시험이며 실제 새 과제 12개가 아닙니다.
선택한 행동만 기록했고 추가 읽기를 오답으로 채점하지 않았습니다.

**현재 제안:** 관찰 시점을 기록할 이유는 남아 있습니다. 후속 수정과 과거 관찰을 구별할 수 있기 때문입니다.
이번 결과만으로 재확인 횟수나 전체 작업 시간이 안정적으로 줄어든다고 주장하지 않습니다.

## 3. 실제 작업 인계 두 조건도 완료했습니다

앞선 Claude가 남긴 회고 처리 코드를 Codex가 이어받았습니다.
카드만 받는 조건과 관찰 파일 링크를 함께 받는 조건은 같은 초기 파일에서 시작했습니다.
두 조건 모두 완료 응답을 받았고, 독립 검사에서 전체 테스트 94개를 통과했습니다.
대상 밖의 파일은 바꾸지 않았고 사람이 남긴 주석도 보존했습니다.

| Codex가 받은 자료 | 도구 사용 | 입력 토큰 | 조건별 자료 준비부터 독립 검증까지 |
|---|---:|---:|---:|
| 작업 카드 | 7번 | 158,693개 | 108.9초 |
| 카드와 관찰 파일 링크 | 7번 | 188,461개 | 115.3초 |

공통 초기화와 파일 복사 시간은 위 시간에서 제외했습니다.
관찰 파일을 제공한 조건에서도 그 파일을 여는 호출은 없었습니다. 실제 소스와 테스트를 읽었습니다.
앞선 비교까지 합쳐 관찰 파일을 제공한 네 번 모두 같은 결과였습니다.
**파일을 저장하고 링크를 붙이는 것만으로 AI가 그 내용을 사용한다고 볼 수 없습니다.**
그 내용을 활용한 효과를 평가하려면 실제로 전달됐는지부터 확인해야 합니다.

독립적인 과거 결함 두 개에서 두 방향·두 조건의 정상 결과를 모두 확보했습니다.
조건은 여덟 개이고 실제 인계 시도는 아홉 번입니다. 앞선 서버 오류 한 번도 그대로 포함했습니다.
각 조건을 한 번씩 마친 결과이므로 일반적인 작업 인계 성공률로 해석하지 않습니다.

**현재 제안:** 목적·대상·완료 검사·남은 일을 담은 Stage 작업 기록은 유지할 근거가 있습니다.
관찰 파일 링크를 별도로 더하는 방식의 효과는 확인하지 못했습니다.

## 이번 비교에서 정리된 판단

| 개선 후보 | 현재 판단 | 근거 |
|---|---|---|
| 목적과 완료 검사를 담은 작업 기록으로 이어갑니다. | 유지할 후보입니다. | 여덟 조건에서 실제 수정과 독립 검사를 마쳤습니다. |
| 짧은 기록에서도 기준을 먼저 추출합니다. | 일괄 적용하지 않습니다. | 판단은 같고 추출 단계와 입력이 늘었습니다. |
| 관찰 파일을 만들어 링크를 추가합니다. | 이번 방식의 적용을 보류합니다. | 제공한 네 번 모두 해당 파일을 열지 않았습니다. |
| 과거 관찰과 후속 변경을 구별합니다. | 기록 원칙으로 유지합니다. | 혼동을 설명할 수 있지만 안정적인 성능 개선은 입증하지 못했습니다. |
| 같은 조건의 판단을 재사용합니다. | 실무 절감량은 미확인입니다. | 실험에서는 호출을 줄였지만 실제 반복 비율을 계산할 기록이 부족합니다. |

## 완료한 범위와 남은 연구

서버 오류 때문에 밀렸던 비교는 모두 결과를 확보했습니다.
원래 요청으로 실패한 기준 추출은 보존했고, 출처 단위를 명시한 요청을 별도로 평가했습니다.
두 호스트에서 기준을 적용한 판단은 총 24번이며 모두 기대 답과 일치했습니다.
관찰 시점 비교는 12번, 실제 인계는 여덟 조건을 확인했습니다.

아직 남은 질문은 두 가지입니다.

1. Stage의 드라이버·독립 리뷰·회고·공식 종료까지 연결해도 같은 작업을 정확히 이어갈 수 있는지 확인해야 합니다.
2. 실무에서 같은 조건의 판단이 얼마나 반복되는지 기록해야 실제 절감량을 계산할 수 있습니다.

이 두 가지를 검증하지 않은 상태에서 연구 전체나 제품 적용을 완료했다고 표시하지 않습니다.

## 해석의 범위

실행기와 이전 입력을 바꾸지 않았고, CLI 버전 변화는 별도로 기록했습니다.
기본 모델 설정을 유지했으며 모델 ID를 명시적으로 고정한 비교는 아닙니다.
이전 서버 오류와 출처 검사 실패는 그대로 보존했습니다.

이번 비교는 Stage 카드에 적힌 목적·대상·검사를 읽고 실제 코드를 고치는 과정까지 다룹니다.
Stage 드라이버·독립 모델 리뷰·회고·공식 종료까지 연결한 운영 시험은 아직 수행하지 않았습니다.
실무에서 같은 판단이 반복되는 비율도 현재 로그만으로 계산할 수 없습니다.

후속 시험과 재시도의 CLI 호출은 총 53번이며 서버 오류는 기존 여섯 번입니다.
이번 16번에서는 오류가 없었지만 업데이트가 원인이었다고 단정하지 않습니다.
별도 연결 확인은 이 횟수에 포함하지 않았습니다.
Claude의 보고 비용 합계는 $0.703585이며 이번에는 Claude를 추가로 호출하지 않았습니다.
Codex 과금 금액과 오류가 난 호출의 사용량은 알 수 없습니다.

이전 기록 JSON 68개가 그대로 남아 있는지 확인했습니다.
실행기·입력·추출 근거·채점·수정 전후 파일 해시를 대조했고 불일치는 없었습니다.
연구 기록과 실행기만 작성했습니다. 플러그인 코드·버전·사용자 설정·원래 작업 카드는 바꾸지 않았습니다.
