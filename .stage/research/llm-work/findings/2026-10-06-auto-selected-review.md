# 검토할 함수를 AI가 찾게 하자 전체 비용이 늘었습니다

2026년 10월 6일에 실제 Claude·Codex CLI 호출 48번을 마쳤습니다.
최종 판정 32개는 모두 기대 답과 일치했습니다. 그러나 함수를 고르는 호출까지 더하자 입력과 시간이 늘었습니다.
Claude가 보고한 금액도 두 과제 모두 늘었습니다. Codex는 금액을 반환하지 않아 계산하지 않았습니다.

**자료를 줄이는 단계만 보면 절약처럼 보였지만, 자료를 찾는 비용까지 합치면 손해였습니다.**
이는 과거 결함 두 개에서 확인한 결과입니다. 모든 검색이나 코드 리뷰에 일반화하지 않습니다.

## 무엇을 비교했나요

[앞선 실험](2026-10-05-selected-review.md)에서는 사람이 검토를 시작할 함수를 지정했습니다.
이번에는 그 선택을 AI에게 맡겼습니다. 선택 비용을 포함해도 이득이 남는지 확인하려 했습니다.

| 조건 | 수행한 일 | 요청당 CLI 호출 |
|---|---|---:|
| 전체 파일 | 파일 전체를 전달해 검토합니다. | 1번 |
| AI가 범위를 선택 | 함수 목록에서 시작 함수를 고릅니다. 코드로 연결된 범위를 모은 뒤 별도로 검토합니다. | 2번 |

함수 목록에는 이름·인자·설명·같은 파일의 참조 관계를 넣었습니다.
함수 본문과 정답, 수정 전후를 알리는 표시는 주지 않았습니다.
검토하는 호출에는 함수를 고른 이유를 전달하지 않았습니다.
선택이 잘못된 형식이거나 목록에 없는 이름이면 전체 파일을 사용하도록 정했습니다.

과거 결함 두 개의 수정 전후를 두 호스트에서 각각 두 번 비교했습니다.
총 요청은 32번입니다. 전체 파일 검토 16번, 함수 선택 16번, 선택한 범위 검토 16번으로 CLI 호출은 48번입니다.
호스트마다 조건 순서를 번갈아 바꿨습니다. 입력과 실행 규칙은 호출 전에 고정했습니다.
서버 오류와 누락은 없었습니다. 틀린 답을 버리고 재시도한 기록도 없습니다.

## 코드를 줄인 과제에서도 전체 비용이 늘었습니다

회고 파일의 소유자가 충돌하는 결함을 검토했습니다.
두 호스트 모두 여덟 번의 선택에서 `write_driver_retrospective`를 골랐습니다.
이 함수에 연결된 코드만 전달해 검토 입력을 줄일 수 있었습니다.

아래 각 행은 수정 전후를 두 번씩 검토한 요청 네 번의 합계입니다.
입력에는 캐시에서 읽은 토큰도 포함합니다. 금액은 CLI 보고값이며 실제 청구서를 확인한 값은 아닙니다.

| 호스트 | 조건 | 전체 입력 토큰 | 보고 금액 | 요청 시간 합계 | 기대 답과 일치 |
|---|---|---:|---:|---:|---:|
| Claude | 전체 파일 | 25,429 | $0.113330 | 19.31초 | 4/4 |
| Claude | AI가 범위를 선택 | 27,336 | $0.127072 | 33.96초 | 4/4 |
| Codex | 전체 파일 | 44,632 | 미확인 | 31.50초 | 4/4 |
| Codex | AI가 범위를 선택 | 74,848 | 미확인 | 61.35초 | 4/4 |

Claude의 전체 입력은 7.5%, 보고 금액은 12.1% 늘었습니다. Codex의 전체 입력은 67.7% 늘었습니다.
관찰한 시간도 모두 늘었습니다. 표본이 작고 서버 상태가 달라질 수 있어 일반적인 지연율로 제시하지 않습니다.

### 검토 단계만 계산하면 반대 결론이 나옵니다

Claude의 요청 네 번을 단계별로 나누면 아래와 같습니다.

| 단계 | 입력 토큰 | 보고 금액 | CLI 실행 시간 합계 |
|---|---:|---:|---:|
| 시작 함수를 고릅니다. | 9,460 | $0.043864 | 14.35초 |
| 선택한 코드를 검토합니다. | 17,876 | $0.083208 | 19.56초 |
| 두 단계를 합칩니다. | 27,336 | $0.127072 | 33.91초 |

검토만 보면 전체 파일의 $0.113330보다 **26.6% 저렴합니다.**
함수를 고른 비용 $0.043864를 더하면 **12.1% 더 비쌉니다.**
Claude의 로컬 읽기·선택·저장 등에 쓴 시간은 네 요청을 합쳐 약 0.047초였습니다.
이번에는 추가 CLI 호출이 대부분의 부담을 만들었습니다. CLI 시간에서 모델 추론과 서버 대기를 따로 나누지는 못했습니다.

Codex도 범위를 고르는 데 입력 토큰 35,028개와 약 28.58초를 더 썼습니다.
이후 검토의 입력은 39,820개였으며, 그중 캐시에서 읽은 입력은 5,632개였습니다.
따라서 입력 증가율을 금액 증가율로 바꿔 말할 수는 없습니다.

## 다른 과제에서는 입력을 줄이지도 못했습니다

마일스톤 기준을 반복해서 전달하는 결함에서는 Claude가 `create_milestone`을, Codex가 `main`을 골랐습니다.
각각 네 번 모두 같은 함수를 골랐습니다. 하지만 기존 선택기는 어느 경우에도 파일 전체를 반환했습니다.
모듈의 실행문을 보존하고 그곳에서 참조하는 함수까지 따라가면 전체 함수가 포함되기 때문입니다.

| 호스트 | 조건 | 전체 입력 토큰 | 보고 금액 | 요청 시간 합계 | 기대 답과 일치 |
|---|---|---:|---:|---:|---:|
| Claude | 전체 파일 | 44,266 | $0.194158 | 23.40초 | 4/4 |
| Claude | AI가 범위를 선택 | 56,390 | $0.250348 | 47.09초 | 4/4 |
| Codex | 전체 파일 | 56,732 | 미확인 | 30.84초 | 4/4 |
| Codex | AI가 범위를 선택 | 93,458 | 미확인 | 59.54초 | 4/4 |

최종 검토 입력은 여덟 비교 쌍 모두 같은 해시였습니다. 범위를 고르는 호출만 추가됐습니다.
이 결과는 이번 선택기의 한계입니다. 이 파일을 어떤 방법으로도 줄일 수 없다는 뜻은 아닙니다.
입력이 같아도 출력과 시간은 달라졌으므로 차이 전부를 선택 단계 탓으로 돌리지는 않습니다.

## 호출을 마친 뒤 코드로 더 확인했습니다

모델을 추가로 부르지 않고 모든 시작 함수에 기존 선택기를 적용했습니다.
마일스톤 파일은 수정 전후 각각 함수 23개 중 어느 것을 골라도 원문 전체가 남았습니다.
각 파일을 확인하는 데 약 0.12초와 0.11초가 걸렸습니다.
이 선택기를 계속 쓴다면, 줄일 수 있는 범위가 있는지 먼저 확인해 불필요한 AI 호출을 피할 후보가 됩니다.
실제 운영에 이 검사를 연결해 절약량을 측정한 결과는 아닙니다.

회고 과제는 검토 기준에 `write_driver_retrospective`라는 이름이 이미 들어 있었습니다.
이번에는 이미 주어진 단서를 찾으려고 AI를 한 번 더 부른 셈입니다.
다만 기준에 등장하는 함수가 언제나 올바른 시작점은 아닙니다. 금지한 동작이나 보조 함수를 설명할 수도 있습니다.
작업 기록에 검토 시작점을 명시하고 그 출처와 현재 코드를 확인하는 방식을 다음 후보로 남깁니다.

이 분석은 결과를 본 뒤 추가했습니다. 세 번째 비교 조건으로 집계하지 않습니다.
처음에는 함수 이름 뒤에 한국어 조사 `로`가 붙으면 이름을 놓쳤습니다.
ASCII 식별자 경계로 고치고 두 검사를 추가한 뒤 분석 결과를 다시 저장했습니다.
앞선 CLI 호출 48번과 원본 응답은 바꾸지 않았습니다.

## 무엇을 적용할 후보로 남기나요

1. **이미 아는 범위는 다시 찾지 않습니다.** 작업 기준이나 변경 내역에서 출처가 분명한 시작점을 확인합니다.
2. **코드로 입력을 줄일 수 있는지 먼저 확인합니다.** 선택 결과가 항상 원문 전체라면 범위를 고르는 AI 호출을 생략할 수 있습니다.
3. **AI가 범위를 고를 때는 전체 요청을 측정합니다.** 선택·검색·검토·누락을 보완한 비용까지 합쳐 비교합니다.

지금 근거로 모든 검토 앞에 AI 선택 단계를 붙일 이유는 없습니다.
범위가 정해지지 않은 새 과제에서 이득이 생기는지는 별도로 확인해야 합니다.
Stage·Distill·Avatar에도 기록을 정리하거나 찾는 비용을 포함해 효과를 판단해야 한다는 제안으로 남깁니다.
이번 연구에서 제품 동작을 바꾸지는 않았습니다.

## 확인한 범위와 한계

- 대상 파일은 이미 주어졌습니다. 저장소 전체에서 파일을 찾는 비용은 재지 않았습니다.
- 앞선 연구에서 사용한 결함 두 개를 재사용했습니다. 처음 보는 과제로 검증한 결과는 아닙니다.
- 최종 행동과 대상 기준 ID를 채점했습니다. 설명 전체와 범위 밖의 결함, 다른 파일의 의존성은 채점하지 않았습니다.
- 함수를 고른 응답 16개는 이름·형식 검사를 통과했습니다. 이 검사만으로 의미상 올바른 선택을 보장하지는 않습니다.
- 요청 시간은 원본 읽기부터 첫 결과 저장까지입니다. 개발 시간과 과제 준비, 실험 후 집계는 제외했습니다. 병렬로 실행한 두 호스트의 합계를 실험 경과 시간으로 해석하지 않습니다.
- Claude Code 2.1.289에서 `claude-sonnet-5-5`를 요청했습니다. Codex CLI 0.160.0에서는 기본 모델과 `low` effort를 요청했습니다. 양쪽 실제 모델을 모두 고정한 비교가 아니므로 호스트 순위를 매기지 않습니다.
- 이번 실험 전체에서 Claude CLI가 보고한 금액은 $0.684908입니다. Codex 금액은 미확인으로 남겼습니다.
