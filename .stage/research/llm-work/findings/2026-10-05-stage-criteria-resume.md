# 출처 규칙을 명시한 뒤 기준 추출과 판단을 이어간 결과

이 문서는 업데이트 전의 실행 기록입니다. 이후 [남은 비교 16번을 마친 결과](2026-10-05-stage-after-update.md)를 별도로 남겼습니다.

**기준 추출은 검사를 통과했습니다. 두 상황에서 원문과 추출한 기준을 각각 사용한 네 판단도 모두 맞았습니다.**
다만 서버 혼잡이 반복돼 전체 비교를 마치지는 못했습니다.
정상 응답을 받은 판단만으로 기준 추출이 정확도를 높였다고 해석하지 않습니다.
[원본과 대조한 집계](../experiments/stage-followup/retry-3/summary.json)

## 1. 요청문과 출처 검사에서 같은 단위를 요구했습니다

앞선 요청에서는 기준 한 개에 출처 두 개를 합쳐 적어 검사가 멈췄습니다.
이번에는 기준마다 원문 ID 하나와 그 원문에 연속해서 나오는 인용만 적으라고 명시했습니다.
두 원문이 필요하면 기준을 나누도록 했습니다. 원래 실패 기록은 그대로 남겼습니다.

이번 Codex 응답은 기준 일곱 개를 만들었고 형식과 인용 검사를 통과했습니다.
추출에는 약 20.0초가 걸렸습니다. 입력 토큰 8,696개와 출력 토큰 695개를 보고했습니다.
[실제 추출 응답](../experiments/stage-followup/retry-2/criteria-single-source/extract--codex.json),
[검사 결과](../experiments/stage-followup/retry-2/criteria-single-source/extraction-check--codex.json)

| 원문 | 이번 추출 결과를 읽고 확인한 내용 |
|---|---|
| N1: A의 목적 | 인터넷 없이 내보내기와 정확한 결과라는 기준 두 개로 나눴습니다. |
| N2: A의 기본 방침 | 새 패키지 제한과 표준 라이브러리 우선이라는 기준 두 개로 나눴습니다. |
| N3: 제한된 예외 | P를 허용하는 범위를 A의 CSV로 남겼습니다. |
| N4: AI의 미확인 추측 | 상태를 `unconfirmed`로, 프로젝트를 `미지정`으로 남겼습니다. |
| N5: B의 허용 | Q를 허용하는 범위를 B로 남겼습니다. |

이전 응답은 프로젝트명이 없는 N4를 A로 분류했지만 이번에는 미지정으로 남겼습니다.
한 번의 응답 차이이며, 출처 지침만으로 범위 추정 문제가 해결됐다고 단정할 수 없습니다.

N4의 `rule` 문장만 읽으면 “정확성보다 속도를 중시한다”라고 나옵니다.
같은 항목의 `unconfirmed`와 원문 인용을 함께 읽어야 AI의 추측임을 알 수 있습니다.
**기준을 짧게 전달할 때도 적용 범위와 확인 여부를 함께 보존해야 합니다.**
이번 자료의 구조를 읽고 얻은 판단입니다. 상태를 뺐을 때 실제로 오판하는지까지 시험하지는 않았습니다.

## 2. 판단 두 종류를 두 조건에서 확인했습니다

원래 계획한 여섯 상황 중 두 상황에서 정상 응답을 확보했습니다.
성공한 추출과 판단은 다시 호출하지 않았습니다. 이후 호출에는 같은 추출 결과를 사용했습니다.

| 확인한 상황 | 원문 기록을 사용 | 추출한 기준을 사용 |
|---|---|---|
| A의 JSON 요구를 표준 라이브러리가 모두 충족합니다. | 표준 라이브러리를 선택했습니다. | 같은 선택을 했습니다. |
| A의 CSV에는 P가 필요하고 사용자가 이미 허용했습니다. | P를 선택했습니다. | 같은 선택을 했습니다. |

각 조건의 정상 응답 두 번만 비교하면 다음과 같습니다.

| 받은 자료 | 기대 답과 일치 | 입력 토큰 | 응답 시간 합계 |
|---|---:|---:|---:|
| 원문 | 2/2 | 15,034개 | 22.9초 |
| 추출한 기준 | 2/2 | 15,470개 | 23.9초 |

위 표에는 추출 자체의 비용과 서버 오류·대기를 더하지 않았습니다.
전체 시도는 [집계의 원본 목록](../experiments/stage-followup/retry-3/summary.json)에 남겼습니다.
짧은 원문을 정리한 이번 두 상황에서는 판단이 같고 입력은 늘었습니다.
긴 기록을 여러 번 재사용할 때의 효과는 아직 확인하지 못했습니다.

## 3. 실패한 호출을 오답으로 세지 않았습니다

남은 판단을 이어가는 별도 실행에서는 요청 사이에 5초 간격을 뒀습니다.
혼잡 오류가 나오면 30초 뒤 한 번만 재시도하도록 정했습니다.
다음 문제는 A에서 PDF를 만드는 상황이었습니다. Q가 필요했지만 기존 허용은 CSV의 P로 제한돼 있었습니다.
그 입력에서 두 번 연속 오류가 나 추가 호출을 중단했습니다.
[재시도 정책과 입력](../experiments/stage-followup/retry-3/manifest.json),
[종료 상태](../experiments/stage-followup/retry-3/status.json)

기존 실행기 일부는 응답이 없을 때도 `matches: false`를 저장합니다.
이번 종합 집계에서는 CLI 오류가 있으면 채점값을 `null`로 해석했습니다.
실패한 호출은 그대로 세고, 실제 답을 받아 채점한 횟수를 별도로 보여 줍니다.

지원 목록에 있던 GPT-5.6 Sol을 직접 지정한 연결 확인에서도 같은 혼잡 오류를 받았습니다.
이 호출은 연구 비교 횟수에 포함하지 않았습니다. 연구 입력을 다른 모델의 성공으로 대체하지 않았습니다.
[별도 연결 확인 기록](../experiments/stage-followup/retry-3/sol-probe.json)

## 이번에 확보한 결과와 남은 일

이번 연구 호출은 여덟 번입니다. 다섯 번은 정상 종료했고 세 번은 서버 오류로 끝났습니다.
정상 종료한 결과는 기준 추출 한 번과 판단 네 번입니다. 별도 연결 확인 한 번도 오류로 끝났습니다.
앞선 연구까지 합치면 CLI 호출 37번 중 오류가 여섯 번입니다.
Claude의 기존 보고 비용 합계는 $0.703585이며 이번에 Claude를 추가로 호출하지 않았습니다.
Codex 과금 금액과 오류가 난 호출의 사용량은 알 수 없습니다.

다음 실행에서는 이미 얻은 추출과 판단을 그대로 사용하고 남은 항목을 이어갈 수 있습니다.

- **기준 적용 여덟 번:** 예외 범위, 현재 지시 변경, 다른 프로젝트의 기준, 미확인 추측을 각각 두 조건에서 확인해야 합니다.
- **관찰 시점 비교 여섯 번:** Codex에서 정상 응답을 확보해야 합니다.
- **Codex 작업 인계 두 조건:** 앞선 오류가 난 조건과 아직 실행하지 않은 조건이 남았습니다.
- **운영 검증:** Stage의 전체 실행 과정과 실무 판단 재사용률은 별도 검증이 필요합니다.

이전 기록 JSON 60개와 실행기·입력·채점 결과를 대조했고 불일치는 없었습니다.
연구 전체를 완료했다고 표시하지 않았습니다. 제품 코드·버전·원래 작업 카드·사용자 설정은 바꾸지 않았습니다.
