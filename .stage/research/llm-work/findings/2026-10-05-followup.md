# 반복 실험에서 얻은 결과와 얻지 못한 결론

**후속 실행 174건과 문제를 보완한 96건을 마쳤습니다. 가장 분명한 차이는 정보의 보존과 결과 확인에서 나왔습니다.**
목적을 먼저 적게 하는 지침은 효과를 확정하지 못했습니다.
잘못 만든 평가 문제도 발견했으므로 원래 점수와 그 한계를 함께 남깁니다.

## 방법과 규모

아래 표는 먼저 수행한 174건의 조건입니다. 보완한 96건은 별도 절에 정리했습니다.

| 항목 | 조건 |
|---|---|
| 문제 | 합성 문제 30개입니다. 목적 12개, 문맥·결과·기억 각 4개, 규칙 6개입니다. |
| 반복 | 조건마다 3번 실행했습니다. 문맥은 세 조건, 나머지 비교는 두 조건입니다. 규칙은 모델 조건 하나와 로컬 함수를 비교했습니다. |
| 실행 | Claude Agent SDK `0.2.163`, Claude Code `2.1.289`, 요청 모델 `claude-sonnet-5-5` |
| 추론 | 비활성화를 요청했지만 2건에서 추론 토큰이 보고됐습니다. 완전히 통제하지 못했습니다. |
| 격리 | 매 실행마다 새 임시 폴더와 대화를 썼습니다. 도구·MCP·프로젝트 설정을 사용하지 않았습니다. |
| 순서 | 미리 정한 시드로 순서를 섞었습니다. 두 실행씩 병렬로 수행했습니다. |
| 채점 | 모델에 보내지 않은 기대값과 응답의 decision을 비교했습니다. 본문 검토로 평가 오류도 살폈습니다. |
| 실행·파싱 오류 | 0건이었습니다. 시작한 174건 모두 기록했습니다. |
| 비용 | SDK 보고 합계 1.16535달러입니다. 기존 예비 실험까지 합하면 1.2253886달러입니다. 실제 청구액은 조회하지 않았습니다. |

원본과 문제별 반복 결과는 [전체 집계](../experiments/runs/2026-10-05-followup-summary.json)에 있습니다.
입력·기준·해시는 실행 전에 고정했습니다. [자료와 재실행 방법](../experiments/README.md)
캐시와 서버 내부 동작은 완전히 통제하지 못했습니다.
174건을 서로 다른 문제 174개처럼 해석하지 않습니다.
특히 문맥 문제 4개는 같은 구조에서 지역과 자료 위치를 바꾼 변형입니다.

## H01 목적을 먼저 적게 하면 나아졌나요

원래 기대값과 일치한 횟수는 기본 지침 31/36건, 목적 점검 27/36건이었습니다.
**이 숫자로 목적 점검이 나빠졌다고 결론 내리지 않습니다.**

불일치한 14건의 이유를 모두 읽었습니다.
수정할 파일, 참고할 예시, 안내문에 넣을 내용이 빠진 문제에서 모델이 질문했습니다.
자료 없이 다음 행동을 고르는 과제인데 채점표는 요청 종류만 보고 수정을 정답으로 둔 셈입니다.
이 차이는 평가 설계의 결함입니다. 정당한 질문을 오답으로 세는 비율은 성능 지표로 쓸 수 없습니다.

예를 들어 `clear_edit`는 '파일을 수정해 달라'고만 했습니다.
목적 점검 조건은 3번 중 2번 파일을 먼저 물었습니다.
`example_post`는 '아래 내용'이라고 했지만 그 내용을 주지 않았습니다.
두 조건 모두 3번씩 추가 정보를 요청했습니다. 이 행동은 타당합니다.

점검 조건의 SDK 보고 출력은 평균 약 263토큰으로 기본 조건의 약 93토큰보다 많았습니다.
여기에는 일부 실행의 추론 토큰도 들어가므로 화면에 보이는 글의 길이와 같지 않습니다.
더 쓰도록 요구한 실험이므로 예상할 수 있는 결과입니다.
실제 과제 완료율 향상은 측정하지 않았습니다.
이후 자료를 보완한 72건에서는 두 조건 모두 36건씩 기준을 충족했습니다.
**판단: 일률적으로 목적 점검 문장을 추가하는 방안은 보류합니다.**
기존에 계획한 사람 검토와 전체 과제 실행을 거친 정식 평가를 대체하지 않습니다.

## H03 자료를 줄이면 무엇을 잃고 얻었나요

| 조건 | 실행 12건의 판단 | 평균 입력 토큰 |
|---|---|---:|
| 전체 자료 | 12건 모두 예외 지역에서 사용할 수 없다고 답했습니다. | 3,684 |
| 일반 규칙과 예외를 함께 추렸습니다. | 12건 모두 같은 판단을 유지했습니다. | 862 |
| 예외를 지우고 일반 규칙만 남겼습니다. | 12건 모두 확인할 수 없다고 답했습니다. | 823 |

입력 토큰은 SDK의 일반 입력·캐시 생성·캐시 읽기 필드를 합산한 값입니다.
필요한 조건을 함께 남긴 입력은 이번 자료에서 약 76.6% 짧았습니다.
이 비율은 읽을 문장을 작성한 단계의 비용이나 실제 요금 절감률을 뜻하지 않습니다.

예외를 잃은 모델이 전부 거짓 지원을 주장한 것은 아닙니다.
판단을 보류했지만, 원래 자료로는 답할 수 있던 질문에 답하지 못했습니다.
따라서 요약의 위험은 오답뿐 아니라 답할 수 있는 능력의 상실에도 있습니다.

추린 자료는 실험 작성자가 정답을 알고 만들었습니다.
자동 검색·추출기가 실제로 이 부분을 정확히 선택할지는 시험하지 않았습니다.
**판단: 적용 조건을 보존하는 자료 선택은 채택 후보입니다. 무조건 짧게 만드는 방법은 채택하지 않습니다.**

## H04 실제 결과를 알려 주면 무엇이 달라졌나요

임시 파일에서 정상 쓰기, 잘못된 경로, 일부 쓰기, 쓰지 않기를 만들었습니다.
실제 파일을 읽은 [관찰값](../experiments/followup-state-fixtures.json)과 모델의 판단을 대조했습니다.

| 제공한 정보 | 실행 12건의 판단 |
|---|---|
| 성공 신호만 제공했습니다. | 12건 모두 완료 여부를 모른다고 답했습니다. |
| 다시 읽은 파일 내용도 제공했습니다. | 정상 3건과 미완료 9건을 모두 구별했습니다. |

거짓 완료 보고는 두 조건 모두 0건입니다.
따라서 '거짓 완료 보고를 줄였다'는 원래 가설의 효과는 입증하지 못했습니다.
확인한 이점은 **보류하던 상황에서 실제 완료 여부를 판단할 수 있었다**는 점입니다.
**판단: 목표 상태를 읽어 주는 도구 응답은 채택 후보입니다.**
실제 도구 호출을 모델이 스스로 계획한 시험은 아닙니다. 저장한 관찰값을 입력으로 제공했습니다.

## H05 기억에 적용 범위를 붙이면 나아졌나요

적용 버전이 있는 조건은 12건 모두 기대한 판단을 내렸습니다.
같은 버전인 6건은 기능 지원 여부를 답하고, 다른 버전인 6건은 보류했습니다.

버전 없는 조건은 6건에서 미지원이라고 답하고, 6건에서 보류했습니다.
원래 채점표는 이 조건에서 전부 보류해야 한다고 정했습니다.
그러나 질문 직후에 제공한 기록을 질문한 버전의 자료로 읽을 가능성이 있습니다.
따라서 6/12건에서 12/12건으로 정확도가 개선됐다는 주장은 하지 않습니다.
정보를 더 준 조건이므로 모델 자체가 더 잘 판단하게 됐다는 증거도 아닙니다.

이후 적용 버전을 미기록으로 명시하자 해당 조건의 12건 모두 판단을 보류했습니다.
범위를 제공한 조건은 이전과 같이 6건은 답하고 6건은 보류했습니다.
**판단: 범위를 명시하는 기억 형식은 채택 후보입니다. 낡은 기억의 오류율 감소는 아직 보류합니다.**
이번에는 기록을 검색하거나 저장하는 과정, 시간이 흐른 뒤 갱신하는 과정은 시험하지 않았습니다.

## H06 일부 판단을 규칙으로 옮길 수 있었나요

명시한 형식과 규칙을 적용하는 문제 6개에서 모델은 18건 모두 같은 기대값을 냈습니다.
같은 규칙을 짧은 Python 함수로도 처리했습니다.
추가로 문자열 숫자, 누락된 승인, 알 수 없는 버전 등 15개 입력을 검사했습니다.
범위 밖 입력은 임의로 실행하지 않고 fallback을 반환했습니다.
완료 기준을 확인하는 모의 검사 3개도 통과했습니다. [로컬 검사 결과](../experiments/runs/2026-10-05-local-rules.json)

로컬 검사에는 모델 호출이 0회 필요했습니다.
다만 자연어를 정해진 형식으로 바꾸는 비용과 fallback 이후 처리 비용은 포함하지 않았습니다.
모델이 필요한 구간을 작은 모델로 대체하는 시험도 하지 않았습니다.
**판단: 규칙이 완전히 정해지고 입력 형식이 검사된 구간은 채택 후보입니다. 일반 의도 판단으로 확대하지 않습니다.**

## 모호한 문제를 고친 뒤 96건을 더 실행했습니다

목적 문제에는 수정할 파일의 내용, 글에 넣을 자료, 예시 등을 추가했습니다.
기억 문제에서는 버전 정보가 없을 때 '적용 버전 필드는 미기록'이라고 명시했습니다.
목적 문제 12개와 기억 문제 4개를 두 조건에서 3번씩 실행했습니다.
호출 함수와 요청 모델은 앞선 시험과 같습니다. 새 입력과 기준은 보완 실행 전에 저장했습니다.
다만 앞선 응답을 본 뒤 문제를 고쳤으므로 독립된 최종 평가로 보지 않습니다.

| 문제와 조건 | 실행 결과 | 평균 출력 토큰 | SDK 보고 비용 |
|---|---|---:|---:|
| 목적 — 기본 지침 | 36건 모두 기대한 행동을 골랐습니다. | 111 | 0.209558달러 |
| 목적 — 목적 점검 추가 | 36건 모두 기대한 행동을 골랐습니다. | 279 | 0.277898달러 |
| 기억 — 적용 버전 미기록 | 12건 모두 보류했습니다. | 98 | 0.065499달러 |
| 기억 — 적용 범위 제공 | 6건은 답하고 6건은 보류했습니다. 12건 모두 기준과 일치했습니다. | 105 | 0.069457달러 |

목적 점검을 추가해 더 많은 글을 쓰게 했지만, 이 문제들에서 판단이 나아지지는 않았습니다.
기억의 범위는 답할 수 있는 근거를 제공했습니다. 같은 정보를 더 잘 추론한 결과는 아닙니다.
계속하라는 문제에는 명시적인 재개 요청을 넣었습니다.
따라서 '네네'처럼 짧게 확인한 말을 해석하거나 장기 작업을 계속하는 능력을 입증하지 않습니다.

실행과 JSON 파싱 오류는 0건입니다. 보고된 추론 토큰도 96건 모두 0이었습니다.
문제·조건별로 첫 번째 응답 32건을 읽었고, 전체 96건의 상태값을 자동 대조했습니다.
별도의 사람이 검토한 결과는 아닙니다. [보완 실행 집계](../experiments/runs/2026-10-05-repaired-summary.json)

### 전체 실행 수와 비용

- 예비 10건, 후속 174건, 보완 96건으로 CLI 실행 총 280건을 기록했습니다.
- 보완 실행 비용은 0.622412달러입니다. 후속·보완 합계 1.787762달러로 정한 상한 5달러 안에서 마쳤습니다.
- 예비 실험까지 합한 SDK 보고 비용은 **1.8478006달러**입니다. 실제 청구액은 조회하지 않았습니다.
- 추가 모델 사용량도 보고돼 CLI 실행 280건을 서버의 모델 호출 280회로 바꾸어 말하지 않습니다.
- 로컬 규칙 검사 18개 항목은 CLI 실행 수에서 제외했습니다.

## 실제 개선 효과로 말할 수 없는 것

- 짧은 합성 문제를 잘 풀었다고 장기 작업도 끝까지 수행한다고 볼 수 없습니다.
- 반복 3번과 유사 문제 4개로 일반적인 성공률이나 통계적 유의성을 주장하지 않습니다.
- 정보량이 달라진 결과는 같은 정보를 더 잘 추론한 결과와 구별합니다.
- 캐시와 두 실행의 간섭을 제거하지 않았으므로 시간 차이를 처리 방식의 인과 효과로 보고하지 않습니다.
- 채점 기준에 문제가 있는 항목은 점수만 남겨 성능 향상을 주장하지 않습니다.
- 한국어 자연스러움과 사용자 만족도는 이 실험으로 채점하지 않았습니다.

## 설정한 값과 관찰값도 대조했습니다

추론 비활성화를 요청했지만 `example_cafe--purpose_check--3`에는 334토큰,
`example_post--purpose_check--1`에는 137토큰이 추론 사용량으로 기록됐습니다.
SDK 소스는 이 설정을 CLI의 `--thinking disabled`로 전달합니다.
[전달 코드](https://github.com/anthropics/claude-agent-sdk-python/blob/9c69ce7aced5cdf2aa1ac86fe62e877b4962de8b/src/claude_agent_sdk/_internal/transport/subprocess_cli.py#L757)
CLI·서버·집계 중 어디서 차이가 생겼는지는 확인하지 못했습니다.
따라서 입력 옵션이 같다는 사실만으로 실제 계산 조건까지 같았다고 주장하지 않습니다.
숨겨진 추론 내용은 읽거나 저장하지 않았습니다. 사용량 필드만 대조했습니다.
