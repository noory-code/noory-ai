# 실패한 결과에서 어느 단계를 고칠지 찾습니다

**결과가 틀렸다는 사실만으로는 무엇을 고쳐야 하는지 알 수 없습니다.**
아래에서는 직접 관찰한 사건, 다른 연구의 보고, 의도적으로 만든 시험을 구별합니다.

## 직접 관찰: 연구가 남았는데 응답을 끝냈습니다

이 연구 대화에서 사용자는 처음부터 연구를 진행해 문서로 남기라고 요청했습니다.
이후 진행 상태를 물었고, assistant는 남은 일이 있다고 보고했습니다.
사용자가 '네네'라고 하자 assistant는 '네, 알겠습니다.'라고만 답했습니다.
추가 작업이 없었고, 사용자는 연구가 끝났는지 다시 물었습니다.
assistant는 끝나지 않았다고 인정했습니다. 사용자는 연구를 끝까지 계속하라고 다시 요청했습니다.

**관찰할 수 있는 실패:** 맡은 연구가 남았는데 작업을 이어가지 않았습니다.
사용자가 다시 지시해야 했습니다. 그 순간 잘못된 연구 내용을 생성한 실패는 아닙니다.

**해석:** 짧은 확인 응답을 처리하면서 기존의 미완료 목적을 유지하지 못했습니다.
목적을 알고 설명하는 능력과, 다음 행동에서도 그 목적을 유지하는 능력은 구별해야 합니다.
내부의 기억 손실, API의 `phase` 누락, 숨겨진 프롬프트 중 무엇이 원인인지는 확인하지 못했습니다.
따라서 이 사례를 특정 API 결함으로 분류하지 않습니다.

**개선 후보:** 작업 상태에 목적·완료 기준·남은 일을 남깁니다.
진행 상황을 알리는 응답이 끝나더라도 작업 완료로 처리하지 않습니다.
진짜 완료, 사용자의 중단, 사용자 입력이 반드시 필요한 경우를 각각 구별합니다.
이는 프로그램에서 검사할 후보입니다. 모델이 '계속하겠다'고 말하는 것만 검사하면 부족합니다.

이 대화는 가설을 만드는 자료로 썼습니다. 동일한 발화를 평가 문제로 재사용해 개선율을 계산하지 않습니다.
새 합성 문제에서 다음 행동을 고르는 시험도 실제 장기 작업의 지속성을 대신하지 않습니다.

## 다른 연구: 자료를 못 찾은 실패와 찾고도 틀린 실패

[검색 에이전트 연구](https://arxiv.org/html/2608.01913v1)는 검색된 문서와 정답 근거를 대조합니다.
자료를 확보하지 못한 경우와 확보한 자료를 답으로 연결하지 못한 경우를 나눕니다.
검색 호출 형식이 실행기와 맞지 않아 거부된 경우도 별도로 설명합니다.
우리는 방법·실패 분류·한계 부분을 읽었습니다. 실험 전체를 재현하거나 원본 실행 기록을 검토하지는 않았습니다.

이 연구는 사전 공개 논문입니다. 최종 답 판정에 모델을 사용하며 자료 집합의 제약도 있습니다.
보고한 비율을 현재 서비스의 일반적인 실패율로 사용하지 않습니다.
연구 질문은 가져올 수 있습니다. **검색기를 바꾸기 전에, 질문이 검색기에 도달했는지부터 확인했나요?**

## 다른 자료: 평가 기준 때문에 틀렸다고 나오는 경우

Anthropic의 [평가 방법 글](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)은
최종 상태와 실행 기록을 구별하고, 사람이 기록을 읽어 평가 오류도 확인하라고 설명합니다.
모델이 올바른 다른 해법을 냈는데 고정된 절차만 정답으로 인정하면 개선 판단이 어긋날 수 있습니다.
이는 개발사의 경험 보고이며, 우리 시험의 타당성을 대신 보증하지 않습니다.

우리 시험에서도 기억의 버전이 생략된 문장을 어떻게 읽을지는 모호할 수 있습니다.
따라서 버전 없는 답변을 전부 모델 오류로 계산해 성능 개선을 주장하지 않습니다.
실험에서 정보가 늘어난 효과와 모델의 판단 능력이 좋아진 효과를 구별합니다.

## 통제 시험: 도구의 성공 신호와 실제 파일이 달랐습니다

임시 폴더에서 네 가지 경로를 만들었습니다.
정확히 쓰기, 다른 파일에 쓰기, 일부만 쓰기, 아무것도 쓰지 않기입니다.
각 경로 뒤 실제 파일을 다시 읽어 [상태 기록](../experiments/followup-state-fixtures.json)을 남겼습니다.
네 경로 모두 같은 성공 신호를 준 조건과, 실제 내용을 더 준 조건을 비교합니다.
실제 서비스에서 자연스럽게 발생한 결함을 발견했다는 뜻은 아닙니다.
어떤 정보가 있어야 완료를 확인할 수 있는지 시험한 것입니다.

## 실패를 조사할 순서

| 먼저 확인할 사실 | 다르면 먼저 살펴볼 곳 |
|---|---|
| 사용자가 원하는 결과와 실행 중 목적이 같은가요? | 목적 유지, 범위 변경 처리 |
| 필요한 자료가 검색 결과에 있었나요? | 검색 질문, 도구 인자, 접근 권한 |
| 찾은 자료가 모델 입력까지 전달됐나요? | 선택, 축약, 대화 보존 |
| 적용 조건과 출처가 남았나요? | 문맥과 기억의 형식 |
| 제안한 행동과 실제 실행한 행동이 같은가요? | 허용·수정·도구 실행 경로 |
| 실제 상태가 완료 기준을 만족하나요? | 재조회, 결과 검증, 종료 규칙 |

관찰한 사실이 없는 칸은 '모름'으로 둡니다.
그 칸을 추측으로 채우고 모델이나 검색기를 교체하지 않습니다.
