# 판단할 범위를 좁히자 한 과제의 입력과 보고 금액이 줄었습니다

**연결된 코드만 전달할 수 있었던 과제에서는 판정을 유지하며 입력이 줄었습니다.**
Claude 입력은 29.7%, Codex 입력은 10.8% 감소했습니다.
Claude 보고 금액은 26.7% 줄었습니다. 안정적으로 빨라졌다는 결과는 얻지 못했습니다.
다른 과제는 여러 명령이 한 진입점에 연결돼 있어 전체 파일을 유지했습니다.

이는 과거 결함 두 개로 수행한 작은 비교입니다. 일반 코드 리뷰의 절감률이 아닙니다.
[실행 전에 정한 범위](../experiments/selected-review/README.md),
[모든 응답과 집계](../experiments/selected-review/summary.json)

## 무엇을 바꿨나요

같은 기준을 검토할 때 전체 파일을 주는 조건과 연결된 코드만 주는 조건을 비교했습니다.
선택 조건에서는 Python AST로 함수가 참조하는 이름을 따라갔습니다.
대상 함수, 같은 파일의 연결된 함수, 모듈 수준의 문장을 원문 그대로 전달했습니다.
모델로 요약하거나 새로운 판단 기준을 만들지 않았습니다.

시작 함수는 연구자가 과제에서 읽어 지정했습니다. 자동으로 검토 대상을 찾은 시험은 아닙니다.
선택 규칙으로 범위를 좁힐 수 없으면 파일 전체로 돌아가게 했습니다.
외부 모듈과 템플릿은 기존 실험과 같은 정상 환경을 가정했습니다.

| 과제 | 선택한 시작점 | 실제 결과 |
|---|---|---|
| 다른 작업이 이미 쓰는 회고 번호를 처리 | `write_driver_retrospective` | 연결된 함수 두세 개와 모듈 수준 문장을 남겼습니다. 코드 문자 수가 약 40~42% 줄었습니다. |
| 명령줄로 받은 마일스톤 기준 여러 개를 보존 | `main` | 명령 파서가 다른 명령의 함수도 참조했습니다. 전체 파일을 유지했습니다. |

명시한 동작에 필요한 코드가 빠지지 않는지 확인하려고, 과거 수정 전후를 회귀 테스트로 다시 실행했습니다.
각 결함의 수정 전 버전은 실패했고 수정 후 버전은 통과했습니다. 총 네 번입니다.
AI에게는 이 결과와 수정 시점, 정답을 주지 않았습니다.
[복원과 회귀 검사](../experiments/selected-review/regression-results.json)

## 모델 응답은 모두 정한 판정과 일치했습니다

정상 입력 32번은 결함 두 개의 수정 전후·두 조건·두 호스트를 각각 두 번 실행한 결과입니다.
자료가 없는 경우도 네 번 확인했습니다. 합계 **36번**이며 CLI 오류는 없었습니다.

- 수정 전 코드는 모두 수정이 필요하다고 답했습니다.
- 수정 후 코드는 모두 명시한 기준을 만족한다고 답했습니다.
- 파일을 통째로 뺀 네 번은 모두 판단할 자료가 부족하다고 답했습니다.

독립적인 업무 36건을 성공한 결과가 아닙니다. 실제 과거 결함은 두 개입니다.
행동과 대상 기준 ID를 채점했습니다. 설명 전체와 다른 결함을 찾아내는 능력은 평가하지 않았습니다.
자료 누락 시험도 파일 전체를 뺀 경우입니다. 외부 의존 파일 일부가 빠지는 모든 경우를 검증하지 않았습니다.

## 코드를 줄인 과제에서는 입력과 보고 금액이 줄었습니다

회고 번호 충돌 과제만 비교한 값입니다. 각 조건은 수정 전후를 두 번씩 판단한 네 호출입니다.

| 측정 항목 | 전체 파일 | 연결된 코드 | 차이 |
|---|---:|---:|---:|
| Claude 입력 토큰 | 25,426개 | 17,879개 | 29.7% 감소 |
| Claude 보고 금액 | $0.114068 | $0.083600 | 26.7% 감소 |
| Claude 요청 시간 합계 | 21.02초 | 20.17초 | 약 0.85초 감소 |
| Codex 입력 토큰 | 44,636개 | 39,820개 | 10.8% 감소 |
| Codex 요청 시간 합계 | 32.69초 | 32.00초 | 약 0.69초 감소 |

자료 읽기·선택·입력 해시·CLI 실행·응답 파일 첫 저장까지 시간에 넣었습니다.
선택 조건에서 자료를 읽고 입력을 준비하는 시간은 요청당 평균 약 3.6~4.2밀리초였습니다.
이 작은 입력에서는 자료 선택 비용이 입력 감소 효과를 지우지 않았습니다.
선택기를 개발한 시간, 시작점을 사람이 지정한 시간, 공통 회귀 검증 시간은 제외했습니다.

이 과제의 두 조건 모두 캐시 읽기 토큰은 0개였습니다.
다만 시스템 입력과 토큰 집계가 다르므로 두 호스트의 감소율 차이를 모델 효율 순위로 해석하지 않습니다.
Claude 금액은 CLI가 보고한 값이며 실제 청구액은 확인하지 않았습니다. Codex는 금액을 반환하지 않았습니다.

## 동일한 입력에서도 시간은 크게 달랐습니다

전체 파일을 유지한 마일스톤 과제는 두 조건의 입력 해시가 같았습니다.
판정도 모두 같았습니다. 그런데 다음처럼 시간 차이가 났습니다.

| 호스트 | 전체 파일 조건 네 호출 | 선택 조건 네 호출 |
|---|---:|---:|
| Claude | 24.39초 | 26.38초 |
| Codex | 44.45초 | 33.57초 |

Codex에서는 입력을 줄이지 않았는데도 합계가 약 10.88초 달랐습니다.
이 가운데 전체 파일 조건의 한 호출은 17.81초가 걸렸습니다.
선택 조건에서만 캐시 읽기 5,632개가 기록된 차이도 있습니다.
서버 지연, 캐시, 출력 길이를 모두 통제한 실험이 아닙니다.

따라서 앞 과제의 작은 시간 차이를 자료 선택의 속도 개선으로 주장하지 않습니다.
두 과제를 합쳐 Codex 시간이 줄었다고 보고하면, 입력이 같은 과제의 차이를 개선 효과에 섞게 됩니다.
입력이 달라진 비교와 동일한 비교를 나눠 남겼습니다.

## 무엇을 배웠나요

**검토할 동작과 그 동작에 필요한 코드의 범위를 알면, 매번 전달하는 자료를 줄일 수 있었습니다.**
반면 파일 안의 여러 명령이 한 진입점에 연결된 경우에는 단순한 참조 추적만으로 범위를 좁히지 못했습니다.
이 한계를 피하려고 결과를 본 뒤 시작점을 바꾸지는 않았습니다.

제품에 적용할 후보는 다음과 같습니다. 이번에 제품 코드를 바꾼 것은 아닙니다.

1. 검토 요청에 확인할 동작과 그 시작점을 함께 남깁니다.
2. 그 동작에 연결된 근거를 찾아 전달합니다. 범위를 확인할 수 없으면 전체 자료를 전달합니다.
3. 코드와 기준이 바뀌면 자료를 다시 구성합니다. 이번 선택기는 호출마다 현재 입력을 읽었습니다.
4. 독립 검토 여부와 판단 근거를 함께 기록합니다. 같은 질문이어도 새 관점의 검토를 요청하면 새로 검토합니다.

Stage의 작업·완료 기준과 Distill의 적용 조건을 이용할 가능성은 있습니다.
그 연결이 실제 작업 전체의 비용을 줄이는지는 아직 시험하지 않았습니다.
특히 시작점을 찾는 비용, 외부 파일·환경의 의존 관계, 좁힌 범위 밖의 결함은 다음 검증에 포함해야 합니다.

## 검증과 기록

- 전체 소스를 반환하던 첫 선택기에서 불필요한 함수를 제거하는 검사 두 개가 실패했습니다.
- 정적 참조를 따라가도록 바꾼 뒤 로컬 검사 여덟 개가 통과했습니다.
- 연결된 함수·전역값, 함수만 바뀐 경우, 재귀, 시작점 누락, 문법 오류, 동적 조회, 데코레이터, 중복 이름을 확인했습니다.
- 실제 과거 결함의 회귀 테스트 네 번을 다시 실행했고 수정 전후가 예상대로 달랐습니다.
- 계획한 36번이 모두 있고 원본 입력·해시·채점을 다시 계산했을 때 불일치가 없었습니다.
- 이번 Claude 18번의 보고 금액 합계는 $0.604388입니다. Codex도 18번 호출했습니다.

Claude Code는 `2.1.289`, Codex CLI는 `0.160.0`이었습니다.
Claude 사용량에서 `claude-sonnet-5-5`를 확인했습니다. Codex의 실제 모델 ID는 공개 기록에서 확인하지 못했습니다.
기존 CLI 실행기를 사용했고, 임시 디렉터리에서 도구 사용을 제한한 판단만 받았습니다.
macOS에서 실행했습니다. 다른 OS에서의 실행 결과는 없습니다.

준비할 때 실행한 코드는 `prepare-recorded.py`로 보존했습니다.
현재 `prepare.py`에서는 오류 안내 두 문장만 한국어로 고쳤습니다. 기존 입력과 회귀 기록은 바꾸지 않았습니다.
실제 호출 전에 입력·실행 코드·선택 규칙을 고정했고 결과를 본 뒤 수정하지 않았습니다.
