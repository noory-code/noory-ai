# 실제 실행에서 기록 누락과 추가 지침의 효과를 확인했습니다

**이번에는 관찰 방법을 검증했고, 지침을 늘려서 답이 좋아졌다는 증거는 얻지 못했습니다.**
도구 기록을 확인하는 실행 2건과 근거 판단을 비교하는 실행 8건을 수행했습니다.
모두 정상 종료했습니다. 대규모 성능 평가나 모델 간 비교는 아닙니다.

## 실행 조건

| 항목 | 이번 조건 |
|---|---|
| 실행일 | 2026-10-05, 한국 시간. 원본에는 UTC로 기록했습니다. |
| 실행 경로 | Python Agent SDK → 설치된 Claude Code CLI |
| SDK / CLI | `0.2.163` / `2.1.289` |
| SDK 소스 | [S15](../sources.md#s15)의 커밋으로 고정했습니다. |
| 요청한 모델 | 도구 실험은 `sonnet`, 근거 실험은 `claude-sonnet-5-5` |
| 응답에 기록된 모델 | 두 실험 모두 `claude-sonnet-5-5` |
| 실행 폴더 | 임시 폴더. 도구 실험에서는 시험 파일 하나만 읽게 했습니다. |
| 추가 설정 | 프로젝트·사용자 설정을 읽는 경로와 MCP 서버, 슬래시 명령을 껐습니다. |
| 추론 설정 | CLI와 모델의 기본값입니다. 별도로 고정하지 않았습니다. |
| 제한 | 실행마다 120초, 최대 4턴, SDK 비용 한도 0.50달러 |

이 조건에서도 서버와 CLI의 모든 내부 동작을 통제했다는 뜻은 아닙니다.
실행에 전달한 지침은 저장했지만, 모델 서버가 받은 요청 전체를 수집하지는 못했습니다.

## 1. 권한 콜백만 세면 도구 사용을 놓칩니다

같은 시험 파일을 읽게 하고 허용 경로를 바꿨습니다.

| 조건 | 실행 전 훅 | 권한 콜백 | 실행 후 훅 | 파일 내용과 최종 답 일치 |
|---|---:|---:|---:|---|
| `Read`를 미리 허용했습니다. | 1회 | 0회 | 1회 | 일치했습니다. |
| 실행 전 훅이 권한 확인을 요구하고 콜백이 허용했습니다. | 1회 | 1회 | 1회 | 일치했습니다. |

**관찰:** 소스에서 읽은 조건을 실제 호출에서도 확인했습니다.
권한 콜백이 없었다고 도구가 실행되지 않은 것은 아닙니다.
근거는 [미리 허용한 기록](../experiments/runs/2026-10-05-hooks/allowed_read.json)과
[콜백을 거친 기록](../experiments/runs/2026-10-05-hooks/ask_callback.json)입니다.

**연구에 미치는 영향:** 도구를 덜 썼는지 비교하려면 권한 콜백 횟수를 쓰면 안 됩니다.
모델이 요청한 호출, 실행 전후 훅, 실제 결과를 연결해야 합니다.
이번에는 읽기 성공 경로만 확인했습니다. 실패·취소·인자 수정 경로의 기록은 검증하지 않았습니다.

두 조건은 한 번씩만 실행했습니다. 캐시 사용량도 달랐습니다.
관측한 시간과 비용 차이를 권한 처리 방식의 효과로 해석하지 않습니다.

## 2. 쉬운 근거 판단에서는 추가 지침의 이점을 확인하지 못했습니다

가상의 제품 문서로 네 가지 상황을 만들었습니다.
모델에는 자료와 질문만 주고, 채점 기준은 보내지 않았습니다.
기본 지침에 더해 관련성·근거·버전·충돌·충분성을 확인하라는 문장을 붙인 조건과 비교했습니다.

| 제공한 자료 | 기대한 판단 | 기본 지침 | 점검 지침 추가 |
|---|---|---|---|
| 질문한 버전의 기능을 명시합니다. | 지원한다고 답합니다. | 충족 | 충족 |
| 가져오기만 설명하고 내보내기는 설명하지 않습니다. | 확인할 수 없다고 답합니다. | 충족 | 충족 |
| 다른 버전의 기능만 설명합니다. | 질문한 버전은 확정하지 않습니다. | 충족 | 충족 |
| 같은 권위를 가진 두 문서가 충돌합니다. | 충돌을 밝히고 보류합니다. | 충족 | 충족 |

상태값은 [집계 스크립트](../experiments/scripts/summarize_pilot.py)로 대조했습니다.
본문과 문서 ID는 이 연구를 수행한 Codex가 8건 모두 읽었습니다.
기능 지원을 말할 수 있는 사례에서는 실제로 답했습니다.
나머지 사례에서는 근거가 부족하거나 충돌하는 이유를 설명했고, 임의로 지원 여부를 정하지 않았습니다.
사람이나 독립된 평가자가 검토한 결과는 아닙니다.

**해석:** 이번 문제로는 [H02](../hypotheses.md#h02)의 개선 효과를 입증하지 못했습니다.
가설이 모든 상황에서 틀렸다는 결과도 아닙니다.
문제가 짧고 단순했으며, 기본 지침부터 `insufficient`와 `conflicting`을 선택지로 줬습니다.
이미 보류할 수 있도록 안내한 조건이므로 아무 지침 없는 응답과도 다릅니다.

각 문제를 조건마다 한 번만 실행했습니다. 한국어 품질이나 긴 문맥에서의 성능은 채점하지 않았습니다.
실제 검색, 문서 선택, 반복 질문도 포함하지 않았습니다.
다음에는 먼저 실제 실패 사례를 모아야 합니다. 차이를 만들려고 임의로 문제를 꼬지는 않습니다.

## 3. 응답 모델과 전체 사용량 기록이 달랐습니다

**관찰:** 10건 모두 응답에는 Sonnet이 표시됐습니다.
하지만 결과의 `model_usage`에는 Sonnet과 Haiku 두 모델이 들어 있습니다.
이 값은 CLI가 보고한 사용량이며, 개별 네트워크 호출을 직접 센 결과는 아닙니다.

**아직 모르는 점:** Haiku에 보낸 입력과 받은 출력, 호출 시점, 맡긴 작업은 수집하지 못했습니다.
권한 판단, 제목 작성, 분류 중 어느 일을 했다고 단정할 수 없습니다.
사용량에 나타난 모델 수를 호출 횟수로 바꿔 읽을 수도 없습니다.

**연구에 미치는 영향:** 사용자가 선택한 모델 하나만 보고 전체 구조나 비용을 설명하면 빠지는 부분이 생깁니다.
앞으로는 요청한 모델, 응답에 표시된 모델, 모델별 사용량을 따로 남깁니다.
추가 모델의 역할은 공개 문서나 별도 관찰로 확인할 때까지 미확인으로 둡니다.
후속 조사에서 [보조 작업의 토큰 사용](../sources.md#s26)과 [Haiku 관련 설정](../sources.md#s27)을 확인했습니다.
그러나 이번 실행에서 어떤 보조 작업을 했는지까지 연결할 기록은 없습니다.

## 4. 이번 실행에 든 비용

SDK가 보고한 합계는 **0.0600386달러**입니다.
도구 실험은 0.0136106달러, 근거 실험은 0.046428달러였습니다.
실제 청구서를 확인한 값은 아닙니다. 모델별 기록은 `costBasis: list`를 표시했습니다.
현재 가격표를 따로 적용해 다시 계산하지 않았습니다.

시간은 SDK 연결 시작부터 연결을 닫을 때까지 쟀습니다.
모델 계산 시간뿐 아니라 CLI 시작과 통신, 종료 대기도 들어갑니다.
`duration_api_ms`와 같은 값으로 취급하지 않습니다.
