# 아이디어 여섯 가지의 시제품과 비교 결과

**여섯 아이디어의 시제품과 1차 시험을 2026-10-05에 마쳤습니다.**
로컬 테스트 54개를 통과했고 Claude와 Codex에서 총 96번 비교했습니다.
기본 자료만 받은 조건에서도 대부분 기대한 답을 냈습니다.
시제품 자료를 받은 조건에서는 Claude의 결과 필드 누락 한 건이 나타나지 않았습니다.
이 결과만으로 일반적인 정확도 향상이나 비용 절감을 입증하지는 못했습니다.

사용자가 여섯 후보를 모두 시험하자고 요청해 수행했습니다.
제품 코드에 바로 넣기 전에, 정한 조건에서 작동하는 부분과 아직 만들지 않은 부분을 구별했습니다.
원래 제안은 [아이디어 문서](../ideas.md), 실행 방법은 [실험 안내](../experiments/ideas-lab/README.md)에 있습니다.

## 실제로 만든 것

| 아이디어 | 이번에 구현하고 확인한 동작 | 이번에 구현하지 않은 범위 |
|---|---|---|
| 근거가 바뀐 판단을 다시 확인합니다. | 실제 파일의 해시를 비교하고 직접·간접 의존 관계를 따라 재검토할 판단을 찾습니다. 삭제와 불명확한 관계도 처리합니다. | 코드나 자연어에서 의존 관계를 자동 추출하지 않습니다. 관계가 잘못 기록됐는지도 자동으로 알지 못합니다. |
| 답에 필요한 조건까지 찾습니다. | 로컬 JSON 자료의 주제·버전·예외·출처를 비교합니다. 조건 누락과 충돌을 보류합니다. | 자유 문서에서 조건을 추출하거나 검색어를 바꿔 추가 자료를 찾지 않습니다. |
| 오류 뒤 남은 작업을 복구합니다. | 실제 파일 내용을 읽어 완료·미완료·충돌을 구별합니다. 이미 쓴 파일은 다시 쓰지 않고 남은 파일만 씁니다. 중간 오류 뒤 복구도 검사했습니다. | 외부 API 복구나 여러 파일을 한꺼번에 확정하는 트랜잭션을 구현하지 않았습니다. 모든 작성자가 같은 잠금을 따라야 합니다. |
| 상황을 답한 뒤 계속할지 정합니다. | 허용된 작업과 완료한 작업을 보관하고, 분류된 지시에 따라 계속·중단·범위 검토·정보 대기를 고릅니다. | 자연어 지시 분류와 다음 모델 호출을 자동 시작하는 기능은 없습니다. |
| 실패한 구간을 다시 시험합니다. | 입력·도구 응답·파일 상태를 해시로 기록합니다. 복사본에서 한 자료 묶음만 바꿔 결과를 비교하고 원본을 보존합니다. | 숨겨진 모델 상태나 원래 검색 엔진을 재현하지 않습니다. 자동으로 원인을 확정하지 않습니다. |
| 반복 절차를 도구로 옮깁니다. | 시험용 manifest 두 개를 실제로 읽고 형식·이름·버전을 검사합니다. 형식 밖의 입력은 돌려보냅니다. | 작업 기록에서 절차를 자동 추출하지 않습니다. 실제 manifest의 모든 필드도 지원하지 않습니다. |

첫 두 기능은 [evidence.py](../experiments/ideas-lab/evidence.py), 다음 두 기능은 [recovery.py](../experiments/ideas-lab/recovery.py)에 있습니다.
마지막 두 기능은 [replay.py](../experiments/ideas-lab/replay.py)에 있습니다.
모두 Python 표준 라이브러리로 실행하며 함수 자체는 모델을 호출하지 않습니다.

|---|---:|---|

| 복구와 작업 상태 | 23개 | 중간 오류, 재시도, 다른 작성자의 변경, 경로 이탈, 중단·대기 상태 |
| 재시험과 정해진 절차 | 13개 | 원본 보존, 해시 불일치, 여러 조건 변경 거절, manifest 오류와 누락 |

시제품 세 묶음은 테스트부터 작성해 실패를 관찰한 뒤 구현했습니다.
모듈이나 미구현 함수 때문에 실패한 초기 결과와, 실제 경계 조건에서 실패한 결과를 구별했습니다.
[근거 기능 기록](../experiments/ideas-lab/evidence-red-green.md), [복구 기능 기록](../experiments/ideas-lab/recovery-red-green.md), [재시험 기능 기록](../experiments/ideas-lab/replay-red-green.md)에 명령과 결과가 있습니다.
비교 입력·채점 검사 4개는 이미 작성한 실행기를 검증했으므로 RED를 관찰했다고 주장하지 않습니다.

## Claude와 Codex에서 비교한 것

각 아이디어마다 합성 사례 4개를 만들었습니다.
두 조건과 두 CLI를 조합한 본 비교는 총 96건입니다. 연결 확인 2건은 점수에서 제외합니다.
기본 조건에는 원본 자료와 적용 규칙을 제공합니다.
시제품 조건에는 같은 자료를 함수로 처리한 결과를 제공합니다. 일부 조건에는 원본도 함께 남깁니다.

**시제품이 계산한 행동과 대상을 제공하므로, 점수가 높아져도 모델 능력이 향상됐다는 뜻은 아닙니다.**
정해진 계산을 코드로 맡긴 뒤 모델이 결과를 요청한 형식으로 전달하는 과정을 봅니다.
모델이 스스로 도구를 선택·실행한 실험이나, 실제 장기 작업을 끝낸 실험은 아닙니다.
도구가 잘못 계산한 답을 모델이 잡아내는지도 이번 비교로 확인하지 않습니다.

입력과 기준은 실행 전에 저장했습니다. [고정한 사례](../experiments/ideas-lab/cases.json)
기대값은 시제품 반환값을 복사하지 않고 각 사례에 따로 적었으며 모델에 전달하지 않았습니다.
검토 중에는 지원하는 예외가 빠진 분기와 작업 목적에 맞지 않던 안내를 고쳤습니다.
수정은 본 비교를 시작하기 전에 마쳤습니다.

설명의 내용과 한국어 품질까지 채점한 결과는 아닙니다.

행동만 비교하면 96번 모두 일치했습니다. 차이 한 건은 대상 목록에서 생겼습니다.
96번은 서로 다른 실제 업무 96개를 뜻하지 않습니다. 합성 사례 24개에 조건과 CLI를 달리한 횟수입니다.

### 한 건의 차이는 판단 설명과 결과 필드 사이에서 생겼습니다

의존 관계를 모르는 판단 `audit`과 이를 근거로 삼는 `publish`를 함께 보류하는 문제였습니다.
Claude는 기본 조건에서 설명에 두 판단을 모두 적었지만 `targets`는 빈 배열로 반환했습니다.
시제품 조건에서는 두 대상을 모두 담았습니다.

따라서 의존 관계를 이해하지 못했다고 단정할 수 없습니다.
다음 프로그램이 `targets`만 읽는다면 필요한 대상을 놓친다는 점이 문제입니다.
이번 사례는 코드가 계산한 대상을 전달하는 방식이 이런 누락을 줄일 후보임을 보여 줍니다.
같은 사례를 반복하지 않았으므로 효과의 크기나 재현 가능성은 아직 모릅니다.
[기본 조건 원본](../experiments/ideas-lab/runs/comparison/I01_unknown--baseline--claude--1.json)과
[시제품 조건 원본](../experiments/ideas-lab/runs/comparison/I01_unknown--enhanced--claude--1.json)을 비교할 수 있습니다.

|---|---:|---:|
| 근거 변경 확인 | 969.25자 | 1,134자 |

| 남은 파일 복구 | 1,470.5자 | 1,593.5자 |
| 계속할 작업 결정 | 863.75자 | 1,061.25자 |
| 실패 구간 재시험 | 1,734.25자 | 1,819.25자 |
| 정해진 절차 실행 | 1,138.5자 | 1,034자 |

여섯 가지 중 다섯 가지에서 입력이 길어졌습니다. 계산 결과와 해시를 덧붙인 영향이 있습니다.
글자 수는 토큰 수나 비용과 같지 않지만, 도구를 추가하면 곧바로 문맥이 줄어든다는 예상은 지지하지 않습니다.
정해진 규칙을 코드로 처리할 수 있다면 그 판단을 매번 모델에 다시 시키는 단계도 검토해야 합니다.
권고는 코드가 계산한 행동과 대상을 다음 프로그램에 그대로 넘기고 모델에는 설명을 맡기는 것입니다.
이 방식이 실제 실행 경로에서도 누락을 막는지는 아직 시험하지 않았습니다.
이번 함수들은 모델 없이 실행됩니다. 실제 업무에서 몇 번의 호출을 없앨 수 있는지는 따로 확인해야 합니다.

### 비용과 시간은 어디까지 쟀나요

Claude가 보고한 본 비교 48번의 비용은 0.341592달러입니다.
연결 확인 한 번의 0.004382달러를 더하면 이번 Claude 실행 합계는 0.345974달러입니다.
Codex도 본 비교 48번과 연결 확인 한 번을 실행했습니다. 비용을 반환하지 않아 금액은 미확인입니다.
실제 청구액은 조회하지 않았습니다. 앞선 연구의 Claude 실행 280번과 비용은 이 집계에 포함하지 않았습니다.

시간은 각 CLI 호출이 시작되고 끝날 때까지 쟀습니다.
시제품이 자료를 준비하고 파일을 읽는 시간은 포함하지 않았고 최대 네 호출을 병렬로 실행했습니다.
따라서 기록한 시간을 작업 전체의 소요 시간이나 개선으로 절약한 시간으로 해석하지 않습니다.
입력 글자 수, 응답 토큰 수, 호출 시간은 집계 원본에 남겼습니다.

## 무엇부터 적용할 가치가 있나요

다음은 시험 결과를 바탕으로 한 권고입니다. 제품에 통합한 효과를 확인한 결과는 아닙니다.

| 아이디어 | 이번 판단 | 적용하려면 필요한 것 |
|---|---|---|
| 근거 변경 확인 | 기록된 의존 관계를 따라 재검토 대상을 고르는 기능은 작동했습니다. Stage에 연결할 후보로 유지합니다. | 실제 작업에서 의존 관계가 빠지는지 확인하고 놓친 변경과 불필요한 재검토를 함께 셉니다. |
| 적용 조건 조회 | 구조를 정한 JSON에서는 조건 누락과 충돌을 찾았습니다. RAG에 적용할 후보로 유지합니다. | 자유 문서에서 조건을 추출하고 출처를 확인해야 합니다. 검색부터 답까지 이어지는 시험이 필요합니다. |
| 남은 파일 복구 | 일부 쓴 파일과 남은 파일을 구별해 복구했습니다. 같은 잠금을 쓰는 로컬 파일 작업에 한정해 검토합니다. | 기존 실행기에 연결하고 충돌·강제 종료 뒤에도 사용자의 변경을 보존하는지 확인합니다. |
| 계속할 작업 결정 | 분류된 지시에 맞춰 상태를 바꾸는 규칙은 통과했습니다. 자동 재개 기능이 완성됐다고 판단하지 않습니다. | 자연어 지시를 해석하는 부분과 다음 호출을 시작하는 부분을 붙여 실제 대화에서 시험합니다. |
| 실패 구간 재시험 | 저장한 자료에서 한 조건만 바꿔 비교하는 연구 도구로 쓸 수 있습니다. | 실제 실패 기록을 수집하고 재현하지 못한 외부 상태를 표시합니다. |
| 정해진 절차 실행 | 작고 명확한 규칙을 모델 없이 처리할 수 있었습니다. 실제 반복 업무 하나에 좁게 적용할 가치가 있습니다. | 기존 검사 명령을 먼저 재사용합니다. 새 도구가 필요하면 실제 입력 형식과 예외를 지원합니다. |

**다음 구현은 반복 절차 하나를 코드로 처리하고, 근거 변경 확인을 기존 작업 기록에 연결하는 순서가 적절합니다.**
전자는 맡길 범위를 좁게 정할 수 있고, 후자는 무엇을 다시 확인할지 제어할 수 있습니다.
이번 시험에서 두 방법의 일반적인 우월함이 입증된 것은 아닙니다.
조건 조회와 복구는 실제 자료·실행기와 연결할 설계가 더 필요합니다.
자동 재개는 사용자 지시 해석까지 이어져야 원래 문제를 해결합니다.

## 적용할 때 남는 조건

- 근거 변경 확인은 의존 관계가 정확히 기록된 경우부터 적용합니다. 관계를 모르면 재검토를 생략하지 않습니다.
- 적용 조건 조회는 구조가 명확한 자료부터 사용합니다. 자유 문서에서 조건을 추출하는 정확도는 별도로 재야 합니다.
- 복구는 같은 잠금을 따르는 로컬 파일 작업으로 한정합니다. 마지막 확인과 교체 사이에 잠금을 무시한 외부 쓰기가 끼는 문제는 남아 있습니다.
- 작업 재개는 상태기계만으로 해결되지 않습니다. 최신 사용자 지시를 해석하고 실제 호출을 이어 주는 부분이 필요합니다.
- 재시험은 실패 원인을 좁히는 연구 도구로 사용할 수 있습니다. 저장하지 않은 환경까지 재현했다고 주장하지 않습니다.
- 정해진 절차는 허용한 입력에서 코드로 직접 처리할 수 있습니다. 모든 결과를 다시 모델에 확인시키면 호출을 없애는 이점을 얻지 못합니다.

## 해석의 한계

문제가 짧고 규칙을 명시했습니다. 실제 업무의 복잡함을 대신하지 않습니다.
같은 사례를 여러 번 반복하지 않았으며 사람이 채점 기준을 독립적으로 검토하지 않았습니다.
사례별 선택한 행동과 대상만 자동 비교합니다. 설명의 자연스러움과 한국어 품질을 평가하지 않습니다.

Claude는 `claude-sonnet-5-5`를 요청했습니다. Codex는 CLI의 기본 모델과 낮은 reasoning effort를 요청했습니다.
Codex의 공개 실행 이벤트에는 실제 모델명이 없어 모델 버전을 확정하지 못했습니다.
CLI 버전, 입력, 호출 옵션과 사용량을 보관했습니다. [실행 목록과 해시](../experiments/ideas-lab/runs/comparison/manifest.json)
캐시와 내부 시스템 입력은 통제하지 못했으므로 두 서비스의 성능 순위를 매기지 않습니다.

이번 시험은 macOS의 Python 3.14.6에서 실행했습니다. Linux와 Windows에서는 직접 실행하지 않았습니다.
기존 Stage·RAG·Evonest에 통합하거나 배포한 결과가 아닙니다.

## 기록 확인

예정한 실행 96번이 모두 있으며 추가되거나 빠진 실행은 없습니다.
실행 전 저장한 소스 해시와 입력 해시를 원본 기록에 대조했고 불일치는 없었습니다.
기대값이나 실패 응답을 고쳐 점수를 올리지 않았습니다.
연구 문서 26개, 내부 링크 210개, JSON 파일 400개와 Python 파일 18개를 검사했습니다.
링크·형식·문법 검사에서 오류가 없었고 `git diff --check`도 통과했습니다.
실험을 다시 호출하지 않고 결과를 확인하는 명령은 [실험 안내](../experiments/ideas-lab/README.md)에 있습니다.
