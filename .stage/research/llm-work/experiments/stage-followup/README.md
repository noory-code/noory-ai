# 목표와 검사를 맞추고 실제 CLI에서 이어받습니다

## 먼저 정한 범위

앞선 실험의 회고 사례는 모델에게 준 목표와 전체 테스트가 요구한 API가 달랐습니다.
이번에는 회고 번호를 작업 번호만으로 구하는 API도 목적과 완료 기준에 명시합니다.
수정 전·알려진 수정 후 코드에서 모델에게 공개한 전체 검사 명령을 먼저 실행합니다.
모델이 같은 명령을 실행하고 실패를 확인할 수 있게 합니다.

독립적인 과거 결함은 두 개입니다. 앞선 실험에서 Claude·Codex가 실제로 남긴 첫 수정 네 개를 재사용합니다.
첫 AI를 다시 호출하지 않습니다. 이전 공개 기록의 출처를 보존하고 다른 호스트가 이어받습니다.

## 비교 조건

- `stage_card`: 현재 Stage의 초기화·작업 등록 명령으로 임시 프로젝트를 만듭니다. 작업 본문에 목적, 완료 기준, 첫 수정, 미확인 사항과 다음 행동을 적습니다.
- `stage_card_observation`: 같은 카드에 인계 시점의 대상 파일 내용·해시를 추가한 자료를 제공합니다. 이후 수정 결과가 이 관찰을 대체한다고 명시합니다.

각 조건에서 모델은 자기 CLI의 실제 파일·명령 도구를 사용할 수 있습니다.
처음에는 카드 경로만 주고, 거기서 대상 파일과 검사를 찾아 읽게 합니다.
조건별로 같은 상태를 복사하며 두 호스트의 실행 순서를 반대로 둡니다.
두 결함 × 두 방향 × 두 조건으로 이어받기 여덟 번을 수행합니다. 조건당 반복은 한 번입니다.

이번 시험은 Stage가 만든 작업 기록을 이용합니다. Stage 드라이버, 모든 훅, 독립 모델 리뷰,
회고·승격·배포까지 연결한 운영 시험은 아닙니다. CLI의 내장 대화 재개도 사용하지 않습니다.
관찰을 미리 제공하는 효과와 관찰 시점을 설명하는 효과는 함께 바뀝니다.
이를 각각의 인과 효과로 나눠 주장하지 않습니다.

## 완료 기준과 경계

대상 파일만 고치고 전체 검사 명령을 통과해야 합니다.
테스트·목표·완료 기준을 바꾸면 실패입니다. 회고 사례의 추가 주석도 보존해야 합니다.
첫 구간에서 결과 응답이 없다는 사실만으로 이전 수정을 반복하지 않습니다.
독립 검증은 같은 전체 테스트를 다시 실행하고 변경 경로와 주석을 검사합니다.
완료 보고와 실제 통과를 따로 저장합니다.

CLI 한 번은 최대 300초입니다. Claude는 한 번에 보고 비용 1달러를 상한으로 둡니다.
전체 Claude 호출은 네 번이므로 최대 4달러이며 Codex의 과금 금액은 알 수 없습니다.
오류와 권한 거절은 보존합니다. 성공한 실행으로 바꿔치기하거나 제한을 우회하지 않습니다.

입력 준비·파일 복사·CLI·독립 검증 시간을 나눠 기록합니다.
사용량은 CLI가 보고한 그대로 보관합니다. 도구 호출과 공개 응답은 저장하며 비공개 추론은 저장하지 않습니다.
실행기와 입력 해시를 기록하고 원래 실험 파일은 바꾸지 않습니다.

```text
python3 .stage/research/llm-work/experiments/stage-followup/run.py
python3 .stage/research/llm-work/experiments/stage-followup/summarize.py
```

## 나머지 연구와 연결하는 방법

이 시험은 파일과 테스트를 스스로 찾아 실행하는 좁은 과정을 봅니다.
자유 문서에서 판단 기준을 배우는 능력, 여러 프로젝트에서의 개인화, 실제 업무의 재사용 비율은 대신하지 않습니다.
별도 로그 조사와 기준 적용 시험에서 얻은 근거를 합쳐 후보별 적용·보류·기각을 정합니다.

기준 적용 시험은 합성 프로젝트 기록 다섯 개에서 각 AI가 기준을 뽑고, 별도 상황 여섯 개에 적용합니다.
원문을 그대로 준 조건과 그 AI가 뽑은 기준을 준 조건을 비교합니다.
Claude·Codex에서 추출 두 번과 판단 24번을 수행합니다. 추출 때에는 평가 상황과 기대 답을 주지 않습니다.
출처 인용이 원문에 있는지 검사하며, 잘못 추출한 내용을 연구자가 고쳐 넣지 않습니다.
형식·인용 검사가 의미의 정확성까지 보증하지는 않습니다.
사람의 실제 취향을 알아냈다는 시험이 아니며, 개인의 기준을 모으는 Avatar 연구는 계속 보류합니다.
기준 시험은 실제 CLI 인계 측정이 끝난 뒤 실행해 두 실험의 모델 호출을 겹치지 않습니다.

```text
python3 .stage/research/llm-work/experiments/stage-followup/audit_reuse.py
python3 .stage/research/llm-work/experiments/stage-followup/criteria.py
```

## 관찰 시점 표시를 따로 비교합니다

이전 실험에서 Claude가 검사 통과 뒤 파일을 다시 읽었던 입력 한 개를 재사용합니다.
원본과, `current_files`를 인계 직전의 관찰이라고 표시한 조건을 비교합니다.
파일 내용과 실제 수정·검사 결과는 같습니다. 설명이 더해지므로 입력 길이는 완전히 같지 않습니다.
두 호스트에서 각 조건을 세 번씩 실행해 총 12번 비교합니다. 순서는 고정한 난수로 섞습니다.
새 실제 과제 12개가 아니라 결과를 본 뒤 골라낸 입력 한 개의 후속 시험입니다.
선택한 다음 행동만 기록하며 도구를 다시 실행하지 않습니다. 추가 읽기를 오답으로 채점하지 않습니다.
이 시험으로 전체 작업 시간이나 안전성이 좋아졌다고 주장하지 않습니다.

```text
python3 .stage/research/llm-work/experiments/stage-followup/freshness.py
```

관찰 시점 시험을 시작하기 전에 Codex가 서로 다른 두 시험에서 같은 서버 혼잡 오류를 반환했습니다.
실행 기록은 보존하고 Codex 호출은 더 하지 않습니다. 관찰 시점 비교는 `--host claude`로 여섯 번만 실행합니다.
Codex 쪽 여섯 번은 미실행으로 남깁니다. 모델을 바꾸거나 성공할 때까지 재호출하지 않습니다.

## 사용자가 요청한 재시도

이후 사용자가 다시 실행하도록 요청했습니다. 위 결과를 유지하고 `retry-1/`에 별도로 저장합니다.
기존 실행기의 해시와 CLI 버전을 대조한 뒤 같은 설정을 사용했습니다.
기준 추출은 정상 응답했지만 한 항목에 원문 두 개를 합쳐 기존 검사를 통과하지 못했습니다.
관찰 시점 비교의 첫 Codex 호출에서는 서버 혼잡 오류가 다시 나왔습니다.
출처를 하나만 쓰도록 요청을 명확히 한 시험은 계획만 저장했고 아직 실행하지 않았습니다.
Claude가 이어받는 두 조건은 별도로 완료했고 각각 테스트 94개를 통과했습니다.

- [재시도 계획](retry-1/manifest.json): 원본 해시, 실행 순서와 범위를 남겼습니다.
- [출처 형식을 명시한 추가 계획](retry-1/continuation-manifest.json): 원래 추출 실패와 구별합니다.
- [Claude의 남은 인계 계획](retry-1/claude-continuation-manifest.json): 첫 AI의 보존된 수정에서 시작합니다.
- [재시도 결과](../../findings/2026-10-05-stage-retry.md): 완료한 범위와 남은 일을 정리합니다.
- [집계](retry-1/summary.json): 원본 보존 여부와 결과를 다시 계산합니다.

다음 명령은 모델을 호출하지 않고 저장한 결과만 대조합니다.

```text
python3 .stage/research/llm-work/experiments/stage-followup/summarize_retry.py
```

## 성공한 결과를 보존하며 다시 이어갔습니다

`retry-2/`에서는 준비한 요청으로 기준 일곱 개를 추출했고 검사에 통과했습니다.
이후 원문과 추출한 기준을 각각 준 두 판단이 맞았지만 다음 호출이 서버 오류로 끝났습니다.

판단 두 번을 더 마친 뒤 같은 입력에서 연속으로 오류가 나 중단했습니다.

## CLI 업데이트 후 남은 비교를 마쳤습니다

사용자가 Codex를 업데이트했고 CLI가 `0.146.0`에서 `0.160.0`으로 바뀐 것을 확인했습니다.
성공한 추출과 판단 네 번은 보존했습니다. 남은 판단 여덟 번, 관찰 시점 비교 여섯 번과 실제 인계 두 조건을 실행했습니다.
추가한 16번은 모두 정상 종료했습니다. 실제 인계 두 조건은 각각 전체 테스트 94개를 통과했습니다.
호출 인자는 유지했지만 CLI 버전이 바뀌었으므로 업데이트 전후 시간과 토큰을 같은 환경에서 반복한 값처럼 비교하지 않습니다.

- [실행 계획](after-update/manifest.json): 이전 입력과 성공한 결과, CLI 버전을 남겼습니다.
- [최종 집계](after-update/summary.json): 정상 응답과 기존 실패를 구별하고 버전별로 집계했습니다.
- [후속 결과](../../findings/2026-10-05-stage-after-update.md): 유지할 후보와 남은 운영 검증을 정리했습니다.

아래 명령은 모델을 호출하지 않고 원본과 집계를 대조합니다.

```text
python3 .stage/research/llm-work/experiments/stage-followup/summarize_update.py
```
