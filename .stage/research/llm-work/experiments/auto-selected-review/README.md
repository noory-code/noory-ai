# AI가 검토할 함수를 고르는 비용까지 포함합니다

## Purpose

자료를 좁혀 읽는 효과가 함수를 찾는 비용을 포함해도 남는지 확인합니다.
사용자는 앞선 결과를 읽고 “또 뭐 진행합시다.”라고 요청했습니다.

## 기존 실험과 다른 점

앞선 시험에서는 사람이 검토 시작 함수를 지정했습니다.
이번에는 AI가 함수 이름·인자·설명·같은 파일의 참조 목록을 읽고 시작 함수를 하나 고릅니다.
그 뒤 기존 선택기로 연결된 코드를 모아 별도 호출에서 검토합니다.
함수를 고른 답의 이유는 검토하는 호출에 전달하지 않습니다.

대상 파일과 검토 기준은 기존 과제에서 이미 주어집니다. 저장소 전체에서 파일을 찾는 시험은 아닙니다.
회고 과제의 기준에는 함수 이름도 있습니다. 어려운 검색 과제나 새로운 과제라고 주장하지 않습니다.
기존 과거 결함 두 개의 수정 전후 입력을 그대로 사용합니다.

## Conditions

| 조건 | 처리 순서 |
|---|---|
| full | 전체 파일을 한 번의 CLI 호출로 검토합니다. |
| auto | 함수 목록을 만드는 코드 → AI가 시작 함수를 선택 → 연결된 코드 선택 → 별도 CLI로 검토합니다. |

AI가 `select_entry`와 실제 존재하는 함수 이름 하나를 반환하면 해당 함수를 사용합니다.
`use_full`과 빈 목록을 반환하거나 응답 값이 이 규칙에 맞지 않으면 전체 소스를 전달합니다.
함수 선택이 의미상 적절한지는 이 검사만으로 증명하지 않습니다. 최종 판정을 같은 회귀 결과와 대조합니다.
실제 CLI 오류가 나면 기록을 남기고 해당 호스트의 후속 요청을 멈춥니다.

선택 규칙은 앞선 실험의 코드를 그대로 사용합니다. 함수를 잘 골라도 연결된 범위가 전체면 원문 전체를 반환합니다.
선택기의 한계를 해결하려고 실험 중 규칙을 바꾸지 않습니다.

## Call plan

결함 두 개 × 수정 전후 두 상태 × 두 호스트 × 두 반복으로 비교 쌍 16개를 만듭니다.
각 쌍은 full의 호출 한 번과 auto의 호출 두 번으로 이뤄집니다.
계획은 요청 **32번**, CLI 호출 **48번**입니다. 호스트마다 CLI 호출 24번입니다.
조건 순서는 과제·호스트·반복에 따라 번갈아 바꿉니다. 두 호스트는 병렬로 실행합니다.
틀린 답은 그대로 남기며 정답이 나올 때까지 다시 호출하지 않습니다.

기존 CLI 실행기를 수정 없이 씁니다. Claude Sonnet과 Codex 기본 모델·low effort를 요청합니다.
실제 모델 버전까지 양쪽 모두 고정하지 못하므로 호스트 간 순위를 매기지 않습니다.
호출당 제한은 120초이며 Claude 보고 금액의 호출당 상한은 $0.20입니다.
Claude 24번의 상한 합계는 $4.80입니다. Codex의 금액은 추정하지 않습니다.

## Measurements

- 원본 읽기·함수 목록 생성·선택·해시·모든 CLI 호출·결과 첫 저장을 요청 시간에 포함합니다.
- 함수를 고르는 비용과 검토 비용을 나눠 남깁니다.
- 전체 요청의 입력·캐시·출력·보고 금액과 걸린 시간을 비교합니다.
- 최종 판정의 행동과 대상 ID를 검사합니다. 설명 전체나 범위 밖의 결함은 채점하지 않습니다.
- 선택 실패로 전체 파일을 전달한 경우도 비용 합계에 넣습니다.
- 원본과 입력·실행 규칙을 호출 전에 고정합니다.

이미 있는 회귀 결과와 원본 해시를 다시 확인합니다. 제품 코드는 수정하지 않습니다.
개발 시간과 사람이 과제를 만든 시간, 전체 저장소의 파일 검색은 이번 시간에서 제외합니다.
같은 함수를 고른 결과를 재사용하는 방법은 실행하지 않습니다. 손익을 계산하더라도 가정한 값으로 표시합니다.
