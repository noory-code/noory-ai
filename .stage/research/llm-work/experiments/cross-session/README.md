# 다른 AI가 실제 수정을 이어받는 실험

**계획을 먼저 기록합니다.** 현재 제품 파일과 원래 Stage 작업 카드는 바꾸지 않습니다.
앞선 입력 비교에서 확인하지 못한 실제 파일 수정·검증까지 임시 환경에서 수행합니다.

## 비교할 질문

이전 요청·응답 기록을 넘기는 방식과, 결정 이유·현재 파일·확인한 결과를 묶어 넘기는 방식 중 어느 쪽이 적은 반복으로 일을 끝내나요?

## 사례와 중단 지점

앞서 복원한 실제 결함 두 개를 다시 사용합니다.
[원본 커밋과 회귀 검사](../review-reuse/fixtures.md)는 이미 보존돼 있습니다.

- 마일스톤의 완료 기준을 여러 번 전달할 때 마지막 값만 남는 결함
- 다른 작업이 소유한 회고 번호와 충돌할 때 새 번호로 우회하는 결함

각 수정 커밋의 Stage 트리를 임시 디렉터리에 꺼내고, 대상 파일만 수정 전 코드로 바꿉니다.
실제 과거 환경 전체를 복원했다고 보지 않습니다. 지원 파일과 테스트는 수정 후 버전입니다.
먼저 수정 전에는 회귀 검사가 실패하고 알려진 수정 후에는 통과하는지 확인합니다.

첫 AI에게 목표와 허용된 파일을 알려 줍니다. AI가 선택한 읽기·수정·검사를 프로그램이 수행합니다.
첫 수정이 실제 파일에 적용되면 그 결과 응답을 AI에게 전달하기 전에 첫 구간을 끝냅니다.
프로세스가 우연히 죽은 사례가 아니라 실험자가 통제한 인계입니다.
회고 충돌 사례에는 그 뒤 보존해야 할 주석을 추가합니다. 두 비교 조건에 같은 주석을 넣습니다.

## 조건

| 조건 | 다음 AI가 처음 받는 내용 |
|---|---|
| transcript | 목표, 사용 가능한 도구, 첫 구간의 모든 공개 요청·응답. 마지막 수정 결과 응답은 없습니다. |
| state_packet | 같은 목표·도구, 직전 수정 요청과 공개된 이유, 기존 검사 결과, 인계 시점의 대상 파일 원문과 해시. 마지막 요청이 성공했다는 기록은 지어내지 않습니다. |

모든 조건에서 도구로 현재 파일을 읽고 실제 검사를 실행할 수 있습니다.
짧은 조건에만 정답 코드나 테스트 정답을 제공하지 않습니다.
state_packet은 프로그램이 현재 파일을 미리 읽습니다. 이 읽기와 자료 구성 비용도 별도로 셉니다.
단순 요약 효과와 현재 관찰을 미리 제공하는 효과가 함께 바뀌므로, 둘의 효과를 분리했다고 주장하지 않습니다.
기존 Stage 플러그인을 끝에서 끝까지 실행하는 비교는 아닙니다. Stage의 인계 항목을 참고한 제한된 도구 루프입니다.

## 실행 횟수와 범위

두 결함을 각각 Claude → Codex, Codex → Claude로 넘깁니다.
첫 AI가 남긴 같은 상태를 복사해 두 조건에서 시작합니다.
첫 구간 네 번, 이어받기 여덟 번이며 같은 구간을 반복 측정하지는 않습니다.
조건 순서는 방향에 따라 바꿉니다. 모델과 서버의 변동을 제거한 시험은 아닙니다.

AI는 매번 다음 행동 하나를 JSON으로 고릅니다.
프로그램이 임시 파일에 그 행동을 실행하고 결과를 다음 호출에 제공합니다.
같은 구간에서는 공개된 이력을 이어서 전달하며, 인계 때는 선택한 조건의 자료로 새 구간을 시작합니다.
각 호출은 별도 CLI 프로세스입니다. Claude Code·Codex의 내장 대화 재개 기능을 시험하지 않습니다.

읽기는 대상 파일과 회귀 검사 파일에 한정합니다.
수정은 대상 파일의 정확히 한 번 나타나는 문자열을 교체합니다.
테스트는 미리 고정한 회귀 검사만 실행합니다. 임의의 셸 명령은 받지 않습니다.
AI가 완료를 보고하면 별도 검증에서 회귀 검사와 해당 테스트 모듈 전체를 실행합니다.
다른 파일이 바뀌거나 보존할 주석이 사라져도 실패로 셉니다.

첫 구간은 최대 다섯 번, 이어받기는 최대 여덟 번의 모델 호출로 제한합니다.
답이 틀렸다고 새 실험으로 다시 시도하지 않습니다. 같은 구간의 수정은 정한 호출 한도 안에서 허용합니다.
CLI 오류는 원본과 함께 남기고 이후 호출을 중단합니다.
Claude는 호출당 0.20달러, 전체 보고 비용 8달러를 상한으로 둡니다.
Codex는 금액을 제공하지 않으면 비용을 계산하지 않습니다.

## 측정할 값

- 실제 완료 여부와 잘못된 완료 보고
- 이미 적용한 수정의 재요청, 내용이 변하지 않는 쓰기, 거절된 수정
- 모델이 요청한 파일 읽기와 프로그램이 미리 수행한 파일 읽기
- 실제 검사 횟수, 모델 호출 수, 입력·출력 토큰, CLI 보고 비용
- 자료 구성부터 이어받기·독립 검증까지 걸린 시간

복원과 첫 구간의 비용도 기록합니다. 두 조건에 공통인 비용과 이어받기 비용을 구분합니다.
성공률과 비용은 이 두 결함과 제한된 도구에서만 해석합니다.
목적 변경, 여러 파일의 복잡한 의존 관계, 외부 API 중복 실행과 동시 쓰기는 이번 범위에 포함하지 않습니다.

```text
python3 .stage/research/llm-work/experiments/cross-session/run.py
python3 .stage/research/llm-work/experiments/cross-session/summarize.py
```

## 실행 뒤 확인한 결과

첫 구간 네 번과 이어받기 여덟 번을 마쳤습니다. 모델 호출은 총 34번입니다.
[결과 보고서](../../findings/2026-10-05-cross-session.md)와 [집계](summary.json)를 남겼습니다.
현재 상태를 미리 전달한 조건에서 모델 호출은 줄었고 전체 시간은 줄지 않았습니다.

전체 검사에는 요청하지 않은 새 API를 확인하는 테스트가 섞여 있었습니다.
원래 판정은 보존하고, [추가 진단](diagnostics.json)에서 수정 전에도 같은 API 검사가 실패했음을 확인했습니다.
이 진단에는 모델을 쓰지 않았습니다. 인계 방식이나 모델의 성능에 따른 실패로 단정하지 않습니다.

`run.py`는 기존 `runs/`가 있으면 중단합니다. 이번 원본을 덮어쓰며 다시 실행하지 않습니다.
`summarize.py`는 모델 호출 없이 기록과 해시를 대조하고 집계를 다시 만듭니다.
`diagnose.py`는 후속 진단을 위한 코드이며 기존 `diagnostics.json`이 있으면 중단합니다.
