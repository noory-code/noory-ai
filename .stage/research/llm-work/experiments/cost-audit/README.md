# 기존 기록에서 비용이 든 곳을 다시 계산합니다

[결과 보고서](../../findings/2026-10-05-cost-audit.md)에서 수치와 개선 순서를 확인할 수 있습니다.

## Purpose

AI가 다시 읽고 판단하고 검토할 때 쓴 시간과 토큰을 원본 기록으로 확인합니다.
사용자는 비용 설명 뒤 “좋네 ㅇㅋ 하세요”, “잘 확인하고 굿굿”이라고 답했습니다.

## Scope

- 실제 CLI로 작업을 이어받은 후속 실험의 모든 시도를 셉니다.
- 기준 추출, 기준 적용, 관찰 시점 판단, 실제 작업 수행을 구별합니다.
- 실행 오류, 사용량 누락, 공급자 캐시와 독립 검사 시간을 따로 계산합니다.
- 앞선 판정 재사용과 문맥 축소 실험은 같은 조건 안에서만 비교합니다.
- 모델을 새로 부르거나 제품 코드를 바꾸지 않습니다. 계정 전체 사용 기록은 읽지 않습니다.

## Success criteria

- 원본 파일마다 경로와 해시가 남고, 기존 집계와 호출 수·비용이 맞습니다.
- 실패한 호출과 비용을 모르는 호출을 0원으로 처리하지 않습니다.
- 무엇을 많이 썼는지와 무엇을 줄일 수 있는지를 구별한 보고서를 남깁니다.
- 전체 업무의 비용 순위를 아직 정할 수 없는 이유와 다음 측정 항목을 적습니다.

## Method

`python3 .stage/research/llm-work/experiments/cost-audit/analyze.py`로 다시 계산합니다.
같은 응답이 여러 집계 문서에 반복돼도 원본 호출 파일 한 개만 셉니다.
같은 입력으로 실제 재시도한 파일은 별개 호출로 셉니다.
원본을 읽으며 요약 문서의 토큰 합계를 다시 더하지 않습니다.

시간은 호출별 경과 시간의 합입니다. 병렬 실행을 포함하므로 연구 전체의 벽시계 시간과 다릅니다.
CLI 내부에는 모델 응답 대기와 로컬 도구 실행이 함께 들어 있습니다.
둘의 시간이 따로 없으면 모델이 생각한 시간이라고 이름 붙이지 않습니다.
Claude의 보고 금액과 Codex의 토큰은 서로 다른 측정값입니다. 서비스 간 가격 순위를 매기지 않습니다.
