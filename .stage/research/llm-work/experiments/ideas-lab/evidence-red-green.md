# 근거를 다시 확인하는 시제품을 시험했습니다

2026-10-05에 두 아이디어를 구현했습니다. Python 표준 라이브러리와 임시 파일만 썼습니다.
모델이나 외부 API를 호출하지 않았습니다.

## 무엇을 구현했나요?

### ① 근거가 바뀐 판단만 다시 확인합니다

`snapshot`은 파일의 실제 바이트를 읽어 SHA-256 해시를 만듭니다.
`plan_review`는 이전 해시와 현재 해시를 비교합니다.
파일을 직접 근거로 쓴 판단과 그 판단을 다시 근거로 쓴 판단을 찾습니다.

파일을 삭제해도 재검토 대상으로 잡습니다.
의존 관계가 없거나, 모르는 자료를 가리키거나, 판단끼리 순환하면 보류합니다.
이때 영향을 받는 다른 판단도 함께 보류합니다.

### ② 답에 필요한 조건을 함께 읽습니다

`extract_evidence`는 로컬 JSON 자료를 읽습니다.
주제와 버전이 맞는 자료를 고르고 예외 조건을 비교합니다.
선택한 자료의 버전·예외·출처를 결과에 그대로 남깁니다.

필수 조건이 빠졌거나 자료끼리 충돌하면 답을 보류합니다.
예외를 적용할지 결정할 정보가 없어도 보류합니다.
자료를 읽지 못했거나 ID가 중복된 경우도 확인 대상으로 남깁니다.

## 어떻게 시험했나요?

다음 명령을 구현 전과 구현 후에 같은 조건으로 실행했습니다.

```text
python3 -m unittest discover -s .stage/research/llm-work/experiments/ideas-lab -p test_evidence.py -v
```

| 시점 | 결과 | 뜻 |
|---|---|---|
| 구현 전 | 종료 코드 1, 오류 14개 | 네 함수의 빈 틀이 `NotImplementedError`를 냈습니다. 기존 기능의 회귀를 관찰한 것은 아닙니다. |
| 구현 후 | 종료 코드 0, 14개 모두 통과 | 실제 파일 변경과 조건 비교가 정한 계약대로 작동했습니다. |

다음 항목을 확인했습니다.

- 파일 변경이 직접 연결된 판단과 간접 연결된 판단에만 전달됩니다.
- 파일이 그대로이면 재검토하지 않습니다.
- 삭제한 파일을 변경으로 셉니다.
- 의존 관계가 없거나 알려지지 않은 자료·판단을 가리키면 보류합니다.
- 순환하는 의존 관계를 보류합니다.
- 지정한 폴더 밖의 파일을 읽지 않습니다.
- 같은 주제의 이전 버전을 제외하고 현재 버전의 출처와 예외를 보존합니다.
- 조건에 맞는 예외가 일반 규칙보다 우선합니다.
- 예외 조건이 불명확하거나 자료가 충돌하면 보류합니다.
- 적용 조건 누락, 깨진 JSON, 중복 ID를 조용히 넘기지 않습니다.
- 비교용 사례 8개가 직렬화되고, 실제 함수 결과가 별도로 작성한 예상값과 맞습니다.

`git diff --check`도 종료 코드 0을 반환했습니다.
이는 추적 중인 파일의 차이만 검사하므로 새 파일의 기능 검사를 대신하지 않습니다.

## 모델 비교에는 무엇을 주나요?

`build_cases()`는 아이디어마다 사례 4개를 만듭니다.
임시 파일을 쓰고, 바꾸거나 삭제한 뒤 실제 함수를 실행합니다.
모델에 줄 원본도 파일에서 읽습니다.

기본 조건과 개선 조건에는 같은 원본과 적용 규칙을 줍니다.
개선 조건에는 시제품이 계산한 결과도 추가합니다.
따라서 개선 조건이 더 잘 맞히더라도 모델의 추론 능력이 좋아졌다고 말할 수 없습니다.
명확한 일부 판단을 코드로 처리한 효과를 보는 비교입니다.
이 구분은 각 사례의 `scoring_note`에도 남겼습니다.

`expected`는 사람이 읽을 수 있는 규칙에 따라 별도로 작성했습니다.
이를 모델 입력에 포함하면 안 됩니다.

## 무엇을 아직 할 수 없나요?

| 함수 | 한계와 대가 |
|---|---|
| `snapshot` | 파일의 의미를 비교하지 않습니다. 공백만 바뀌어도 다시 확인합니다. 읽은 바이트 수만큼 비용이 듭니다. 읽는 동안 파일이 바뀌는 상황은 통제하지 않습니다. |
| `plan_review` | 사람이 기록한 관계만 따라갑니다. 잘못 기록한 관계나 숨은 관계를 자동으로 발견하지 못합니다. 작은 그래프만 시험했습니다. 관계를 유지하는 비용을 재지 않았습니다. |
| `extract_evidence` | 이미 구조화한 JSON만 처리합니다. 자연어 문서에서 조건을 찾거나 새 자료를 검색하지 않습니다. 주제·버전·조건 값은 정확히 같아야 합니다. 출처가 참인지도 검증하지 않습니다. |
| `build_cases` | 작은 합성 사례만 만듭니다. 실제 프로젝트에서 재검토량·오류율·총비용이 줄어드는지는 별도로 확인해야 합니다. |

의존 관계와 적용 조건이 정확히 기록되었다는 가정이 두 시제품의 가장 큰 한계입니다.
기존 플러그인이나 실제 서비스에 연결한 상태는 아닙니다.
