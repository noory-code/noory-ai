# 실제 Git 수정 두 개를 복원한 사례

2026-10-05에 과거 수정 두 개를 임시 디렉터리에 복원했습니다. 조건마다 같은 회귀 검사를 한 번씩 실행했습니다. 총 네 번 실행했고, 두 사례 모두 수정 후에는 통과하고 수정 전 대상 파일을 넣으면 실패했습니다.

이 결과는 과거 작업 당시의 실행 기록이 아닙니다. 수정 커밋의 Stage 전체 트리와 그 커밋의 검사를 사용해 새로 실행했습니다. 수정 전 조건에서는 대상 파일 하나만 부모 커밋의 내용으로 바꿨습니다. 다른 파일과 검사는 수정 후 상태를 유지했습니다.

| 사례 | 검사 결과와 확인한 문제 |
|---|---|
| 마일스톤에 완료 기준 여러 개를 저장합니다. | 수정 후에는 통과했습니다. 수정 전 파일에서는 세 번 전달한 값 중 마지막 값만 남아 실패했습니다. |
| 다른 작업의 회고 번호와 충돌할 때 처리합니다. | 수정 후에는 통과했습니다. 수정 전 파일에서는 충돌을 알리는 빈 ID 대신 `R-00000042`를 반환해 실패했습니다. |

## 파일 구성

- [prepare.py](prepare.py)는 기존 자료가 있으면 실행을 중단합니다. 새 실험 폴더에서는 `git archive`로 각 수정 커밋의 `stage/`를 임시 디렉터리에 꺼냅니다. 일반 파일과 디렉터리만 허용하며 외부 경로나 링크는 거부합니다.
- [prepare-recorded.py](prepare-recorded.py)는 회귀 검사 네 번을 실행할 당시의 원본 스크립트입니다. 결과에 기록한 `prepare_sha256`와 일치합니다. 재현 근거로 보관하며 직접 실행하지 않습니다.
- [fixtures.json](fixtures.json)은 판정 기준과 수정 전후 대상 파일 전체 내용을 보관합니다. 모델에는 필요한 버전의 `files`와 `criterion`만 전달합니다. `provenance`는 실험 추적용이며 모델 입력에서 제외합니다.
- [regression-results.json](regression-results.json)은 커밋·부모·Git 트리·파일 해시와 실제 명령, 종료 코드, 출력 전체를 보관합니다. 이 기록은 모델에 전달하지 않습니다.

모델용 소스에는 커밋 메시지, 회귀 검사 결과, 별도 정답을 추가하지 않았습니다. 두 사례의 판정은 좁은 동작에 한정합니다. 관련 변경 분기는 대상 파일 안에 있으므로 로컬 보조 모듈은 추가하지 않았습니다. 전체 Stage 트리는 회귀 검사를 실행할 때 사용했습니다.

## 고정한 Git 기준

| 사례 | 수정 커밋 | 부모 커밋 |
|---|---|---|
| 완료 기준 여러 개 | `a1cd08dac15ddac5ac873d5d73e2db2c9aa48a68` | `7692c3b3b1d8d4be918823d4586fe02620180176` |
| 회고 번호 충돌 | `244a219957377557af4c85c5c81426aee6f12b8a` | `a54a3c972ed4444aca8ec86c34ba9bdd14443ec3` |

각 사례에서 테스트 파일 해시는 두 조건이 같았습니다. 검사 실행 전후의 Stage 파일 해시도 모두 같았습니다. 수정 전 조건에서 archive와 달라진 파일은 대상 파일 하나뿐이었습니다. 전체 Stage 트리의 Git 객체 ID와 추출한 파일 내용으로 계산한 SHA-256도 결과에 남겼습니다.

## 다시 실행하는 방법

```text
python3 .stage/research/llm-work/experiments/review-reuse/prepare.py
```

`fixtures.json`, `regression-results.json`, `runs` 중 하나라도 있으면 검사에 들어가기 전에 종료 코드 2로 중단합니다. 현재 폴더에는 원본 결과가 있으므로 다시 실행하지 않습니다. 새 실험은 기존 자료와 분리한 폴더에서 준비해야 합니다. 원래 저장소의 제품 파일과 Git 상태는 바꾸지 않습니다. 임시 디렉터리는 실행 뒤 정리합니다.

원본 결과를 만든 뒤 `prepare.py`에 덮어쓰기 방지를 추가했습니다. 수정하기 전에 원본을 `prepare-recorded.py`로 보존했습니다. 원본 결과와 그 안의 스크립트 해시는 바꾸지 않았습니다.

두 개의 알려진 수정만 복원했습니다. 무작위로 고른 사례가 아니며, 일반적인 리뷰 정확도를 대표하지 않습니다. 모델이 코드에서 같은 결함을 찾는지와 이전 판단을 재사용할 때 어떤 조건을 확인해야 하는지를 좁게 시험할 자료입니다.
