# 첫 비교 실험에서 목적과 근거를 확인합니다

상태: **이 문서는 초기 정식 평가 설계의 기록입니다. 사람 검토와 전체 과제 실행을 거친 정식 평가는 수행하지 않았습니다.**
근거 판단은 예비 실험 8건을 수행했습니다. 목적 해석은 더 좁은 합성 판단 문제로 반복했습니다.
탐색 결과와 설계 결함, 보완한 시험은 [후속 보고서](../findings/2026-10-05-followup.md)에 남겼습니다.
실행 조건과 한계는 [예비 실험 보고서](../findings/2026-10-05-pilot.md)에 남겼습니다.
아래에 계획한 사람의 기준 검토와 반복 실행을 마친 정식 비교는 아닙니다.

이번 실험의 목적은 새로운 제품을 검증하는 것이 아닙니다.
관찰에서 나온 가설을 작은 범위에서 반박할 수 있는지 확인합니다.

## 먼저 실제 기록을 표시합니다

2026-10-05 소스 분석에서 [콜백에 따라 기록이 누락될 수 있는 조건](../findings/2026-10-05-claude-sdk.md)을 확인했습니다.
예비 실험에서는 실제 `Read` 호출 2건의 실행 전후 훅과 권한 콜백을 대조했습니다.
실패와 취소 경로는 추가로 확인해야 합니다.
권한 콜백만으로 전체 호출 횟수를 세지 않습니다.

1. 사용자 요청, assistant의 공개 응답, 도구 호출과 결과를 순서대로 정리합니다.
2. 각 사건에 [동작 지도](../work-map.md)의 항목을 붙입니다. 한 사건에 여러 항목을 붙일 수 있습니다.
3. 직접 관찰한 동작과 연구자가 해석한 동작을 구별합니다.
4. 실제 입력을 확보하지 못했다면 입력 누락을 원인으로 확정하지 않습니다.
5. 성공한 작업과 실패한 작업을 함께 고릅니다.

[이 대화의 사례](../observations/2026-10-04-session.md)는 이 단계의 첫 기록입니다.
토큰과 시간 정보를 수집하지 않았으므로 수치로 비교하지 않습니다.

## 비교 A 목적과 가정을 먼저 적게 합니다

검증할 가설: [H01](../hypotheses.md#h01).

### 문제를 구성합니다

초기 점검용으로 12개 시나리오를 만듭니다.

- 목적과 범위가 명확한 사례 4개
- 예시와 실제 요구를 구별해야 하는 사례 4개
- 대화 중 목적을 수정하는 사례 4개

각 사례에는 사용자 발화, 제공할 자료, 허용할 도구 결과, 완료 기준을 둡니다.
완료 기준과 허용 가능한 여러 행동은 실행 전에 사람이 검토합니다.
모호한 사례에서 질문하는 행동도 정답이 될 수 있습니다.
모델이 보지 않을 채점표는 입력과 다른 파일로 보관합니다.

이 대화는 가설을 만드는 데 사용했으므로 최종 평가 문제로 재사용하지 않습니다.
새 시나리오는 소재와 표현을 바꿉니다.

### 조건을 맞춥니다

| 항목 | 기존 조건 | 변경 조건 |
|---|---|---|
| 모델과 버전 | 동일 | 동일 |
| 도구와 자료 | 동일 | 동일 |
| 기본 지침 | 동일 | 동일 |
| 추가 절차 | 없음 | 첫 행동 전에 목적·제약·미확인 사항을 짧게 적습니다. |
| 도구 결과 | 고정한 모의 결과 | 같은 모의 결과 |
| 실행 한도 | 사전에 같은 값으로 고정 | 사전에 같은 값으로 고정 |

목적 점검 때문에 무조건 사용자에게 확인을 요구하지 않습니다.
정보가 부족해 올바른 행동을 고를 수 없는 사례에서만 질문이 필요한지 평가합니다.

12개 시나리오를 조건별로 3회씩 실행하면 총 72회입니다.
이는 실행 오류와 큰 차이를 찾는 예비 규모입니다. 일반적인 성능을 입증하는 표본 수로 보지 않습니다.
조건 순서를 섞고, 시나리오별로 두 조건을 짝지어 비교합니다.
각 실행은 이전 실행의 대화나 기억을 공유하지 않습니다.

### 결과를 평가합니다

먼저 각 실행에서 아래 항목을 따로 기록합니다.

- 사용자가 요청한 목적을 지켰는지
- 지켜야 할 범위를 넘었는지
- 사용자 정정이 필요할 만큼 방향이 어긋났는지
- 필요한 질문을 했는지, 불필요한 질문을 했는지
- 최종 결과가 완료 기준을 충족했는지
- 중단, 오류, 재시도를 포함해 얼마나 걸렸는지

채점할 때 조건 이름을 가립니다. 평가자는 전체 실행 기록을 봅니다.
점검 절차 자체가 기록에 나타나므로 완전한 눈가림은 불가능하다는 한계도 남깁니다.
모델 채점은 보조로만 사용합니다. 기준이 애매하거나 판정이 갈리면 사람의 판단을 기록합니다.

분모는 시작한 모든 실행입니다. 오류와 시간 초과를 성공한 실행의 통계에서 말없이 빼지 않습니다.
반복 3회를 서로 독립된 시나리오 3개처럼 세지 않습니다.
시나리오별 결과와 전체 합계를 함께 보고합니다.

### 결과를 보고 정합니다

- 목적 오류가 줄고 완료율도 유지되면, 더 다양한 사례에서 반복합니다.
- 목적 오류는 줄지만 불필요한 질문이 늘면, 어느 사례에서 절차를 적용할지 검토합니다.
- 차이가 없으면 절차를 채택하지 않습니다. 요약에도 같은 오해가 들어갔는지 확인합니다.
- 결과가 오락가락하면 표본을 늘리기 전에 시나리오와 채점 기준이 명확한지 점검합니다.

## 비교 B 관련 자료와 충분한 증거를 구별합니다

검증할 가설: [H02](../hypotheses.md#h02). 비교 A와 따로 실행합니다.

자료 묶음을 고정하고 아래 4가지 유형을 포함합니다.

1. 관련 있고 답에 필요한 근거도 충분합니다.
2. 주제는 같지만 질문에 답할 근거는 없습니다.
3. 서로 충돌하는 근거가 있습니다.
4. 답은 있어 보이지만 다른 버전이나 조건에서 나온 자료입니다.

기존 조건은 자료를 읽고 답합니다.
변경 조건은 관련성, 주장 지지 여부, 범위 일치, 충분성을 확인한 뒤 답합니다.
이 비교에서는 H01의 절차를 동시에 추가하지 않습니다.

주요 결과는 근거 없는 주장과 답할 수 있는 문제의 완료율입니다.
추가 검색과 보류가 늘어 오답만 줄어든 경우도 구별합니다.
최초 비교는 고정 자료로 수행하고, 이후 실제 검색을 연결해 전체 효과를 확인합니다.

## 실행 전에 고정할 항목

- 정확한 모델 식별자, SDK와 도구 버전
- 입력 지침, 자료, 채점표의 파일과 해시
- 출력·추론 설정, 도구 호출·시간·재시도 한도
- 캐시 사용 조건과 기록할 사용량 항목
- 자료 접근 범위와 실행을 멈출 조건
- 실행 당시 가격표와 비용 계산 방법

예비 실행에 쓴 값은 [실행 기록](README.md)에 남겼습니다.
추론 기본값과 캐시를 완전히 통제하지는 못했습니다. 파일 해시는 실행 후 별도로 기록했습니다.
정식 비교 전에 이 조건을 보완해야 합니다.
유료 API를 여러 제공자로 확대하기 전에 소규모 실행에서 실제 사용량을 확인합니다.

## 기록 형식

한 실행마다 다음 항목을 남깁니다. 없는 값은 추정하지 않고 `null`로 둡니다.

```yaml
run_id: null
scenario_id: null
condition: null
model_id: null
model_settings: null
input_reference: null
input_sha256: null
event_log_reference: null
started_at: null
finished_at: null
input_tokens: null
cached_input_tokens: null
output_tokens: null
reasoning_tokens: null
cost: null
cost_basis: null
tool_calls: null
retries: null
termination_reason: null
goal_preserved: null
completion_criteria_met: null
unnecessary_question: null
unsupported_claims: null
reviewer: null
review_notes: null
```

위 형식은 한 실행 전체의 기록입니다. 실행 안의 사건은 별도 로그에 시간순으로 남깁니다.

| 사건별 항목 | 남길 내용 |
|---|---|
| 식별자와 연결 | 사건 ID, 실행 ID, 상위 호출 ID |
| 시점 | 시작과 종료, 시간대 |
| 수행 주체 | 모델, 프로그램, 도구, 사람 |
| 입력 | 실제 전달한 값이나 보관한 파일의 참조와 해시 |
| 출력 | 응답, 도구 호출 인자, 오류의 참조 |
| 외부 수정 | 최초 요청한 인자, 외부에서 수정한 인자, 실제 실행한 인자와 확인 방법 |
| 상태 변화 | 실행 전후 비교와 확인 방법 |
| 동작 표시 | 지도 항목, 직접 관찰인지 연구자의 해석인지 |
| 확인하지 못한 부분 | 미수집 입력, 비공개 설정, 알 수 없는 원인 |

숨겨진 추론을 필수 수집 대상으로 삼지 않습니다.
비밀키와 개인정보는 재현에 필요한 값과 구별해 제거하고, 제거한 사실을 표시합니다.
