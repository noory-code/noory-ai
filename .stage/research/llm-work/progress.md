# 연구 진행 기록

## 2026년 10월 6일 AI가 검토 범위를 고르는 비용까지 비교했습니다

사용자가 연구를 더 진행하자고 요청했습니다.
사람이 지정했던 시작 함수를 AI가 고르게 하고 전체 파일 검토와 비교했습니다.
계획한 요청 32번과 실제 CLI 호출 48번을 모두 마쳤습니다. 최종 판정은 모두 기대 답과 일치했고 서버 오류는 없었습니다.
코드를 줄인 과제도 선택 비용을 더하자 Claude 보고 금액이 12.1%, Codex 입력이 67.7% 늘었습니다.
다른 과제에서는 기존 선택기가 전체 파일을 유지했습니다. 최종 검토 입력은 두 조건이 같았습니다.
호출을 마친 뒤 코드로 모든 시작점을 확인했고, 추가 호출을 생략할 후보를 찾았습니다.
이 후속 분석은 별도 비교 조건으로 집계하지 않았습니다.
[결과와 한계](findings/2026-10-06-auto-selected-review.md)에 단계별 비용과 다음 적용 후보를 남겼습니다.
새 선택 코드의 검사 여섯 개와 한국어 조사가 붙은 코드 이름을 다룬 검사 두 개를 통과했습니다.
제품 통합과 전체 운영 비용, 실무 재사용률 측정은 남았습니다.

## 2026년 10월 5일 비용 재집계 뒤 자료를 골라 전달하는 비교를 마쳤습니다

사용자가 비용을 더 확인하고 연구를 계속하도록 요청했습니다.
[기존 CLI 호출 125번을 다시 집계](findings/2026-10-05-cost-audit.md)해 토큰·캐시·보고 금액·실패 시간을 구별했습니다.
이후 과거 결함 두 개에서 전체 코드와 연결된 코드를 전달하는 [실제 비교 36번](findings/2026-10-05-selected-review.md)을 수행했습니다.
한 과제의 입력과 Claude 보고 금액이 줄었고 판정은 유지됐습니다. 다른 과제는 전체 파일을 유지했습니다.
동일한 입력에서도 시간이 크게 달라 속도 개선은 주장하지 않았습니다.
기존 원본을 보존했고 새 실험의 입력과 호출, 실패에서 통과로 바뀐 로컬 검사와 회귀 검증을 남겼습니다.
제품 통합, 전체 운영 비용과 실무 재사용률 측정은 남았습니다.

## 2026년 10월 5일 전체 연구를 한 문서로 정리했습니다

사용자가 전체 내용을 정리하자고 요청했습니다.
[연구 종합 정리](synthesis.md)에 목적·세 가지 후보·실험 결과·제품별 역할·남은 검증을 모았습니다.
초기 보고서의 제목과 종료 표현을 당시 범위에 맞췄고, 연구 인덱스에서 종합 정리를 먼저 안내했습니다.
판단 재사용의 조건부 절약과 다른 방법에서 이득을 확인하지 못한 결과를 구분했습니다.
Stage 전체 운영 검증과 실무 절약량 측정은 남겨 두었습니다. 새 실험이나 제품 변경은 수행하지 않았습니다.
문서 48개, 내부 링크 470개, JSON 파일 647개와 Python 파일 50개를 검사했고 오류는 없었습니다. `git diff --check`도 통과했습니다.

## 2026년 10월 5일 Codex 업데이트 후 남은 비교 16번을 마쳤습니다

사용자가 업데이트를 마쳤다고 알려 왔습니다. 실험용 CLI가 0.146.0에서 0.160.0으로 바뀐 것을 확인했습니다.
성공한 추출과 판단 네 번은 그대로 보존했습니다.
남은 판단 여덟 번과 관찰 시점 비교 여섯 번에서 정상 응답을 얻었습니다.
실제 파일 수정을 이어받는 두 조건도 정상 완료했고 각각 전체 테스트 94개를 통과했습니다.
추가한 16번에서 서버 오류는 없었습니다. 업데이트가 오류 해소의 원인이라고 단정하지 않았습니다.
두 호스트의 기준 적용 24번, 관찰 시점 비교 12번과 실제 인계 여덟 조건을 모두 집계했습니다.
앞선 서버 오류 여섯 번과 출처 검사 실패는 보존했습니다. CLI 버전별로 집계해 시간 비교의 한계를 남겼습니다.
관찰 파일을 제공한 네 번 모두 해당 파일을 열지 않았습니다. 기준 추출도 짧은 기록에서는 정확도 차이 없이 입력을 늘렸습니다.
[최신 결과](findings/2026-10-05-stage-after-update.md)에 유지할 후보와 남은 연구 두 가지를 정리했습니다.
Stage 전체 운영 검증과 실무 재사용률 관측은 남았습니다. 제품 코드·버전·설정·원래 작업 카드는 바꾸지 않았습니다.

## 2026년 10월 5일 출처를 명시한 추출과 판단 네 번을 확보했습니다

사용자가 기존 연구를 계속하도록 요청했습니다.
출처 하나와 연속된 인용을 요구한 Codex 추출이 검사를 통과했습니다. 기준은 일곱 개였습니다.
처음 두 판단 뒤 서버 오류가 났습니다. 성공한 결과를 보존하며 요청 사이에 간격을 두는 실행을 따로 기록했습니다.
두 판단을 더 확보한 뒤 같은 입력에서 30초 간격으로 두 번 연속 혼잡 오류가 나 추가 호출을 멈췄습니다.
GPT-5.6 Sol을 직접 지정한 연결 확인도 같은 오류로 끝났습니다. 비교 실험의 호출 수에는 넣지 않았습니다.
정상 응답 네 번은 모두 기대 답과 일치했습니다. 추출한 기준을 준 조건은 원문보다 입력이 늘었습니다.
N4를 미확인 추정이며 프로젝트 미지정으로 남긴 것도 확인했습니다. 적용 범위와 확인 여부를 함께 전달해야 원문 뜻이 유지됩니다.
[최신 보고서](findings/2026-10-05-stage-criteria-resume.md)와 [종합 집계](experiments/stage-followup/retry-3/summary.json)를 추가했습니다.
남은 비교는 Codex 판단 여덟 번, 관찰 시점 비교 여섯 번과 인계 두 조건입니다.
제품 코드·버전·설정·원래 작업 카드는 바꾸지 않았으며 연구 전체를 완료했다고 표시하지 않았습니다.

## 2026년 10월 5일 중단된 비교를 재시도하고 Claude 인계 두 건을 추가로 마쳤습니다

사용자가 다시 실행하도록 요청했습니다. 앞선 원본 JSON 38개와 실행기를 보존했습니다.
같은 입력으로 보낸 Codex 기준 추출은 정상 응답했지만 원문 두 개를 합친 항목이 기존 검사를 통과하지 못했습니다.
검사가 요구한 출처 단위를 요청문에 충분히 명시하지 않았던 점도 확인했습니다.
출처 하나와 연속된 인용을 요구하는 별도 시험을 준비했으나 아직 실행하지 않았습니다.
독립된 관찰 시점 비교를 먼저 시작했고 Codex 서버 혼잡 오류가 다시 나 추가 Codex 호출을 멈췄습니다.
Claude의 남은 인계 두 건은 정상 완료했습니다. 각각 전체 테스트 94개를 통과했고 보호한 파일과 주석을 지켰습니다.
관찰 파일을 제공한 조건에서도 해당 파일을 읽지 않았습니다.
이번 호출 네 번의 결과와 남은 항목은 [재시도 보고서](findings/2026-10-05-stage-retry.md)에 정리했습니다.
연구 전체를 완료했다고 표시하지 않았습니다. 제품 코드·버전·설정·원래 작업 카드는 바꾸지 않았습니다.

## 2026년 10월 5일 실제 CLI 인계와 기준 적용을 시험했으며 Codex 서버 오류로 일부를 남겼습니다

사용자가 남은 연구와 순서에 동의했습니다. [후속 범위](followup-plan.md)를 기록했습니다.
먼저 모델에게 준 목표와 전체 검사 범위를 맞추고 수정 전·후 동작을 확인했습니다.
Stage의 초기화·등록 명령으로 임시 카드를 만들고 실제 CLI 파일 도구로 이어받게 했습니다.
네 실행이 정상 완료됐고 다섯 번째는 파일 수정 뒤 Codex 서버 혼잡 오류로 끝났습니다.
독립 검사에서는 그 다섯 번째 수정도 전체 테스트를 통과했습니다. 모델의 완료 응답은 받지 못했습니다.
실제 로그 73개와 판정 파일 43개에서는 재사용 비율을 계산할 입력 근거를 확보하지 못했습니다.
Claude의 기준 적용 12번은 모두 기대값과 일치했지만 추출한 기준을 제공하면 입력과 비용이 늘었습니다.
Codex의 기준 추출도 같은 서버 오류로 중단돼 추가 Codex 호출을 하지 않았습니다.
Claude에서 관찰 시점만 설명한 비교 여섯 번을 추가했습니다. 원본에서 나온 추가 읽기 한 번이 표시한 조건에서는 없었습니다.
[중간 결과](findings/2026-10-05-stage-followup.md)에 실패와 미실행 항목을 보존했습니다.
실제 CLI 인계 세 번, Codex 기준 추출·적용, Codex 관찰 시점 비교는 남았습니다. 연구 전체가 끝났다고 표시하지 않습니다.
제품 코드·원래 Stage 작업 카드·설정·버전은 바꾸지 않았고 커밋·푸시는 하지 않았습니다.

## 2026년 10월 5일 다른 AI가 실제 수정을 이어받는 실험을 마쳤습니다

사용자가 다음 연구를 진행하자고 요청했습니다.
과거 결함 두 개를 임시 환경에 복원하고, 첫 AI의 수정 결과 응답이 빠진 상태를 다른 AI가 이어받게 했습니다.
Claude → Codex와 Codex → Claude에서 같은 파일 상태를 두 조건으로 비교했습니다.
첫 구간 네 번과 이어받기 여덟 번에 모델을 총 34번 호출했습니다.
현재 파일을 미리 전달하면 이어받기의 호출은 13번에서 11번으로 줄었지만 독립 검증까지 걸린 시간은 줄지 않았습니다.
원래 정한 전체 검사에는 여덟 번 중 네 번이 통과했습니다. 목표로 삼은 회귀 검사는 모두 통과했습니다.
회고 사례의 전체 테스트에는 AI에게 요구하지 않은 새 API 검사가 섞여 있었습니다.
모델을 다시 호출하지 않고 수정 전 상태를 검사해 같은 API 실패가 있었음을 확인했습니다.
이 실패를 인계 효과나 모델의 거짓 완료 보고로 해석하지 않습니다.
실행 기록·입력 해시·코드 해시·수정 전후 내용의 일치 여부를 검사하고 [결과와 한계](findings/2026-10-05-cross-session.md)를 남겼습니다.
다음 비교에서는 목적과 검사를 맞추고, 관찰 시점과 후속 변경을 연결하는 효과를 따로 확인합니다.
제품 코드와 원래 Stage 작업 카드는 변경하지 않았습니다.

## 2026년 10월 5일 본래 연구를 재개하고 세션 인계 자료를 시험했습니다

사용자가 파생 아이디어를 기록한 뒤 연구를 계속하자고 요청했습니다.
Avatar / Clone 구현은 보류하고, AI가 다음 세션에서 상황을 다시 파악하는 비용을 연구 대상으로 골랐습니다.
Stage 기록의 복사본에서 열린 작업 여섯 건의 문맥을 만들고, 전체 작업을 보여 주는 부분을 뺀 입력과 비교했습니다.
대상·상위 작업의 원문은 보존했으며, 문자 수와 비어 있는 지정 항목을 기록했습니다.
이어 실제 릴리스 작업 한 건의 질문 두 개를 Claude·Codex에서 비교하도록 [실험 범위](experiments/context-handoff/README.md)를 먼저 적었습니다.
세 조건을 두 호스트에서 두 번씩 실행한 24번의 판정이 모두 기대값과 일치했습니다.
자료를 줄인 조건에서 입력 토큰은 감소했지만 평균 응답 시간은 줄지 않았습니다.
실행 수와 입력 해시를 검사하고 [결과와 한계](findings/2026-10-05-context-handoff.md)를 정리했습니다.
실제 세션을 연결해 개발 작업 전체를 끝낸 시험으로 해석하지 않습니다.
제품 코드와 원래 작업 기록은 변경하지 않았습니다.

## 2026년 10월 5일 Avatar / Clone을 파생 아이디어로 기록하고 구현을 보류했습니다

사용자는 프로젝트를 넘어 개인의 판단 기준을 모을 플러그인을 따로 만들자고 했습니다.
이름으로 avatar를 제안한 뒤 clone도 언급했고, 본인의 의사결정을 돌아보는 메타인지 목적을 더했습니다.
이어 본래 연구에서 벗어나고 있다며 우선 모두 기록하라고 요청했습니다.
[Avatar / Clone 기록](avatar.md)에 발언, 목적, Stage·Distill과의 구분과 남은 질문을 보존했습니다.
여러 세션에서 작업을 이어가는 논의는 [별도 기록](session-continuity.md)에 남겼습니다.
플러그인 생성에 앞서 관련 스킬을 읽고 열린 마일스톤이 없음을 확인했지만, 새 작업을 등록하거나 코드를 만들지는 않았습니다.
마지막 요청에 따라 문서 정리까지만 수행했습니다. 구현·설치·릴리스·커밋·푸시는 하지 않았습니다.

## 2026년 10월 5일 개인의 판단 기준은 프로젝트를 넘어 다루도록 정리했습니다

사용자는 한 프로젝트를 벗어나 한 사람의 의사결정 기준을 모으는 데 큰 의미가 있다고 설명했습니다.
[판단 기준 연구](decision-criteria.md#person-across-projects)에 이 방향을 명시했습니다.
Stage에서 세 기능을 함께 쓰더라도 개인의 기준을 한 프로젝트에 가두지 않도록 제안했습니다.
