# 기록 절차를 명시한 후속 인계 시험

2026-10-07. W-00000277. 첫 시험의 독립 리뷰 뒤, 새 AI 호출 전에 조건을 고정합니다.

첫 시험은 코드 동작을 여섯 사례 모두 통과했지만 인계 기록은 세 사례에서 틀렸습니다.
근거 없이 기준을 `superseded`로 적은 사례 한 개와 끝낸 일을 다음 할 일로 남긴 사례 두 개입니다.
원래 지시·응답·잘못된 검사 판정·다시 검사한 판정을 모두 보존합니다.

## Purpose

기록 절차를 명시하면 현재 구현으로 올바른 인계를 마칠 수 있는지 확인합니다.
제품 코드는 바꾸지 않습니다. SSOT·TDD·Honesty·Completion을 적용합니다.

## 고정할 변경

- 새 전달 세션 두 개와 새 수신 세션 여섯 개를 한 번씩 실행합니다. 실패하면 추가 재시도하지 않습니다.
- 원래 `real-host-plan.md`의 모델·과제·조건·격리·180초 제한을 유지합니다.
- 전달 세션에 Stage 문서의 `Evidence: {JSON}` 형식을 그대로 알려 줍니다.
  인계 글이 앞선 파일을 `matches`로 대조했는지 검사합니다.
- 받은 세션은 조회한 상태만 기록합니다. 조회하지 못한 상태를 변경·철회로 추정하지 않도록 명시합니다.
- 받은 세션이 덧붙인 적용 기록을 보려면 앞선 카드의 기록 개수를 빼고 검사합니다.
- 일을 끝내면 `Next action`도 갱신하도록 명시합니다. 끝낸 함수를 다시 구현하라는 기록은 실패입니다.
- Avatar에 첨부한 이력에 실제 적용한 참조와 프로젝트가 포함되는지 검사합니다.

현재 기준을 주지 않는 C0에도 앞선 카드와 코드는 남습니다. 이전의 `ConfigError` 처리도 보입니다.
따라서 C0은 조회를 연결하지 않은 조건이며, 과거의 영향까지 지운 완전한 대조군이 아닙니다.
조건 간 비용 차이를 인과 효과로 해석하지 않습니다.
