# 세 플러그인 연결 시험

2026-10-06, 실행 전에 입력과 기대 결과를 고정합니다.

## Purpose

각 플러그인의 명령이 실제로 연결되는지 확인합니다. AI가 그 결과를 따르는지는 별도로 봅니다.
SSOT, TDD, Honesty, Completion을 적용합니다. W-00000277의 성공 조건을 줄이지 않습니다.

## CLI 계약 시험

임시 시험 폴더 안에 프로젝트, Distill DB, Avatar DB를 만듭니다. 실제 개인 저장소는 쓰지 않습니다.
발언은 모두 시험용으로 작성했다고 표시합니다. 모델이 실제 사용자의 말이라고 오인하게 하지 않습니다.

1. 프로젝트 키는 `test/demo-app`입니다. 카드의 목적은 설정 파서를 이어서 만드는 것입니다.
2. v1은 잘못된 입력에서 `ConfigError`를 던집니다. v2는 `None`을 돌려줍니다.
3. Distill에서 v1을 기록하고 같은 요청을 다시 보내면 같은 참조와 `replayed: true`가 나와야 합니다.
4. v1 packet을 만든 뒤 v2로 수정합니다. 다음 packet의 현재 기준에는 v2만 들어가야 합니다.
   v1을 쓴 앞선 판단은 `superseded`로 표시돼야 합니다. 기준 확인 argv를 실제로 실행합니다.
5. 확인하지 않은 추정은 현재 기준에 들어가지 않아야 합니다. 다른 프로젝트 참조는 `scope_mismatch`입니다.
6. Avatar는 제안만 한 기준을 내보내지 않습니다. 시험용 사용자 확인을 넣으면 새 참조를 내보냅니다.
   확인은 불변 이력을 지키기 위해 @1을 남기고 @2를 만듭니다. 이후 명령은 반환받은 참조를 씁니다.
7. 같은 전역 세대에서 조회한 서로 다른 Distill 기준의 이력을 Avatar에 모두 첨부할 수 있어야 합니다.
8. 철회 이력을 첨부한 뒤 예전 이력을 다시 첨부해도 더 최신 이력이 있음을 표시해야 합니다.
9. 기록한 결과 파일을 바꾸면 packet에 `changed`, 지우면 `missing`이 나와야 합니다.
10. 생산자 없이도 packet을 만들 수 있어야 합니다. 이때 기준을 조회하지 않았다고 밝혀야 합니다.

각 명령의 argv, 종료 코드, stdout, stderr, 걸린 시간을 남깁니다. 소스 파일의 SHA256도 남깁니다.
검사기는 저장한 원본 JSON과 packet을 다시 읽습니다. 명령이 성공했다는 사실만으로 통과시키지 않습니다.

### 첫 실행 뒤 검사 코드 수정

첫 실행은 24번째 명령 뒤 검사 코드에서 멈췄습니다. 카드에는 v1을 적용한 기록만 있는데,
검사 코드가 packet에 v2의 `revoked`가 나오기를 요구했습니다. v1은 v2로 대체됐으므로
`superseded`가 맞습니다. 원본 출력은 보존합니다. 제품은 바꾸지 않습니다.
두 번째 실행은 v2를 `check`로 직접 조회해 `revoked`를 확인합니다. packet에서는 v1의
`superseded`와 철회한 기준이 현재 목록에 없는지를 확인합니다. 시험 목적과 기대 동작은 그대로입니다.

## 실제 AI 세션 시험

원래 설계의 두 방향과 세 조건을 유지합니다. Claude → Codex, Codex → Claude 각각에 대해
기준 없음(C0), v1(C1), v2(C2)를 실행합니다. 앞선 과제 P는 `parse_port`, 이어받는 과제 H는
`parse_host`입니다. 결과 파일, 적용한 참조, 재질문 횟수, P를 다시 고쳤는지, 입력량을 기록합니다.

### 실제 세션 실행 전에 고정할 파일 검사

아직 실제 양방향 실행은 시작하지 않았습니다. `check_host_result.py`는 `app/host.py`를 별도 프로세스에서
실행합니다. `parse_host("example.com")`은 `"example.com"`을 반환해야 합니다. `"bad"`에는 C1이
`ConfigError`를 던지고 C2가 `None`을 반환해야 합니다. C0의 잘못된 입력 처리 방식은 관찰만 합니다.
앞선 세션의 `app/port.py` SHA256과 비교해 파일을 다시 고쳤는지도 검사합니다.
받은 세션은 카드에 `Applied criteria: <ref 또는 none>`을 적습니다. C2에서는
`Stale judgment: <v1 ref> superseded`도 적도록 실행 전에 지시합니다.
조건·예상 참조·앞선 파일 digest·카드 경로는 `frozen_input`에 먼저 저장합니다.
기존 결과의 `passed`만 읽지 않고 보존한 파일을 다시 실행합니다. 검사기의 합성 테스트를 실제 AI 실행으로 세지 않습니다.

Codex CLI 실행기는 사용량 오류로 멈췄습니다. 사용자가 이 감독 세션에서 직접 구현하도록
허용했지만, 그것만으로 새 Codex 세션의 인계 시험이 실행됐다고 보지는 않습니다.
실제 세션 기록이 부족하면 `verify_integration.py --require-real-hosts`는 실패해야 합니다.
실행하지 못한 조건을 가짜 응답이나 이 세션의 사전 지식으로 채우지 않습니다.
