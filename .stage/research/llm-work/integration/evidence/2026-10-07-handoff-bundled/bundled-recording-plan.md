## Purpose

AI가 같은 형식의 JSON과 명령을 여러 번 만들지 않아도 선택과 출처를 보존할 수 있는지 봅니다.
SSOT·SoC·TDD·Honesty·Completion을 적용합니다. 제품에 넣기 전에 연구 폴더에서 검증합니다.

## 바꿀 부분

Avatar의 선택 저장 → 개인 기준 제안 → 시험용 확인 발언 전달 → 적용한 Distill 이력 첨부 → 조회를
실험용 명령 하나로 묶습니다. 내부에서는 기존 공개 CLI를 순서대로 실행하고 응답을 모두 남깁니다.
AI가 고른 값과 적용 참조를 인자로 받습니다. 이 명령이 오류 처리 방식을 대신 고르지는 않습니다.
시험용 자료임을 확인하고, 정해 둔 정확한 문장을 확인한 발언이 있을 때만 확인 명령을 실행합니다.
실제 사용자 데이터에 쓰는 제품 명령으로 배포하지 않습니다. 제품 소스도 바꾸지 않습니다.

Stage 카드 작성, 코드 구현과 검사, 선택 직전 Distill 조회는 AI가 계속 수행합니다.
앞선 세션이 남긴 파일과 카드도 그대로 받습니다. 이 부분까지 코드로 대신하면 다른 실험이 됩니다.

## 실행 조건

- 앞선 후속 시험의 전달 세션 두 개와 결과를 그대로 재사용합니다. 새 전달 세션이라고 세지 않습니다.
  원본 경로와 해시를 남기고 복사한 내용이 같은지 검사합니다.
- 받은 세션은 방향 두 가지 × C0·C1·C2의 여섯 사례입니다. 모두 새 세션에서 한 번씩 실행합니다.
- 기존 180초 제한, 모델, 과제, 기준, 최대 동시 실행 두 개를 유지합니다. 실패한 사례를 골라 다시 실행하지 않습니다.
- C0에는 현재 기준 조회를 연결하지 않지만 옛 카드와 코드는 남습니다. 완전히 영향을 없앤 대조군은 아닙니다.
- 새 명령은 쓰기 전에 입력을 검사합니다. 중간 CLI가 실패하면 멈추고 실행한 응답을 보존합니다.
  전체 처리가 한 트랜잭션이라고 주장하지 않습니다. 같은 입력의 재요청은 각 제품의 idempotency key를 재사용합니다.
