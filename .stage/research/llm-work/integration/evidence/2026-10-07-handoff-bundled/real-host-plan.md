# 실제 두 호스트 인계 시험

2026-10-07. W-00000277. 첫 모델 실행 전에 아래 조건을 고정합니다.

## Purpose

한 AI가 끝낸 작업을 다른 AI가 현재 기준으로 이어가는지 확인합니다. SSOT·Honesty·Completion을 적용합니다.

## 조건과 기대 결과

- 실제 Codex CLI 0.160.0의 `gpt-6-sol`을 사용합니다. 현재 사용자 설정의 모델입니다.
  앞선 실패는 `gpt-5.6-sol`을 호출한 실행기에서 났습니다. 새 환경의 성공을 그 실패의 원인 규명으로 보지 않습니다.
- Claude는 `opus[1m]`을 요청하고 응답의 실제 모델명을 남깁니다.
- 각 호스트가 기준 v1을 공개 CLI로 기록하고 `parse_port`를 만듭니다. 이 두 결과를 각각 세 번 복사합니다.
  받은 AI는 매번 새로운 세션이며 앞선 세션의 대화 이력을 받지 않습니다.
- Claude → Codex, Codex → Claude 각각에 C0·C1·C2를 적용합니다.
  C0은 현재 기준을 주지 않습니다. C1은 v1을 줍니다. C2는 복사한 저장소에서 v2로 바꾼 뒤 줍니다.
- `parse_port("443")`은 443을 반환합니다. 잘못된 값과 범위 밖 값에는 v1의 `ConfigError`를 던집니다.
- `parse_host("example.com")`은 원문을 반환합니다. `"bad"`는 잘못된 입력입니다.
  C1은 `ConfigError`, C2는 `None`을 기대합니다. C0은 처리 방식을 관찰합니다.
- 받은 AI에게는 과제와 Stage가 만든 인계 글을 줍니다. 검사기의 기대값은 따로 보존하고 프롬프트에 붙이지 않습니다.
  현재 기준이 없을 때는 방식을 선택하고 이유를 적도록 합니다. 같은 설명이 부족해 질문하면 원문에 남깁니다.
- 앞선 `parse_port`의 바이트가 바뀌면 반복 작업으로 기록합니다. 적용 참조와 C2의 낡은 판단도 확인합니다.
- 받은 세션은 과제 뒤 Avatar에 시험용 선택과 이유를 기록합니다. 정해 둔 개인 기준을 제안하고 시험용 확인 발언으로 확인합니다.
  이 기록을 실제 사용자의 성향이나 확인으로 취급하지 않습니다. 공개 CLI의 `show`·`export`로 결과를 확인합니다.

## 격리와 증거

프로젝트와 두 DB는 새 임시 디렉터리 안에 둡니다. 전역 설정이나 실제 개인 DB는 바꾸지 않습니다.
Claude의 훅은 이번 실행에만 끕니다. Codex는 이번 실행에만 사용자 config를 제외하고 임시 프로젝트 쓰기 권한을 줍니다.
제품의 공개 CLI를 명시적으로 알려 주는 시험입니다. 스킬 자동 선택이나 무인 드라이버를 검증한다고 주장하지 않습니다.

각 AI 호출은 180초로 제한합니다. 독립된 사례는 최대 두 개씩 실행합니다. 오류나 실패를 덮어쓰거나 같은 사례를 성공할 때까지 반복하지 않습니다.
프롬프트·argv·종료 코드·원본 응답·사용량·경과 시간·최종 파일·앞선 파일 digest를 보존합니다.
완료했다고 한 답변과 파일 검사 결과를 구별합니다. 검사기 코드와 제품 소스의 digest도 보존합니다.

하나의 앞선 결과를 조건 세 가지가 공유하므로 여섯 사례를 완전히 독립적인 표본으로 세지 않습니다.
작은 파서 과제의 관찰만 보고합니다. 비용 절감률이나 일반적인 성공률로 확대하지 않습니다.
