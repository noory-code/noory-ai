# Avatar가 업무 기록을 수집하지 않고 분석하는 방법

2026-10-07. W-00000280. Codex와 Claude가 주고받은 토론을 정리했습니다.
설계는 아직 확정하지 않았습니다. 분석 정확도나 수요를 검증한 실험 결과도 아닙니다.

## Purpose

Avatar에 쌓인 선택을 돌아보며 자신을 이해하도록 돕습니다.
사용자는 업무에 기업의 비밀이 들어갈 수 있다고 지적했습니다.
이어서 “데이터를 모으지 않는다는게 중요한거죠..”라고 말했습니다.
운영 서버에 업무 원문과 개인 분석 결과를 모으지 않는 방법을 검토합니다.
대략적인 통계를 서버에 보낼 수 있는지도 아직 정하지 않았습니다.

## Discussion

Claude CLI에 반론을 두 차례 요청했습니다. 실행 결과가 보고한 모델은 `claude-opus-5-5`입니다.
Codex의 제안, Claude의 반론, Codex의 재반론, Claude의 수정, Codex의 정리를 총 5개 라운드로 남겼습니다.
Claude에는 제품 구상과 가상 사례만 전달했습니다. 개인 DB와 업무 대화 원문은 전달하지 않았습니다.
Claude는 도구를 쓰지 않았으며 코드와 외부 자료를 직접 검증하지 않았습니다.
실행에서는 `--safe-mode`, 빈 도구 목록, 빈 MCP 설정과 임시 작업 폴더를 사용했습니다.
이 토론 자체는 외부 AI를 사용했습니다. 오프라인 분석을 실증한 작업이 아닙니다.

### 가장 큰 반론

**저장한 기록이 그 사람의 모든 결정을 대표하지는 않습니다.**
Claude는 AI 의견을 거절한 순간만 저장한 사람을 예로 들었습니다.
이 기록만 보면 실제보다 반대가 잦은 사람으로 해석할 수 있습니다.
이 반론을 받아들였습니다. 리포트가 설명할 범위를 선택한 기록으로 한정해야 합니다.
빠진 기록의 비율은 별도 근거가 없으면 알 수 없습니다.

**행동이 같아도 이유는 다를 수 있습니다.**
버릴 시제품이라 테스트를 줄인 경우와 마감 때문에 줄인 경우를 구별해야 합니다.
작업량과 선택 횟수만으로 두 사람의 기준이 같다고 말할 수 없습니다.
당시 이유가 없으면 이유를 알 수 없다고 표시해야 합니다.

**기록을 만드는 AI가 자기 판단을 사용자 판단으로 잘못 적을 수 있습니다.**
AI가 제안했고 도구가 실행했더라도 사용자가 동의했다는 뜻은 아닙니다.
누가 말했는지, 정확히 무엇을 말했는지, 무엇이 추정인지 남겨야 합니다.
출처를 적었다고 발언자의 신원을 증명하는 것도 아닙니다.

## Proposed architecture

분석 엔진은 다음 일을 나누어 맡는 안을 제안합니다. 아직 구현하지 않았습니다.

| 할 일 | 맡길 곳 | 확인할 점 |
|---|---|---|
| 선택과 이유의 초안 만들기 | 이미 작업에 참여한 AI 또는 기기에서 도는 모델 | 사용자의 말과 AI의 말을 구별하는지 봅니다. 이유를 지어내면 해당 초안을 채택하지 않습니다. |
| 출처와 기록 정리하기 | 로컬 프로그램 | 중복, 같은 작업의 여러 세션, 기준 변경, 페르소나를 시험한 기간을 관리합니다. 같은 작업인지 모르면 합치지 않습니다. |
| 상황과 이유를 비교하기 | 로컬 규칙, 사람의 판단, 필요 시 선택한 모델 | 단순 집계와 의미 해석을 구별합니다. 비슷한 상황인지 판단하는 기능은 별도 검증이 필요합니다. |
| 결과와 근거 보여주기 | 브라우저 또는 로컬 앱 | 사용자가 선택한 범위를 표시합니다. 해석을 수정하거나 보류할 수 있게 합니다. |
| 화면과 상품 제공하기 | 운영 서버 | 개인 기록을 받지 않는 구성을 검토합니다. 결제에 필요한 정보와 업무 기록은 약속을 따로 정해야 합니다. |

현재 쓰는 Claude나 Codex에 초안을 맡기면 해당 제공자는 내용을 처리합니다.
Avatar 운영 서버가 기록을 받지 않는다는 약속과 모든 외부 AI에 내용을 보내지 않는다는 약속을 구별해야 합니다.
모든 외부 전송을 막으려면 선택한 기기에서 실제로 처리할 수 있는지 시험해야 합니다.
모델, 설치 방법, 지원 기기는 정하지 않았습니다.

사용자가 고른 파일은 브라우저에서 읽을 수 있습니다.
다만 브라우저에서 처리한다는 사실만으로 전송이 없다고 증명할 수는 없습니다.
오류 보고, 외부 스크립트, 결제 확인, 업데이트 경로도 실제 구성에 맞춰 검사해야 합니다.

## Experiments to run

아래 시험은 아직 실행하지 않았습니다. Claude의 가상 사례 답변을 실제 추출 시험의 통과 결과로 세지 않습니다.

### 첫째: 선택을 정확히 기록하는가

- 가상 사례 12개를 만듭니다. 명확한 사례와 애매한 사례를 짝으로 둡니다.
- 실행 전에 발언자, 이유, 중복 관계, 페르소나 기간, 말하면 안 되는 결론을 적습니다.
- 사용자가 직접 저장하는 현재 방식과 AI가 초안을 만드는 방식을 비교합니다.
- 없는 승인·인용·확정 기준을 만들면 자동 채택을 막습니다.
- 명확한 근거가 있는 사례에서는 그 근거를 추출해야 합니다. 모든 답을 보류하면 통과하지 못합니다.
- 오류, 수정 단계, 실행 시간을 따로 기록합니다. 사람이 실제로 고치기 전에는 수정 시간을 주장하지 않습니다.

### 둘째: 근거를 잘 보여주는 것보다 해석이 더 도움이 되는가

- 선택과 이유를 읽기 좋게 정리한 화면을 기준으로 둡니다. 숫자만 나열한 화면보다 강한 비교 대상입니다.
- 같은 수준의 자료로 AI 해석을 더한 리포트와 비교합니다. 보여주는 순서를 바꿉니다.
- 근거가 있는 차이와 반례를 짚을 수 있는지 봅니다. 새로운 발견만 유용하다고 보지는 않습니다.
- 이후 사용자가 고른 상황에도 그 구별이 도움이 되는지 확인합니다.
- 해석 때문에 오류와 수정 수고만 늘면 기능을 줄이거나 다시 설계합니다. 판단할 기준은 시험 전에 정합니다.

### 셋째: 기록이 밖으로 나가는가

- 가상 비밀 문구를 넣고 불러오기, 화면 표시, 오류, 내보내기 경로를 실행합니다.
- 외부 요청에 원문, 파일 이름, 분석값이 섞이는지 확인합니다.
- 결제나 업데이트 경로를 만들면 그 경로도 검사합니다.
- 결과는 검사한 버전과 경로에만 적용합니다. 한 번 통과했다고 미래의 모든 배포가 안전하다고 말하지 않습니다.

## Current implementation

현재 로컬 미리보기는 사용자가 고른 기록을 Claude로 보내 해석할 수 있습니다.
전송 내용에는 질문, 선택, 이유와 상황이 들어갑니다. 익명 통계만 보내는 구조가 아닙니다.
이번 토론에서 제품 동작을 바꾸거나 공개 배포하지 않았습니다.
자동 대화 수집, 여러 세션의 작업 연결, 완전한 로컬 모델 분석도 구현하지 않았습니다.
구현 검증은 [기존 구현 기록](implementation.md)이 소유합니다.

## Open questions

- 서비스가 약속할 범위는 Avatar 운영 서버의 비수집인가, 외부 AI까지 포함한 무전송인가?
- 대략적인 통계도 기기 밖으로 보내지 않을 것인가?
- 해석이 틀린 비용과 사용자가 고치는 수고를 어느 수준까지 허용할 것인가?
- 기록이 드문 사람에게도 근거를 보여주는 리포트가 반복해서 쓸 만큼 도움이 되는가?
- 배지와 꾸미기는 그 가치를 확인한 뒤 어느 시점에 더할 것인가?

이 질문들을 사용자에게 한꺼번에 답하라고 요구하지 않습니다.
먼저 가상 사례와 비교 화면을 만들어 선택의 영향을 살펴볼 수 있습니다.
실제 개인 자료를 다루거나 설계를 확정할 때는 남은 선택을 확인합니다.

## Principles

Completion: 남은 질문과 현재 구현의 한계를 함께 남깁니다.
