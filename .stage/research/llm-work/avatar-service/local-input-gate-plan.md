# 가상 대화 파일을 로컬에서 읽는 첫 시험

2026-10-08. W-00000280. 앞선 모델 실험은 메시지 작성자를 입력에서 그대로 믿었습니다.
이번에는 그 전제를 작은 파일 읽기 단계에서 확인합니다. 제품의 Claude·Codex 대화
가져오기 기능은 아직 만들지 않습니다.

## 고정한 자료와 기준

`fixtures/avatar-conversation-synthetic-1.jsonl`은 이 연구를 위해 만든 형식입니다.
첫 줄은 `avatar-conversation-lab/1`과 `synthetic: true`를 표시합니다. 뒤의 일곱 줄에는
가상 메시지를 넣었습니다. 실제 Claude·Codex 내보내기 형식이라는 뜻이 아닙니다.

| ID | 역할 | 발생 경로 | 기대 결과 |
|---|---|---|---|
| U1 | user | human_input | 사람이 직접 입력한 메시지 후보 |
| A1 | assistant | assistant_output | 제외 |
| T1 | user | tool_result | 제외. 역할이 user여도 사람이 쓴 말로 보지 않음 |
| M1 | user | human_input, 메타 표시 | 제외 |
| X1 | user | unknown | 작성 경로를 몰라 제외 |
| U2 | user | human_input, 본문에 도구 블록 혼합 | 제외. 텍스트만 골라 쓰지 않음 |
| U3 | user | human_input | 사람이 직접 입력한 메시지 후보 |

읽기 실행기는 호출자가 지정한 파일 한 개만 읽습니다. 연구 폴더의 `fixtures/` 안에 있는
이름이 `avatar-conversation-synthetic-`로 시작하는 파일만 허용합니다. 첫 줄의 가상 표시,
파일 크기와 줄 수, 중복 ID, 역할·발생 경로·본문 형식을 검사합니다. 실패하면 파일 전체를
거절합니다. 모델과 네트워크를 부르지 않고 DB에도 쓰지 않습니다. 화면 출력에는
메시지 ID와 제외한 이유, 개수만 적고 본문·경로는 내보내지 않습니다.

`human_input`은 이 **가상 형식에서 붙인 표시**일 뿐, 실제 사람의 신원을 증명하지
않습니다. 사람 입력 후보 안에 동료의 인용이나 AI 요약이 있을 수도 있습니다.
따라서 후보를 개인의 말투·판단 기준으로 바로 분석하지 않습니다.

## 완료 기준

- 일곱 메시지 중 U1·U3만 사람 입력 후보로 나옵니다.
- `role=user`인 T1과 본문이 섞인 U2를 그대로 제외합니다.
- 실제 폴더를 자동으로 찾지 않습니다. 가상 표시·발생 경로·ID·본문이 잘못되면 거절합니다.
- 출력에 원문이 섞이지 않습니다. 모델·네트워크·개인 DB를 건드리지 않습니다.

이 검사를 통과해도 Claude·Codex 실제 기록의 작성자를 가려냈다고 말하지 않습니다.
각 호스트 파일을 지원하려면 공개된 형식 또는 사용자가 제공한 샘플에서 어떤 필드가
사람 입력을 뜻하는지 별도로 확인하고, 변한 형식은 거절해야 합니다.

Honesty: 가상 형식의 분류와 실제 호스트 지원을 구별합니다.
SSOT: 시험 자료와 기대 결과는 이 계획과 가상 파일이 소유합니다.
AHA: 모델보다 앞단의 작성 경로부터 가립니다.
