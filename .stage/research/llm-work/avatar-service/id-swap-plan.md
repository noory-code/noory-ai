# 같은 문구의 ID만 바꾼 가상 실험

2026-10-08. W-00000280. 지난 실험에서 “부록은 시간 순서로 정리해
주세요”가 행동 요청과 직접 조건 양쪽으로 읽혔습니다. 이번에는 분류 지침에
우선순위를 줍니다. 사용자가 지금 할 일의 형식·순서·길이·단위 같은 조건을
직접 말하면, 행동을 함께 부탁해도 `user_task_constraint`로 표시합니다.
`request_action`은 그런 새 조건이나 앞 조건의 적용 없이 행동만 부탁할 때
씁니다. 앞 실험의 기대 판정과 점수는 고치지 않습니다.

`id-swap-fixture.json`의 A와 B는 문장 세 개와 순서가 같습니다. A에서는
읽는 습관이 Z1, 부록 조건이 Z2입니다. B에서는 두 문구의 target ID와
message ID를 맞바꿉니다. 마지막 부탁 Z3은 두 사례에서 모두 읽는 습관을
가리켜야 합니다. 따라서 A의 참조는 Z1, B의 참조는 Z2입니다. B에서도
Z1을 내면 작은 ID를 따라 고른 것으로 보아 실패입니다.

각 사례를 두 번씩 실행합니다. 네 번의 호출에서 문구 12개를 채점합니다.
사례를 실행하기 전에 기대 판정과 문구가 같고 ID만 바뀐 사실을 검사합니다.
모델에는 기대 판정을 주지 않습니다. 분류 지침의 우선순위 변경을 기록하고
도구를 끈 Claude Sonnet low로 실행합니다. 실제 CLI 인자도 남깁니다.

이 실험은 ID만 고르는 규칙을 가립니다. 두 사례 모두 정답 문구가 먼저
나오므로 첫 문구만 고르는 규칙까지 가리지는 못합니다. 또 정답은 유일한
자기 보고 문구이고 마지막 부탁과 “읽”이라는 낱말이 겹칩니다. 실제
대화나 개인 DB를 읽지 않고 개인 기준으로 저장하지 않습니다. CLI 정가
기준 사용량은 실제 청구액과 구별합니다.
