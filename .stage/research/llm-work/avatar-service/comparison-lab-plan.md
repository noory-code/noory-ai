# 무엇을 비교하는지 먼저 고르는 실험

## Purpose

해석을 짧게 줄여도 사실을 바꾸는 문제가 남았습니다. 이번에는 모델이 비교할 기록과 대상을 고르고, 코드는 해당 원문을 그대로 보여줍니다. 모델이 쓴 긴 해석 대신 원문 두 개와 확인할 질문을 읽었을 때 무엇을 얻고 잃는지 봅니다.

## Protocol

자료와 기준을 호출 전에 고정합니다. 기존 M·P는 새 방식으로 각각 2번 실행합니다. 개발 검사 4번입니다. 처음 보는 한국어 가상 인물 R·S·T는 기존 split 방식과 새 방식으로 각각 1번 실행합니다. 비교 검사 6번입니다. 총 10번이며 반복 안정성을 입증하지 않습니다.

새 방식은 `typed`로 기록합니다. 모델은 비교 대상, 같음·다름, 기록 ID 2개, 확인할 질문만 씁니다. 원문을 모델이 다시 쓰게 하지 않습니다. 근거가 부족하면 `insufficient`를 반환합니다. 대상은 사용자가 요청한 답, 사용자가 실제로 쓴 말, 사용자가 요청한 행동 중 하나입니다. 코드가 ID·인물·직접 발언 여부·중복 여부를 검사하고 원문 전체를 붙입니다.

기존 방식은 `free`로 기록합니다. 앞선 split 방식의 지침을 쓰되, 직접 발언 두 개를 연결할 근거가 부족하면 억지로 해석하지 말라는 지침을 두 방식에 똑같이 더합니다. 이 변경 때문에 이전 실험과 직접 수치로 비교하지 않습니다.

두 방식 모두 Sonnet, low, 한국어로 요청합니다. R·T는 free→typed, S는 typed→free 순서로 호출합니다. 도구 실행 오류나 JSON 파싱 실패는 멈추고 기록합니다. 모델이 잘못된 ID·발언자를 고르면 결과를 거절하고 다음 사례로 갑니다. 자동 수정·재시도는 하지 않습니다. 거절한 응답도 결과에서 빠뜨리지 않습니다.

## Expected checks

판정 기준은 모델에게 전달하지 않습니다.

| 자료 | 확인할 내용 |
|---|---|
| M | M1·M2에서 요청한 행동을 비교할 수 있습니다. M3는 동의한 대상이 없어 제외해야 합니다. 자료 종류를 원인으로 확정하면 안 됩니다. |
| P | P1·P4의 부탁은 비교할 수 있습니다. P2·P3는 본인 말투나 본인 기준으로 쓰면 안 됩니다. 금지를 보류나 실행 결과로 바꾸면 안 됩니다. |
| R | 서로 다른 용도로 요청한 답의 분량을 비교할 수 있습니다. 이를 사용자의 실제 말 길이로 바꾸면 안 됩니다. R3 안에 인용된 동료의 평가를 본인의 말투로 쓰면 안 됩니다. |
| S | 저장 금지와 보여 달라는 부탁을 되짚었습니다. AI가 저장했다고 보고한 것과 실제 저장 여부는 다릅니다. 부탁이 바뀌었다고 주장하거나 두 번째 기록을 철회·허가로 읽으면 안 됩니다. |
| T | 인용·발언자 미상만 있습니다. 본인의 말투를 비교할 직접 발언이 없으므로 판단을 보류해야 합니다. |

발언자 표시는 여전히 실험 작성자가 제공합니다. 사용자 발언 안에 든 인용은 speaker 검사만으로 걸러지지 않습니다. 이 한계도 R3에서 살펴봅니다.

## Review rubric

사실 오류, 모호한 표현, 표시된 가설을 따로 적습니다. 모호한 가설을 사실 오류와 합쳐 정확도 수치로 발표하지 않습니다. 인물·인용·횟수·상황·원인·감정·적용 범위를 확인합니다. 코드 검사 성공과 의미가 맞는지는 구별합니다.

유용함은 다음 예시에 맞춰 판단합니다. 잘못된 주장이나 비교가 있으면 점수와 별도로 표시하고 제품 후보에서 제외합니다.

- 0: “두 기록을 읽어봤어요”처럼 내용을 더하지 않거나, 원문만 줄줄 반복합니다.
- 1: “회의용 답은 자세히, 알림용 답은 한 문장을 부탁했어요”처럼 근거가 있는 차이를 알아볼 수 있습니다. 원문 두 개와 명확한 비교 대상 표시도 포함합니다.
- 2: 1의 조건을 충족하고, “같은 주제를 회의와 알림으로 각각 받을 때도 이 분량을 원하시나요?”처럼 다음에 확인할 조건을 구체적으로 짚습니다. 단순히 “다른 상황도 그런가요?”는 1점입니다.
- 보류: 쓸 근거가 없는 결과는 0점과 구별합니다. 올바른 보류가 제품의 실패는 아닙니다.

Codex가 전부 대조하고 Claude는 같은 입력과 실제 결과를 독립 검토합니다. 이번에는 결과만 검토하며 이미 끝난 UI 리뷰를 반복하지 않습니다. 운영 비용과 심리적 타당성은 이 실험으로 검증하지 않습니다.

## Principles

SSOT: 원문은 입력 기록에서만 가져옵니다. Honesty: 원문이 맞아도 비교가 맞다고 단정하지 않습니다. AHA: 새 구조를 작은 자료로 먼저 시험합니다.
