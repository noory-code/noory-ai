# 조건 둘 중 하나를 명시한 가상 사례

2026-10-08. W-00000280. 첫 실험에서 H의 마지막 문구는 `unresolved`로 나왔습니다.
하지만 모델이 문장을 읽은 것인지, 조건이 두 개면 무조건 `unresolved`를 고른 것인지
구별하지 못했습니다. Claude의 독립 검토가 제안한 짝 사례를 먼저 고정합니다.

`reference-pair-fixture.json`의 H와 HP는 같은 가상 사용자 메시지입니다. 마지막 문장만
H의 “이번에는 그렇게 맞춰 주세요.”에서 HP의 “이번에는 팀장님 말대로 맞춰 주세요.”로
바꿉니다. 나머지 문장과 검사할 두 조건은 같습니다. 사례마다 두 번씩 실행합니다.
모델에는 기대 판정을 주지 않고, 앞 실험과 같은 지침·출력 형식을 씁니다.

H의 H3은 두 조건 중 어느 것인지 알 수 없어 `unresolved`가 정답입니다. HP의 H3은
팀장님의 한 장 조건인 H1을 가리켜야 합니다. 각 실행에서 H3의 `act`는
`request_apply_constraint`여야 합니다. H에서 H1·H2를 고르거나 HP에서
`unresolved`·H2를 고르면 실패입니다. H1·H2도 앞 실험과 같은 판정이어야 합니다.
형식이 틀리면 그 실행을 실패로 세고 원본을 남깁니다. 모델이 맞힌 값과 코드가 채운
문구·작성자·개인 규칙 여부는 나눠 적습니다.

네 번의 실행이 모두 맞아도 실제 대화에서 조건을 정확히 찾는다는 뜻은 아닙니다.
문구와 작성자 역할을 미리 줬고, 지침도 모호한 조건을 설명합니다. 실제 대화나
개인 DB는 읽지 않습니다. 청구액은 확인하지 않고 CLI의 정가 기준 숫자만 기록합니다.

Honesty: 맞힌 범위와 미검증 범위를 구별합니다.
SSOT: 이 계획과 fixture가 기대 판정을 소유합니다.
AHA: 문장 하나를 바꾼 뒤에 필요한 구별이 되는지 봅니다.
