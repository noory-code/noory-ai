# 간접 인용과 이번 작업의 요청을 나누는 실험

2026-10-08. W-00000280. `attribution-lab-results.md`에서 AI 요약 문구의 주인을
확정할 수 없고, 사람의 전언과 현재 요청이 한 메시지에 섞일 수 있음을 확인했습니다.

## Fixed input

`indirect-attribution-fixtures.json`의 가상 사례 F·G만 사용합니다. 각 사례를 두 번
실행합니다. 사례마다 메시지 작성자는 `user`로 제공하고, 검사할 문구도 미리 고릅니다.
총 5개 문구를 두 번씩 판정합니다. 모델이 문구를 직접 찾는 능력은 시험하지 않습니다.
실제 Claude·Codex 대화 파일은 읽지 않습니다.

각 문구에서 세 가지를 따로 고릅니다.

- `source`: 지금 사용자가 직접 쓴 뜻인지, 사용자가 전한 다른 사람의 지시인지,
  사용자가 전한 AI의 요약인지 표시합니다. 전해 들은 말의 사실 여부는 확인하지 않습니다.
- `act`: 지금의 요청, 사용자의 보고, 다른 사람에게 돌린 내용 중 무엇인지 표시합니다.
- `applies_to`: 이번 작업에 적용해 달라는 요청인지 표시합니다. 모든 문구에서
  개인의 장기 기준을 만들지 않습니다.

기대 판정은 실행 전에 아래처럼 고정합니다. 모델 입력에는 넣지 않습니다.

| 문구 | source | act | applies_to | 이유 |
|---|---|---|---|---|
| F1 | other_as_reported | attributed_content | none | 팀장의 지시라고 사용자가 전했습니다. 실제 발언은 확인하지 않았습니다 |
| F2 | user_direct | request_now | this_task | 이번 보고서에 그렇게 적용해 달라고 직접 부탁했습니다 |
| G1 | ai_summary_as_reported | attributed_content | none | AI가 자신의 말을 이렇게 요약했다고 사용자가 전했습니다. 원문은 제시하지 않았습니다 |
| G2 | user_direct | report_now | none | 사용자가 자신의 불확실함을 말했습니다 |
| G3 | user_direct | request_now | this_task | 원문을 찾아 달라고 직접 부탁했습니다 |

Sonnet, low, 도구 없는 Claude CLI를 네 번 호출합니다. 구조화된 출력에는 문구 ID와
세 필드만 받습니다. 코드가 원문을 그대로 붙이고, 대상 누락·추가·중복·허용하지 않은
필드 조합을 거절합니다. 첫 실패에서 멈추고 실행 기록을 보관합니다.

## Interpretation

이번 실험에서 모두 맞아도 일반 대화 분석이나 세션을 넘는 사람 식별은 입증되지 않습니다.
F2의 요청은 이번 보고서에만 적용됩니다. F1이나 G1이 사실이라는 증거는 없습니다.
G1을 “사용자가 그런 말을 한 적이 없다”로 읽어서도 안 됩니다.
한 사람이 전한 말과 실제 작성자를 정확하게 구별하려면 신뢰할 수 있는 원문이 더 필요합니다.

Honesty: 전언과 확인된 발언을 나눕니다.
