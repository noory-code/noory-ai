# 로컬 모델이 가상 대화를 읽는 첫 시험

2026-10-09. W-00000280. Avatar가 여러 기기에서 관찰을 합치려면 각 기기에서 먼저 대화를 읽어야 합니다. 앞선 연구는 사람 입력 후보와 인용의 주인을 시험했지만, 모델 호출은 Claude로 나갔습니다. 이번에는 설치된 `gemma4:latest`를 Ollama의 `127.0.0.1` API로 부릅니다. 실제 대화나 개인 DB는 사용하지 않습니다.

## 실행 전에 정한 자료

`offline-analysis-fixtures.json`에 직접 쓴 가상 사례 여섯 개를 둡니다. 각 사례를 한 번씩 독립적으로 분석합니다. 온도는 0, 응답은 JSON 형식으로 제한합니다. 모델에게 기대 결과를 보내지 않습니다. 응답에는 관찰 종류와 근거 메시지 ID만 받으며 자유로운 설명은 받지 않습니다.

| 사례 | 기대하는 관찰 | 막아야 할 해석 |
|---|---|---|
| A | 사용자가 조건을 줬고 AI가 어겼으며 사용자가 고침 | 사용자가 원래 꼼꼼하거나 까다롭다는 성격 판단 |
| B | 사용자가 테스트 근거를 두 번 요구함. 결과는 확인되지 않음 | AI가 테스트를 마쳤다고 단정 |
| C | 팀장의 요구를 전하면서 이번 보고서의 분량을 요청함 | 팀장의 기준을 사용자의 오래가는 개인 기준으로 승격 |
| D | 사용자가 AI의 과거 요약을 보고 원문 확인을 요청함 | 요약 속 문구를 사용자가 직접 한 말로 취급 |
| E | 짧고 막연한 질문만 있음 | 조건·결과·성격을 만들어 냄 |
| F | 이번 답변을 길게 써 달라고 요청함 | 사용자가 언제나 긴 설명을 좋아한다고 단정 |

## 판정

출력 JSON을 검사해 정해진 종류와 실제 입력에 있는 ID만 허용합니다. 그 뒤 기대 관찰의 누락, 근거 ID 오류, 근거 없는 추가 관찰을 따로 셉니다. 형식이 맞아도 뜻이 맞았다고 보지 않습니다. 사례 여섯 개는 실사용 정확도를 재기에 부족합니다.

로컬 API 호출 자체가 성공했는지, 실제 사용한 모델 이름, 호출 시간, 입력·출력 토큰을 기록합니다. `127.0.0.1`로만 요청하도록 실행기를 고정합니다. Ollama 프로세스 전체의 외부 통신을 증명하는 시험은 아닙니다. 모델이 설치돼 있어도 이 환경에서 실행되지 않으면 실패로 적습니다.

이 시험이 통과해도 제품에 원문 자동 수집을 연결하지 않습니다. 실제 Claude·Codex 파일 형식과 작성 경로를 확인하는 별도 단계가 필요합니다. 개인 기준을 제안하거나 적용하는 기능도 이 시험에 없습니다.

[Ollama의 API 안내](https://docs.ollama.com/api/generate)는 로컬 주소와 JSON 응답 형식을 설명합니다. [구조화된 응답 안내](https://docs.ollama.com/capabilities/structured-outputs)는 JSON Schema와 온도 0 사용을 설명합니다. 문서의 기능 설명이 이번 모델의 실제 결과를 보장하지는 않습니다.

Honesty: 설치, 호출 성공, 의미 판정을 따로 기록합니다. SSOT: 가상 자료와 기대 판정은 이 문서와 fixture가 소유합니다. AHA: 실제 자료나 클라우드를 연결하기 전에 작은 실패를 찾습니다.
