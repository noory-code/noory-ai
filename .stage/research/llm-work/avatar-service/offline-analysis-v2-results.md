Ollama API에 JSON Schema를 넘겼어도 A·B의 `message.content`는 최상위 배열이었습니다. 실행기는 이를 거절하고 원문 응답을 연구 증거에만 저장했습니다. 이것은 가상 문장입니다. 실제 사용자 자료로 같은 일이 일어나면 모델 출력도 민감한 자료가 됩니다. 따라서 분석 결과의 JSON 형식, 발언자, 근거 ID를 코드로 검사해야 합니다. 검사를 통과한 분류도 C·D·F처럼 사람의 뜻을 잘못 읽을 수 있습니다. 사용자 확인 없이 개인 기준이나 동기화 항목으로 올리지 않습니다.

다음 제품 단계는 모델의 자유로운 분석 결과를 바로 저장하는 일이 아닙니다. 로컬에서 출처가 확실한 작은 관찰만 후보로 만들고, 사람에게 원문 근거와 함께 보여줘야 합니다. 사람이 고친 뒤에야 하루·주간 화면에 반영합니다. 여러 기기로 보내는 항목은 그 다음에 따로 고릅니다. 실제 호스트 파일과 키 관리·동기화 서버는 아직 연결하지 않습니다.

이번 여섯 사례는 로컬 모델의 실사용 정확도나 외부 통신 부재를 입증하지 않습니다. 실행기가 호출한 주소는 `127.0.0.1`뿐이며 실제 대화·개인 DB는 읽지 않았습니다. JSON Schema 사용은 [Ollama의 공식 안내](https://docs.ollama.com/capabilities/structured-outputs)에 따랐습니다. 여기 적은 실패는 이번 설치 모델과 이번 자료에서 실제로 관측한 결과입니다.
