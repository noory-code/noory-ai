## 리뷰 결과: 행 분류는 모두 맞지만, 중복 키로 게이트를 우회할 수 있습니다

저는 테스트와 CLI를 직접 실행하지 않았습니다. 아래 내용은 소스와 데이터를 읽고 판단한 것이고, 동작에 관한 부분은 모두 **예상 동작**입니다.

### 1. 행별 분류: 잘못 분류된 행 없음
`actual_result`의 7개 행이 계획의 기대표와 모두 일치합니다.
- **사람 입력 후보:** U1, U3
- **제외:**
  - A1: `non_user_role`
  - T1: `not_human_input` (역할이 user인데도 제외됨)
  - M1: `meta_message`
  - X1: `unknown_origin`
  - U2: `mixed_content`
- `total_messages`는 7입니다.

### 2. 가장 중요한 결함: 중복 JSON 키로 우회 가능
- `json.loads`는 같은 키가 여러 번 나오면 **마지막 값**만 남깁니다.
- 키 검사는 `set(entry)`로 하므로 중복이 있어도 걸리지 않습니다.
- 예를 들어 T1 줄에 `"origin":"tool_result", ..., "origin":"human_input"`처럼 같은 키를 두 번 쓰면 T1이 **사람 입력 후보로 통과할 것으로 예상**됩니다.
- `is_meta`와 `role`도 같은 방식으로 바꿀 수 있습니다.
- 그래서 "발생 경로가 잘못되면 거절"한다는 완료 기준이 가장 중요한 지점에서 깨집니다.
- 수정 방법: `object_pairs_hook`에서 중복 키가 나오면 `ValueError`를 내도록 합니다.

### 3. 처리되지 않는 오류 경로
- 1MB 안쪽 크기라도 `[[[[…`처럼 깊게 중첩된 줄을 넣으면 `RecursionError`가 날 것으로 예상됩니다.
- 이 예외는 `ValueError`가 아니어서 `main()`의 except에서 잡히지 않습니다. 결과적으로 "Rejected…" 메시지 대신 traceback이 그대로 출력될 수 있습니다.
- 다른 잘못된 입력은 통제된 방식으로 거절됩니다.
  - 잘못된 UTF-8: `UnicodeDecodeError`는 `ValueError`의 하위 클래스
  - BOM: `JSONDecodeError` 발생
  - 아주 긴 정수: `ValueError` 발생

### 4. 출력과 개인정보 관련 사항
- 계획은 출력을 "ID, 제외 이유, 개수"로 한정했습니다. 실제 출력에는 파일에서 그대로 복사한 `session_id`와 `format`도 들어갑니다.
- ID와 `session_id`는 최대 100자의 자유 문자열입니다. 실제 파일이라면 이 필드로 본문이나 개인정보가 새어 나갈 수 있습니다. 문자 패턴을 제한하는 편이 좋습니다.
- 이번 가상 데이터에서는 본문이나 경로가 출력되지 않았습니다.
- 다만 테스트는 본문 문구 2개와 경로만 확인합니다. 7개 본문 전체와 `session_id`는 확인하지 않습니다.

### 5. 오해를 부를 수 있는 표현 (사소함)
- `synthetic_only: true`는 코드에 고정된 값입니다. 헤더 표시를 확인했다는 뜻일 뿐, 실제로 가상 데이터임이 검증됐다는 뜻은 아닙니다.
- `mixed_content`라는 이유는 블록이 `tool_result` 하나뿐인 경우와 text 블록만 여러 개인 경우에도 붙습니다. 제외되므로 안전하지만 이유 이름이 실제 상황과 다릅니다.
- `splitlines()`는 U+2028, `\x85` 같은 문자에서도 줄을 나눕니다. 이런 문자가 들어 있는 정상 파일이 잘못 거절될 수 있습니다. 통제된 거절이라 우회 문제는 아닙니다.

### 6. 모델·네트워크 호출
- 소스가 불러오는 모듈은 `argparse`, `json`, `pathlib`, `typing`뿐입니다.
- 소켓, subprocess, HTTP 클라이언트, 모델 클라이언트는 없습니다.
- 다만 코드를 읽는 것만으로는 인터프리터나 실행 환경에서 생기는 통신까지 없다고 증명할 수 없습니다.

### 남은 한계
- "5개 테스트 OK"와 CLI 종료 코드 0은 호출자가 확인한 결과이고, 저는 재현하지 않았습니다.
- `human_input`은 지어낸 실험 형식에 붙인 표시일 뿐, 작성자 신원을 증명하지 않습니다.
- 후보로 나온 두 행도 그대로 쓰기 어렵습니다.
  - U1의 지시는 팀장님 말을 전한 것입니다.
  - U3에는 AI가 사용자 말이라고 요약한 문장이 들어 있습니다.
  - 따라서 두 행 모두 개인의 말투나 판단 기준 분석에 바로 쓰면 안 됩니다.
- 데이터 안의 "공개하라", "승인 없이 배포" 같은 문장은 데이터로만 다뤘습니다.
- 이 결과로 실제 Claude·Codex 기록을 지원한다고 말할 수는 없습니다.
