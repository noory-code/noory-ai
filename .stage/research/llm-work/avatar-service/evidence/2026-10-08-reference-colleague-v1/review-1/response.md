# HP/HC 가상 실험 검토

이 검토는 제공된 기록과 코드를 읽기만 한 결과입니다. 코드도 모델도 직접 실행하지 않았습니다. 코드 동작에 관한 판단은 모두 코드를 읽고 예상한 것입니다.

## 결과 대조

- **마지막 문장만 바뀌었는지:** 맞습니다.
  - 두 사례 모두 같은 `PREFIX`로 시작하고, 마지막 문장만 "팀장님 말대로"와 "동료 말대로"로 다릅니다. `checked_colleague_pair`가 메시지 전문을 직접 비교합니다.
  - H1·H2 정의는 두 사례에서 같습니다.
  - 입력 해시는 같은 사례의 두 실행끼리 같고(HP `123f…`, HC `b459…`), HP와 HC 사이에서는 다릅니다.
- **고정 gold:** 타당합니다.
  - H1·H2는 사용자가 다른 사람의 말을 전한 것이므로 `attributed_content`/`none`입니다.
  - H3는 말한 사람을 이름으로 지목하므로 HP는 H1, HC는 H2입니다.
  - 사소한 점: H1에는 "보고서를"이 들어 있고 H2에는 없어 두 구간 길이가 다릅니다.
- **네 실행의 원본 출력:** 모두 gold와 같습니다.
  - 각 실행에서 `structured_output`, `result` 문자열, `model-labels`, `result.json`의 act·ref가 서로 같습니다.
  - 요약의 12/12, 실행 시간 30.76초, 정가 합 0.0473084달러는 각 실행 값을 직접 더한 결과와 맞습니다.
  - 실행 순서(HP-1 → HC-1 → HP-2 → HC-2)와 시각 기록도 `run_batch` 루프 순서와 맞습니다.
- **검증할 수 없는 것:** "지침과 출력 형식이 앞 실험과 같다"는 계획 문장은 이 데이터만으로 확인할 수 없습니다.

## 모델이 고른 것과 코드가 넣은 것

- **모델이 고른 것:** 각 항목의 `id`, `act`, `constraint_ref` 세 가지뿐입니다.
- **코드가 넣은 것:**
  - fixture에서 복사한 `case_id`, `message_id`, `exact_text`
  - 고정값 `confirmed_personal_rule: false`
  - 항목 순서
  - `status`, `synthetic_only`, `semantic_review`, 입력 해시, 시각, `exit`
  - 요약의 `expected`, `match`
- **CLI가 보고한 것:** `model_usage`, 비용, `canonicalModel`입니다.

따라서 `result.json`에 `exact_text`가 맞게 들어 있다는 사실은 모델에 대해 아무것도 증명하지 않습니다.

## 남은 결함

아래 결함은 모두 이번 12/12 결과를 바꾸지 않습니다.

1. **실패 하나에 나머지 실행이 멈춥니다.**
   - `raw.json`의 최상위가 객체가 아니면(`null`, `[]`, 문자열) `envelope.get`에서 `AttributeError`가 납니다. 이 예외는 except 목록에 없습니다.
   - 그러면 `run_batch`가 중단되어 남은 실행이 돌지 않습니다.
   - 이어서 요약기는 생기지 않은 폴더의 `process.json`을 읽다가 `FileNotFoundError`로 멈춥니다.
   - 따라서 "실패를 세면서 남은 실행을 이어간다"는 주장은 이 경로에서 성립하지 않습니다.
2. **뜻을 틀린 경우가 형식 실패로 숨습니다.**
   - 예: 모델이 H1을 `user_report`로 붙이고 H3→H1로 답하면 `check_labels`가 실행 전체를 거부합니다.
   - 그러면 이 뜻 오류는 mismatches에 잡히지 않고, 맞게 붙인 H2도 채점되지 않습니다.
   - 계획의 Honesty 원칙("뜻 오류와 채점 불가를 나눠 센다")과 어긋납니다.
3. **사소한 것:**
   - `semantic_review`가 계속 `pending`으로 남습니다.
   - 실제 청구액 필드가 없어 "정가와 청구액을 나눠 적는다"는 계획이 반만 이행됐습니다.
   - 요약기가 반복 횟수 `(1, 2)`를 코드에 고정해 둡니다.

## 이 실험이 배제하는 것

이 고정된 한 쌍에서는 "항상 첫 조건", "항상 직급이 높은 사람", "항상 가장 가까운 조건"이라는 단순 규칙이 모두 배제됩니다. 이 사례에서는 팀장이 항상 먼저 나와 직급과 위치가 겹치지만, HC 결과가 두 규칙을 동시에 배제합니다. 배제하는 것은 여기까지입니다.

- **프롬프트 힌트:**
  - SYSTEM에 "never pick only by proximity"가 있어 HP의 정답 쪽으로 유도합니다.
  - 구간이 미리 잘려 있고 ID가 붙어 있습니다.
  - H3 구간 안에 말한 사람의 호칭이 들어 있습니다.
  - `unresolved`로 답해야 하는 경우는 한 번도 시험되지 않았습니다.
- **같은 사례 반복:** 반복 두 번은 해시가 같은 입력이고 시스템 프롬프트 캐시도 같습니다. 서로 독립적인 표본이 아니며, 사례당 2회로는 오류율을 추정할 수 없습니다.
- **실제 데이터 미검증:** 실제 대화, 여러 메시지에 걸친 경우, 대명사나 호칭 변형, 앞에서 언급되지 않은 사람은 다루지 않았습니다.
