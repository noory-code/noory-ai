# Avatar 선택 타임라인 리뷰 결과

**판정: 조건부 PASS.** 차단할 만한 회귀는 없습니다. 바로 고칠 만한 것은 접근성 문제 1건, 낮은 심각도 문제 3건입니다. 테스트는 실행하지 않았고 제공된 소스만 읽고 판단했습니다.

## 발견 사항

### 1. [접근성·중간] 하루/한 주 토글을 누르면 포커스가 사라짐
- **위치:** `avatar/web/app.mjs:255`
- **영향:** `render()`가 `#main`의 innerHTML을 통째로 바꿉니다. 그래서 방금 누른 `aria-pressed` 버튼이 DOM에서 사라지고 포커스가 `body`로 떨어집니다. 키보드나 스크린리더 사용자는 바뀐 상태를 듣지 못하고, 처음부터 다시 탐색해야 합니다.
- **최소 수정:**
  ```js
  if (button.dataset.timeline) {
    timelineMode = button.dataset.timeline; render();
    $('[data-timeline="' + timelineMode + '"]')?.focus(); return;
  }
  ```

### 2. [정확성·낮음] 연도 경계 값이 들어오면 타임라인 화면 전체가 예외로 멈춤
- **위치:** `avatar/web/timeline.mjs:18-19`, `:25-29`, `:50`
- **영향:** 예를 들어 `9999-12-31T23:00:00-14:00`은 검증을 통과합니다. 그런데 UTC나 현지 시간으로 바꾸면 연도가 10000이 됩니다.
  - `day`는 `"10000-01-01"`이 됩니다.
  - `new Date(day + 'T00:00:00Z')`는 Invalid Date가 됩니다.
  - `toISOString()`이 RangeError를 던집니다.
  - 그 결과 `timelinePage()`와 `render()` 전체가 실패합니다.
  - `1000-01-01T00:00:00+01:00`처럼 연도가 999로 내려가는 경우도 같은 위험이 있습니다.
  - `view`는 이미 `'timeline'`이므로, 이후 AI 완료 등에서 `render()`를 호출할 때마다 계속 실패합니다.
  - 가져온 파일 한 줄만으로 이 상태가 됩니다.
- **최소 수정:** `timestamp()`의 결과 범위를 제한합니다.
  ```js
  if (!Number.isFinite(valueMs) || valueMs < Date.UTC(1000, 0, 2)
      || valueMs >= Date.UTC(9999, 11, 20)) return null;
  return valueMs;
  ```
  이렇게 하면 해당 값은 `omittedCount`에 포함되고 화면은 계속 표시됩니다.

### 3. [정확성·낮음] 같은 선택의 날짜가 화면마다 다르게 보임
- **위치:** `avatar/web/app.mjs:48`
- **영향:**
  - 타임라인은 이 컴퓨터의 시간대 기준 날짜를 씁니다.
  - 나의 기록, 근거/비교 모달, 검색 결과는 `recorded_at.slice(0, 10)`, 즉 기록한 쪽 오프셋 기준 날짜를 씁니다.
  - 예를 들어 `2026-10-04T15:30:00Z`는 서울 기준 타임라인에서 10-05, 나의 기록에서 10-04로 보입니다. 어느 시간대 기준인지 표시가 없어 서로 모순으로 읽힙니다.
- **최소 수정:** 둘 중 하나를 택합니다.
  - `timeline.mjs`에 `localDay(value, timeZone)`를 export하고 `recordHtml`의 대체 경로에서도 사용합니다.
  - 또는 대체 경로의 `<time>`에 "기록 시점 기준"과 같은 표기를 덧붙입니다.

### 4. [출처 라벨·낮음] 예시 모드에서도 "직접 남긴 선택"이라고 표시됨
- **위치:** `avatar/web/app.mjs:116`
- **영향:** `mode === 'demo'`일 때도 "Avatar에 직접 남긴 선택만"이라고 표시됩니다. 상단 source-bar가 이를 완화하긴 합니다. 하지만 discover 화면(`:91`)은 예시 문장임을 따로 밝히는데, 이 화면만 그 구분이 없습니다.
- **최소 수정:** `mode === 'demo'`일 때 "설명용 예시 기록을" 같은 문구로 바꾸거나 한 문장을 덧붙입니다.

## 확인했고 문제없는 항목
- **날짜 검증:** 다음이 모두 맞게 처리됩니다.
  - `Date.UTC(year, month, 0)`로 말일 판정
  - 2월 30일 거부
  - 시간대가 없는 값 거부
  - 오프셋 ±14:00 상한
  - Monday 주 계산을 UTC 달력 연산으로 해서 DST 영향 없음
  - 같은 시각일 때 index로 안정 정렬
- **index 오인 방지:** `recordHtml`이 `map(recordHtml)`의 index 인자를 날짜로 착각하는 문제는 `typeof localDay === 'string'` 가드가 막습니다.
- **모듈 제공:** `/timeline.mjs`가 `ASSETS`에 들어 있고, import 추적 테스트(`test_avatar_web.py:44-56`)가 이를 확인합니다. 공개 갤러리(`avatar_public.py`)에 이 모듈이 없는 것은 의도에 맞습니다. 개인 기록 모듈이 노출되지 않습니다.
- **XSS:** `group.start`와 `end`는 숫자로만 조립되고, `timeZone`은 escape됩니다.
- **빈 상태:** 날짜가 있는 선택이 0건이면 안내 문구가 나오고, 제외된 건수 안내도 함께 표시됩니다.
- **작은 화면(320px 기준):** 토글 버튼 두 개는 약 240px로 들어갑니다. 주 범위 제목은 공백에서 줄바꿈되고, 건수 표시는 `nowrap`이지만 넘치지 않습니다.

## 데이터 형식 확인 필요
제공된 소스만으로는 실제 Avatar 저장 형식을 확인할 수 없습니다. 실제 `recorded_at`에 오프셋이 없거나(예: SQLite `CURRENT_TIMESTAMP`), 구분자가 공백이거나, 소문자 `z`를 쓰면 전부 제외됩니다. 그러면 타임라인이 비어 보입니다. `avatar show --json` 출력 형식이 정규식과 맞는지 확인이 필요합니다.
