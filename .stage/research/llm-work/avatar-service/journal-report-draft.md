# 하루 기록과 주간 돌아보기 시안

2026-10-09. 사용자는 세 번째 ‘작은 책’과 네 번째 ‘대화 코치’를 좋아한 뒤 “이거 일기 처럼 해도 되겠네”, “데일리리포트 위클리 리포트 이렇게”라고 제안했습니다. 두 화면을 묶어 `/journal.html` 시안을 만들었습니다.

하루 기록은 대화 한 장면을 읽습니다. 사용자가 한 말, AI가 한 일, 아직 모르는 결과를 갈라 보여줍니다. AI가 조건을 빠뜨린 날에는 사용자의 재요청을 대화 실력 부족으로 채점하지 않습니다. 사용자는 해석을 자기 말로 고칠 수 있습니다.

주간 돌아보기는 날짜가 있는 여러 장면을 펼칩니다. 그 주에 보인 모습과 AI가 놓친 일을 함께 읽되, 오래가는 성격으로 확정하지 않습니다. 다음에 해볼 일은 제안이며 개인 규칙에 자동으로 넣지 않습니다.

사용자는 주간 해석이 맞는지 답하고 다른 뜻을 적을 수 있습니다. 화면은 다음 한 주에 시험할 한 가지와, 한 주 뒤에 되물을 질문을 보여줍니다. 다음 주의 기록이나 답은 아직 없으므로 개선됐다고 말하지 않습니다. 지금 만든 시안은 알림을 예약하거나 답을 영구 저장하지 않습니다. 피드백은 이 탭에서만 남습니다.

제품으로 이어갈 때의 순서는 다음과 같습니다. 먼저 한 주의 근거와 AI의 누락을 보여줍니다. 사용자가 해석이 맞는지 고칩니다. 바꿔볼 일을 한 가지 고른 뒤 다음 주에 실제 결과를 확인합니다. 같은 문제가 반복되고 사용자가 원할 때만 AI에 적용할 규칙을 제안합니다. 이 마지막 단계는 이번 시안에서 구현하지 않았습니다.

가상 인물 M의 2026년 10월 5일·7일·9일 기록을 새로 썼습니다. 기존 K 기록에는 날짜가 없으므로 하루·주간 보고에 끼워 넣지 않았습니다. 금요일에는 M이 테스트 결과를 다시 요청했지만 후속 답이 없습니다. 화면도 완료를 주장하지 않습니다. 실제 사용자 대화를 읽거나 분석한 결과가 아닙니다.

정적 미리보기는 `http://127.0.0.1:4174/journal.html`에 둡니다. 원문과 해석을 고쳐 적은 메모는 브라우저 탭 메모리에만 남습니다. 개인 DB, 자동 수집, 광고, 외부 분석 요청은 연결하지 않았습니다. 실제 제품에서는 날짜와 대화의 출처를 확인하는 방법, 여러 날을 묶어도 되는 범위, 사용자에게 보낼 자료를 먼저 정해야 합니다.

화면을 본 뒤 살필 질문: 하루 중 어떤 장면을 일기에 넣어야 다시 읽을 가치가 있는가? 주간 화면은 무엇이 반복됐다고 말할 만큼 근거를 갖추었는가? 사용자가 해석을 고친 뒤 다음 보고에도 그 수정이 이어져야 하는가? 다음 주에 묻는 내용은 사용자의 개선과 AI의 누락을 어떻게 갈라야 하는가?

검증: 제품 Python 검사 47개, 플러그인 계약 검사 7개, Node 검사 25개와 두 체크아웃의 변경 검사가 통과했습니다. 브라우저에서 하루·주간 전환, 날짜별 해석 메모 분리, 주간 피드백 저장, 새로고침 뒤 탭 메모리 초기화, 390px 화면의 가로 넘침 없음, 입력한 HTML 문구가 실행되지 않고 문자로만 표시되는 것을 확인했습니다. 브라우저 오류·경고는 없었습니다. 로컬 공개 서버에는 개인 기록이나 분석 요청 경로를 연결하지 않았습니다.
