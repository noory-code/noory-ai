# 다시나 하루 리포트로 노블 시험하기

## 시험 목적

사용자는 다시나를 노블의 작은 실전 사례로 쓰자고 했습니다. 첫 시험에서는 가상 AI 대화로 하루 리포트 한 편을 설계합니다. 노블에서 이 일이 미션과 어떻게 이어지는지, 화면의 행동 순서까지 나타낼 수 있는지 확인합니다.

다시나의 미션은 사람이 AI와 나눈 대화를 돌아보고 더 잘 함께 일하도록 돕는 일입니다. 하루 리포트는 그 목적을 이루는 한 방법입니다. 사람이 다음에 무엇을 할지 고르는 일은 리포트의 가능한 결과이며 미션은 아닙니다.

## 실제 제품과 가상 시안의 차이

- `/journal.html`은 가상 인물 M의 대화를 사람이 직접 써서 만든 시안입니다. AI가 앞서 들은 조건을 놓쳐 M이 다시 설명한 장면이 있습니다. 사용자 대화를 읽거나 분석하지 않습니다.
- 현재 로컬 기록 화면은 Avatar의 선택 기록을 읽습니다. Claude·Codex의 일반 대화 파일은 가져오지 못합니다.
- 하루 출석은 날짜와 파일을 열었는지만 남깁니다. 대화가 나아졌다는 증거로 쓰지 않습니다.

따라서 하루 리포트의 설계와 실제 대화 분석의 구현을 같은 결과로 세지 않습니다.

가상 M의 10월 7일 장면에서는 M이 처음부터 “로그인은 넣지 마세요”라고 말했습니다. AI의 첫 시안에는 로그인 버튼이 있었고, M이 다시 말하자 다음 시안에서 빠졌습니다. 이 장면에서 근거가 허용하는 설명은 **AI가 조건을 놓쳤고 M이 고쳤다**는 것입니다. M이 요구를 잘못 전달했다거나 다음 작업이 성공했다는 말은 근거가 없습니다. 하루 리포트가 이 차이를 보여주어야 사용자가 AI와 일하는 방식을 정확히 돌아볼 수 있습니다.

## 노블에서 실행한 시험

실제 `dasina` 캔버스에는 확인된 미션과 “원문은 기기에 둔다” 기준만 남겨 두었습니다. 사용자 역할과 서비스 이름은 아직 확정하지 않았습니다.

임시 폴더에 가상 노블 프로젝트를 두 번 만들었고 시험 뒤 폴더를 삭제했습니다. 첫 시험에서는 미션과 기준, AI 사용자, 대화 돌아보기 서비스, 하루 리포트 기능을 만들었습니다. 각 항목을 프로젝트 중심이나 부모 서비스에 연결했습니다. 서비스가 사용자와 기준을 참조하도록 연결했고, 하루 리포트의 세부 캔버스가 생긴 것을 다시 읽었습니다. 읽힌 항목은 Foundation 노드 2개, 사용자 역할 1개, 서비스와 기능 2개였습니다. 세부 캔버스에는 기능의 시작 노드 1개가 있었습니다.

두 번째 시험에서는 AI 사용자 역할을 세부 캔버스에 참조하고, “가상 대화를 고른다”와 “발언과 근거를 확인한다”는 행동 2개를 연결했습니다. 다시 읽은 세부 캔버스에는 기능, 사용자 역할 참조, 행동 2개와 연결 2개가 있었습니다. 이 검사는 노블의 로컬 Python API가 기본 구조를 저장하고 다시 읽는다는 것만 확인합니다. 화면 품질이나 설계 내용의 타당성은 확인하지 않습니다.

세 번째 임시 프로젝트에서는 근거를 확인할 수 있는지에 따라 갈라지는 흐름을 그렸습니다. “확인됨”이면 근거가 붙은 하루 리포트를 보고, “확인 안 됨”이면 해석을 보류한 이유를 봅니다. 세부 캔버스를 다시 읽었을 때 노드 6개와 연결 4개가 있었고 두 갈래의 문구도 남았습니다. 이 흐름은 기술 시험용 가상 설계이며 실제 다시나 캔버스에 등록하지 않았습니다.

Codex에 연결된 노블 MCP에서 `get_canvas_framing`과 `get_canvas`를 호출하면 둘 다 `Error -3 while decompressing data: incorrect header check`가 반환됩니다. 앞선 프로젝트 목록 호출도 같은 오류였습니다. 같은 Mashbill 구현을 로컬 Python API로 부르면 읽기와 쓰기가 됩니다. 이번 시험은 **로컬 엔진 통과, Codex MCP 연결 실패**로 기록합니다. 실패 원인은 확인하지 못했습니다.

Codex 설정에 적힌 노블 실행 파일을 별도 stdio 클라이언트에서 실행했습니다. MCP 초기화와 `get_canvas_framing` 호출은 응답했습니다. 따라서 실행 파일 자체가 전혀 작동하지 않는다는 설명은 맞지 않습니다. Codex의 도구 연결에서 왜 압축 오류가 나는지는 아직 모릅니다. 이 수동 호출도 Codex의 연결이 복구됐다는 증거는 아닙니다.

## 설계하며 드러난 빈칸

1. 노블의 기준은 두 선택이 충돌할 때 무엇을 우선하고 어떤 불편을 감수하는지 적도록 합니다. 현재 “원문은 기기에 둔다”는 우선순위는 분명하지만 사용자가 감수할 불편은 확정하지 않았습니다.
2. 실제 캔버스에는 사용자 역할과 서비스가 없습니다. 노블은 서비스를 만들기 전에 참여자, 없는 경우의 불편, 좋아지는 결과, 지킬 기준, 접근하는 태도를 묻습니다. 마지막 태도도 아직 정하지 않았습니다.
3. 가상 M의 장면은 AI가 조건을 놓친 사건입니다. 이를 M의 대화 능력 부족으로 바꾸어 말하면 잘못된 피드백입니다. 하루 리포트는 사람이 한 일과 AI가 한 일을 분리해야 합니다.
4. 실제 대화 파일을 가져오는 경로와 발언자·인용의 주인을 확인하는 방법이 없습니다. 원문을 서버로 보내지 않는다는 약속만으로 로컬 분석이 완성되지는 않습니다.

## 다음 행동

사용자에게 “AI 대화 돌아보기”를 첫 서비스로, “하루 리포트”를 그 안의 기능으로 둘지 확인하고 있습니다. 답을 받으면 실제 노블 캔버스에 확인된 항목만 넣습니다. 그다음 가상 M의 장면으로 파일 선택, 근거 확인, 해석 수정, 근거 부족 시 보류를 행동 순서로 그립니다. 사용자에게 알리지 않은 업로드나 실제 개인 자료 분석은 하지 않습니다.
