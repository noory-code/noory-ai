# 다시나와 Avatar의 소스 경계

## 왜 나눴나

Avatar는 사용자가 남긴 선택과 확인한 기준을 기록합니다. 다시나는 그 기록을 읽고 자신을 돌아보는 화면을 만듭니다. 제품 화면이 플러그인 안에 있으면 웹 화면을 바꿀 때도 플러그인 배포와 검사에 묶입니다. 사용자가 두 소스를 다른 레포로 나누자고 한 이유에 맞춰 소유 장소를 나눴습니다.

## 현재 위치와 동작

- Avatar 플러그인: `/Users/woogis/.codex/worktrees/avatar-service/noory-ai/avatar/`. 선택과 기준의 저장, 조회, JSON 내보내기를 맡습니다.
- 다시나 제품: `/Users/woogis/Workspace/repo/dasina/`. 로컬 웹 화면, 가상 이야기, 선택 기록 보기, 일기 시안, 제품 검사를 맡습니다.
- Novel 기획: `/Users/woogis/Workspace/repo/dasina/.noory/novel/`. `dasina` 프로젝트에서 확인한 목적 문구와 데이터 비수집 기준을 보관합니다.

사용자가 미션을 바로잡은 뒤 Novel의 목적 문구를 “사람들이 AI와 나눈 대화를 돌아보고, 더 잘 대화하며 함께 일하도록 돕는다”로 고쳤습니다. 대화를 통해 자신을 알아보고 다음 행동을 고르는 일은 이 목적을 돕습니다. 제품 이름의 DA·SI·NA는 이름에 붙인 설명이며 기능이나 미션을 각각 확정한 목록은 아닙니다.

다시나는 Avatar의 Python 내부 모듈이나 SQLite 파일을 직접 열지 않습니다. 사용자가 내보낸 `show --json` 파일을 화면에서 고를 수 있습니다. 로컬 저장소를 직접 읽으려면 서버 시작 때 Avatar CLI와 저장소 경로를 지정해야 합니다. 화면에서 읽기를 요청하면 그때 CLI의 `show --json`을 실행합니다. `--ai claude`는 기본으로 꺼져 있으며, 켜더라도 사용자가 전송 내용을 보고 확인해야 선택한 기록을 보냅니다.

Avatar JSON의 `avatar-session/1`, `avatar-public/1` 같은 형식 이름은 호환을 위해 유지했습니다. 이름에 Avatar가 남았다고 두 소스가 같은 레포에 있어야 하는 것은 아닙니다.

## 확인한 것과 남은 것

다시나 Python 검사 27개와 Node 검사 37개가 통과했습니다. 제품 파일을 옮긴 뒤 Avatar Python 검사 24개와 플러그인 계약 검사 7개도 통과했습니다. 실제 Avatar CLI를 가상 빈 저장소에 연결했을 때 빈 기록을 반환했고 DB 파일은 만들지 않았습니다. 로컬 `127.0.0.1:4175`에서 다시나 첫 화면을 열었습니다. 실제 개인 대화나 DB는 읽지 않았습니다.

새 저장소는 아직 로컬 Git 저장소이며 첫 커밋과 원격 연결이 없습니다. 공개 배포, 광고, 계정, 여러 기기의 동기화, 일반 대화 분석은 만들지 않았습니다. 가상 예시 화면의 문장은 실제 사용자에 대한 분석이 아닙니다. 제품 이름의 설명인 DA(대화 분석)·SI(자기 이해)·NA(다음 행동)는 제품 방향을 나타내며 지금 세 기능이 모두 완성됐다는 뜻은 아닙니다.

이동 전 제품 자료는 `/Users/woogis/Workspace/repo/dasina-migration-backup-2026-10-09.tar.gz`에 보관했습니다. Avatar worktree의 다른 작업에서 만든 `avatar/.gitignore`는 보존했습니다. 이전 야간 작업 문서에는 당시의 제품 위치가 적혀 있으므로 현재 위치는 이 문서와 W-00000282를 따릅니다.
