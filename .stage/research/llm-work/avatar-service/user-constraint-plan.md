# 사용자가 직접 말한 조건을 가리키는 가상 실험

2026-10-08. W-00000280. 앞 실험 도구는 같은 메시지 안에서 다른 사람에게
돌린 조건만 연결했습니다. 사용자가 직접 말한 조건이나 앞선 메시지는 연결하지
못했습니다. `user-constraint-fixture.json`의 네 가상 사례로 범위를 확인합니다.

`user_task_constraint`는 사용자가 지금 하는 일에 직접 붙인 조건입니다.
`user_report`는 자신에 관해 말한 내용입니다. 둘 다 개인의 장기 기준을 확인한
것은 아닙니다. “이번에도 그 순서로”처럼 사용자가 현재 일에 적용하라고
명시하면 앞의 자기 보고를 이번 요청에만 연결합니다. 직접 조건을 말한 문구에는
참조를 붙이지 않습니다.

| 사례 | 고정한 기대 판정 | 확인할 점 |
|---|---|---|
| U | U1 직접 조건, U2→U1 | 같은 메시지 안의 사용자 조건 |
| V | V1 직접 조건, V2→V1 | 앞선 메시지의 사용자 조건 |
| Y | Y1 자기 보고, Y2→Y1 | 사용자가 지금 적용하라고 명시한 자기 보고 |
| X | X1 자기 보고, X2 직접 조건·참조 없음 | 지난 자기 보고를 멋대로 새 조건에 붙이지 않음 |

각 사례를 두 번씩, U·V·Y·X 순서로 실행합니다. 총 여덟 번, 문구 16개입니다.
모델에는 문장·작성자 역할·검사할 문구를 주고 기대 판정은 숨깁니다. 도구를 끈
Claude Sonnet low를 씁니다. 먼저 지금 검사기가 이 기대 판정을 거절함을 확인하고,
같은 메시지와 이전 메시지를 구별하도록 고칩니다. 그 뒤 실제 모델을 부릅니다.

형식이 틀린 실행은 따로 남기고 다음 호출을 이어갑니다. 형식은 맞지만 뜻이
틀린 값은 모델이 낸 값 그대로 기대값과 비교합니다. 실제 발언자를 추측하거나
개인 기준으로 저장하지 않습니다. 같은 문장을 두 번 맞혀도 실제 대화 정확도를
