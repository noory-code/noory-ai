# 하루 출석과 자료 가져오기: 로컬 시제품

2026-10-09. 사용자는 하루에 한 번 Avatar에 들러 자료를 올리는 흐름을 제안했습니다. 앞서 정한 원칙에 따라 첫 화면에서는 파일을 사용자의 컴퓨터에서만 엽니다. 클라우드로 보낼 자료의 종류는 아직 정하지 않았습니다.

## 사용자가 겪는 순서

1. 첫 화면에서 오늘 출석합니다. 자료가 없어도 들를 수 있습니다.
2. Avatar 선택 기록이 있으면 파일을 직접 고르거나, 뷰어를 실행할 때 지정한 로컬 저장소를 읽습니다.
3. 같은 날 다시 들어와도 출석을 한 번만 셉니다. 기록을 열었다면 그 사실을 따로 표시합니다.
4. 한 주가 지나면 날짜별 선택을 다시 볼 수 있습니다. 지금 화면은 선택이 기록된 날짜를 보여줍니다. 파일을 가져온 날짜를 새 선택의 날짜로 바꾸지 않습니다.

## 지금 되는 일

- 브라우저는 최근 출석 날짜를 최대 35일치까지 저장합니다. 각 날짜에는 그날 기록을 열었는지만 남습니다. 원문, 파일 이름, 프로젝트 이름, 기록 개수는 출석 정보에 넣지 않습니다.
- 사용자가 고른 Avatar JSON과 이어보기 파일은 현재 탭에서만 엽니다. 파일을 골랐다는 이유로 클라우드 전송을 시작하지 않습니다. 화면의 AI 분석을 직접 요청하면 사용자가 고른 기록을 Claude로 보내는 기존 흐름은 별개입니다.
- 잘못된 파일은 가져오지 않고 출석의 자료 열기 표시도 바꾸지 않습니다. 출석 날짜는 사용자가 화면에서 지울 수 있습니다.

## 아직 안 되는 일과 이유

- Claude·Codex 대화 내보내기 파일은 이 화면에서 읽지 못합니다. 지금 읽는 자료는 Avatar의 선택 기록입니다. 대화 분석 결과나 AI와 잘 대화했는지에 대한 평가는 표시하지 않습니다.
- 출석 정보는 접속한 주소의 브라우저 저장소에 남습니다. 포트나 브라우저를 바꾸면 이어지지 않습니다. 여러 기기를 합치는 기능도 없습니다.
- 매일 같은 누적 파일을 다시 열어도 새 기록이 생겼다고 세지 않습니다. 출석 날짜와 파일을 연 날짜만 알 수 있습니다.
- 분석 자료를 클라우드에 올리는 기능은 아직 없습니다. [로컬 우선 동기화 초안](local-first-sync.md)의 자료 제한, 기기 암호화, 계정 연결과 삭제 방식을 검증한 뒤에 만들 수 있습니다. 원문과 자유 문장은 올리지 않습니다.

## 확인한 결과

- 출석 저장 코드가 없을 때 Node 검사 1개가 모듈을 찾지 못해 실패했습니다. 첫 구현 뒤 Node 검사 34개가 통과했습니다. 같은 날짜 중복, 파일 열기 표시, 지우기, 브라우저 저장소 오류와 로컬 날짜를 검사했습니다.
- 새 모듈을 서버가 제공하지 않아 Python 검사 1개가 404로 실패했습니다. 경로를 추가한 뒤 Avatar Python 검사 49개와 플러그인 계약 검사 7개가 통과했습니다. `git diff --check`도 통과했습니다.
- 브라우저에서 출석 → 새로고침 → 출석 유지 → 가상 파일 열기 → 자료 열기 표시 → 새로고침 → 출석 날짜 지우기를 확인했습니다. 시험용 출석은 지웠습니다. 실제 개인 기록과 DB는 사용하지 않았습니다.
- 잘못된 가상 파일을 고르자 처음에는 오류가 대화창 뒤에 떠서 보이지 않았습니다. 오류를 대화창 안으로 옮긴 뒤 같은 파일로 다시 확인했습니다. 화면에 오류가 보였고 출석은 0일로 남았습니다.
- 브라우저 화면의 너비는 655px였습니다. 390px로 바꾸려는 도구 호출 뒤에도 실제 화면 너비가 655px이어서 작은 화면 검사를 통과했다고 기록하지 않습니다.

Claude Opus의 첫 소스 검토는 REVISE였습니다. 손상됐거나 더 새로운 출석 형식이 있으면 현재 코드가 이를 덮어쓸 수 있다고 지적했습니다. 읽기에 실패하면 저장을 멈추도록 바꾸고, 두 시간대에서 날짜가 달라지는 검사와 35일 한도 검사를 추가했습니다. 새 검사는 수정 전 두 개가 실패했고 수정 뒤에는 전체 Node 검사 36개가 통과했습니다. 다른 브라우저와 로컬 저장소에서 다시 읽는 경우에 맞춰 안내 문구를 고쳤습니다. 날짜가 넘어가거나 다른 탭이 출석 정보를 바꾸면 화면을 갱신하고, 출석 버튼을 누른 뒤에는 제목에 초점을 돌립니다.

두 번째 소스 검토도 REVISE였습니다. 저장값을 읽지 못할 때 출석 0일로 보이는 문제, 새로고침 뒤 예시 화면에 기록이 열린 것처럼 말하는 문제, 날짜가 바뀔 때 다른 화면까지 다시 그리는 문제를 찾았습니다. 저장 상태를 화면에 따로 보이고, 읽지 못하는 값을 지울 수 있게 했습니다. 삭제 전에는 복구할 수 없음을 대화창에 알립니다. 지금 탭에서 실제 기록을 보고 있는지에 따라 문구를 나눴고, 출석 화면이 열려 있을 때만 날짜가 바뀐 화면을 다시 그립니다.

세 번째 제한 검토는 위 세 문제에 PASS를 반환했습니다. 코드 읽기에 따른 판정이며 화면 검사를 대신하지 않습니다. 추가로, 어제 연 탭을 그대로 둔 채 오늘 출석하면 안내가 어긋날 수 있다고 지적했습니다. 이때 자료를 오늘 새로 열었다고 기록하지 않고, 이전에 연 자료가 탭에 남아 있다고 알리도록 문구를 고쳤습니다. 이어보기 파일은 `restoreSession`이 항상 `session` 모드로 열므로, 검토자가 조건부로 제기한 데모 모드 복원 문제는 해당하지 않습니다. 다른 탭이 출석을 바꿀 때는 출석 카드만 다시 그리게 고쳤습니다. 가상 두 탭으로 리포트 창을 연 사이 다른 탭에서 출석을 바꿨고, 창을 닫은 뒤 리포트 버튼에 초점이 남는 것을 확인했습니다. 이후 시험 출석을 지웠으며 원래 탭의 초점도 유지됐습니다. 마지막 두 수정은 Claude가 다시 읽지 않았습니다.

브라우저에서 출석 버튼을 누른 뒤와 시험용 출석을 지운 뒤 모두 제목에 초점이 왔습니다. 시험용 출석은 다시 지웠습니다.

## 다음에 정할 일

사용자가 매일 가져올 자료가 Avatar 선택 기록인지, Claude·Codex 대화 내보내기 파일인지 정해야 합니다. 또한 “올린다”가 파일을 로컬 화면에서 여는 뜻인지, 분석한 일부 자료를 여러 기기용 클라우드에 보내는 뜻인지 정해야 합니다. 어느 쪽이든 출석을 분석 성과나 새 작업량으로 표시하지 않습니다.

적용 원칙: SSOT는 기록 원문을 로컬에 둡니다. Honesty는 출석과 새 기록을 구별합니다. AHA는 가상 파일로 먼저 흐름을 확인하고 동기화 방식을 나중에 정합니다.

## 2026-10-09: 다시 올 이유를 먼저 보여주는 시안

사용자는 출석만 시키면 사람들이 쓸 이유가 없다고 지적했습니다. 기존 화면은 날짜를 저장한 뒤 기록 가져오기를 권했습니다. 들어온 직후 얻는 내용은 없었습니다.

첫 화면에 그날 다시 읽을 선택 한 개를 놓았습니다. 질문과 당시 답을 먼저 보여줍니다. 사용자가 펼치면 이유 원문, 상황, 출처를 봅니다. 그 선택이 다른 선택과 확인된 현재 기준을 함께 참조했다면 그 사실과 연결된 선택 수를 보여줍니다. 같은 기준을 참조했다는 사실만 말하며 성격이나 성장으로 해석하지 않습니다. 예시는 가상 자료라고 밝힙니다. 빈 기록에는 가져오기만 권합니다.

선택은 브라우저의 오늘 날짜와 기록 ID로 고릅니다. 기록 순서가 달라도 같은 날짜에는 같은 선택을 고릅니다. 기록 수가 적으면 며칠 뒤 같은 선택이 다시 나옵니다. 선택을 펼치면 출석 날짜만 남기며 새 선택이나 새 파일을 가져왔다고 세지 않습니다. 원문과 어떤 선택을 펼쳤는지는 출석 저장소에 넣지 않습니다.

이 시안이 다시 방문할 동기를 준다는 주장은 아직 검증하지 않았습니다. 검증할 질문은 세 가지입니다. 사용자가 이유를 자발적으로 펼치는가, 자신의 선택을 새롭게 볼 내용이 있는가, 다음 날 다른 선택을 보러 돌아오고 싶은가. 같은 기록이 반복될 때는 새 선택을 직접 남기는 길이나 일반 대화에서 근거 있는 장면을 뽑는 기능이 필요할 수 있습니다. 일반 대화 분석과 주간 피드백 반영은 아직 연결하지 않았습니다.

구현 전에는 날짜별 선택 함수가 없어 Node 검사가 실패했습니다. 구현 후 날짜와 파일 순서가 달라져도 선택이 안정적인지 확인했습니다. 오래된 연도에서는 음수 날짜를 배열 위치로 쓰는 결함을 새 검사로 재현한 뒤 고쳤습니다. 전체 검증과 브라우저 확인 결과는 W-00000281에 이어 적습니다.

Avatar Python 검사 49개, 플러그인 계약 검사 7개, Node 검사 37개가 통과했습니다. `node --check avatar/web/app.mjs`와 `git diff --check`도 통과했습니다. Stage 감사는 오류 0개와 기존 경고 32개였습니다. 브라우저에서 가상 선택의 질문을 보고 이유와 출처를 펼쳤습니다. 출석이 하루 한 번만 늘어나는 것을 보고 시험 날짜를 지웠습니다. 별도 시험 탭에서 기록을 비우자 개인 선택 카드는 사라지고 가져오기 안내가 남았습니다. 이때 기록이 없는데도 “그때의 선택”을 읽으라고 하던 문구를 찾아 고쳤습니다. 수정 후 Node 검사와 문법 검사를 다시 통과시켰습니다. 실제 개인 기록은 열지 않았습니다.
