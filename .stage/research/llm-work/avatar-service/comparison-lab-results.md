# 비교 대상을 먼저 고른 결과

## Result

모델이 기록 두 개와 비교 대상을 고르고, 코드는 원문 전체를 붙이는 방식을 시험했습니다. 새 자료 R에서는 요청한 답을 본인의 말투와 구별했습니다. S에서는 저장 금지를 되풀이한 두 부탁을 같게 읽었습니다. T에서는 본인 발언으로 확인된 기록이 없어 판단을 보류했습니다.

개발 사례 4번과 새 사례 6번, 총 10번을 실행했습니다. 모두 생성과 코드 검사를 통과했습니다. 작은 사례의 결과이며 정확도나 사용자 만족도가 입증된 것은 아닙니다. 특히 한 번씩만 실행한 새 사례에서 반복 안정성은 확인하지 않았습니다.

계획은 `comparison-lab-plan.md`, 당시 자료와 코드는 `evidence/2026-10-08-comparison-v1/preregistered.json`에 있습니다. 모델에게 긴 해석을 쓰게 한 `free`와 기록·대상·같음/다름·질문만 고르게 한 `typed`를 비교했습니다. 두 방식 모두 부족한 근거로 인물을 억지로 설명하지 말라는 지침을 받았습니다.

## Findings after independent review

Codex가 실제 결과를 읽고 Claude가 별도로 검토했습니다. Claude에게 Codex의 판정은 전달하지 않았습니다. 아래는 독립 검토를 반영한 정리입니다. 유용함 점수는 계획의 예시에 따른 검토자의 판단이며 사용자 실험 점수가 아닙니다.

| 결과 | 확인한 점 | 남은 문제 | 유용함 |
|---|---|---|---|
| M-typed-1 | M1·M2의 부탁을 비교하고 뜻을 모르는 M3를 제외했습니다. | 질문의 “자료 종류 말고”는 자료 종류가 이유였다는 전제를 약하게 깝니다. | 2 |

| P-typed-1 | 동료와 작성자 미상의 기록을 본인의 기준으로 삼지 않았습니다. 금지 요청도 보존했습니다. | 다른 일을 부탁했으니 다르다는 데 그칩니다. 선택지 내용을 묻는 질문은 비교에서 나온 질문이 아닙니다. | 1, 0과 경계 |

| R-free-1 | 요청한 답의 분량을 비교했습니다. | 다른 설명에서 회의에서 “소리 내어” 읽는다고 구체화했습니다. 원문에는 없습니다. | 1 |

| S-free-1 | 요청과 AI의 저장 보고를 구별했습니다. | 다른 설명에서 사용자가 확인하려 했다는 동기를 붙였습니다. 원문은 부탁을 다시 한 것입니다. | 1 |
| T-free-1 | 비교할 근거가 부족하다는 결론은 맞았습니다. | “두 기록 모두 사용자 본인의 직접 발언이 아니에요”는 틀립니다. T2는 작성자 미상이지 타인의 말로 확인된 기록이 아닙니다. | 보류, 문장은 수정 필요 |
| T-typed-1 | 근거가 부족하다고 보류했습니다. | 화면에 부족한 이유는 아직 표시하지 않습니다. | 올바른 보류 |

자유로운 해석을 줄이자 새로운 사례에서 읽을 만한 대비 하나가 나왔습니다. 그러나 무엇을 비교하는지의 범위가 여전히 넓습니다. 서로 다른 일을 다르다고만 말하는 결과도 통과합니다. 질문에도 모르는 이유를 끼워 넣거나 이미 주어진 정보를 다시 묻는 문제가 남았습니다.

R3는 사용자 발언 안에 동료의 평가가 들어 있습니다. 모델이 이를 고르지 않았습니다. 코드가 인용을 찾아내 막은 것은 아닙니다. 원문·발언자 검사를 통과했다고 해석이나 질문까지 옳다고 표시하지 않아야 합니다.

## Checks and execution

새 연구 검사 실행은 모듈 누락으로 실패했습니다. 구현 후 새 검사 5개와 기존 연구 검사 8개, 총 13개가 통과했습니다. 다른 인물·잘못된 ID·동료와 미상의 발언·중복 기록을 비교 근거로 고르면 거절합니다. 보류와 빈 비교를 구별하고 원문 전체를 보존합니다.

Claude Opus의 독립 검토는 117.96초, 정가 기준 $0.350096을 보고했습니다. `review-1/response.md`에 결과 10개를 모두 다뤘습니다. 이 비용은 연구용 검토 비용입니다. 사용자 분석마다 같은 리뷰를 실행하는 제품을 구현한 것은 아닙니다.

## Product follow-through

R1·R2의 대비를 기존 `/stories`에 옮겼습니다. R3도 별도 장면으로 편집해 동료의 평가와 확인된 행동을 구별하도록 했습니다. 자동 생성된 문장을 그대로 연결한 화면은 아닙니다. 직접 편집한 가상 예시라는 기존 안내를 유지합니다.

화면은 한국어 원문을 그대로 보여줍니다. 영어로 바꿔도 원문을 남기고 영어 번역을 따로 표시합니다. 수정은 인물·장면별 탭 메모리에 남으며 개인 기준으로 자동 적용되지 않습니다. 이 페이지에서 AI 호출이나 외부 전송은 발생하지 않았습니다.

추가 기록은 `story-r-results.md`에 있습니다. 이 연구를 근거로 일반 대화 분석 엔진이 완성됐다고 설명하지 않습니다.

## Next

새 비교 축을 더하는 실험을 바로 반복하기보다 지금 화면에서 얻는 가치와 실제 연결 흐름을 정리합니다. 원문 두 개만으로 차이를 알아볼 수 있는 사례와 추가 맥락이 필요한 사례를 나눕니다. 이미 있는 내용을 다시 묻지 않고, 질문은 사용자가 보고 싶을 때만 펼치는 방향을 유지합니다.

다음 연구는 무료 글로벌 서비스의 공개 예시와 개인 기록 화면을 어떻게 나눌지 구체화합니다. 광고를 붙일 공개 페이지와 개인 자료가 머무는 경로를 구별합니다. 비용 계산에는 실제 실험 수치와 운영 가정을 섞지 않습니다. 공개 배포와 광고 연결은 하지 않습니다.

## Principles

SSOT: 원문은 보관된 입력에서 가져옵니다. Honesty: 코드 검사와 의미 검토, 실제 사용자 검증을 구별합니다. Completion: 검토한 관찰을 화면에 옮겨 확인합니다.
