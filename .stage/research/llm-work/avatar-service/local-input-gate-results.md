# 가상 파일에서 사람 입력 후보를 가린 결과

2026-10-08. W-00000280. 자료와 기대 결과는 `local-input-gate-plan.md`에 있습니다.
원래 실행과 검토, 고친 뒤 실행은 `evidence/2026-10-08-local-gate-v1/`에 보관했습니다.
실제 Claude·Codex 대화나 개인 Avatar DB는 읽지 않았습니다.

## 실제로 실행한 일

호출자가 가상 파일 한 개를 지정해 로컬에서 읽었습니다. 메시지 일곱 개 가운데
U1·U3 두 개만 사람이 직접 입력했다고 **파일에 표시된 메시지 후보**로 남겼습니다.
역할이 `user`인 T1도 도구 결과라 제외했습니다. 메타 메시지 M1, 작성 경로를 모르는
X1, 본문에 도구 블록이 섞인 U2도 제외했습니다. 출력은 ID, 제외 이유와 개수만 담습니다.
원문과 파일 경로, 파일 속 세션 ID는 출력하지 않습니다.

이 실행기는 연구 폴더의 정해 둔 가상 파일만 명시적으로 읽습니다. 소스에는 모델이나
네트워크 호출이 없습니다. 다만 독립 **소스 검토**에는 가상 자료를 Claude로 보냈습니다.
실행기가 실제 호스트 대화 형식을 읽거나 사람 신원을 확인한 것은 아닙니다.
U1에는 팀장의 지시를 전한 말이, U3에는 AI의 요약이 들어 있습니다. 두 메시지를
후보로 남겼다고 해서 그 안의 모든 문장이 사용자의 의견이나 개인 기준이 되지는 않습니다.

## 실패를 보고 고친 것

새 검사는 처음에 모듈이 없어 실패했습니다. 구현 뒤 타입을 배열로 바꾼 입력에서
`TypeError`가 새어 나왔고, 이를 통제된 거절로 고쳤습니다. Claude Opus가 첫 소스
검토에서 더 큰 문제를 찾았습니다. JSON 한 줄에 `origin`을 두 번 적고 두 번째 값을
`human_input`으로 바꾸면, 원래 도구 결과인 T1이 사람 입력 후보로 넘어갈 수 있었습니다.
중복 키를 넣은 검사는 수정 전에 실패했고, 지금은 파일 전체를 거절합니다.

깊이 중첩한 JSON이 오류를 새어 내는 경우도 고쳤습니다. 출력에 실험 세션 ID가
남는 것도 없앴습니다. 메시지 ID에는 짧은 영문·숫자·기호만 허용하고, 본문 일곱 개가
출력에 섞이지 않는지 확인했습니다. 원문에 U+2028 문자가 있어도 JSONL의 줄을
잘못 자르지 않도록 고쳤습니다. 첫 검토자의 원문과 수정 전 실행은 그대로 보관했습니다.

수정 후 이 기능에 관한 검사 일곱 개와 연구 폴더 전체 검사 28개가 통과했습니다.
가상 파일을 다시 읽어 같은 메시지 두 개를 후보로 얻었습니다. `git diff --check`가
통과했고 Stage 감사는 오류 0개, 기존 경고 32개였습니다. 제품 코드는 바꾸지 않았습니다.

Claude Opus의 두 번째 검토는 **고친 범위에 한해 PASS**를 반환했습니다. 중복 키,
깊이 중첩한 JSON, 잘못된 타입, 출력에서 세션 ID를 뺀 부분을 소스로 확인했습니다.
모델은 검사를 직접 실행하지 않았습니다. 첫 검토는 85.68초, 정가 기준 사용량
0.2977758달러를 보고했습니다. 두 번째는 85.78초, 0.17198달러를 보고했습니다.
실제 청구액은 확인하지 않았습니다. 응답과 실행 기록은 각각 `review-1/`과
`review-2/`에 있습니다.

## 남은 한계

파일의 `human_input` 표시는 연구자가 넣었습니다. 사용자가 파일을 직접 골랐다는 사실이나
`synthetic: true` 표시만으로 작성자를 인증할 수 없습니다. 실제 Claude·Codex 기록에
대응하는 어댑터도 아직 없습니다. 중복 키 방어는 이 가상 형식의 우회를 막지만,
실제 파일의 출처 신뢰 문제를 해결하지 않습니다. 이 단계는 모델 분석을 하지 않으므로
“그렇게”가 가리키는 조건도 아직 연결하지 않습니다.
검토자는 ID 자체에 짧은 정보를 넣을 가능성을 남겼습니다. 실제 자료를 지원한다면
출력용 ID를 로컬에서 다시 매겨야 합니다. `mixed_content`라는 제외 이유도 여러 텍스트
블록에 쓰면 뜻이 맞지 않습니다. 제품에 옮기기 전에 이유를 분리합니다.

다음에는 `scope-reference-correction.md`에 적은 현재 작업의 요청과 조건 참조를
가상 자료에서 시험합니다. 실제 호스트 파일은 형식과 작성 경로를 확인한 뒤에만
별도로 다룹니다. 개인 파일을 자동으로 찾거나 업로드하지 않습니다.

Honesty: 파일에 붙인 작성 경로와 확인한 사람의 신원을 구별합니다.
SSOT: 원래 입력·출력과 수정 후 결과는 증거 폴더에 따로 남깁니다.
AHA: 누가 직접 입력했는지 표시할 수 있는지 확인한 뒤 본문 해석을 넓힙니다.
