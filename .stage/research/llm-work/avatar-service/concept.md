# Avatar 서비스 기획 초안

2026-10-07. W-00000280. 사용자 정정을 반영한 제안이며 구현·가격·수요를 검증한 결과는 아닙니다.

후속 요청에서 사용자는 업무 기록을 운영 서버에 모으지 않는 점을 강조했습니다.
[분석 위치와 비수집 방식에 관한 토론](private-analysis-discussion.md)에 반론과 시험 계획을 정리했습니다.
아래 첫 버전은 선택한 기록을 Claude로 전송합니다. 새 비수집 구성을 구현한 상태로 읽으면 안 됩니다.
후속 [심화 토론 결과](conversation-profile-discussion.md)와 [아이디어 9개](ideas.md)를 정리했습니다.
현재 사업 방향은 [글로벌 서비스와 광고 수익](business-model.md)을 따릅니다.

## Purpose

대화가 쌓일수록 사용자를 더 깊이 이해하고, 그 이해를 사용자에게 보여주는 Avatar를 만듭니다.
선택과 판단 기준, 말투, 설명 방식, 관심사와 상황에 따른 반응을 서로 연결해 살펴봅니다.
사용자가 스스로 돌아보고 원하는 방향으로 변화하도록 돕는 것이 목적입니다.
사용자는 “대화를 통해서 심리상담사들이 상대를 프로파일링하는 것과 마찬가지라는거죠. 내말은.”이라고 취지를 설명했습니다.
이 비유는 대화의 맥락을 보며 한 사람에 대한 이해를 쌓아가는 제품 방향으로 반영합니다.
전문 상담과 같은 정확도를 검증했다는 뜻으로 쓰지 않습니다.
사용자는 “아니지 아바타에 쌓인 데이터로 분석해준다는게 컨셉인데”라고 명확히 했습니다.
“심리테스트처럼”은 가볍고 재미있게 결과를 경험한다는 뜻으로 반영합니다.
새 설문을 중심으로 잡았던 이전 기획은 철회합니다.

### Build and revise an understanding of the person

말투나 문장 길이는 사람을 이해할 때 참고할 근거입니다. 각 항목을 측정한 뒤 서로 어떻게 연결되는지 살펴봅니다.
예를 들어 짧게 지시한 문장과 길게 이유를 설명한 문장이 함께 있다면, 어떤 상황에서 달라졌는지 확인합니다.
“짧게 말하는 사람”으로 고정하기보다 그 차이를 설명할 수 있는 가설을 제안합니다.
가설에는 근거, 맞지 않는 사례, 아직 모르는 부분을 함께 둡니다.
새 대화나 사용자의 정정이 들어오면 가설을 고치고, 왜 달라졌는지 남기는 방식을 검토합니다.
사용자의 동의만으로 해석이 입증됐다고 처리하지 않습니다. 실제 근거와 맞는지도 확인합니다.

화면에는 지금까지 이해한 모습, 그렇게 본 이유, 예외가 된 상황, 이전과 달라진 점을 보여주는 안을 제안합니다.
표현을 고치거나 일부 해석을 보류할 수 있게 합니다. 이 해석을 AI가 따라야 할 개인 규칙으로 자동 등록하지 않습니다.
기존 선택 기록을 분석하는 기능과 새로 제안한 대화 분석 기능의 구현 상태를 구별합니다.
어떤 대화를 읽을지와 어디에서 분석할지는 별도로 정합니다. 제품 목적의 확장을 대화 수집 동의로 해석하지 않습니다.

## Product experience

1. 사용자가 Avatar 기록 중 분석할 기간과 범위를 고릅니다.
2. 선택과 표현, 상황에 따른 반응을 살펴보고 여러 장면을 연결한 해석을 제안합니다.
3. 발견한 내용마다 실제 발화와 선택, 당시 조건을 연결합니다. 관찰한 사실과 AI의 해석을 구별합니다.
4. 사용자가 해석을 고치거나 보류합니다. 이 동작만으로 개인 기준을 확정하지 않습니다.
5. 결과를 짧은 카드, 캐릭터의 이야기, 배지와 상세 리포트로 살펴봅니다.
6. 기록이 더 쌓이면 앞선 분석과 비교합니다. 서로 비교한 기록의 범위와 조건도 보여줍니다.

가입 직후 기록이 없다면 기록이 없다고 안내합니다. 새 자료가 들어오기 전에는 개인화한 분석을 꾸며내지 않습니다.
개인 기록의 업로드·분석 범위와 외부 AI 전송 여부는 서비스 설계에서 명시해야 합니다. 이번 기획은 실제 개인 DB를 읽지 않습니다.

## Analysis and play

| 분석할 내용 | 재미있게 보여주는 방법 | 근거를 확인하는 방법 |
|---|---|---|
| 여러 번 중요하게 여긴 것 | 사용자가 고를 수 있는 이번 기간의 캐릭터 별명과 발견 카드 | 관련 선택과 이유를 펼칩니다. |
| 상황에 따라 바뀐 우선순위 | 두 상황의 나를 나란히 보여줍니다. | 두 상황의 조건을 함께 봅니다. |
| 과거와 달라진 기준 | 이전 모습과 지금 모습을 비교하는 이야기 | 기준의 변경 이유와 시점을 봅니다. |
| 서로 다른 일에 공통으로 드러난 기준 | 발견한 내용을 배지와 컬렉션으로 모읍니다. | 각 기록이 해석을 뒷받침하는지 직접 확인합니다. |

별명과 캐릭터는 사용자가 바꿀 수 있는 표현입니다. 고정된 성격 유형이나 심리적 점수로 제시하지 않습니다.
배지는 기록을 돌아본 일과 발견한 내용을 기념합니다. 특정 선택, AI에 대한 동의, 결제를 좋은 성격의 증거로 취급하지 않습니다.
분석할 근거가 부족하면 부족하다고 표시합니다. 업무 기록만 있는 사람의 관계 성향을 추측하지 않습니다.

## Language and expression

사용자는 “선택뿐만 아니라 이 사람이 어떤 언어를 쓰는지 말을 이쁘게 하는지 등등도 보여주면 좋을 것 같은데....”라고 제안했습니다.
자신을 알아가는 범위를 선택과 기준에서 언어·표현 습관으로 넓힙니다. 아직 구현하지 않은 기획입니다.

| 살펴볼 내용 | 보여줄 항목 | 가상 리포트 문장 |
|---|---|---|
| 어떤 말을 쓰는가 | 한국어·영어 사용, 자주 쓰는 표현, 전문 용어와 일상어 | “이번 기록에서는 기술을 설명할 때 영어 용어를 섞어 썼어요.” |
| 얼마나 자세히 설명하는가 | 문장과 발화의 길이, 결론의 위치, 배경과 예시, 같은 내용의 반복 | “작업을 부탁할 때는 짧게 말하고, 방향을 설명할 때는 배경과 예시를 덧붙였어요.” |
| 어떻게 부탁하는가 | 요청의 구체성, 이유 설명, 질문과 지시, 대안 제시 | “수정을 부탁할 때 원하는 결과도 함께 설명했어요.” |
| 어떻게 배려를 표현하는가 | 감사, 격려, 상대의 기여 인정, 비판할 때 쓴 표현 | “잘못된 부분을 짚으면서 도움이 된 부분도 함께 말했어요.” |
| 어떻게 반대하고 조율하는가 | 반대 이유, 확인 질문, 타협안, 오해를 바로잡는 방식 | “의견이 다를 때 다른 방법을 제안한 장면이 있었어요.” |
| 상황에 따라 어떻게 달라지는가 | 같은 사람의 탐색·수정 요청·완료 대화, 기간별 표현 변화 | “아이디어를 나눌 때와 오류를 고쳐 달라고 할 때 문장 길이가 달랐어요.” |

“말을 예쁘게 한다”를 보여주는 기준은 감사 표현, 존중, 명확한 요청처럼 구체적으로 나눠 제안합니다.
사용자는 “장황하게 설명하는지 아니면 간략하게 설명하는지 같은 것들도 들어갈 수 있죠.”라고 덧붙였습니다.
길이와 장황함을 따로 봅니다. 긴 설명에는 필요한 배경이 담길 수 있고, 짧은 설명에는 필요한 조건이 빠질 수 있습니다.
결론부터 말하는지, 같은 뜻을 되풀이하는지, 예시가 이해를 돕는지 살펴보는 안을 더합니다.
여러 메시지로 나누어 설명한 경우에는 한 메시지의 길이와 대화 전체의 길이를 구별합니다.
AI가 오해하거나 재질문해서 사용자가 반복한 경우도 표시합니다. 그 반복을 사용자의 평소 말버릇으로 단정하지 않습니다.
짧게 말하거나 존댓말을 쓰지 않았다는 이유만으로 무례하다고 판정하지 않습니다.
단어의 횟수와 상황을 읽어야 알 수 있는 해석을 구별합니다. 반어, 인용문, AI가 대신 쓴 문장도 분리해야 합니다.
AI와 나눈 대화에서 발견한 말투는 그 범위로 표시합니다. 사람과 대화할 때도 같다고 일반화하지 않습니다.
평가는 사용자가 고칠 수 있게 합니다. 보고서의 표현을 사용자의 성격이나 도덕성을 판정하는 점수로 만들지 않습니다.

카드에서는 실제 표현, 해석한 이유, 다른 해석이 가능한 상황을 함께 보여주는 안을 제안합니다.
사용자는 부드럽게 말하기, 명확하게 부탁하기 등 시도할 방식을 고를 수 있습니다.
시도 전후에는 비슷한 대화 상황을 비교합니다. 이를 영구적인 성향이나 확인한 개인 기준으로 자동 등록하지 않습니다.

### Data and privacy

선택 기록에 남긴 이유만으로 평소 말투를 평가하기는 어렵습니다. 자료가 특정 장면에 치우칠 수 있습니다.
분석하려면 사용자가 고른 범위에서 직접 쓴 발화를 확인할 방법이 필요합니다.
대화 전체를 자동 수집하는 방식으로 확대하지 않습니다. 읽을 범위와 추출 방법은 아직 정하지 않았습니다.
운영 서버가 업무 기록을 받지 않는 원칙을 유지하며, 원문과 근거를 로컬에서 확인하는 구성을 우선 검토합니다.
어휘 목록이나 말투를 요약한 결과도 개인과 업무의 특징을 드러낼 수 있습니다. 서버 전송을 기본으로 정하지 않습니다.
이미 작업에 참여한 외부 AI에 분석을 맡기는 방식과 기기에서만 분석하는 방식의 차이는
[기존 토론](private-analysis-discussion.md)을 따릅니다.

### Next checks

- 사용자가 직접 쓴 문장과 인용문·AI 작성문을 정확히 구별하는지 확인합니다.
- 감사 표현의 유무만 바꾼 문장, 정중하지만 공격적인 문장, 짧지만 우호적인 문장을 비교합니다.
- 길지만 필요한 정보를 담은 설명, 짧지만 조건이 빠진 설명, AI의 오해 때문에 반복한 설명을 비교합니다.
- 말투를 설명한 카드가 근거를 제대로 보여주는지 확인합니다. 기분 좋은 칭찬만으로 평가하지 않습니다.
- 선택을 분석하는 경우와 말투를 분석하는 경우에 필요한 자료를 따로 정합니다.

## Global service and advertising

사용자는 “글로벌 서비스로 만들고 수익은 광고로 합시다.”라고 방향을 정했습니다.
“그냥 구글 애드 같은거 붙이는 거지 뭐.. ㅎㅎ”라고 설명했고 Meta 광고도 예로 들었습니다.
AI 사용자를 대상으로 무료 서비스를 제공하고, 기존 광고망의 배너 광고로 수익을 내는 안을 기준으로 잡습니다.
이전 유료 리포트·꾸미기 판매·구독 제안은 현재 수익 모델에서 제외합니다.

AI 사용자가 모인다는 점이 광고주에게 매력적일 수 있다는 가설을 기록합니다.
타깃이 명확하다는 이유만으로 높은 광고 단가나 수익성을 확정하지 않습니다.
방문 국가, 광고가 실제로 표시된 페이지 수, 방문당 수익, 운영비와 분석비를 확인해야 합니다.
웹 광고는 AdSense를 우선 검토합니다. Meta Audience Network의 현재 공식 안내는 앱 수익화에 초점을 둡니다.
Meta를 웹에 같은 방식으로 붙일 수 있다고 가정하지 않습니다. 실제 공급사는 아직 선택하지 않았습니다.
근거와 미정인 부분은 [사업 방향](business-model.md)에 둡니다.

대화와 프로필을 광고 타기팅 자료로 제공하지 않는 구성을 검토합니다.
광고가 다루는 기술 정보와 Avatar가 분석하는 업무 기록을 구별해 설명합니다.
분석의 깊이와 광고 수익을 함께 확인하되, 광고를 늘리려고 결과를 여러 페이지로 쪼개는 방식은 첫 안에 넣지 않습니다.
글로벌 서비스는 지원 언어별로 해석 품질을 검증해야 합니다. 화면 번역만으로 검증을 대신하지 않습니다.
공유할 때는 사용자가 고른 결과 카드만 미리 보고 내보냅니다. 원문과 개인 기록은 기본 공유 대상에 넣지 않습니다.

## Plugin relationship

기존 플러그인은 사용자가 허용한 선택과 근거, 기준의 확인·변경 이력을 보관합니다.
서비스는 이 자료를 사용자가 고른 범위에서 분석하고 보여줍니다.
새 분석 결과가 기존 기준을 자동으로 덮어쓰지 않습니다. 개인 기준으로 쓸 때는 기존 Avatar의 확인 절차를 거칩니다.

## Try a way of working

사용자는 “닮고 싶은 캐릭터가 있으면 에이아이에 룰이나 퍼소나로 적용할 수 있으면 좋구요”라고 제안했습니다.
기록으로 드러난 현재 기준과 사용자가 시도하려는 작업 방식을 따로 보여줍니다.
공개 글에서 확인한 개발 원칙은 출처와 함께 제공하며, 당사자가 직접 제공한 AI 설정인 것처럼 표현하지 않습니다.
사용자가 방식을 고르면 실제 적용할 규칙과 적용 범위를 먼저 보여주고 파일로 내보냅니다.
기존 프로젝트 지시와 충돌하면 해당 규칙을 자동으로 덮어쓰지 않습니다. 이 선택을 개인 성향으로 확정하지도 않습니다.

## First working version

사용자가 “해봅시다. 해봐!!”라고 실행을 요청했습니다. 먼저 로컬에서 열 수 있는 작동 버전을 만듭니다.
Avatar show JSON과 명시적으로 연결한 로컬 기록을 읽습니다. 예시 기록은 별도로 표시합니다.
기록 수와 근거 연결, 현재 확인된 기준과 변경 이력을 계산합니다.
사용자가 분석할 기록과 전송 내용을 확인하면 Claude가 선택의 이유를 해석합니다. 각 해석에 기록과 다른 설명의 가능성을 붙입니다.
AI 해석은 개인 기준으로 자동 등록하지 않습니다. 성격 진단과 심리검사 점수는 제공하지 않습니다.
리포트와 AI 규칙은 미리 보고 내려받을 수 있게 합니다. 결제와 공개 서비스 운영은 이 첫 버전에 포함하지 않습니다.
제한을 화면과 완료 보고에 명시합니다. 관련 없는 사용자 DB와 설정은 읽거나 바꾸지 않습니다.

## Visual plan

- 색: 종이색 `#FFFEFB`, 잉크 `#292647`, 연보라 `#E9DFFC`, 노랑 `#FFF2AC`, 민트 `#DDF2D5`, 살구 `#F4AA97`.
- 글자: 한국어 시스템 고딕을 쓰고 제목은 짧고 굵게, 근거는 편히 읽을 수 있게 배치합니다.
- 구성: 위에 현재 기록의 종류를 표시합니다. 큰 캐릭터와 발견 요약을 먼저 보여주고 아래에서 기록과 근거를 펼칩니다.
- 특징: 작은 캐릭터가 기록을 품고 있는 장면을 중심에 둡니다. 주제별 발견과 작업 방식은 서로 다른 모습으로 표현합니다.
- 검토: 숫자와 동일한 카드만 늘어놓으면 관리 화면처럼 보이므로 캐릭터와 실제 기록의 한 문장을 먼저 배치합니다. 과장된 성격 점수와 숨겨진 유료 결과는 넣지 않습니다.

## First validation

사용자가 분석을 허용한 기록 묶음 하나로 짧은 결과와 상세 리포트 예시를 만듭니다.
각 해석이 어느 기록에서 나왔는지, 상황 차이를 놓치지 않았는지 검토합니다.
사용자에게 새로 발견한 내용, 틀린 해석, 다시 보고 싶은 내용, 광고가 이용을 방해하는지 확인합니다.
실제 개인 기록을 분석하는 범위와 저장 위치는 별도로 정해야 합니다. 이번 대화의 서비스 기획 승인을 대화 전체 수집 동의로 해석하지 않습니다.

## Principles

SSOT: 선택과 확인한 기준은 기존 Avatar 기록을 따릅니다.
Honesty: 기록으로 확인한 사실, AI가 제안한 해석, 사용자가 확인한 기준을 구별합니다.
AHA: 첫 분석의 가치를 확인한 뒤 반복 이용과 과금 방식을 구체화합니다.
Completion: 예쁜 결과만으로 끝내지 않고 근거와 사용자 수정까지 연결합니다.
