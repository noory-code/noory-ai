# 닫기 리뷰가 실행해 보고 회의적으로 판정하게 하는 방법

[M-00000006](../../roadmap/milestones/M-00000006.md) 의 (다)와 W-00000401 의 연구 자료입니다.
여기의 설계안은 선택지와 작업 세션의 추천이고 공식 결정이 아닙니다. 고른 것과 누가 골랐는지는
[DE-00000101](../../decisions/pending/DE-00000101.md) 에 있습니다.

| 자료 | 내용 |
|---|---|
| [근거](evidence.md) | 2026-11-23 에 저장소에서 세고 직접 실행해 본 것, 셀 수 없었던 것 |
| [설계안](design.md) | 질문 세 개, 질문마다 선택지와 근거와 반대 관점과 추천 |
| [재기](measurement.md) | 2026-11-23 에 지금의 리뷰어를 결함이 기록된 과거 변경 11개와 통과한 판 8개에 돌린 결과, `ran` 바닥에 대한 추천 (W-00000414) |

## 한눈에 보기

- 닫기 리뷰의 판정자가 누구인지 기록에 남은 카드는 36장이고 전부 Claude 대역(`claude_review_companion`)입니다.
  그중 34장은 닫을 때 돌린 검사에 `audit_stage.py` 가 들어 있었는데, 대역 리뷰어는 `python3 -m unittest` 만 실행할 수 있습니다.
  2026-11-23 에 같은 권한으로 리뷰어를 띄워 `audit_stage.py` 를 시켜 보니 거부됐습니다.
- 지금 계약은 리뷰어가 "실행하지 않았다"고 적어도 `PASS` 를 낼 수 있습니다. 실행 여부는 판정 파일의 `reason` 문장 안에만 있고,
  그 문장은 커밋되지 않습니다. 36장의 리뷰어가 무엇을 실행했는지는 지금 알 수 없습니다.
- 판정 37건 중 반려는 1건입니다. 이 수치만으로는 리뷰어가 너그러운지, 일이 잘된 것인지 가를 수 없습니다. 맞춰 볼 정답이 없기 때문입니다.

## 추천 요약

| 질문 | 추천 | 한 줄 까닭 |
|---|---|---|
| 판정자를 누구로 두는가 | 닫기 리뷰 하나. 실행 권한을 넓힌다. 검증 세션은 관문에서 뺀다 | 잰 구멍(권한)을 가장 적은 새 장치로 메우고, 판정이 손으로 옮겨지지 않는다 |
| 실행을 어떻게 강제하는가 | 판정 파일에 기준마다 판정 방법을 적고, 실행이 필요한 기준을 읽기만 했으면 닫기가 실패한다 | 지금 `reason` 문장에 묻힌 것을 기계가 읽는 칸으로 올리는 일이고 venue 를 가리지 않는다 |
| 사람의 판정과 어떻게 맞춰 보는가 | 결함을 아는 과거 변경으로 먼저 재고, 사용자가 5장을 리뷰어 판정을 보지 않고 판정한다 | 앞의 것은 사용자의 시간을 쓰지 않고 되풀이할 수 있고, 뒤의 것만이 글자 그대로 사람의 판정이다 |

추천이 틀렸다고 볼 관측은 [설계안](design.md) 의 질문마다 적었습니다.

## 재기의 결과 (W-00000414)

- 결함이 기록된 판을 돌린 22번 중 거짓 통과는 3번입니다. 통과한 판을 돌린 16번 중 반려는 5번이고, 리뷰어가 틀렸다고 볼 수 있는 것은 많아야 2번입니다.
- 닫기 전에 이미 찾아낸 결함은 14번 모두 다시 찾았고, 닫기를 통과한 뒤에 드러난 결함은 8번 중 한 번도 짚지 못했습니다.
- 38번 모두 `ran` 인 기준이 있었습니다. 작업 세션은 `ran` 바닥을 지금은 넣지 않기를 추천합니다. 표본이 작다는 점과 반대 관점은 [재기](measurement.md)에 있습니다.
