# W-00000071 드라이버가 실행자에게 대상 작업 항목을 전달한다

## Purpose

드라이버가 실행자 명령을 venue로만 찾아 고정 문자열 그대로 셸에 넘기므로, 실행자는 자기가 어느 작업 항목을 수행하는지 알 수 없다. 실행자가 대상 항목을 알 수 있게 한다.

## Scope

### 지금 상태

`stage/scripts/drive.py` 는 실행자 명령을 항목의 venue 로만 찾는다:

```python
executor_command, executor_error = resolve_executor_command(
    load_executors_config(stage_root), item.venue
)
...
executor_ok, executor_evidence, _executor_raw = run_check(
    executor_command, args.timeout, project_root
)
```

`resolve_executor_command`(`stage/hooks/stage_paths.py:515`)는 `.stage/settings.json` 의
`executors` 에서 문자열을 꺼내 그대로 돌려주고, `run_check`(`stage/skills/stage-retrospective/
close_work.py:131`)는 그 문자열을 `subprocess.run(..., shell=True)` 로 넘긴다. 사이에 항목 id 가
끼어들 자리가 없고, 자식 프로세스에 넘어가는 환경 변수도 없다.

결과: **실행자는 자기가 어느 작업 항목을 수행하는지 알 수 없다.** venue 당 명령 하나가 전부라
"claude 로 뭔가 해라" 까지만 전달되고 "무엇을" 이 빠진다. 감독 모드(`--execute`)와 무인
모드(`--unattended`) 둘 다 같은 경로를 쓴다.

기존 테스트가 놓친 이유: `stage/scripts/tests/test_drive.py` 의 실행자는 파일 하나를 만들고
끝나는 고정 명령이라 애초에 항목을 알 필요가 없었다 (`test_drive.py:180` 근처).

### 고치는 방향 (결정됨)

환경 변수로 넘긴다. 실행자 명령은 셸 문자열이므로 `$STAGE_WORK_ITEM` 이 자연스럽게 풀리고,
이미 설정된 명령을 깨뜨리지 않는다. 명령 문자열에 자리표시자를 치환하는 방식은 명령 안에
`{` 가 들어 있을 때 조용히 망가지므로 쓰지 않는다.

넘길 것 (최소):

- `STAGE_WORK_ITEM` — 항목 id (예: `W-00000070`)
- `STAGE_WORK_ITEM_PATH` — 카드 파일의 절대 경로
- `STAGE_PROJECT_ROOT` — 프로젝트 루트 절대 경로

주입 자리는 `drive.py` 의 실행자 호출 지점이다. `run_check` 는 검증 명령과 리뷰 명령도 함께
쓰는 공용 함수이므로, 안에서 무조건 주입하지 말고 선택적 `env` 인자를 받아 호출자가 정하게
한다 (SoC). 기존 호출자는 인자를 넘기지 않으므로 동작이 바뀌지 않는다.

`stage/docs/SCHEMA_V4.md` 의 `### Supervised driver and executor settings` 에 실행자가 받는
환경 변수를 문서화한다. `executors` 예시도 항목을 실제로 쓰는 모양으로 고친다.

제약:

- **커밋하지 않는다.** 작업 트리에 변경만 남기고 멈춘다.
- 저장소 산출물은 영어로 쓴다. `.stage/` 안의 글만 한국어다.
- 플러그인 파일을 고쳤으므로 두 `plugin.json` 의 version 을 patch 로 올리고
  `stage/CHANGELOG.md` 에 항목을 추가한다.
- scope 밖은 건드리지 않는다.

## Success criteria

- 실행자 프로세스가 위 세 환경 변수를 받고, 값이 실제 선택 항목과 일치한다.
- 그 사실을 확인하는 테스트가 `stage/scripts/tests/` 에 있다 — 실행자 명령이 환경 변수를
  읽어 파일에 적고, 테스트가 그 내용이 선택된 항목 id 인지 검사한다. 이 테스트는 고치기
  전 코드에서 반드시 실패해야 한다.
- 감독 모드와 무인 모드 양쪽 실행 경로가 같은 방식으로 주입한다 (한쪽만 고치지 않는다).
- `run_check` 의 기존 호출자(검증 명령, 리뷰 명령)의 동작이 바뀌지 않는다.
- `python3 -m unittest discover -s stage/hooks/tests -q` 통과.
- `python3 -m unittest discover -s stage/scripts/tests -q` 통과.

**위험**: 환경 변수는 자식 프로세스 전체가 물려받는다. 카드 경로와 프로젝트 루트 말고 다른 것을
넣지 말 것 — 설정값이나 자격증명이 실행자 로그에 새는 길이 된다. 그리고 무인 모드 경로를 빠뜨리기
쉽다. 감독 모드만 고치면 정작 자동으로 도는 쪽이 여전히 눈먼 채로 남는다.
