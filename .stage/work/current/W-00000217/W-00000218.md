# W-00000218 잘린 바퀴의 끝난 일을 드라이버가 알아본다

## Purpose

잘린 실행자가 일을 이미 끝낸 바퀴를 드라이버가 제자리걸음으로 읽어 카드가 갇히므로, 작업 트리가 그대로일 때 인수 검사를 먼저 돌려 통과하면 진전으로 처리하고, 명령 시간 한도도 자식 수 대신 카드가 선언한 크기 신호로 재게 한다

## Source

O-00000030 의 네 고리 실측(W-00000200, 세 바퀴): 900초에 잘림 → 늦은 보고문이 다음 바퀴에
떨어져 시도 하나 소진 → 셋째 바퀴는 고칠 게 없음 → 작업 트리가 그대로라 제자리걸음 판정.
일은 첫 바퀴에 끝나 있었다. O-00000031: 그 잘림의 원인 — 액션 없는 스토리는 자식 수가 0이라
`subtree_command_timeout`(`drive.py:1767`)이 최소 900초를 준다.

## User value

큰 카드의 첫 바퀴가 잘려도 카드가 드라이버 안에서 빠져나온다. 지금은 시도 셋을 태우고 사람이
검사를 대신 돌려 닫는다.

## Scope

### Included

- 제자리걸음 판정 앞에 한 단계: 작업 트리가 직전 바퀴와 같으면 **먼저 인수 검사를 돌리고**,
  통과하면 그 바퀴를 진전으로 삼아 판정(리뷰)으로 넘어간다. 실패하면 지금처럼 막는다.
- 명령 시간 한도 산정: 자식 수 대신 카드가 선언한 크기 신호 — 선언 범위(scope) 항목 수와
  성공 기준 수 — 로 잰다. 자식이 있으면 지금처럼 자식 수도 신호다(더 큰 쪽을 쓴다).
- 두 동작의 회귀 시험을 `test_drive.py` 에 더한다.

### Excluded

- 잘린 실행자를 실제로 거두는 것(reaper 확장)과 늦은 보고문 구분은 이 액션이 안 한다 —
  O-00000030 의 세 후보 중 가장 싼 하나(제자리걸음 판정이 먼저 본다)만 싣는다.

## Dependencies

없음. 이 스토리의 첫 액션이다.

## Risks

- "인수 통과 = 진전"이 판정을 건너뛰는 길이 되면 안 된다. 통과는 판정으로 **넘어가는**
  조건일 뿐이다.
- 크기 신호 산정을 바꾸면 기존 카드들의 시간이 같이 변한다. 최소 900초 바닥은 유지한다.

## Success criteria

- 작업 트리가 직전 바퀴와 같아도 인수 검사가 통과하면 드라이버가 막지 않고 판정으로 넘어간다
- 액션 없는 스토리의 명령 시간이 선언 범위 항목 수와 성공 기준 수에서 나오고, 최소값 900초로 떨어지는 것은 정말 작은 카드뿐이다

## Next action

`drive.py` 에서 제자리걸음 판정 자리(변화 없음 → 막음)와 `subtree_command_timeout` 을 찾아
두 갈래를 끼운다.
