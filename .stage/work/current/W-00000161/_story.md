# W-00000161 쓰기 직전에 무엇을 위한 일인지 다시 띄운다

## Purpose

목적이 세션을 열 때 한 번만 들어오고, 그 뒤로는 다시 안 들어온다.

- 세션을 열 때 실리는 글에 마일스톤은 **제목 한 줄만** 들어온다. 왜 하는 일인지는 안 들어온다.
- 그다음부터 아무것도 다시 안 실린다. `stage/hooks/hooks.json` 이 거는 자리 넷 가운데 글을
  실어 보내는 것은 세션 시작 하나뿐이다.
- 규칙은 있다 — "질문이 생기면 상위 목적부터 찾아라." 다만 그건 에이전트가 스스로 **찾아가는**
  것이라, 규칙을 기억하고 있을 때만 돈다. 대화가 길어지거나 중간에 줄여지면 그때가 위험하다.

사고가 나는 자리는 실측으로 한 군데에 몰린다. 최근 회고 45장에서 "빠진 맥락" 칸을 뽑으면
**새로 쓰기 직전**이 대부분이다.

- 닿는 자리를 다 안 센다 — 45장 중 11장. 코드와 설정은 세고 문서, 한국어판, 검사 명령,
  이미 다르게 정해 둔 하위 규칙을 빠뜨린다.
- 건드릴 대상의 지금 값을 안 읽고 기억으로 쓴다 — R-00000144, R-00000147. 하루에 두 번 밟았다.
- 성공 기준을 구조로만 쓴다 — R-00000139 이 네 번째 반복이라고 적었고, 매번 사람이 뒤늦게 채웠다.

## Actions

둘로 나눈다. 무엇을 띄울지는 정답이 없어 사람과 함께 정하고, 정해진 뒤 코드로 옮기는 일은
기계적이라 실행 창으로 넘긴다.

- [W-00000162](W-00000162.md) — 무엇을 어느 자리에서 띄울지 정한다 (설계 · claude)
- [W-00000163](W-00000163.md) — 정한 대로 쓰기 직전 훅에 싣는다 (구현 · codex)

## User value

대화가 길어져도, 카드나 규칙 문서를 쓰기 직전에 지금 무엇을 위해 일하는지가 그 자리에서 다시
보인다. 사람이 "그거 목적이 뭐였지"를 매번 되짚어 주지 않아도 된다.

## Scope

### Included

- 쓰기 직전에 목적을 실어 보내는 길과 그 조건.

### Excluded

- 목적을 안 적은 카드를 막는 검사. 아직 안 만든다 — 근거가 얇아 손으로 몇 번 굴려 보고 정한다.
- 마일스톤 완료 기준을 다시 쓰는 일. 따로 남아 있다.

## Risks

- 매번 다 실으면 대화가 무거워진다. 무엇을 얼마나 실을지는 W-00000162 가 정한다.
- 자주 뜨면 읽히지 않고 흘러간다. 뜨는 자리를 좁히는 것이 설계의 핵심이다.

## Success criteria

- 세션이 한참 지난 뒤 카드나 규칙 문서를 쓸 때, 테마와 마일스톤의 목적이 그 자리에서 다시 실린다.
- 조건에 안 맞는 쓰기에서는 안 실린다.
- 파일 쓰기를 막지 않는다. 글만 얹는다.
- 사람이 겪는 결과: 긴 세션 중간에 사람이 목적을 다시 말해 주지 않아도, 에이전트가 쓰기 직전에
  목적을 보고 있다.
