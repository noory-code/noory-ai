# W-00000040 Enum gate honors planned-card status enum

## Purpose

The PreToolUse enum gate validated every work card's `status` against the current-work enum
(`active/blocked/review/completed/archived/rejected`), so a new `work/planned/` card in a planned
status (`triaged/ready/deferred/...`) was denied though the audit accepts it — no new planned card
could be written. Fix the gate to pick the status set by the card's zone.

## Scope

`stage/` — `hooks/stage_work.py` (`work_item_enum_error`), `hooks/stage_guard.py`
(`enum_validity_blocker`), `hooks/tests/test_enum_gate.py`, CHANGELOG + version bump.

## Success criteria

Planned card write with a planned status passes the enum gate; an invalid status still denies;
current/archive cards unchanged. Full hook + scripts suites green.

## Related truth

Mirrors the audit split (BACKLOG001 planned vs WORK005 current). Origin report:
novel-workspace O-00000005 (planned card W-65 blocked by the gate).

## Progress

Fixed (2026-07-15): zone-selected status enum in `work_item_enum_error(text, relative)`; caller
passes the relative path. Red test (planned `triaged` denied) → green.
