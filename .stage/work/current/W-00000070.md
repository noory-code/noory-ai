# W-00000070 stage-drive 스킬 — 드라이버 진입점

## Purpose

드라이버는 다른 생애주기 흐름과 달리 스킬이 없어, 플러그인을 읽는 에이전트가 존재를 알 수 없다. 진입 스킬로 노출한다.

## Scope

새 스킬 하나를 만든다: `stage/skills/stage-drive/SKILL.md`. 다른 스킬과 같은 모양이다 —
디렉터리 하나에 `SKILL.md` 하나 (`stage/skills/stage-handoff/`를 본보기로 볼 것).
플러그인은 `skills: "./skills"` 로 자동 수집하므로 등록 코드는 따로 없다.

스킬은 `stage/scripts/drive.py` 로 가는 길을 연다. 지금 이 드라이버는
`stage/docs/SCHEMA_V4.md`(`### Supervised driver and executor settings` 이하)에만 적혀 있어,
플러그인의 스킬 목록만 읽는 에이전트는 존재 자체를 모른다. 문서를 옮겨 적지 말고, 언제 이
스킬을 쓰는지와 무엇을 조심해야 하는지를 쓴 뒤 세부는 그 문서로 링크한다 (SSOT).

스킬이 반드시 담아야 할 것:

- 기본 호출은 부작용 없는 dry-run이다. `--execute` 는 한 스텝만 돌리고 커밋·종료·에스컬레이션·
  승격·부모 전진을 하지 않는다.
- 실행 전에 `.stage/settings.json` 의 `executors` (venue → 명령) 가 있어야 한다. 없거나
  비어 있으면 드라이버는 그 자리에서 멈춘다.
- 독립 리뷰어의 venue는 항목의 venue와 달라야 한다. 같으면 자기 채점이라 막힌다.
- 대상은 `acceptance` 가 비어 있지 않은 말단 자식만 고른다.
- `--unattended` 는 격리 브랜치에서 하위 전체를 돌린다. `limits` 설정이 없으면 시작을
  거부한다 — 설정 없음은 무제한이 아니다.

같이 손볼 것: `stage/.claude-plugin/plugin.json` 과 `stage/.codex-plugin/plugin.json` 의
`version` 을 0.42.1 → 0.43.0 으로 올리고, `stage/CHANGELOG.md` 에 대응 항목을 추가한다.
`stage/docs/SCHEMA_V4.md` 는 스킬이 생겼다는 사실을 가리키는 한 줄만 필요하면 손댄다.

제약:

- **커밋하지 않는다.** 작업 트리에 변경만 남기고 멈춘다. 커밋은 검토 뒤에 이뤄진다.
- 저장소 산출물은 영어로 쓴다 (`CLAUDE.md`). `.stage/` 안의 글만 한국어다.
- scope 밖의 파일은 건드리지 않는다.

## Success criteria

- `stage/skills/stage-drive/SKILL.md` 가 존재하고, 위에 적은 다섯 가지를 모두 담는다.
- frontmatter 의 `description` 이 언제 이 스킬이 걸려야 하는지를 말하고, 다른 stage 스킬의
  description 과 겹치지 않는다.
- 두 `plugin.json` 의 version 이 같은 값으로 올라가 있고 `CHANGELOG.md` 에 대응 항목이 있다.
- `python3 -m unittest discover -s stage/hooks/tests -q` 통과.
- `python3 -m unittest discover -s stage/scripts/tests -q` 통과.

**위험**: 이 스킬은 `--unattended` 로 가는 문도 같이 연다. 그 모드는 코드로는 두 번 검토받았지만
실제로 돌아본 적이 한 번도 없다. 스킬이 그것을 평범한 선택지처럼 적으면, 읽는 사람이 검증되지
않은 자동 실행을 진짜 작업에 걸게 된다. 아직 실전에서 돌려본 적 없다는 사실을 스킬 안에 적을 것.
