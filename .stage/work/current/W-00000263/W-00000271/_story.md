# W-00000271 시험한 Plainly 지침을 적용하고 새 질문으로 한국어를 확인한다

## Purpose

뜻을 바꾸거나 불필요한 설명을 붙이는 지침을 고치고 새로운 답변에서 한국어가 자연스러운지 확인한다

## Actions

- 검증한 수정안을 스타일과 설명 문서에 적용한다.
- 한국어 자료를 조사하고 새 질문의 실제 응답을 분석한다.

## User value

사용자 요청: “네 일단 적용하구요. 그리고 한국어 잘 쓰는지도 확인해야해요. 2차로 그걸로 가죠.”
추가 요청: “한국어의 특성에 대해서 리서치 하고요. 오퍼스 응답 하는거 보고 무엇이 부족한지 분석해보세요”.
초점 보완: “제가 불편한건 명사 중심의 영어를 동사 중심의 한국어로 번역을 잘 못한다는것도 있어요.”
추가 초점: “영어 직역을 하다 보니 어디 사전을 참고하는지는 모르겠지만 한국에서는 잘 쓰지 않는 말을 쓰게 되요.”
문장 길이: “그리고 긴 문장은 좋지 않아요.” 이어서 사용자가 “암튼 하던거 계속 해봅시다”라고 요청했다.
기존 설명을 풀어 드린 뒤 받은 적용 승인을 이번 세션의 직접 수정 승인으로 기록한다.
기존 변경을 보존하며 커밋하지 않는다.
후속 승인: 사용자가 “고칠 수 있는건가요? 플레인리를 강화해서?”라고 물었다.
문장 재구성·정확한 용어·뜻 확인 절차를 제안한 뒤 “네네 하세요”라고 승인했다.
이 승인에 따라 시험과 본체 적용까지 기존 작업에서 이어 간다.
릴리스 요청: “ㅇㅋ 버전 업데이트했고 깃에 푸시도 했죠? 다른데서 사용해볼까요?”
이 요청에 따라 0.7.1로 올리고 플레인리 변경만 커밋·푸시한다. 설치본 갱신과 새 세션의 로드도 확인한다.

## Scope

### Included

- 1차 검증안 적용, 기존 검사 갱신, README와 Unreleased 설명 수정.
- 한국어의 문장 구조·생략·어휘 결합·높임 표현 조사와 새 질문의 응답 분석.
- 결과와 원문을 이 카드 및 `.stage/.runtime/plainly-opus-lab/`에 보존.
- 한국어 지침을 다듬어 새 질문으로 비교하고 검증한 지침을 본체와 설명 문서에 반영.
- 후속 요청에 따른 버전 갱신, 플레인리 변경 커밋·푸시, 설치본 로드 확인.

### Excluded

- 플레인리와 관계없는 변경의 커밋, 다른 플러그인 변경.
- 실제 응답을 비교하지 않은 한국어 규칙의 적용.

## Risks

- 짧아진 답변을 자연스러워진 한국어로 잘못 판정할 수 있다. 의미·어휘·문맥을 따로 본다.
- 반복마다 출력이 달라진다. 단일 응답으로 오류율이나 모델 전체 능력을 추정하지 않는다.
- 공공언어 자료의 문체를 동료 대화나 UI 이름에 그대로 강요하지 않는다.
