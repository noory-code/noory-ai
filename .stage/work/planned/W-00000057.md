# W-00000057 안내 산문 드리프트 감사 + 명시적 갱신 명령 (DE-00000028)

## Purpose

감사가 .stage 안내 산문을 현행 템플릿과 대조해 드리프트를 경고하고, 명시적 갱신 명령이 이를 고친다

## Source

DE-00000028(결정), W-00000056(결정 카드), Q-00000001(원 질문). 계보는 이 절이 소유한다 —
frontmatter `parent`는 집계 관계(하위가 열려 있으면 상위는 미완)이고, W-00000056은 결정까지만
소유하므로 그 관계가 아니다.

## User value

Stage 사용자가 플러그인을 올린 뒤에도 `.stage/`의 안내 문서가 현행 템플릿과 같다고 믿을 수
있다. 다르면 감사가 알려 주고, 명령 한 번으로 맞춘다. 지금은 낡은 문서가 오류 0 뒤에 조용히
남는다.

## Scope

### Included

- 감사 체크 추가: 안내 문서를 해당 경로의 현행 템플릿(프로젝트 `language`의 로케일 파일이
  있으면 그것)과 바이트 비교해 다르면 경고.
- `settings.json`에 선언 키 추가(예: `guidance_overrides`) — 선언된 경로는 프로젝트 소유로
  보고 경고하지 않는다. `operations_overrides`와 같은 형태.
- 갱신 명령 추가. 파일 안에서 어디까지 교체하는지는 DE-00000029가 정한 세 갈래를 따른다:
  표가 없는 문서는 통째로 교체, 템플릿이 빈 표를 담은 문서는 프로젝트가 쌓은 표의 데이터
  줄만 옮겨 넣고 나머지 교체, 템플릿이 내용이 든 표를 담은 문서는 기본 대상에서 제외하고
  사용자가 파일을 지정했을 때만 교체. `--dry-run`으로 계획만 볼 수 있어야 한다.
- 세 갈래 판정은 템플릿의 표 모양에서 계산한다. 파일 목록을 코드에 박지 않는다.
- 위 항목의 테스트(로케일 파일 경로, 선언된 예외, 표 데이터 보존, 빈 표 2개 이상일 때
  교체 거부).
- `stage-audit` 스킬 문서와 CHANGELOG, 두 플러그인 매니페스트의 버전 갱신.

### Excluded

- 안내 문서의 소유권 재편(DE-00000028의 후보 D). 복사본 자체를 없애지 않는다.
- `init_stage.py --force`의 동작 변경. 갱신 경로가 아니라는 사실만 문서에 반영한다.
- `migrate_stage.py`의 `rewrite_verification` 경로 변경. `operations/verification.md`는
  갱신 명령의 기본 대상이 아니므로 두 경로가 겹치지 않는다.

## Dependencies

DE-00000028(무엇을 할지), DE-00000029(파일 안에서 어디까지 손댈지). 둘 다 decided.

## Risks

- 부분 교체는 프로젝트가 표 앞뒤에 추가한 문단을 잃을 수 있다. 판정이 애매하면 교체하지 않고
  보고만 하는 쪽으로 실패한다(Fail Fast, 데이터 우선).
- 로케일 파일이 없는 언어의 프로젝트는 영어 템플릿과 비교된다 — 정상 동작이지만 경고 문구가
  이를 분명히 말해야 한다.

## Success criteria

- 언어가 `ko`인 프로젝트가 영어 템플릿 문서를 들고 있으면 감사가 경고한다
  (W-00000053에서 실제로 겪은 사례가 회귀 테스트로 존재한다).
- 선언된 예외 경로는 경고하지 않는다.
- 갱신 명령 실행 후 감사가 깨끗하고, 인덱스에 쌓인 프로젝트 표 줄은 그대로 남는다.
- 템플릿이 내용이 든 표를 담은 파일은 기본 실행에서 건드리지 않는다.
- `python3 -m unittest discover -s stage/scripts/tests -q`와 `-s stage/hooks/tests -q` 통과.
