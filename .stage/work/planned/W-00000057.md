# W-00000057 안내 산문 드리프트 감사 + 명시적 갱신 명령 (DE-00000028)

## Purpose

감사가 .stage 안내 산문을 현행 템플릿과 대조해 드리프트를 경고하고, 명시적 갱신 명령이 이를 고친다

## Source

DE-00000028(결정), W-00000056(결정 카드), Q-00000001(원 질문). 계보는 이 절이 소유한다 —
frontmatter `parent`는 집계 관계(하위가 열려 있으면 상위는 미완)이고, W-00000056은 결정까지만
소유하므로 그 관계가 아니다.

## User value

Stage 사용자가 플러그인을 올린 뒤에도 `.stage/` 안내 문서가 현행 템플릿과 일치한다고 믿을 수
있다. 일치하지 않으면 감사가 말해 주고, 한 번의 명령으로 고친다. 지금은 낡은 산문이 감사
오류 0 뒤에 조용히 남는다.

## Scope

### Included

- 감사 체크 추가: 순수 산문 파일(`README.md`, `_template.md`)과 인덱스 문서 머리말을 해당
  경로의 현행 템플릿(프로젝트 `language` 로케일 오버레이 우선)과 바이트 비교해 다르면 경고.
- `settings.json`에 선언 키 추가(예: `guidance_overrides`) — 선언된 경로는 프로젝트 소유로
  보고 경고하지 않는다. `operations_overrides`와 같은 형태.
- 갱신 명령 추가: 드리프트한 문서를 현행 템플릿으로 교체한다. 인덱스 문서는 표 행을 보존하고
  머리말만 교체한다. `--dry-run`으로 계획만 출력할 수 있어야 한다.
- 위 세 가지에 대한 테스트(로케일 오버레이 경로, 선언된 예외, 인덱스 표 보존 포함).
- `stage-audit` 스킬 문서와 CHANGELOG, 두 플러그인 매니페스트의 버전 갱신.

### Excluded

- 안내 산문의 소유권 재편(DE-00000028의 후보 D). 복사본 자체를 없애지 않는다.
- `init_stage.py --force`의 동작 변경. 갱신 경로가 아니라는 사실만 문서에 반영한다.

## Dependencies

DE-00000028(decided). 인덱스 문서의 "머리말"과 "표 영역"을 가르는 경계를 구현 시점에 확정해야
한다 — 현재 인덱스 템플릿은 제목 + 산문 + 표 구조를 공유한다.

## Risks

- 인덱스 머리말만 교체하는 부분 교체는 표 앞뒤에 프로젝트가 추가한 문단을 잃을 수 있다.
  판정이 애매하면 교체하지 않고 보고만 하는 쪽으로 실패한다(Fail Fast, 데이터 우선).
- 로케일 오버레이가 없는 언어의 프로젝트는 영어 템플릿과 비교된다 — 정상 동작이지만 경고
  문구가 이를 분명히 말해야 한다.

## Success criteria

- 언어가 `ko`인 프로젝트가 영어 스켈레톤을 들고 있으면 감사가 경고한다(W-00000053에서 문
  실제 사례가 회귀 테스트로 존재한다).
- 선언된 예외 경로는 경고하지 않는다.
- 갱신 명령 실행 후 감사가 깨끗하고, 인덱스의 프로젝트 표 행은 그대로 남는다.
- `python3 -m unittest discover -s stage/scripts/tests -q`와 `-s stage/hooks/tests -q` 통과.
