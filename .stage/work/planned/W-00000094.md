# W-00000094 codex 실행자 스텝의 리뷰어 인덱스가 비어 전체 삭제 diff 가 된다

## Purpose

2026-07-26 에 두 번(W-00000088, W-00000093 드라이버 스텝) 실측으로 확인됐다. codex 실행자
스텝이 끝난 뒤 리뷰어가 물려받는 임시 인덱스가 사실상 비어 있어, 리뷰어의
`git diff HEAD~1` 이 저장소 962개 파일 중 956개를 "deleted file mode" 로 읽은 9MB diff 를
만들었고, 리뷰어 CLI 가 입력 초과로 죽었다. 증거: `.stage/.runtime/last-review-stdin.bin`
(9,016,382 바이트), Q-00000001(answered).

고칠 것 둘:

- **원인**: 무엇이 codex 실행자 스텝에서 임시 인덱스를 비우는가. 재현 방법: 임시 인덱스를
  진짜에서 복사해 `GIT_INDEX_FILE` 로 주고 codex-companion 실행자를 한 번 돌린 뒤
  `git ls-files | wc -l` 로 항목 수를 비교한다. python 스텁 실행자에서는 안 났고 codex
  실행자에서만 두 번 났다.
- **방어**: 원인과 무관하게, 리뷰어 인덱스의 항목 수가 0 인데 `HEAD` 트리는 비어 있지 않으면
  리뷰를 돌리지 말고 스텝을 fail-closed 로 막는다 — W-00000077 이 "인덱스 파일 없음" 에 세운
  방어를 "파일은 있는데 내용이 빔" 까지 넓히는 것이다. 전체 삭제 diff 는 리뷰로서 무의미하고
  비용만 태운다.

## Success criteria (초안 — 시작 시 확정)

- 빈 리뷰어 인덱스 + 비어 있지 않은 HEAD 조합이면 리뷰 전에 스텝이 실패한다. 그것을 확인하는
  테스트가 있고 고치기 전 코드에서 실패한다.
- 원인 재현 결과가 카드에 기록되어 있다 — 잡히면 근본 수정, 안 잡히면 방어만으로 닫고
  재현 조건을 적는다.
- 기존 테스트 전부 통과, 버전 범프, CHANGELOG.
