# R-00000277 코드가 맞아도 인계 기록은 틀릴 수 있었습니다

## Work

W-00000277에서 공개 CLI 연결과 실제 Claude·Codex 인계를 시험했습니다.
첫 시험의 코드 동작은 맞았지만 인계 기록 세 개는 틀렸습니다. 독립 리뷰가 이를 찾았습니다.
후속 시험은 여섯 사례의 코드·기록 검사를 통과했습니다. 정상 종료는 다섯 사례이며 한 사례는 180초 제한에 걸렸습니다.
이 두 번째 시험의 독립 리뷰는 성공 기준 1·2를 통과시키고 기준 3은 실패로 남겼습니다. 지적한 문서 누락은 보완했습니다.

사용자가 계속 진행하도록 요청한 뒤 정해진 Avatar 기록 절차를 묶는 세 번째 시험을 계획했습니다.
기존 전달 세션을 재사용하고 새 수신 세션 여섯 개를 각각 한 번 실행했습니다. 180초 제한은 유지했습니다.
여섯 사례 모두 정상 종료했고 전체 검사도 통과했습니다. 외부 관점에서는 실제 인계·기준 변경·선택 기록을 확인했습니다.
내부 관점에서는 새 테스트 5개와 기존 검사기 테스트 10개, 자료 검사, 해시 대조를 통과했습니다. 새 독립 리뷰도 세 기준을 통과시켰습니다.
리뷰가 증거 파일 검사 누락 두 곳을 찾았습니다. 원본을 임시 폴더에 복사해 누락과 변경을 재현한 뒤 검사기를 고쳤습니다.
보완 뒤 테스트 17개, 실제 실행 증거 검사, 별도 독립 리뷰도 통과했습니다.

## Decision points

- 감독 세션의 직접 구현과 실제 새 AI 세션의 시험을 따로 셌습니다. 사용자의 직접 구현 허용을 인계 성공으로 바꾸어 세지 않았습니다.
- 검사기가 글머리표를 놓쳤을 때 AI를 다시 호출하지 않고 검사기만 고쳤습니다. 원래 실패와 수정 뒤 판정을 모두 남겼습니다.
- 독립 리뷰가 실제 기록 오류를 찾았을 때 성공 주장을 정정했습니다. 첫 시험을 그대로 보존하고 후속 조건을 먼저 고정했습니다.
- 현재 기준을 주지 않은 조건에도 과거 코드가 남으므로 이를 완전히 영향을 없앤 대조군으로 부르지 않았습니다.
- 기록 절차를 코드로 묶되 선택과 적용 직전 조회는 AI에게 남겼습니다. 확인 발언도 미리 주어진 시험용 원문만 전달했습니다.
- 이전 연구 스크립트의 오류 문장을 고칠 때 실험 당시 소스와 해시를 보존했습니다. scope를 넓히지 않고 경계를 넘은 두 파일을 보고했습니다.
- 리뷰 요청이 시간 초과로 끝났을 때 판정으로 세지 않았습니다. 읽을 범위를 좁혀 다시 요청했고 실험의 시간 제한은 유지했습니다.

## Principles applied

- SSOT: 프로젝트 기준은 Distill, 개인 기준은 Avatar, 작업 기록은 Stage에서 조회했습니다.
- TDD: 검사기 오류를 실패 테스트로 재현한 뒤 고쳤습니다. 제품 코드와 합성 검사기를 구별했습니다.
- Honesty: 최초 실패·오판·후속 시험을 나눴습니다. 비용 절감, 재질문 감소, 자연스러운 스킬 선택은 입증했다고 쓰지 않았습니다.
- Completion: 코드 동작만으로 완료라고 하지 않았습니다. 기준 상태와 다음 할 일, 외부 리뷰까지 확인합니다.

## Context that helped

제품별 테스트와 공개 CLI 원본, 소스 digest가 있어 어떤 코드로 시험했는지 확인할 수 있었습니다.
Stage 문서에는 증거 JSON과 적용 기록의 형식이 이미 적혀 있었습니다.
독립 리뷰는 검사기 자체도 검토해 감독 세션이 놓친 통과 조건을 찾았습니다.

## Context that was missing

첫 전달 지시문은 해시를 남기라고만 했습니다. 정확한 저장 형식을 알려 주지 않아 Stage가 증거를 읽지 못했습니다.
첫 검사기는 앞선 적용 기록과 새 기록을 구별하지 않았습니다. 상태를 근거 없이 추정하거나 다음 할 일을 갱신하지 않는 경우도 놓쳤습니다.
시험용 카드가 연구 폴더 아래에서도 실제 Stage 카드로 인식됐습니다. 원본 바이트를 보존하고 확장자와 경로 대응표로 구분했습니다.
