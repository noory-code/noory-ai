# R-00000372 Stage 를 릴리스한다

## Decision points

- 올리는 폭: minor 로 골랐다. 새 스킬과 스크립트와 설정이 들어가고 닫기 리뷰의 계약이 바뀐다.
- 릴리스 브랜치가 main 보다 뒤처졌을 때: 브랜치를 main 위로 다시 잡아 force push 하려 했으나 권한 검사가 거절했다.
  대신 main 을 브랜치에 합쳤다. 그 결과 릴리스 커밋 뒤에 병합된 세 카드의 변경 기록이 0.68.0 절에 들어갔다.
  지휘 세션이 새 CI 점검(`changelog`)으로 그것을 잡아 세 항목을 0.69.0 으로 옮겼다.
- 성공 기준을 확인하는 버전: 카드는 "새 버전"이라고만 적었다. 0.68.0 을 낸 날 0.69.0 이 나와서 두 기준을 0.69.0 으로
  확인했다.
- CI 가 한 번 실패한 PR 을 병합했다. 결과의 마지막 15줄만 보고 모두 통과했다고 판단했다. 병합한 뒤에 실패를 보고
  그 작업을 다시 실행해 통과를 확인했다.

## Context that was missing

- 릴리스를 시작할 때 다른 세션이 같은 시간에 main 에 기능을 병합하고 있다는 것을 몰랐다. 릴리스 커밋을 만든 뒤
  PR 을 열 때에야 main 이 열 커밋 앞서 있는 것을 봤다.
- `test_run_check_timeout_ends_the_whole_process_tree_in_time` 이 Windows CI 에서 시간 한도(2.0초)를 넘길 수 있다는
  기록이 없었다. 이번에 2.687초가 걸렸고 다시 실행하니 통과했다. 원인은 확인하지 않았다.

## Rule candidate

- **CI 결과는 통과하지 못한 작업의 수를 세어 0 인지 본 뒤에 병합한다.** 결과 목록의 끝부분만 읽으면 앞쪽의 실패가
  보이지 않는다. 이 카드는 작업 30개 가운데 실패 1개를 병합한 뒤에 봤다. (1회차)
