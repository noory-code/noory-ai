# R-00000293 계획 카드 등록도 겹친 번호의 브랜치 이름을 보여 준다

## Work

W-00000293. `--backlog` 등록이 다른 브랜치가 쓴 번호를 거절할 때 그 브랜치 이름을 함께 보여 준다.
외부 결과: 계획 카드를 등록하다 거절돼도 어느 브랜치와 겹쳤는지 바로 안다.
내부 결과: `test_register_work.py` 47개, scripts 전체 701개, hooks 378개가 통과하고, 고치기 전 코드로는
계획 카드 하위 시험이 실패한다.

## Decision points

- `stage_record_ids.branch_record_numbers()` 를 그대로 쓰고, 번호가 다른 브랜치에서 왔을 때만 이름을 붙였다.
- 클라우드 실행 정책(DE-00000082)으로 등록한 첫 카드다. 예외 결정 없이 `environment: cloud` 로 등록됐다.

## Principles applied

SSOT: 브랜치 번호 조회는 `stage_record_ids.py` 한 곳이 소유한다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- W-00000291 닫기 리뷰가 차이를 정확히 짚어 R-00000291 에 남아 있었다.

## Context that was missing

- 닫기 리뷰가 짚은 점: 같은 번호가 지금 체크아웃과 다른 브랜치 양쪽에 있으면 거절 메시지에 브랜치 이름도
  붙는다. 실행 보고는 "지금 체크아웃의 번호는 이름 없이 거절"이라고 적어 이 겹친 경우를 빠뜨렸다. 동작은 정보가
  더 많은 쪽이라 그대로 둔다.
