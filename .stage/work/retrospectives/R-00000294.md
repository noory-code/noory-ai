# R-00000294 닫기 도구가 감사와 같은 승격 기록 검사를 쓴다

## Work

W-00000294. 감사의 WORK027 규칙을 `audit_stage.completed_promotion_errors()` 로 꺼내 감사와 `close_work.py` 가
함께 쓴다. 닫기 도구는 검사를 돌리기 전에 같은 이유로 거절하고 카드를 바꾸지 않는다.
외부 결과: 닫은 직후 감사가 깨지는 일(W-00000292)이 다시 일어나지 않는다.
내부 결과: `test_close_work.py` 70개, scripts 전체 703개, hooks 378개가 통과하고, 고치기 전 코드로는 거절 하위
시험 넷이 실패한다.

## Decision points

- 함수 자리: 규칙은 감사가 소유하고 `close_work.py` 는 이미 `audit_stage` 를 불러오므로 그 모듈에 두었다.
- 거절 시점: 검사를 돌리기 전에 거절해 시간을 쓰지 않고 아무것도 쓰지 않는다.
- 기존 시험: `approved` 로 닫던 시험의 목적은 "지배 결정에 연결된 카드가 최종 선택으로 닫힌다"였다. 감사가
  거부하는 값이 바로 `approved` 라 `deferred` 로 바꿨다.

## Principles applied

SSOT: 승격 기록 검사는 함수 하나가 소유한다.
Fail Fast: 닫기 전에 감사와 같은 기준으로 거절한다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- W-00000292 를 닫을 때 직접 겪은 오류가 정확한 재현 사례였다.

## Context that was missing

- 기존 시험 하나가 감사와 어긋나는 동작을 고정하고 있었다. 도구와 감사 사이의 계약이 시험에서도 갈라져 있었다.
- 함수를 처음에 `@dataclass` 장식자와 클래스 사이에 넣어 감사가 깨졌다. 시험이 바로 잡았다.
