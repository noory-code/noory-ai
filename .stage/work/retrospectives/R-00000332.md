# R-00000332 범위 넘음 알림에서 프로젝트 밖 경로와 같은 명령에서 정한 변수 경로를 뺀다

## Work

W-00000332. 범위 넘음 알림이 프로젝트 파일을 고치지 않은 호출에도 떠서, 열린 카드 전부의 범위와 목적을 담은 글이
대화에 붙던 것을 고쳤다. 헛신호는 셋이었다. 작업 폴더 밖 경로(메모 폴더, `~/` 파일), 같은 명령에서 대입한 셸 변수로
쓴 경로(`S=… && sed -i … "$S"`), 다른 저장소로 `cd` 한 뒤의 `git add`/`git commit` 이다.
외부 결과: 세션 기록 15개의 호출 1,696건을 고치기 전과 후의 훅에 같은 입력으로 넣었을 때, 알림이 붙은 호출이
544건에서 57건으로, 붙은 글이 513,348자에서 51,119자로 줄었다. 두 값을 카드 `## Verification` 에 남겼다.
내부 결과: hooks 전체(399개)가 worktree 루트와 `/private/tmp` 아래 현재 폴더 양쪽에서, scripts 전체(736개)가
worktree 루트에서 통과한다. HEAD 의 훅으로 바꿔 돌리면 새 시험 여섯 개가 깨진다.

## Decision points

- 작업 폴더 밖 경로를 모두 알림에서 뺐다. W-00000311 은 "홈 폴더 설정처럼 밖이지만 실제 변경인 경로는 알린다"고
  정했지만, 범위는 프로젝트 파일의 계획이고 등록 게이트도 밖 경로를 다스리지 않는다. 사용자가 고른 방향(헛신호를 없앤다)과
  오케스트레이터가 정한 첫 완료 기준이 이쪽이다. 대가로 다른 저장소를 고친 사실은 이 알림에 남지 않는다(카드 Risks).
- 같은 명령의 대입은 명령 단어 자리에서만 읽는다. `echo X=/y` 는 대입이 아니다. 값에 `$` 나 백틱이 있으면 버린다.
- 다른 저장소 커밋 판단은 `cd` 를 실행된 것으로 따라간다. 삭제 게이트의 추적기는 `&&` 뒤 `cd` 를 실행 안 됐을 수도
  있다고 보고 두 상태를 모두 두는데(fail closed), 알림은 막지 않으므로 가장 그럴듯한 폴더 하나로 판단했다.
  `cd -`, 모르는 변수, `pushd` 는 안으로 본다.
- 거부 메시지에 붙는 카드 목록 글과 세션 시작 글의 길이는 이 카드의 목적(헛신호) 밖이라 건드리지 않았다.

## Principles applied

Honesty: 측정 전제(호출마다 글이 붙는다)가 0.62.0 이후로는 거짓이었다. 카드 등록 전에 훅에 직접 넣어 확인하고
사용자에게 고쳐 말한 뒤 목적을 다시 물었다. 남은 57건에 측정 한계가 섞여 있다는 것도 카드에 적었다.
Fail Fast: 고치기 전 코드로 바꿔 시험이 깨지는지 보았다.
만든 쪽 ≠ 보는 쪽: 닫기 리뷰는 Claude 대역(같은 모델 계열)이다. DE-00000086 에 따른 것이고 교차 venue 판정은 아니다.

## Context that helped

- O-00000050 과 R-00000311 이 앞선 고침의 범위와 "현재 폴더를 바꿔서도 시험하라"는 교훈을 남겨 두어, 같은 실수를
  닫기 전에 피했다.
- 세션 기록의 실제 호출을 두 훅에 그대로 넣는 측정이 셋째 헛신호(다른 저장소 커밋)를 찾아 주었다. 코드를 읽기만 해서는
  보이지 않았다.

## Context that was missing

- 처음 받은 측정은 "호출마다 붙는다"였다. 실제로는 범위 넘음과 거부 때만 붙는다. 비용 측정이 어떤 경우에 글이 붙는지를
  나눠 세지 않아 생긴 오해다.
- 기록 당시의 임시 폴더가 지금은 없어서, 측정에서 `cd <없어진 폴더>` 뒤의 상대 경로가 프로젝트 경로로 보였다.
  재생 측정은 사라진 폴더를 재현하지 못한다.
