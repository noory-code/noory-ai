# R-00000283 범위를 넘은 호출의 훅 메시지를 대화창 한 줄과 에이전트 맥락으로 나눴다

## Work

W-00000283. 범위를 넘은 허용 호출에서 사용자 화면에는 `Scope boundary crossed: <경로>.` 한 줄만 나가고,
열린 카드의 범위·목적과 보고 지시는 `hookSpecificOutput.additionalContext`로 에이전트에게 간다.
외부 결과: 같은 범위 밖 파일로 재현하니 30줄이던 사용자 메시지가 한 줄이 됐다. 이 세션은 저장소의
`stage/`를 플러그인으로 읽어서, 고친 직후부터 맥락이 대화창이 아니라 Claude에게 왔다.
내부 결과: 드라이버 한 판에서 Codex 실행, 인수 시험 3개, Claude 독립 리뷰가 통과했다. 고치기 전
`stage_guard.py`로 되돌리면 hooks 시험 11개가 실패한다.

## Decision points

- 열린 카드를 관련 카드로 좁히는 방법은 고르지 않았다. 범위 밖 경로는 정의상 어느 카드에도 맞지 않아
  고를 기준이 없다. 사람 화면과 에이전트 맥락을 나누는 쪽이 문제를 그대로 없앤다.
- `systemMessage`에 한 줄은 남겼다. 사람이 범위 넘음을 볼 수 있는 자리가 이것뿐이다.
- 막힌 호출의 출력은 바꾸지 않았다. 막힌 이유는 이미 에이전트에게 간다.
- 드라이버 첫 판이 Codex 플러그인 캐시 검사에서 멈췄다. 원인은 로컬 main이 원격보다 7커밋 뒤처진
  것이었다. 원격에는 Stage 0.63.3이 이미 있었다. 로컬 커밋을 원격 위로 옮기고 다시 돌렸다.

## Principles applied

SoC: 사람에게 보이는 알림과 에이전트에게 주는 지시를 서로 다른 출력에 뒀다.
Honesty: `systemMessage`와 `additionalContext`가 누구에게 가는지는 Claude Code와 Codex 공식 문서로
확인했다. Codex 실제 세션에서는 확인하지 않았고, 카드 Risks와 Verification에 그렇게 적었다.
Fail Fast: 시험이 고침을 가려내는지 고치기 전 코드로 되돌려 확인했다.
Completion: 사용자가 처음 본 현상을 같은 입력으로 다시 재현해 한 줄로 줄어든 것을 봤다.

## Context that helped

사용자가 "다시나하고 관련 없습니다"라고 짚어서, 다시나 화면 문제가 아니라 Stage 훅 문제로 좁혔다.
`stage/operations/hooks.md`의 "Purpose context" 절에 조용한 호출은 아무것도 출력하지 않는다는 의도가
이미 적혀 있었다. 이번 고침은 그 의도를 범위를 넘은 호출까지 넓힌 것이다.

## Context that was missing

`systemMessage`가 모델에게 가지 않는다는 사실이 훅 문서에 없었다. 그래서 "범위를 넘으면 보고하라"는
지시가 에이전트에게 닿지 않는 상태가 오래 이어졌다.
세션을 시작할 때 로컬 main이 원격보다 뒤처졌는지 보지 않았다. 그 때문에 드라이버 한 판을 날렸다.

- O-00000050: 고치지 않은 경로가 넘은 경로로 잡히는 문제를 재현하고 원인을 본다.
