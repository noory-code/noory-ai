# R-00000286 닫기 리뷰가 판정 파일을 쓰게 하고 Codex 명령을 gpt-6-astra high로 고정한다

## Work

W-00000286. `.stage/settings.json` 의 닫기용 리뷰 프로필 명령 네 개에 `--write` 를 넣고, Codex
명령 여섯 개를 `--model gpt-6-astra --effort high` 로 바꿨다. 시험이 두 가지를 모두 지킨다.
외부 결과: 리뷰가 필요한 카드를 `close_work.py` 로 닫을 수 있다. Codex 가 사용자가 고른 모델과
깊이로 돈다.
내부 결과: `test_template_v4.py` 23개가 통과한다. 고치기 전 설정으로 되돌리면 10개가 실패한다.

## Decision points

- 원인: W-00000268 닫기에서 Codex 리뷰가 승인했는데도 "review verdict file is missing" 으로 막혔다.
  프로필 명령에 `--write` 가 없어 읽기 전용으로 돌았기 때문이다. 이 플래그는 2026-07-12 프로필이
  생길 때부터 없었고, 2026-08-03 `e4e96af9` 는 드라이버 리뷰 명령에만 넣었다.
- 리뷰어가 화면에 출력한 판정 JSON 을 Claude 가 대신 파일로 쓰지 않았다. 리뷰어가 직접 쓴 판정만
  인정하는 계약을 우회하게 되기 때문이다.
- 처음에는 Claude 가 직접 고치는 venue 예외를 제안했다가 거두었다. 드라이버의 실행·리뷰 명령은
  멀쩡했고, 사용자가 Codex 를 적극 쓰라고 했기 때문이다. 정책대로 Codex 드라이버가 실행했다.
- 모델 변경은 사용자의 2026-10-31 지시("코덱스 아스트라 하이로 적극 사용하세요")를 따랐다. 바꾸기
  전에 `gpt-6-astra` 에 `--effort high` 를 준 호출이 정상 응답하는 것을 확인했다.
- 리뷰어가 짚은 `CHANGELOG` 의 어긋난 두 줄(예전 `gpt-6-sol` 고정, 새 `gpt-6-astra` 고정)을
  받아들여 한 줄로 합쳤다. 둘 다 아직 배포 전이라 최종 상태 하나만 남기는 것이 맞다.

## Principles applied

Fail Fast: 고치기 전에 모델 호출을 먼저 시험했다.
Honesty: 판정 파일을 손으로 만들지 않았다. 실행자가 손으로 `verification: passed` 로 바꾼 값을
`pending` 으로 되돌려 닫기 도구가 쓰게 했다.
만든 쪽 ≠ 보는 쪽: Codex 가 고치고 Claude 가 드라이버 리뷰를, Codex 가 닫기 리뷰를 했다.

## Context that helped

- `close_work.py` 가 판정 파일이 없으면 승인 출력과 상관없이 닫지 않는 계약이 결함을 바로 드러냈다.
- 모델 고정 시험이 이미 있어서 기대값만 바꾸면 됐다.

## Context that was missing

- 프로필 명령을 처음 만들 때 판정 파일을 써야 한다는 조건을 시험하지 않았다. 그래서 석 달 동안
  드러나지 않았다. 그사이 이 경로로 닫은 카드가 있었는지는 확인하지 않았다.
- 드라이버 실행자가 카드의 `verification` 을 손으로 `passed` 로 바꿨다. 실행 계약에는 그 값을
  건드리지 말라는 문장이 없다.
