# R-00000291 병렬 브랜치가 같은 기록 번호를 쓰지 않게 한다

## Work

W-00000291. `stage/scripts/stage_record_ids.py` 가 지금 체크아웃과 모든 로컬·원격 추적 브랜치의 `.stage/` 에서
한 접두사의 번호를 세어 다음 번호를 알려 준다. `register_work.py` 는 자동으로 번호를 고를 때 다른 브랜치의 W
번호를 함께 세고, 지금 체크아웃에 없는데 다른 브랜치에 있는 번호를 직접 주면 거절한다. 결정 절차는 DE 번호를
이 도구로 고르라고 적는다.
외부 결과: 여러 세션이 병렬 브랜치에서 일해도 새 카드와 결정이 이미 쓰인 번호를 다시 쓰지 않는다.
내부 결과: 인수 시험(4개, 47개), scripts 전체 694개, hooks 378개가 통과하고, 고치기 전 `register_work.py` 로는
새 등록 하위 시험 넷이 실패한다.

## Decision points

- 네트워크를 쓰지 않는다: 이미 받아 둔 브랜치만 센다. 등록이 빠르고 오프라인에서도 돈다. 결정 절차에는
  다른 세션이 push 할 때 먼저 받아 오라고 적었다.
- 지금 체크아웃의 카드가 이긴다: 같은 번호가 다른 브랜치에도 있으면 재실행으로 보고 인덱스만 맞춘다.
  그러지 않으면 push 한 카드를 다시 등록할 때마다 거절된다.
- DE·O 는 도우미만: 그 기록은 아직 템플릿으로 손으로 쓰므로, 번호를 알려 주는 도구만 두고 할당기는 만들지
  않았다.
- 파일 훑기 경계: hooks 시험이 `.md` 기록 훑기를 `record_paths` 밖에서 금지해, 첫 구현의 `rglob` 을 바꿨다.

## Principles applied

User intent: 사용자가 승인한 다음 일(3번)이다.
SSOT: 기록 파일 훑기는 `stage_record_paths.record_paths()` 한 곳이 소유한다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 이 프로젝트의 codex 리뷰 프롬프트로 판정했다. 같은
모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- 오늘 겹친 두 번호(W-00000286, DE-00000076)가 시험의 실제 사례가 됐다.
- hooks 시험의 경계 검사가 파일 훑기를 한 곳으로 모으라는 규칙을 바로 알려 줬다.

## Context that was missing

- git 은 빈 폴더를 추적하지 않아, 브랜치를 오가는 시험에서 생명 주기 폴더가 사라졌다. 시험이 폴더를 다시
  만들게 했다.

## Next changes

- 아직 push 하지 않은 다른 컴퓨터의 번호는 볼 수 없다. 그 경우는 합칠 때 감사가 잡는지 확인한다.

  않는다. Actions 는 이름을 보여 주라고 적었다. 성공 기준에는 영향이 없어 닫은 뒤 작은 카드로 고친다.
