# R-00000367 여러 세션이 목록 파일과 카드 번호에서 부딪히지 않게 설계한다

## Work

두 세션이 따로 일한 뒤 브랜치를 합칠 때 부딪히는 자리를 세고, 목록 파일과 기록 번호에 대한 설계안을 실제로
실행해 본 뒤 사용자에게 보였다. 사용자가 고른 방법을 DE-00000091 과 DE-00000092 로 쓰고, 구현 카드
W-00000374 와 W-00000375 를 계획된 카드로 등록했다.

## Decision points

- **가장 싼 안을 고르기 전에 과거 머지에 실행했다.** 목록 파일 전부에 union 을 거는 안은 설정 파일 하나로
  충돌을 27건에서 2건으로 줄인다. 같은 머지에서 나온 파일을 사람이 커밋한 파일과 비교하니, 줄을 지우는
  목록에서는 18번 가운데 13번이 닫은 카드를 되살렸다. 충돌이 없어졌다는 숫자만 봤다면 이 안을 골랐을 것이다.
- **카드 제목에 없는 파일을 대상에 넣었다.** 카드는 목록 파일과 카드 번호를 물었다. 가장 많이 충돌한 파일은
  `stage/CHANGELOG.md`(14번)였다. 줄을 더하기만 하는 목록이라는 점이 같아서 같은 결정에 넣었다.
- **결정을 둘로 나눴다.** 목록과 번호는 고치는 파일이 겹치지 않고, 하나가 틀려도 다른 하나는 남는다.
- **실행하지 못한 것을 구현 카드의 끝나는 조건으로 넘겼다.** GitHub 의 머지 버튼이 union 을 따르는지와 GitHub 이
  번호를 잡는 ref 를 받아 주는지는 원격에 써야 확인할 수 있다.

## Principles applied

- Fail Fast: 고르기 전에 지는 안을 실행했다. union 이 틀린 목록을 만든다는 것을 구현 전에 알았다.
- SSOT: 카드의 상태는 카드가 갖고, 목록은 카드에서 만든다.
- Honesty: 실행하지 않은 것(카드에서 목록 만들기, GitHub 쪽 동작)을 결정 기록의 Follow-up 과 사용자에게 한 말에
  그대로 적었다.

## Context that helped

- 머지 커밋이 136건 남아 있어서 설계안을 지어낸 예가 아니라 실제 머지에 실행할 수 있었다.
- `.stage/operations/parallel-sessions.md` 가 지금 규칙과 그 규칙이 생긴 회고를 적어 두었다.

## Context that was missing

- 세 목록 파일을 읽는 자리가 관문에서는 "카드 없이 목록에만 줄이 있으면 막는다"는 한 군데뿐이라는 것은 코드를
  읽고서야 알았다. 도면의 레이어 표에는 파일만 있고 파일이 읽는 기록은 없다.

## Next changes

- 설계 카드가 설계안을 실행해 본 스크립트는 저장소에 남지 않는다. 결과 표만 결정 기록에 남는다.

## Rule candidate

- 충돌이나 오류의 개수를 줄이는 안은 줄어든 개수만 보지 않고, 나온 결과가 맞는지를 사람이 만든 결과와
  비교한다. (1회차. union 은 충돌을 25건 줄였지만 13번은 틀린 파일을 만들었다.)

## Promotion decision

DE-00000091 과 DE-00000092 는 결정된 채로 대기 자리에 둔다. 구현 카드가 닫힐 때 승격을 다시 본다.
