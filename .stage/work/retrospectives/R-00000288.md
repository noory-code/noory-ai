# R-00000288 상태 기록이 계획 칸 카드를 가리켜도 STATE001 로 막지 않는다

## Work

W-00000288. `audit_state_links` 가 상태 기록의 `work_items` 를 진행 중·보관 카드뿐 아니라 계획 칸
카드(`graph.backlog_by_id`)에도 대조한다(`stage/scripts/audit_stage.py` 한 줄). 어디에도 없는 카드는
여전히 STATE001 로 실패한다.
외부 결과: `novel-workspace` 감사에서 Q-00000037(계획 칸 W-00000437 연결) 오류가 사라져 오류 0건이다.
내부 결과: 새 시험이 Q·O·A·K 네 종류를 현재 칸과 보관 칸에 두고 확인한다. 고치기 전 코드로 되돌리면
9건이 실패한다. hooks 378개와 scripts 710개가 통과한다.

## Decision points

- 상위 카드 검사(`audit_stage.py:786`)가 이미 쓰는 `backlog_by_id` 를 그대로 써서 계획 칸 카드를 세는
  기준을 한 곳에 두었다.
- 이 카드는 `codex` venue 그대로 로컬 Codex 드라이버가 실행했다. 실행 명령은 W-00000289 가 바꾼
  `stage/scripts/codex_companion.py` 를 거쳤다. 이 실행이 W-00000298 의 근거가 된다.

## Principles applied

SSOT: 계획 칸 카드를 세는 기준을 상위 카드 검사와 같은 출처에 두었다.
Fail Fast: 없는 카드는 계속 실패하게 두고 그 경우를 시험으로 고정했다.
만든 쪽 ≠ 보는 쪽: Codex 가 고치고 Claude 가 드라이버 리뷰를, Codex 가 닫기 리뷰를 했다.

## Context that helped

- 드라이버 리뷰어가 고치기 전 코드로 되돌려 시험이 실패하는지 직접 확인했다. 처음에는 시험 모듈이
  `audit_stage` 를 따로 불러와 바꿔 넣은 검사가 적용되지 않아 헛통과했고, 리뷰어가 이를 알아채 다시 쟀다.

## Context that was missing

- 드라이버 안에서 카드의 인수 명령을 돌리면 드라이버가 설정한 `GIT_INDEX_FILE` 때문에 git 을 쓰는
  시험이 깨진다. 실행자와 리뷰어 모두 그 변수를 지우고 돌렸다. 이 카드 밖의 드라이버 문제다.
