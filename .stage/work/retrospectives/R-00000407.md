# R-00000407 성공 기준이 가정한 기계와 확인한 기계가 달랐다

## Decision points

- kuzu 0.11.3 이 PyPI 의 마지막 판이고 3.14 wheel 은 Linux 용뿐이라, kuzu 를 올리는 길은 없었다. 작업 세션이
  `requires-python` 을 `>=3.11,<3.14` 로 좁혔다. `.python-version` 은 선호일 뿐이라 `uv run --python 3.14` 와 pip 를
  막지 못해서 고르지 않았다.
- 이 상한은 공개 패키지의 모든 사용자에게 걸린다. Python 3.14 만 있고 uv 가 Python 을 내려받지 못하게 설정한 기기는
  소스 빌드 대신 거절을 받는다. kuzu 나 대신할 저장소가 Windows 와 macOS 의 3.14 wheel 을 내면 손으로 풀어야 하고,
  그것을 알려 주는 장치는 없다.
- 카드의 scope 밖인 `rag/README.md` 와 `rag/skills/rag-help/SKILL.md` 의 "Python 3.11+" 를 작업 세션이 고쳤다. 상한을
  두면 그 문장이 틀리기 때문이다.
- 두 성공 기준이 사용자의 기계에서만 보여서, 사용자의 말("맥 윈도우즈 상관하지 말고 하세요")에 따라 닫기 리뷰 없이
  병합하고 카드를 열어 두었다.
- 첫째 성공 기준은 문장 그대로는 관찰되지 않았다. 확인한 Windows 기기가 ARM64 여서 uv 가 ARM64 Python 을 받았고
  `sqlite-vec` 에 `win_arm64` wheel 이 없어 멈췄다. x86_64 Python 을 지정하면 kuzu wheel 을 받고 121개가 통과했다.
  사용자가 2026-11-23 에 이 결과로 기준이 채워진 것으로 판정했다. x86_64 Windows 에서 명령을 그대로 실행한 기록은 없다.

## Context that was missing

- 카드를 등록할 때 그 Windows 기기가 ARM64 라는 것이 카드에 없었다. 성공 기준은 "Python 3.14 만 설치된 한국어 Windows"
  라고만 적어서, 기준을 볼 기계의 아키텍처에서 다른 의존성(`sqlite-vec`)이 먼저 막는다는 것을 병합 뒤에야 알았다.
- ARM64 Windows 를 지원할지는 정해지지 않았다. 카드의 Follow-up candidate 로 남는다.

## Rule candidate

- 성공 기준이 특정 기계에서만 보이면, 등록할 때 그 기계의 OS, 아키텍처, 깔린 런타임을 기준에 적는다(한 번 관찰).
