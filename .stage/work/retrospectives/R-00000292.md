# R-00000292 실행 환경을 venue 와 나누고 클라우드 실행을 정책으로 허용한다

## Work

W-00000292. 카드에 `environment:` 칸을, 설정에 `environment_venues` 를 두었다. 선언된 환경과 그 환경의
venue, 독립 닫기 리뷰가 맞으면 `venue_routing` 과 달라도 예외 결정 없이 등록·시작되고 감사를 통과한다.
어기면 세 자리 모두 이유와 함께 거절한다(감사 VENUE006). 클라우드 실행 절차는
`stage/operations/cloud-execution.md` 로, 대역 리뷰어는 `stage/scripts/claude_review_companion.py` 로
저장소에 들어왔다.
외부 결과: 클라우드에서 카드를 돌릴 때 결정 기록을 새로 쓰지 않는다. 카드가 누가(venue) 어디서
(environment) 실행했는지를 따로 말한다.
내부 결과: 인수 시험 7개, scripts 전체 701개, hooks 378개가 통과하고, 고치기 전 코드로는 새 하위 시험
여덟 개가 모두 실패한다. 이 카드는 저장소에 들어온 대역 리뷰어로 처음 닫았다.

## Decision points

- 칸을 새로 둠: `cloud` 를 venue 값으로 두면 누가와 어디서가 다시 섞이고, 교차 venue 리뷰의 반대편을 정할
  수 없다(DE-00000082).
- 정책의 값: 경로가 닿지 않는 리뷰 venue 대신 독립 닫기 리뷰(`review: pending`)를 조건으로 걸었다.
- 섞인 종류 규칙은 그대로: 그 규칙은 설계와 구현을 나누는 규칙이라 환경과 상관없다.
- 계획 카드: `--environment` 는 시작할 때 받는다. venue 계약이 원래 그때 돈다.
- 범위 밖 변경: 파이썬 대역을 `STAGE_CODEX_COMPANION` 으로 쓰려고 `codex_companion.py` 가 `.py` 를 파이썬으로
  돌리게 했다.
- 마지막 예외: 정책은 이 카드가 끝나야 생기므로 이 카드는 DE-00000083 으로 한 번 더 예외를 세웠다.

## Principles applied

User intent: 사용자가 클라우드 실행을 정책으로 만들라고 지시했고, 토론 없이 바로 하라고 했다.
SoC: venue 는 누가, environment 는 어디서를 맡는다.
SSOT: 클라우드 실행 계약을 결정 일곱 장에서 운영 문서 한 곳으로 옮겼다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 이 프로젝트의 codex 리뷰 프롬프트로 판정했다. 같은
모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- 하루 동안 쌓인 예외 결정 일곱 장(DE-00000075~081)이 모두 같은 조건을 반복했다. 정책의 조건을 그대로 읽어
  낼 수 있었다.
- 등록·시작·감사가 이미 예외 판정 함수 하나를 공유하고 있어, 정책도 같은 자리에 하나만 더하면 됐다.

## Context that was missing

- `approved` 는 승격 경로와 실제 승격을 함께 요구한다. 승격을 미룰 때는 `deferred` 다.
- 템플릿 설정 파일은 백틱을 금지하는 시험이 있다. 주석에서 백틱을 뺐다.
- `start_work.py` 는 아는 칸만 frontmatter 에 다시 쓴다. 새 칸은 순서 목록에 넣어야 남는다.

## Next changes

- DE-00000082 가 정착되면 `official/canon` 으로 승격한다. 이 카드의 승격 선택은 `deferred` 다.
- 이 프로젝트 `.stage/operations/claude-venue.md` 등 로컬 문서가 클라우드 절차를 언급하면 새 운영 문서를
  가리키게 한다.

## Rule candidate

- 같은 모양의 예외 결정이 세 번 이상 쌓이면 정책 후보로 올린다.

WORK027(승격 경로 없음)을 냈고 `deferred` 로 바로잡았다. DE-00000083 은 일회성 venue 예외다.
