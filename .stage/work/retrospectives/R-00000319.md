# R-00000319 CI 에서 드러난 Stage 의 Windows·작업 폴더 버그를 고친다

## Work

W-00000319. PR 의 CI 가 로컬에서 안 보이던 실패 셋을 냈다. 시험이 저장소 루트를 작업 폴더로 가정한 것, Windows 에서
`/dev/null` 이 `<드라이브>:/dev/null` 로 풀려 장치로 안 보인 것, 현재 폴더를 옮긴 시험이 임시 폴더를 지우기 전에 돌아오지
않은 것이다. 셋 다 이번 세션에서 넣은 코드다.
외부 결과: Windows 의 범위 넘음 알림에서도 `/dev/null` 이 빠진다. CI 가 다시 초록이 될 수 있다.
내부 결과: `stage/` 폴더에서(CI 와 같게) 돌린 scripts·hooks 시험 전체가 통과한다. 장치 경로 판별을 지우는 변이를 시험이 잡는다.

## Decision points

- 장치 경로는 경로 계산 전에 글자로 판단한다. Windows 의 경로 계산으로는 드라이브 없는 `/dev/null` 과 현재 드라이브의 경로를 가를 수 없다.
- 프로젝트 리뷰 명령을 절대 경로로 바꾸지 않고 시험이 프로젝트 루트에서 돌게 했다. 리뷰 명령은 늘 프로젝트 루트에서 돈다.

## Principles applied

Honesty: 로컬 시험을 저장소 루트·Linux 에서만 돌려 세 결함을 놓쳤다. CI 가 잡았다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- CI 로그가 OS·버전별로 실패를 나눠 보여 원인을 셋으로 바로 가를 수 있었다.

## Context that was missing

- CI 가 `working-directory: stage` 에서 시험을 돈다는 것을 몰랐다. 로컬 확인도 CI 와 같은 폴더에서 해야 한다.
- 이 컨테이너에서는 Windows 를 돌릴 수 없다. Windows 동작은 PR 의 CI 로만 확인한다.

## Next changes

- 경로나 작업 폴더를 다루는 변경은 저장소 루트, `stage/`, 임시 폴더 세 곳에서 시험을 돌린다.
