# R-00000266 정한 대로 스타일 파일을 내고 훅을 물러나게 한다

## Work

두 번에 나눠 갔다. 먼저 스타일 다섯 개를 `output-styles/` 로 내고 훅과 딸린 코드를 지웠다
(0.5.0). 그다음 사용자가 더 좁혀서 스타일 하나만 남기고 원본과 빌드 스크립트까지 지웠다
(0.6.0). 최종 상태는 마크다운 한 파일과 그 파일을 검사하는 테스트다.

## Decision points

- 훅을 물러나게 할지 지울지. 지웠다. 코덱스에서 안 쓴다는 사용자 말이 근거였다.
- 코덱스 매니페스트를 지우면 저장소 계약 테스트가 깨진다. 모든 플러그인이 두 매니페스트를 갖도록
  요구하던 것을, 한 호스트만 지원하는 플러그인을 허용하게 고쳤다.
- `release_plugin.py` 도 두 매니페스트를 다 요구해서 릴리스가 막혔다. 있는 것만 올리고 하나도
  없으면 거부하게 고쳤다.
- 스타일 이름을 바꾸면 옛 이름을 적어 둔 설정이 조용히 깨진다. 사용자 설정도 함께 고쳤다.

## Principles applied

- **SSOT** — 파일 하나가 원본이자 배포본이 되면서 어긋날 자리가 사라졌다.
- **MECE** — 적용 자리 열여덟 군데를 세어 둔 표 덕에 저장소 계약 테스트와 릴리스 스크립트가
  깨질 것을 미리 알았다.
- **Honesty** — 코덱스에서 안 도는 플러그인을 코덱스 목록에 남겨 두지 않았다.

## Context that helped

`claude -p --plugin-dir --settings --debug-file`. 커밋 전에 실제로 로드되는지 매번 확인할 수
있었다. 디버그 로그가 스타일을 몇 개 읽었는지 숫자로 찍어 준다.

## Context that was missing

`release_plugin.py` 가 두 매니페스트를 하드코딩한다는 사실. 결정 기록의 적용 자리 표에는 넣었지만
그건 이 카드를 하다가 코드를 열어 보고 안 것이다. 계약을 바꾸면 그 계약을 읽는 도구도 함께
세어야 한다는 걸 표가 뒤늦게 잡아 줬다.

설치된 플러그인을 갱신하는 길. `/plugin` 메뉴로는 안 되고 `claude plugin marketplace update` 와
`claude plugin update` 두 줄이 필요했다. 마켓플레이스 기록이 낡으면 두 번째 줄만으로는 안 된다.

## Next changes

`keep-coding-instructions: true` 가 실제로 코딩 지침을 남기는지 대화형 세션에서 확인한다.

## Rule candidate

플러그인 계약을 바꿀 때는 그 계약을 읽는 스크립트까지 센다. 이번에 `release_plugin.py` 가
그랬다. 한 번뿐이라 규칙 파일로 올리지 않는다. 같은 모양이 한 번 더 나오면
`.stage/operations/` 에 올린다.
