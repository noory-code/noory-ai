# R-00000127 리뷰 계약 문서 정합 회고

## Work

문서 넷이 걷어낸 `BLOCK:` 산문 계약을 아직 말하고 있던 것을 실제 동작(판정 파일이 통과를
정한다)으로 고쳤다. 리뷰어 인프라 실패의 무료 재시도 조건을 코드가 참으로 하는 대로 적었고
(판정 파일이 없거나 유효한 승인일 때 — 카드 문구보다 넓다는 것까지 로그에 남김), 리뷰가
막혔을 때의 다음 행동을 감독·무인으로 갈라 적었다 — R-00000118 이 남긴 두 갈래 읽힘이
닫혔다.

첫 병렬 실전의 세 카드 중 유일한 claude venue 카드.

## Decision points

- 드라이버 판정 실패 두 번을 받지 않았다. 1라운드는 900초 안에 실행자가 편집을 끝내고도
  세션이 안 끝난 것(문서 넷 + 코드 대조는 900초짜리 일이 아니다), 2라운드는 그 결과가 이미
  트리에 있어 "진전 없음"으로 막힌 것. 문서 diff 를 내가 직접 읽어 코드와 대조를 확인하고
  수동으로 닫았다.
- 실행자가 카드 문구보다 코드가 넓다는 것을 발견하고 코드 쪽을 적었다 — 문서는 코드를
  사실대로 말하는 것이 목적이므로 옳은 판단이다.

## Principles applied

- Honesty — 문서가 계약을 지어내지 않고 코드가 하는 그대로를 말한다. 실행자가 문서의 모든
  새 서술을 코드에서 직접 재확인했다.
- SSOT — 리뷰 통과의 정의는 판정 파일 하나이고, 문서는 그것을 가리킨다.

## Context that helped

- 1라운드의 잔해(git skip-worktree 1,133개)를 2라운드 실행자가 발견하고 치웠다. claude 세션이
  트리에서 남기는 흔적이 실측으로 잡힌 첫 사례다.

  venue 별 시간 특성이 어디에도 적혀 있지 않다 — 규모 기반 시간 계산(W-00000118)이 venue 를
  모른다.
