# R-00000289 codex 명령이 설치된 컴패니언 스크립트를 찾아 쓴다

## Work

W-00000289. `stage/scripts/codex_companion.py` 가 codex 컴패니언 스크립트를 실행 때 찾아 `node` 로
돌린다. 찾는 순서는 `STAGE_CODEX_COMPANION`, Claude Code 설치 기록의 `codex@openai-codex` 설치 경로,
캐시의 가장 높은 버전이다. `.stage/settings.json` 의 codex 명령 일곱 곳(실행, 리뷰, 프로필 넷, 회수)이
이 스크립트를 부른다.
외부 결과: codex 플러그인을 업데이트하거나 다른 컴퓨터에서 열어도 명령이 고정 경로 때문에 깨지지 않는다.
내부 결과: `test_codex_companion.py` 10개, scripts 전체 684개, hooks 378개가 통과하고, 고치기 전 설정으로
되돌리면 설정 단언 여덟 개가 실패한다. 회수 명령은 가짜 컴패니언으로 끝까지 돌려 대상 카드의 작업만
취소하는 것을 확인했다.

## Decision points

- 찾는 순서: 설치 기록이 실제로 켜진 버전을 말하므로 캐시보다 먼저 본다. 캐시는 오래된 버전이나 새
  버전을 함께 갖고 있을 수 있다.
- 설치 기록 형식: 이 세션의 Claude Code 소스에서 V2 형식(플러그인 ID 마다 `scope`·`installPath` 를 담은
  항목 목록)을 확인하고 따랐다. 읽지 못하면 캐시로 넘어간다.
- 위치: `stage/scripts` 에 두고 프로젝트 상대 경로로 부른다. 모든 명령이 프로젝트 루트에서 돈다.
- 회수 명령: Node 안에서 컴패니언을 두 번 부르던 자리를 같은 스크립트로 바꿨다. 경로 변수 `tool` 이
  없어지므로 끝까지 돌리는 시험을 더했다.
- 판정 자리: 이 세션에 codex 가 없어, 새 `STAGE_CODEX_COMPANION` 덮어쓰기로 컴패니언 자리에 `claude -p`
  를 대신 넣었다. 설정을 덮어쓰지 않고 이 프로젝트의 codex 리뷰 프롬프트 그대로 판정을 받았다.

## Principles applied

User intent: 사용자가 이 세션이 codex 몫까지 하라고 지시했고, 이 카드를 다음 일로 승인했다.
Honesty: 클라우드에는 codex 가 없어 실제 플러그인으로 돌린 적이 없다는 것을 실행 보고와 결정에 적었다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은
아니다.

  세어 드러냈다.
