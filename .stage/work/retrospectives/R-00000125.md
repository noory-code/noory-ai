# R-00000125 보관 인덱스 계약 회고

## Work

보관 인덱스가 최상위 이동 단위마다 한 행만 소유하는 것으로 계약을 정하고, 보관 도구와
감사(ARCHIVE001)를 그쪽으로 맞췄다. 계층의 SSOT 는 폴더 배치이므로 하위 행은 같은 사실의
중복이다. 두 에픽의 손 채움 열두 행을 걷어냈고, 계층 보관이 감사 오류 0 임을 테스트로
고정했다. 오늘 두 번 재발한 그 오류가 이제 안 난다.

첫 병렬 실전의 세 카드 중 하나로, 자기 작업 트리에서 돌았다.

## Decision points

- 계약 방향은 카드가 권한 대로(이동 단위만) 정해졌다. 근거는 DE-00000035 와 같다 — 진실이
  폴더에 있으면 인덱스의 하위 행은 베낀 것이고, 베낀 쪽이 낡는다.
- 드라이버 판정 실패 두 번을 받지 않았다. 1라운드는 드라이버가 물려준 프로젝트 변수가 트리
  검사를 오염시킨 것(W-00000134 의 근거), 2라운드는 내가 박은 변수 값 자체가 hermetic
  테스트를 오염시킨 것 — 둘 다 카드 내용과 무관하고, 일은 1라운드에 이미 완성돼 있었다.
  변수 없는 환경에서 전체 스위트 통과를 직접 확인하고 수동으로 닫았다.

## Principles applied

- SSOT — 인덱스가 폴더의 진실을 베끼지 않는다.
- Honesty — 드라이버의 실패 판정을 그대로 받지도, 무시하지도 않았다. 원인을 실측으로 갈라
  카드 탓과 드라이버 탓을 구분했다.

## Context that helped

- 손 채움 열두 행이 정확히 어느 카드 몫인지 이 카드의 Purpose 가 이미 들고 있었다. 재발
  때마다 근거를 적어 둔 값이다.

## Context that was missing

- 트리 안에서 도는 검사가 프로젝트 변수에 얼마나 민감한지 아무도 몰랐다. 이 카드의 실패
  두 번이 그것을 실측했고, W-00000134 가 그 결과 위에서 고쳐졌다.

## Promotion decision

not_applicable — 플러그인 소스 수정. 보관 인덱스 행 정리는 이 카드의 scope 로 이미 반영됐다.
