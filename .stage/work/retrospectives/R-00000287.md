# R-00000287 실행자가 정한 것을 닫을 때 카드에 남긴다

## Work

W-00000287. `close_work.py` 가 닫을 때 작업 로그의 마지막 `### Executor report` 에서 `What changed`,
`Why`, `Decisions made`, `Work not done` 네 줄을 원문 그대로 카드의 `## Progress` 에 옮긴다. 검증기가
두 판단 칸을 요구하고, 실행자 계약 넷(드라이브 스킬, 스키마, 템플릿, 이 프로젝트의 실행 명령 둘)이
"매 판 아직 유효한 결정을 다시 적는다"를 같은 뜻으로 적는다.
외부 결과: 몇 달 뒤 다른 체크아웃에서도 카드만 열면 실행자가 무엇을 왜 정했는지 읽힌다.
내부 결과: `test_close_work.py` 66개, scripts 전체 671개, hooks 378개가 통과하고, 고치기 전 코드로
되돌리면 새 단언 다섯 개가 실패한다. 이 카드의 닫기가 이 기능을 처음 실제로 쓴다.

## Decision points

- 정본 자리: 사용자와 토론해 카드(A), 커밋 본문(B), 로그 커밋(C) 가운데 A 를 골랐다. 기준은 몇 달
  뒤의 본인이 `.stage/` 로 들어온다는 것이다. 실패한 판은 회고가 소화한다(사용자 결정).
- 여러 판의 결정: 마지막 판만 옮기고 누적 기재를 계약으로 요구했다. 모든 판을 모으면 되돌린 결정도
  남아 기록이 코드와 어긋난다.
- 범위 밖 변경 여섯 곳: 실제 실행 명령이 든 `.stage/settings.json`, 거짓이 될 `operations/review.md`,
  새 문장을 고정하는 시험 하나, 두 칸이 빠진 드라이버 시험 픽스처 셋. 실행 보고에 모두 적었다.
- 번호: 처음에 W-00000286·DE-00000076 으로 적었으나 다른 브랜치에서 이미 쓰인 번호라 push 전에
  W-00000287·DE-00000078 로 바꿨다.
- 판정 자리: 이 세션에는 codex 가 없다. 사용자가 "여기서는 코덱스가 하는 일을 니가 해야 한다"고
  지시했다. 그래서 이 프로젝트의 `reviewers.claude` 명령을 닫기 리뷰에 걸어, 실행 맥락이 없는 새
  Claude 세션이 판정했다.

## Principles applied

User intent: 정본 자리와 실패한 판의 처리는 사용자가 정했다.
Honesty: 범위 넘음, 번호 변경, 같은 모델 계열의 판정을 카드와 결정에 숨기지 않고 적었다.
만든 쪽 ≠ 보는 쪽: 판정은 실행자와 맥락을 나누지 않는 별도 세션이 했다. 다만 같은 모델 계열이라
`operations/review.md` 의 교차 venue 원칙은 지켜지지 않았다.

## Context that helped

- 보관된 W-00000285 의 Progress 가 커밋되지 않는 로그만 가리킨다는 사실. 클라우드 체크아웃에서 그
  로그를 실제로 읽을 수 없었던 경험이 문제를 증명했다.
- 계약 문서가 이미 두 칸을 "비어 있지 않은 한 줄"로 요구하고 있었다. 검증기만 따라오면 됐다.

## Context that was missing

- 같은 시각에 다른 브랜치(`claude/codex-review-write`, `claude/stage-cloud-batch`)에서 번호를 쓰고
  있다는 사실을 등록할 때 몰랐다. 원격 브랜치를 보기 전에 번호를 골랐다.
- 커밋 본문 보고는 72열에서 줄을 바꾸므로 "한 줄" 칸이 여러 줄로 나뉜다. 로그로 옮길 때 그대로
  두면 이 카드의 기능이 첫 줄만 옮긴다. 이번에는 옮기면서 칸마다 한 줄로 이었다.

  자리에서 판정의 독립성을 어떻게 기록할지 정책으로 정할 후보다.
