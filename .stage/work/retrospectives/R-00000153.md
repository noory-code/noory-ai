# R-00000153 빈 목록 그릇을 갱신과 감사가 알아보게 한다

## Work

설명 문서를 새 판으로 바꾸는 명령이 프로젝트가 직접 쓴 내용을 표 안의 줄일 때만 알아봤다. 이제
빈 목록 표시자 하나도 같은 선언으로 읽는다. 프로젝트가 쓴 불릿과 그 아래 들여쓴 줄이 새 템플릿
안으로 그대로 들어가고, 그릇 밖은 템플릿이 덮는다. 감사도 같은 규칙으로 비교하므로 관측을 쌓은
인덱스가 더는 영원히 낡음으로 보고되지 않는다.

이 프로젝트에서 드라이버가 처음으로 카드 하나를 끝까지 끌고 갔다. codex 가 구현하고, 다른 모델
계열이 성공 기준 6개를 판정해 전부 통과했다.

## Decision points

- **리뷰가 남긴 막지 않는 지적 넷을 어디까지 받을지.** 셋을 받고 하나를 미뤘다. 미룬 것은
  "빈 목록 옆에 채워진 목록이 있으면 위치로 짝을 맞춘다"는 자리다.
- **표와 목록을 같은 규칙으로 맞출지.** 안 맞췄다. 빈 표 옆 채워진 표는 거절하는데 목록은 거절
  하지 않는다. 설명글은 불릿을 흔히 쓰므로, 같은 규칙을 쓰면 템플릿이 자기 그릇 위에 설명을
  못 적는다. 다르게 두는 것이 일부러 고른 판단이라고 문서와 시험에 남겼다.
- **시험을 전수로 돌릴지.** 돌렸다. 이 카드가 고친 파일 하나를 감사 명령도 쓰므로, 바뀐 파일의
  시험만 골랐다면 감사 쪽을 놓친다. 실측 80초다.

## Principles applied

- **MECE** — 분류 갈래가 표·목록·빈 그릇 없음·거절로 나뉘고 겹치지 않는다. 채워진 목록이 어느
  갈래에 남는지 시험이 못 박는다.
- **AHA** — 목록이 둘 이상인 템플릿은 아직 없다. 맞출 규칙을 지금 만들면 시험할 사례 없이
  추상을 세우는 것이라 미뤘다.
- **Fail Fast** — 그릇이 없는 프로젝트 파일이 명령 전체를 실패시키던 것을, 이유를 적어 건너뛰고
  사람이 경로를 집으면 열리게 바꿨다.
- **Honesty** — 성공 기준에 박아 둔 "관측 24줄"이 낡은 것을 리뷰가 잡았다. 숫자를 지우고 조건
  으로 바꿨다.

## Context that helped

- 설계 카드가 남긴 결정 기록. 적용 자리 표가 파일과 줄까지 세어 놨으므로 실행자가 무엇을 고칠지
  찾는 시간이 없었다.
- 성공 기준에 사람이 겪는 결과를 하나 넣어 둔 것. 리뷰어가 그 기준 때문에 임시 복사본에서
  override 를 걷고 실제로 돌려 봤고, 거기서 낡은 숫자가 드러났다.

## Context that was missing

- **드라이버가 도는 동안 사람이 문서를 못 쓴다.** 이 세션에서 사용자가 문서 규칙을 정하자고 했을
  때, 카드 범위 밖 파일을 건드리면 실행자 몫에 섞이므로 기다려야 했다(O-00000013). 우회는
  worktree 인데, 문서 한 줄 고치려고 worktree 를 만드는 것은 값이 안 맞는다.
- **드라이버가 도는 동안 진행이 안 보인다.** 출력이 끝날 때 한 번에 나오므로, 20분 동안 살아
  있는지 죽었는지 알 방법이 없었다.
