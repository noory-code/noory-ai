# DE-00000009 Adopt schema v4 PAST-ANCHORED topology and roadmap semantics

## Question

Should Stage keep the top-level past/present/future time directories, and how should the
roadmap hierarchy (Theme/Milestone/W) integrate with the time axis?

## Options

- Time-first status quo: keep all three wrappers; roadmap stays under `future/roadmap/` — no
  migration, but a `done` milestone living under `future/` contradicts the spatial semantics.
- Full space-first: dissolve all three wrappers including `past/` — purest MECE, but destroys
  the single past-containment authorization predicate and moves the heaviest content mass
  (146-file blast radius).
- PAST-ANCHORED (chosen): keep `past/` verbatim as the sole authorization zone; remove only
  `present/` and `future/` (wrappers with zero gate semantics); mutable side reorganizes by
  responsibility; lifecycle lives in vocabulary (planned/current/official) and gates.

## Principles applied

- SSOT: topology knowledge centralizes in a registry module; milestone status derives from
  decision chains only (no cached field); `terminal_disposition` is card-owned with derived
  index; DE identity is permanent through promotion (Contract X).
- MECE: root families are disjoint (official zone / mutable families / direction / rules /
  machine state); every artifact classifies to exactly one lifecycle state, audit-verified.
- Fail Fast: migration is fail-closed at every step (preflight refusals, marker-last, strict
  audit); closure revalidation denies on any basis drift.
- AHA: deferred defenses (bridge release, resume mode, lifecycle claims, sqlite index) wait
  for their declared triggers instead of shipping speculatively.

## Chosen direction

Ship schema v4 PAST-ANCHORED as specified in `stage/docs/SCHEMA_V4.md`, in one release
combining topology v4 with the roadmap semantics (Theme TH- / Milestone M- fixed in
`roadmap/`, W `milestone:` attribution, decision-gated lifecycle), implemented via the C1-C9
card plan.

## Reason

Only `past/` containment has operational force (authorization); `present/` and `future/`
encode information already derivable from family plus status, so removing them upholds MECE
without touching the security predicate. The owner's founding intent — the time triad is a
thinking frame that governs behavior, not storage — is preserved on explicit surfaces
(vocabulary, doctrine, gates). Agreed across two adversarial Claude-Codex debates (5 + 10
rounds, 2026-07-12) ending with no dissent.
