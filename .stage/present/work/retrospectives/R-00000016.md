# R-00000016 Unified work-card lifecycle design

## Work

Designed the board model the user asked for: backlog entries become planned `W-*` work cards and
one card moves `future -> present -> past`, recorded as DE-00000007 with migration and
compatibility rules fixed before implementation.

## Decision points

- One card family versus dual B/W bookkeeping versus a terminal-status patch — DE-00000007
  records why only the move model makes location stop lying about state.
- Kept the planned column's statuses a superset of the old backlog enum (adding `deferred`,
  `rejected`) so un-migrated projects stay audit-clean; folded back into the decision terms.
- Made starting work a script-performed move, not a hand edit, so the venue/split contract has
  one enforcement point.

## Principles applied

- SSOT (one card owns one piece of work), MECE (statuses partition by column), Fail Fast
  (status-outside-column is an error), AHA (directories are the columns; no board engine).

## Context that helped

- The user's kanban framing ("칸반 보드 이동하는 것처럼") and the just-shipped DE-00000005
  split/exception contract, which the mover reuses verbatim.

## Context that was missing

- No prior statement of what happens to realized backlog intents; the migration rule (remove
  when the archived work card carries the record) had to be decided here.

## What changes in later behavior

- Design items produce a decision record as their deliverable and hand implementation to a child
  card — exactly the split this pair dogfooded.

## Routing

- The contract lives in DE-00000007; nothing promotes to `past/`.
