# R-00000025 close/archive ordering guard

## Work

A shared worktree guard (stage/skills/stage-retrospective/worktree_guard.py) makes
close_work and archive_work refuse when uncommitted git changes exist inside the card's
scope, stating the order contract: commit source changes first, then close, then archive.
operations/after.md documents the contract. Executed by codex under the cross-venue
delegation contract; reviewed and committed by the claude host (b6248c0f, 0.25.0).

## Decision points

- Guard reuses stage_work scope matching instead of reimplementing it (SSOT).
- Once inside a git work tree, a git status failure is an error, not a silent pass
  (fail-closed); non-git projects skip the guard.
- .stage/-internal changes are exempt so board bookkeeping never blocks closure.

## Principles applied

- Fail Fast: the tool denies the wrong order instead of the human remembering it.
- SSOT: one guard module serves both call sites; one scope matcher.

## Context that helped

- The W-00000019 incident gave the exact failure sequence to encode as tests.

## Context that was missing

- The guard module lives in stage-retrospective/ and is imported by stage-archive/ — a
  cross-skill import; acceptable now, a shared hooks-level home is the cleaner refactor if a
  third consumer appears (AHA).
