# R-00000028 v4 migration as a user-facing skill

## Work

Amended SCHEMA_V4.md to specify the v3-to-v4 migration as a user-facing stage-migrate skill
and to add the no-stranding release-ordering invariant (no version enforces v4 without the
migration skill present). Recorded as DE-00000011.

## Decision points

- Migration surfaced as a skill, not a bare script (matches how users invoke every other
  lifecycle action).
- Release ordering: C3-C6 dormant/v3-compatible; C7 activates v4 and ships the migration
  together.

## Principles applied

- Fail Fast / Postel: v4-enforcing build fails closed on a v3 project with a banner naming the
  skill.
- SSOT: one migrate_stage.py, wrapped once.
- Honesty: a real user deliverable is exposed as a first-class skill.

## Context that helped

- Daewook flagged that real projects use Stage and that incremental main pushes could strand a
  v3 user — a gap the earlier single-release wording did not make explicit.

## Context that was missing

- The original design said "one release" but did not forbid intermediate v4-enforcing pushes;
  this amendment closes that ambiguity.

## Next changes

- C3 begins the v4 build (templates); C7 delivers the migration skill and activates v4.
