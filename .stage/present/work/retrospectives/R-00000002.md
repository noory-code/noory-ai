# R-00000002 Complete Claude Code and Codex plugin support

## Work

Added a Codex repo marketplace and Codex manifests for all six local plugins. Implemented a real
Codex backend for Evonest, replaced RAG's fictitious project environment variable with an explicit
workspace-cwd contract, made RAG and Pencil workflows host-portable, added dual-host installation
documentation, and added cross-host contract CI.

## Decision points

- Preserved the existing root-level package layout instead of moving packages under `plugins/`;
  marketplace source paths were verified with an isolated Codex home and all six plugins installed.
- Kept Evonest's `claude_runner` module as a compatibility surface while dispatching internally to
  `claude -p` or `codex exec`; this avoided a repository-wide rename with no user-visible benefit.
- Used an explicit `RAG_PROJECT_ROOT_FROM_CWD=1` opt-in for Codex instead of an unconditional cwd
  fallback, preventing accidental state creation in a plugin cache directory.
- Added shared host-contract documents for RAG and Pencil rather than duplicating tool-name mapping
  rules in every skill.
- Used temporary Codex cachebuster versions only for reinstall verification, then restored release
  manifests to clean SemVer values.

## Principles applied

- SSOT — Claude Code and Codex share package logic and skill host contracts; only host manifests and
  host discovery adapters differ.
- MECE — the marketplace and contract tests enumerate all six local plugins and require both host
  manifests for every entry.
- Fail Fast — CLI marketplace loading, plugin validation, RAG cwd resolution, and backend selection
  reject invalid premises instead of silently falling back.
- AHA — Evonest uses a small two-backend dispatch in the existing runner rather than introducing a
  larger provider framework before more backends repeat the pattern.
- Honesty and No partial completion — initial marketplace, Plainly, full lint, Evonest, and RAG
  failures were recorded and fixed; completion is based on rerun command output.
- Completion — user-visible support, internal tests/static checks, and this retrospective are all
  present before marking the work complete.

## Context that helped

The official Codex plugin, marketplace, skill-location, hook, and CLI contracts; live `codex plugin`
commands under isolated `CODEX_HOME`; and Stage's existing verified statement that Codex does not
provide `CODEX_PROJECT_DIR`.

## Context that was missing

Repository instructions and tests had drifted: `CLAUDE.md` omitted RAG's Codex manifest, the Codex
marketplace did not exist, Plainly pinned an obsolete version, RAG tests assumed a fabricated env
variable, and the FLG integration fixture still expected legacy `guide-lib-*` paths.

## Next changes

The new root plugin-contract workflow now owns manifest parity and marketplace coverage. Future
plugin work must update both manifests and preserve the isolated Codex marketplace smoke path.
