# R-00000009 Project-owned Plainly configuration

## Work

Moved persisted Plainly configuration from user/project `.noory/` scopes to one project-owned
`.plainly/settings.json`, made the CLI project-only, added this repository's portable custom style,
updated the public contract and plugin versions, and verified runtime behavior.

## Decision points

- Distinguished a cross-computer project policy from a user-home preference after the user clarified
  that repositories, not machines, should carry the style.
- Kept environment variables as temporary overrides while removing persisted global scope.
- Chose no automatic deletion or legacy fallback for existing home `.noory/` files: the new runtime
  ignores them, avoiding both destructive cleanup and two active SSOTs.

## Principles applied

- SSOT: `.plainly/settings.json` is the one persisted owner.
- KISS: one project scope replaces user/project precedence and `--scope` branching.
- Fail Fast: project style files remain confined to the project root.
- Honesty: legacy files are explicitly ignored, not claimed as migrated or deleted.
- Completion: runtime, CLI, documentation, manifests, tests, smoke behavior, and Stage audit were all
  verified.
- Portability: committed relative paths work across computers and operating systems.

## Context that helped

- The user's cross-computer workflow established that the policy must travel with the repository.
- Existing Plainly runtime and CLI tests exposed every persisted-scope branch that needed removal.
- The repository `.gitignore` confirmed `.plainly/` is available for version control.

## Context that was missing

The initial discussion did not distinguish the repository root from the user home or a personal
preference from a repository-owned policy. The explicit rejection of `.noory/` and global settings
resolved the boundary.

## Next changes

No follow-up is required for this outcome. A future breaking release may document manual cleanup of
unused home `.noory/plainly/` files, but the runtime must not delete them implicitly.

## Promotion decision

No Stage truth promotion is required. The durable product contract is owned by the Plainly runtime,
README, skill, tests, manifests, and changelog.
