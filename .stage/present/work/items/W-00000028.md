# W-00000028 Commit gate misparses quoted arguments in git commit commands

## Purpose

Observed twice on 2026-07-13 while operating this repository: the commit gate rejected legitimate commits by parsing tokens from the commit MESSAGE as file targets — (1) a redirection token 2 greater-than /dev/null inside a chained git add command surfaced as an unregistered target, and (2) a quoted phrase inside a -m body (double-quoted words) was split into bare words treated as governed paths. Root cause is in the hook's git-command argument parsing (stage_guard/stage_work commit gate). Fix the tokenizer to respect shell quoting and to stop treating message/flag arguments and redirections as file targets; add red-first tests reproducing both observed commands.
