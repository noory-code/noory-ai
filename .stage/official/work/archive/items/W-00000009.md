# W-00000009 Make Plainly configuration project-owned under .plainly

## Purpose

Make each repository carry its own Plainly response style so the same behavior follows the project
across computers without user-home synchronization or `.noory/` storage.

## Scope

- Resolve persisted settings only from `<project>/.plainly/settings.json`.
- Keep environment variables as temporary runtime overrides and the built-in profile as fallback.
- Remove user/project scope selection and saved user-global settings from the configuration CLI.
- Store this repository's custom decision-oriented style under `.plainly/`.
- Update runtime behavior, tests, skill instructions, documentation, changelog, and both manifests.
- Leave existing home-directory `.noory/` files untouched but unused.

## Success criteria

- Plainly reads no saved settings from `.noory/` or the user home.
- The CLI writes, shows, and resets only `<project>/.plainly/settings.json`.
- Relative custom-style paths stay confined to the project root.
- A cloned repository applies its committed `.plainly/` style on another computer.
- Environment overrides and the built-in fallback still work.
- The full Plainly test suite passes.

## Related truth

- DE-00000001 owns the settings location and scope decision.

## Progress

- Persisted settings now resolve only from `.plainly/settings.json`.
- The CLI is project-only and writes portable relative style paths.
- This repository carries `.plainly/style.md` as its decision-oriented response policy.
- README, configuration skill, changelog, and both plugin manifests reflect the new contract.
