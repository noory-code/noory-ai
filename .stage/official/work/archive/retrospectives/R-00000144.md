# R-00000144 플러그인이 자기가 만든 배치를 자기 게이트가 못 받고 있었다

## Work

보관된 카드를 다시 열 수 있게 했다. 보관 게이트가 작업 항목 ID 를 파일 이름에서 뽑던 것을, 기록이
든 폴더 이름에서 뽑도록 고쳤다. v4 의 납작한 경로도 그대로 통과한다.

## Decision points

**ID 가 어디에 있나.** v5 계층에서 카드의 정체는 파일 이름이 아니라 **폴더 이름**에 있다
(`W-00000130/_story.md`). 액션만 예외로 스토리 폴더 안의 낱개 파일이라 이름에 ID 가 남는다.
실행자가 실제 보관 트리를 읽고 네 모양을 모두 받는 코드를 썼다.

**감독자가 배치를 잘못 알고 있었다.** 카드를 쓸 때 액션이 `<epic>/<story>/<action>/_story.md`
네 마디일 것으로 적었는데, 실제로는 `<epic>/<story>/<action>.md` 세 마디였다. 실행자의 코드가
맞았고 카드가 틀렸다. **Honesty** — 병합 전에 실제 트리를 세어 확인했고, 그 결과 지적하려던 것이
내 오해였다.

## Principles applied

- **Fail Fast** — 게이트가 열리지 않도록 "다른 카드는 여전히 막힌다"를 시험으로 고정했다. 완화가
  게이트 자체를 열어 버리는 것이 이 종류 수정의 가장 흔한 실패다.
- **Honesty** — 카드에 적은 배치가 틀렸다는 것을 회고에 남긴다. 코드가 카드를 이겼다.

## Context that helped

- 실측 보고가 막힌 명령과 오류 문구를 그대로 담았다. 그 문구로 `stage_work.py` 의 한 줄을 바로
  찾았다.
- 이 저장소의 보관 트리 자체. 액션이 어떤 모양으로 앉는지 `find` 한 번으로 확인했다.

## Context that was missing

- **카드에 배치를 적을 때 실제 트리를 안 봤다.** 기억으로 적었고 틀렸다. 실행자가 안 따라 적어서
  다행이었지, 카드가 지시로 읽혔으면 없는 모양을 받는 코드가 됐을 것이다.
- 보관 뒤에 카드를 고칠 일이 있다는 것을 아무도 예상 안 했다. 그래서 v5 계층 보관(W-00000111)을
  만들 때 게이트를 같이 세지 않았다. **적용 자리를 셀 때 "이 배치를 읽는 쪽"에 게이트가 포함된다.**

## Next changes

- 카드 본문에 파일 배치를 적을 때는 실제 트리를 한 번 세고 적는다. 기억으로 적은 경로는 실행자에게
  지시로 읽힌다.
- 감사 오류 WORK015(결정 하나를 카드 여럿이 참조)는 W-00000145 가 받는다. 이 카드는 그것을 고칠
  **수단**만 열었다.
