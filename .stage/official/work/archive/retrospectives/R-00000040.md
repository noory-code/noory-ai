# R-00000040 Plainly 전달 원칙 강화 회고

## Work

Plainly의 4개 스타일 프로필을 공통 baseline + 얇은 델타 구조로 재편하고, baseline에 정직성
원칙(추측을 사실로 말하지 않기, 미확인 표시, 사실/권고 구분)을 추가했으며, plainly-configure에
예시 기반 온보딩 인터뷰(3축 A/B 질문 → 프리셋 매핑, 다축 조합 시에만 `.plainly/`에 검증된
맞춤 스타일 파일 생성)를 추가했다. plainly 0.3.0. 테스트 37개 통과.

## Decision points

- 사고 원칙 주입은 plainly에서 제외 — SoC/SSOT/자기 보안 계약 위반. 전달 원칙만 보강.
- 4개 프로필 통합 형태: 완전 단일화가 아니라 baseline + 3델타. `plain`=baseline 흡수,
  `brief`=길이 눈금, `guided`/`professional`만 독립 축.
- 인터뷰 조합 해소: A(프리셋 매핑) + 안전판(조합 충돌 시에만 맞춤 파일). 완전 composable 회피.
- venue: development → codex 정책대로 Codex 브리지 위임, Claude 교차 검토.

## Principles applied

- SoC — 전달 원칙(plainly)과 사고 원칙(Stage/CLAUDE.md)의 책임 경계 유지.
- SSOT — 공통 원칙을 baseline 한 곳이 소유, 델타에 중복 없음.
- DRY — plain/brief 중복(길이 한 축) 제거.
- KISS — 완전 composable 대신 프리셋 + 예외 안전판.
- Honesty — 교차 검토를 보고 신뢰가 아니라 diff·테스트 재실행으로 검증.

## Context that helped

- README의 resolution order가 "단일 프로필만 주입"임을 명시 → baseline 부재가 구멍의 원인임을
  빠르게 특정.
- 등록 게이트가 위임 명령의 산문 단어를 경로로 오탐 → 지시를 파일로 옮겨 우회(재현 시 참고).

  Stage 게이트 오탐을 유발함. 향후 위임은 상세 지시를 파일로 전달하는 패턴을 기본으로.
