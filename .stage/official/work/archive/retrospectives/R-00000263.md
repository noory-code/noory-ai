# R-00000263 플레인리 스타일을 클로드 코드 output style 로 내보낸다

## Work

플레인리를 훅에서 Claude Code 의 output style 로 옮겼다(DE-00000073). 한국어 지침을 여러 번
다시 썼다. 처음에는 명사로 묶인 표현을 풀라는 원칙 한 줄이었고, 10월에는 실제 응답 수백 개를
비교해 뜻 보존 검사를 더했다. 11월 16일에는 사용자가 긴 작업 세션에서 고쳐 준 문장들로 "한국어는
동사를 중심으로 문장을 짓는다"는 문단과 실제 보고에서 자주 나오는 모양 네 가지를 예문과 함께
넣었다. 0.7.3 까지 냈고, 사용자가 이 정도면 충분하다고 판정했다.

## Decision points

- **훅이 아니라 output style 로 냈다(DE-00000073).** 훅은 지침을 매번 붙여 넣는 방식이라 시스템
  프롬프트에 들어가지 않았다. output style 은 시스템 프롬프트에 들어간다.
- **판정은 사람에게 맡겼다.** 문구가 들어 있는지 검사하는 테스트는 지침이 빠지지 않았다는 것만
  보여 준다. 한국어가 자연스러운지는 사람이 판정했다.
- **실제로 쓴 문장에서 예문을 골랐다.** 교과서식 번역투("~에 대한", "~을 통해")는 실제 답변에
  거의 없었다. 실제로 많이 나온 모양을 세어서 그것을 예문으로 넣었다.

## Principles applied

- Honesty — 효과를 숫자로 말할 수 있는 만큼만 말했다. 긴 작업 세션에서 효과가 있는지는 다시
  만들지 못했다고 적었다.
- Completion — 지침을 고치고 끝내지 않고 새 세션의 응답으로 비교했다.
- SSOT — 지침은 스타일 파일 한 곳에만 있다.

## Context that helped

- 사용자가 고쳐 준 문장들. 원칙을 설명하는 것보다 고친 예 하나가 더 잘 통했다.
- 실제 답변 기록을 세어 본 것. 예문까지 적힌 규칙은 지켜지고 원칙만 적힌 규칙은 지켜지지 않는다는
  것을 숫자로 봤다.

## Context that was missing

- 긴 작업 세션에서 왜 지침이 덜 통하는지. 영어로 된 코드와 명령 결과를 오래 읽은 뒤에 영어 명사를
  그대로 옮기는 것 같지만 확인하지 않았다.
- 처음 몇 차례는 "한자어를 줄인다"처럼 문제를 낱말로 잡았다. 사용자가 "한자어가 아니라 명사 중심
  문장이 문제"라고 바로잡아 줬다.
