# R-00000366 도면의 위 두 층을 쓰고 도면 자리를 한 곳으로 정한다

## Work

`stage/docs/BLUEPRINT.md` 맨 위에 목표, 레이어 일곱 개의 표, 코드가 말해 주지 않는 것을 썼다. 기존 그림은
기록 레이어의 그림으로 한 단계 내려 두었다. 도면 자리를 이 문서로 정하고(DE-00000090), `stage/README.md`,
`stage/CLAUDE.md`, `stage/AGENTS.md`, `.stage/official/model/overview.md` 가 이 문서를 가리키게 했다.

## Decision points

- **도면 자리를 `stage/docs/BLUEPRINT.md` 로 정했다.** `.stage/official/model/` 은 고칠 때마다 승격 의도가 필요해서
  도면이 코드보다 늦게 고쳐진다. 코드를 고칠 때 읽히는 문서는 `stage/CLAUDE.md` 가 가리키는 `stage/docs/` 다.
- **레이어 그림을 가져다 쓰는 방향 전부가 아니라 굵은 흐름으로 그렸다.** 처음에는 한 방향 그림을 그리고 "다른
  방향은 두 군데"라고 썼다. 레이어마다 모듈을 배정하고 스크립트로 세어 보니 그림과 다른 방향이 여덟 군데였다.
  그림을 줄이고 여덟 군데를 표로 적었다.
- **이유를 모르는 것은 이유를 적지 않았다.** 카드가 물은 두 가지의 이유는 커밋 기록과 구현 감사 문서에서
  찾았다. 나머지 여섯 군데는 사실만 적었다. 공용 모듈을 옮길지, 세 도구를 공용으로 뺄지를 정한 결정 기록은
  없다고 적었다.
- **쓰려던 규칙 두 줄을 뺐다.** "새 공용 규칙은 어디에 둔다", "새 의존을 더하지 않는다"는 정해진 적이 없는
  규칙이다. 지금 상태만 적었다.

## Principles applied

- SSOT: 목표는 `PHILOSOPHY.md` 가 갖고 도면은 링크만 둔다. 아래 두 층도 링크만 둔다.
- Honesty: 가져다 쓰는 방향을 세어 보고 초안의 틀린 문장을 지웠다. 확인하지 못한 결과("가져오다 실패한다",
  "쓰기가 막힌다")는 적지 않았다.
- MECE: 스크립트를 레이어에 배정하면서 빠진 파일 일곱 개를 찾아 표에 넣거나 레이어 밖이라고 적었다.

## Context that helped

- 커밋 메시지의 본문. `close_work.py` 가 드라이버 모듈을 가져다 쓰게 된 세 커밋이 각각 이유를 적어 두었다.
- 모듈의 첫 줄 설명. 드라이버 모듈은 모두 한 줄로 맡은 일을 적어 두어서 레이어에 배정하기 쉬웠다.

## Context that was missing

- `hooks/` 의 모듈 열네 개 가운데 여섯 개(`stage_context`, `stage_git`, `stage_paths`, `stage_runtime`,
  `stage_shell`, `stage_work`)에 첫 줄 설명이 없다. 어느 레이어인지는 이름과 가져다 쓰는 관계로 판단했다.
- 카드는 스크립트 46개 가운데 33개가 공용 모듈을 가져다 쓴다고 적었다. 다시 세면 `scripts/` 40개 가운데
  28개, 스킬 폴더 6개 가운데 5개다. 합은 같다. 도면에는 숫자를 적지 않았다.

## Next changes

- 레이어 표의 파일 목록은 파일을 더하거나 옮기면 낡는다. 낡았는지 잡는 검사는 없다.
- 그림과 다른 방향 여덟 군데를 줄일지는 정하지 않았다.

## Rule candidate

- 구조를 설명하는 문장을 쓰기 전에 그 구조를 코드에서 세어 본다. (1회차. 이번에는 "두 군데"라고 쓴 뒤에 세어서
  여덟 군데를 찾았다.)

## Promotion decision

`.stage/official/model/overview.md` 에 Stage 의 도면으로 가는 링크를 올렸다. DE-00000090 은 결정된 채로 대기
자리에 둔다.
