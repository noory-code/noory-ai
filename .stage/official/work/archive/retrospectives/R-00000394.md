# R-00000394 한국어 Windows 에서 close_work 시험과 검사 출력이 깨지지 않게 한다

## Decision points

- **첫 시도는 스트림이 UTF-8 로 깔끔하지 않으면 통째로 OEM 코드 페이지로 읽었다.** PR #104 의 Windows CI 가 W-00000352 의
  계약("UTF-8 출력에 엉뚱한 바이트 하나가 섞여도 한국어는 남는다")을 지키는 시험에서 실패했다.
- **두 번째 시도는 비율로 가른다.** 비ASCII 바이트의 절반 이상이 UTF-8 로 읽히지 않을 때만 OEM 코드 페이지로 읽는다. 섞인
  바이트 하나는 10% 안팎이고 cp949 로 쓴 메시지는 거의 100% 라서 둘이 한 자릿수 이상 벌어진다.
- **검사 명령 `true` 를 기존 시험 도우미 `python_command("pass")` 로 바꿨다.** 새 상수를 만들지 않았다.

## Context that was missing

- `stage_process` 의 디코딩을 바꾸기 전에 W-00000352 의 시험(`test_subprocess_text_encoding.py`)을 찾아보지 않았다. 리눅스에서는
  폴백이 쓰이지 않아 그 시험이 통과했고, Windows CI 에서야 드러났다.

## Rule candidate

- **출력 디코딩을 바꾸기 전에 `test_subprocess_text_encoding.py` 가 지키는 계약을 읽는다.** 인코딩 실수는 R-00000354,
  R-00000356, R-00000393 에 이어 이번이 네 번째다. 이번 것은 리눅스에서 보이지 않는 갈래(Windows 폴백)였다.
