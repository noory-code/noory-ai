# R-00000218 워크트리에서 실행자 환경이 깨지는 원인을 잰다 (물림)

## Work

측정은 이뤄졌고 결론이 카드를 뒤집었다. 실행자의 정적 대조(허용 목록·설정 파일 유무)는
정확했지만 동적 실험은 코덱스 샌드박스 안에서 `claude -p` 가 시작을 못 해 빈 결과였다 —
판정자가 그것을 "체크아웃이 아니라 샌드박스를 쟀다"로 정확히 읽고 반려했다. 감독 세션이
샌드박스 밖에서 같은 탐침을 본 체크아웃과 워크트리에 돌려 **둘 다 똑같이 막히는 것**을
확인했다. 카드가 찾으라던 차이는 없다.

## Decision points

- **판정 반려 수용.** 지목된 원인(acceptEdits + 허용 목록 없음)은 두 환경에 똑같이 적용돼
  비대칭을 설명할 수 없었다.
- **감독이 계측기가 됐다.** 코덱스 샌드박스 안에서는 클로드 탐침이 구조적으로 불가능하다.
  실행 venue 가 측정 대상과 겹치는 카드는 처음부터 감독 몫으로 남겨야 했다.

## Principles applied

- **Honesty** — 실행자가 빈 결과를 성과로 포장하지 않고 verification 을 안 올렸고, 판정자가
  "추론을 확인된 사실로 올리지 말라"를 짚었고, 감독이 전제 자체를 탐침으로 검증했다.

## Context that helped

- 판정자의 반려 소견이 다음 측정의 조건(샌드박스 밖)을 정확히 지정해, 감독 탐침이 한 번에
  결론을 냈다.

## Context that was missing

- **카드의 전제("본 체크아웃에서는 된다")가 검증된 적 없는 문장이었다.** 감독 세션이 카드를
  쓸 때 어느 실측도 그것을 말한 적이 없는데 Source 에 사실처럼 적었다. 낡은 관측을 그대로
  믿은 지난 실수와 같은 모양의, 검증 안 된 전제 진술이다.

## Next changes

- 카드 Source 에 적는 문장마다 "이걸 어느 실측이 말했나"를 확인한다. 실측이 없으면 가설로
  표시한다.
