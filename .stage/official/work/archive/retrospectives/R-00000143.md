# R-00000143 쌓이는 자리가 자동 갱신을 되찾는 길을 정한다

## Work

DE-00000042 가 후속으로 남긴 길("쌓이는 자리를 템플릿이 빈 표로 배포한다")을 설계했다. 결과는
그 문구를 고치는 것이었다. DE-00000047 이 정한 방향: 템플릿을 바꾸는 대신 **코드가 알아보는
그릇을 표에서 목록까지 넓힌다.** 관측 인덱스 템플릿이 빈 불릿 하나를 이미 배포하고 있었으므로
템플릿 변경은 0이고 마이그레이션도 없다.

곁따라 관측 하나(O-00000014)와 구현 카드 하나(W-00000153)를 세웠다.

## Decision points

- **템플릿 모양을 바꿀지, 코드가 읽는 그릇을 넓힐지.** 실측이 갈랐다. 빈 표 템플릿에 표 없는
  프로젝트 파일이 오면 판정이 `refused` 이고, **경로를 집어도 열리지 않으며** 거절 하나가 명령
  전체를 실패로 끝낸다. DE-00000042 는 이 길의 값을 "마이그레이션이 딸려 온다"로 봤지만, 실제
  값은 "마이그레이션이 없으면 파일이 잠긴다"였다.
- **채워진 목록도 갈래로 세울지.** 세우지 않기로 했다. 세우면 깨끗한 프로젝트의 불변 조건 문서가
  자동 갱신을 조용히 잃는다. 빈 그릇만 선언이라는 선을 DE-00000029 원문과 같은 자리에 두었다.
- **모양이 안 맞을 때의 판정.** `refused` 에서 `skipped` 로 바꾸기로 했다. 사람이 여는 문이 없는
  실패는 Fail Fast 가 말하는 안전한 방향이 아니다.
- **`official/model/` 셋과 불변 조건 문서.** 이 결정에서 손대지 않고 열린 물음으로 남겼다. 그릇의
  모양(표냐 목록이냐, 표라면 열이 무엇이냐)을 정할 근거가 이 저장소 안에 없다.

## Principles applied

- **AHA** — 새 선언 축을 만들기 전에 이미 배포된 정보로 되는지 봤다. 빈 불릿이 이미 있었다.
- **SSOT** — 빈 그릇을 배포했다는 사실이 프로젝트 몫의 경계를 소유한다. 경로 목록은 두 번째
  소유자가 되므로 물리쳤다.
- **MECE** — 그릇을 표와 목록으로 나누고, 채워진 그릇은 선언이 아니라고 못 박아 겹침을 없앴다.
- **Fail Fast** — 출구 없는 거절을 출구 있는 건너뛰기로 바꿨다.
- **Honesty** — 프로젝트 하나에서만 실측했다고 결정 본문에 적었다. novel-workspace 는 이
  체크아웃에 없다.

## Context that helped

- DE-00000042 의 `## Where this applies` 표. 후속의 범위를 이미 좁혀 놓아서 무엇을 세야 하는지
  바로 알았다.
- "설계를 쓰기 전에 그 설계가 건드릴 현재 값을 읽는다"는 규칙. 이번에는 다섯 문서의 실제 모양과
  판정 결과를 먼저 재서, DE-00000042 가 남긴 문구가 틀렸다는 것을 설계 전에 알았다.
- 판정 함수가 순수 함수라 임시 스크립트로 실측이 쉬웠다. 결정의 근거가 추론이 아니라 측정값이다.

## Context that was missing

- **두 번째 프로젝트가 없다.** novel-workspace 가 이 체크아웃에 없어서, 그릇 밖에 프로젝트가
  산문을 쓴 경우를 실측할 수 없었다. 이 저장소에서는 그런 줄이 0이다.
- **`guidance_overrides` 가 실측을 가린다.** 이 저장소의 관측 인덱스가 override 목록에 있어서
  기본 실행이 판정에 닿지 않는다. 이 저장소에서 `refresh_guidance.py --dry-run` 을 돌린 결과는
  이 설계의 근거가 못 된다. 임시 스크립트로 판정 함수를 직접 불러 우회했다.

## Next changes

- **템플릿 뿌리가 두 세대다.** `templates/project-stage` 는 v3 세대이고 살아 있는 것은
  `templates/v4/` 다. 처음 훑을 때 v3 사본을 읽고 한 번 틀렸다. 템플릿을 읽을 일이 있으면
  `init_stage.py` 의 `TEMPLATE_ROOT` 를 먼저 확인한다.
- **"쓰이지 않는다"를 경로 문자열 grep 으로 단정하지 않는다.** `templates/project-stage` 를
  grep 해서 파이썬 참조가 없다고 봤지만, 실제로는 `PLUGIN_ROOT / "templates" / "project-stage"`
  로 조립돼 두 스크립트가 쓰고 있었다. 조립된 경로는 조각으로 찾아야 한다.
- **`.stage` 를 건드리는 임시 검증은 스크립트 파일로 쓴다.** 훅이 인라인 인터프리터 코드를
  거부한다. 스크래치패드에 named script 를 쓰는 것이 정해진 길이다.
