# R-00000377 목록 파일을 union 으로 합치고 줄을 지우는 목록은 카드에서 만든다

## Work

DE-00000091 을 구현했다. 저장소 루트 `.gitattributes` 가 모든 `CHANGELOG.md` 와
`.stage/official/**/archive/index.md` 에 `merge=union` 을 건다. `work/active.md`, `work/review.md`,
`work/planned/index.md` 를 없앴다. 등록, 시작, 막힘, 닫기, 보관이 더는 이 파일들을 쓰지 않고, 세션 시작 글의
Active work 와 Review candidates, `archive_work.py --all-completed` 는 카드의 `status` 를 읽는다. 감사의
INDEX000~INDEX006, BACKLOG008/BACKLOG009 를 없애고, 남은 옛 파일을 알리는 INDEX007 경고를 넣었다.
`init_stage.py` 는 다른 프로젝트에 보관 목록용 union 줄을 넣는다. PR #89.

로컬 브랜치 두 개가 각자 카드를 등록, 닫기, 보관하고 합쳤을 때 충돌이 없었다. GitHub 머지 버튼은
`merge=union` 을 따르지 않았다(메인 세션이 PR #90, #91 로 확인).

## Decision points

- **세 목록을 git-ignore 한 생성 파일로 두지 않고 아예 없앴다.** ignore 한 파일은 GitHub 에서 보는 사람에게도
  다른 세션에게도 안 보인다. 읽던 자리는 모두 카드에서 같은 목록을 만들 수 있었다.
- **남은 옛 파일은 오류가 아니라 경고(INDEX007)로 알린다.** 남은 파일이 도구를 틀리게 만들지는 않고 읽는
  사람만 오도한다. 오류로 두면 새 버전을 받은 다른 프로젝트의 감사가 바로 실패한다.
- **이관 스크립트는 고치지 않았다.** 이관은 저널과 되돌리기가 있는 거래라서 파일 지우기를 끼워 넣는 위험이
  얻는 것보다 컸다. 이관한 프로젝트도 INDEX007 로 같은 안내를 받는다.
- **INDEX000~006 은 v3 구조에서도 없앴다.** 설정 파일이 없는 v3 프로젝트는 아직 쓰기 명령을 실행할 수 있는데,
  쓰기를 멈췄으니 남겨 두면 등록 직후 감사가 실패한다.
- **v3 의 완료 관문 대체 검사는 남겼다.** 카드 없이 목록 줄만 있던 아주 옛 구조를 위한 것이고 쓰기와 무관하다.
- **`--owner` 를 없앴다.** 목록의 Owner 칸만 채우던 값이라 남기면 아무 일도 하지 않는 옵션이 된다.
- **main(W-00000378)을 합칠 때 CHANGELOG 는 union 으로 저절로 합쳐졌다.** 직접 푼 충돌은 `register_work.py`
  한 곳과 `planned/index.md` 의 수정/삭제 하나였다.

## Principles applied

- SSOT: 카드의 `status` 가 상태를 가진다. 같은 사실을 목록의 줄로 한 번 더 적지 않는다.
- Fail Fast: 줄을 지우는 목록에는 union 을 걸지 않았다. 조용히 되살아난 줄보다 충돌이 낫다.
- Honesty: GitHub 머지 버튼의 결과("같지 않다")와 지우지 못한 임시 브랜치를 카드, PR, 운영 문서에 적었다.

## Context that helped

- DE-00000091 의 "Where this applies" 표. 고칠 자리가 파일 단위로 적혀 있었다.
- 과거 머지 27건을 다시 실행한 결과(지우는 목록에서 18번 중 13번 되살아남). 목록을 없앨지 union 을 걸지 다시
  따질 필요가 없었다.
- `.git/info/attributes` 로 `merge=text` 를 걸어 같은 병합을 대조군으로 돌릴 수 있었다.

## Context that was missing

- GitHub 머지 버튼이 `.gitattributes` 의 merge 드라이버를 따르는지. 결정 때 알았다면 "PR 브랜치에 main 을
  git 으로 합친다" 는 절차를 결정에 함께 넣었을 것이다.
- 이 세션은 PR 을 만들거나 원격 브랜치를 지울 수 없다는 것. 임시 브랜치를 올리기 전에 알았다면 메인 세션에
  처음부터 맡겼을 것이다. 지우지 못한 브랜치 세 개가 남았다.
- 스크립트 테스트 55개가 세 파일을 고정해 두고 있었다. 결정 표에 적힌 "25개 파일, 103줄" 이 맞았고, 고치는 데
  작업 시간의 절반이 들었다.
