# R-00000087 무인 모드에서 차단된 리뷰 판정 출력을 보존한다

## Work

무인 드라이버에서 닫기가 검증 실패나 리뷰 차단으로 실패할 때, 그동안 버려지던 `close_work`
출력을 통과 경로와 같은 상한(`clip` 재사용)으로 잘라 에스컬레이션 기록에 남기게 했다. 재시도
뒤에는 마지막 출력만 남는다. 낡아 있던 무인 모드 상태 문단(`stage-drive`)도 현재 사실로
바로잡았다 — 알려진 코드 결함은 닫혔고, 실전 미검증 경고는 유지.

이 카드는 W-00000082 이후 드라이버가 카드 하나를 직접 받아 돌린 **첫 실전 가동**으로
수행됐다. 실행·검증은 자동으로 통과했고, 리뷰 단계는 실제로 리뷰하지 못한 채 통과 처리돼
(아래) 반대 venue 리뷰를 Claude 가 손으로 다시 했다.

## Decision points

- 상한을 새로 정하지 않고 `close_work.clip` 을 그대로 가져다 썼다 — 증거 크기의 소유자를
  한 곳으로 유지(SSOT).
- 드라이버의 통과 판정을 그대로 믿지 않고 리뷰 출력 원문을 읽었다 — 그 덕에 "통과" 속의
  리뷰 실패를 발견했다. 판정 요약이 아니라 증거 원문을 읽는 습관이 이번에도 값을 했다.
- 실전에서 드러난 구멍 둘은 이 카드의 범위를 넓혀 고치지 않고 카드로 갈랐다(W-00000089,
  W-00000090) — 조용한 범위 확장 금지.

## Principles applied

- **Fail Fast** — 막힌 쪽일수록 근거가 남아야 한다는 것이 이 카드의 본질. 리뷰어 래퍼의
  fail-open 발견도 같은 원칙의 위반 사례다.
- **SSOT** — 증거 상한의 소유자는 `close_work.clip` 하나.
- **Honesty** — RED 를 저장소 밖 사본에서 직접 재현했고, 드라이버의 통과 판정을 원문으로
  재검증했다.

## Context that helped

- 오늘 만든 것들이 실전 한 번에 전부 걸렸다: 단일 카드 대상(W-82), 실행자 임시 인덱스(W-81),
  무변경 실패 판정(W-83)은 정상 동작했고, 리뷰 계약(W-85)은 프롬프트까지는 갔으나 리뷰어
  CLI 가 입력 초과로 죽으면서 래퍼의 fail-open 이 드러났다.

## Context that was missing

- 드라이버를 Claude 세션 안에서 돌리면 세션 식별 환경 변수가 자식(리뷰어 `claude -p`)에게
  내려가 세션 대화 전체가 입력으로 딸려 간다는 것을 아무 문서도 경고하지 않았다. 원인 변수
  확인과 수정은 W-00000090.
