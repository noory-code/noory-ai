# R-00000307 시도 횟수를 되돌릴 때 지난 판정과 되돌린 변경 경로를 지운다

## Work

W-00000307. `drive.py --reset-attempts` 가 지난 판정 파일과 기준 지문을 지워 다음 판이 전체 리뷰로 돈다. 쌓인
실행자 변경 경로에서는 사람이 되돌린 경로만 빼고 기준 커밋과 아직 다른 경로는 남긴다. 상태 기록이 실패하면 지운
파일과 실행 상태를 되살린다. O-00000047 을 닫았다.
외부 결과: 카드를 다시 설계하고 되돌린 뒤의 다음 판이 버린 설계의 판정이나 되돌린 경로 때문에 시도를 태우지 않는다.
내부 결과: scripts 전체 719개, hooks 393개가 통과한다. 새 시험은 고치기 전 코드에서 실패하고, 복원 줄을 빼는 변이도
잡는다.

## Decision points

- 카드는 "변경 경로를 지운다" 였지만 다 지우지 않았다. 드라이버는 이전 판 결과를 작업 트리에 남기고 항목 커밋이
  `base_head` 이후를 합치므로, 다 지우면 남긴 결과가 커밋에는 들어가고 리뷰에서는 빠진다. 실행 전에 카드를 고쳐
  따로 커밋했다.
- 판정 파일을 상태 기록 뒤가 아니라 앞에서 지우고, 실패하면 되살린다. 뒤에서 지우다 실패하면 시도 횟수가 이미 0 이라
  되돌리기를 다시 돌릴 수 없다.
- Git 이 경로를 비교하지 못하면 되돌리기를 거절한다.

## Principles applied

Honesty: 커밋에 들어가는 결과는 리뷰가 본다. 관찰 기록의 처방을 그대로 따르지 않고 반대 방향의 위험을 먼저 확인했다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- 기존 시험이 `executor_changed_paths` 를 남기는 쪽을 단언하고 있었다. 그게 "왜?" 를 묻게 했고, `commit_item` 의
  squash 와 `restore_item_output` 의 mixed reset 을 읽게 했다.

## Context that was missing

- O-00000047 은 경로 목록을 "비운다" 고만 적었고, 작업 트리에 남은 결과가 어떻게 되는지는 적지 않았다. 처방이
  들어간 관찰은 그 처방이 건드리는 다른 흐름까지 적어야 한다.
- 기존 되돌림 시험들은 `base_head` 에 가짜 값을 넣었다. Git 을 실제로 보는 순간 깨졌다.

## Next changes

  밟으면 관찰로 남긴다.
