# R-00000379 Stage CI 의 테스트를 여러 잡으로 나눠 PR 결과가 빨리 나온다

## Work

Stage 워크플로가 두 테스트 묶음을 OS 와 Python 조합마다 세 잡으로 나눠 돌린다. 테스트를 id 순으로 세운 뒤
돌아가며 나눠 주는 `.github/scripts/unittest_shard.py` 를 더했다. PR #87 에서 워크플로 전체가 10분 39초에서
4분 5초로 줄었다.

## Decision points

- **모듈이 아니라 테스트 하나하나를 돌아가며 나눴다.** 무거운 모듈 셋(`test_drive`, `test_close_work`,
  `test_drive_unattended`)이 로컬 시간의 절반이다. 모듈로 나누면 한 잡에 몰린다.
- **Windows 만이 아니라 모든 OS 를 세 잡으로 나눴다.** 사용자가 Ubuntu 도 줄이자고 했다. 전체 시간은 가장
  느린 잡이 정하므로 Ubuntu 를 나눠도 전체 시간은 줄지 않는다고 사용자에게 먼저 말했다.
- **나누는 도구를 `stage/` 가 아니라 `.github/scripts/` 에 두었다.** 저장소의 CI 도구이고 플러그인으로
  배포할 것이 아니다.
- **카드 범위 밖의 `stage/scripts/tests/test_ci_workflows.py` 와 `stage/CHANGELOG.md` 를 고쳤다.** 잡 수와
  `SHARD_TOTAL` 이 어긋나면 한 샤드의 테스트가 실패 없이 사라진다. 그것을 막는 시험을 워크플로 시험 옆에 뒀다.

## Principles applied

- Fail Fast: 샤드 번호가 빠지면 테스트가 조용히 사라지는 대신 시험이 실패한다. 일부러 `[1, 2]` 로 바꿔
  실패하는 것을 확인했다.
- Honesty: 사용자가 "변경한 플러그인만 돌리면 되지 않느냐"고 했을 때 이미 그렇게 돌고 있다고 말했다.
- MECE: 샤드들이 실행한 테스트 수의 합을 CI 로그에서 셌다(455, 806).

## Context that helped

- 잡마다 단계별 시간을 본 것. 10분 가운데 536초가 Windows 의 Scripts suite 한 단계였다.
- 지난 PR 의 `test_ci_workflows.py`. 워크플로를 지키는 시험을 둘 자리가 이미 있었다.

## Context that was missing

- 닫기 리뷰가 HEAD 커밋의 경로만 받는다(O-00000058). 코드 커밋이 둘이라 합친 커밋을 로컬에서 만들어 닫았다.
