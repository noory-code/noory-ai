# R-00000295 claude 리뷰어에게 판정 파일 쓰기와 시험 실행만 허락한다

## Work

W-00000295. 프로젝트의 `reviewers.claude` 명령과 대역 리뷰어가 판정 파일 하나에만 쓰기, 변경 경로 폴더 읽기,
`python3 -m unittest` 실행만 허락받는다. 프로젝트 파일 편집 권한(`acceptEdits`)은 없앴다.
외부 결과: claude 리뷰어가 사용자 권한 설정 없이도 판정 파일을 쓰고 시험을 돌리며, 판정하는 작업을 고칠 수
없다.
내부 결과: 인수 시험과 scripts 전체 704개, hooks 378개가 통과한다. 실제 리뷰 명령을 가짜 `claude` 로 셸에서
돌리는 시험이 고치기 전 설정으로는 실패한다. 이 카드는 좁힌 권한의 대역 리뷰어로 닫았다.

## Decision points

- 폴더가 아니라 파일 하나: 드라이버의 좁은 재리뷰는 판정 파일을 임시 폴더에 둔다.
- 절대 경로 규칙은 앞에 `//`, 여러 값을 받는 옵션 뒤에는 `--` 를 둔다.
- 셸은 `python3 -m unittest` 만 허락한다. 리뷰어가 시험을 직접 확인할 수 있게 하되 일반 셸은 주지 않는다.
- 세 가지 모두 이 세션에서 `claude -p` 로 먼저 실험해 확인했다.

## Principles applied

만든 쪽 ≠ 보는 쪽: 판정하는 쪽이 판정 대상을 고칠 수 없어야 판정이 독립적이다.
Fail Fast: 권한 규칙의 동작을 문서가 아니라 실험으로 먼저 확인했다.
만든 쪽 ≠ 보는 쪽(판정): 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은
아니다.

## Context that helped

- W-00000287 닫기에서 권한 없는 리뷰어가 판정 파일을 못 쓴 기록, `--add-dir` 이 프롬프트를 삼킨 기록.

## Context that was missing

- 실험에서는 `Write` 와 `Edit` 를 함께 줘서 어느 규칙이 쓰기를 허락하는지 가르지 못했다.
- 드라이버의 좁은 재리뷰에서 판정 파일이 임시 폴더에 있다는 것을 처음에는 몰랐다. 드라이버 코드를 읽고 알았다.

## Next changes

- 리뷰어들이 "시험을 돌리지 못했다"고 적던 일이 이번 닫기부터 줄어드는지 본다.
- 이 카드의 닫기에서 리뷰어가 인수 시험 둘을 직접 돌렸다(7개, 24개 통과). 처음으로 리뷰어가 시험을 확인했다.
- 닫기 로그 맨 위에 Claude Code 경고가 나왔다: 파일 권한 검사는 `Edit(path)` 규칙만 맞추고 `Write(path)`
  규칙은 쓰지 않는다. 판정 파일은 `Edit` 규칙 덕분에 써졌으므로 동작은 맞지만 `Write` 규칙은 쓸모없고 경고만
  남긴다. 두 명령과 시험에서 `Write` 규칙을 빼는 작은 카드로 고친다.
