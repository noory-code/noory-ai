# R-00000116 릴리스 시점 버전 매기기 회고

## Work

플러그인 카드가 버전을 올리지 않게 했다. 카드는 CHANGELOG 의 미출시 절에만 적고,
`release_plugin.py` 가 릴리스할 때 그 절에 제목을 붙이며 매니페스트 둘을 같이 옮긴다. 빈
미출시 절과 매니페스트·CHANGELOG 불일치는 각각 거절한다. 버전 단계는 인자로 받는다.

`CLAUDE.md` 의 Plugin Changes 규칙을 같은 커밋에서 고쳤다 — 두 진실이 공존하는 창을 안
만들려고.

이 카드부터 새 규칙을 지켰다. 매니페스트는 0.54.4 에 그대로 두고 미출시 절만 열었다.

## Decision points

- 드라이버 판정을 받지 않았다. O-00000004 의 여섯 번째 사례인데, 이번에는 리뷰어가 자기
  판정을 **실제 파서로 검증까지 하고** 그 사실을 설명하다 걸렸다. 검증한 사람이 검증을
  말해서 실패한다면 고칠 것은 리뷰어가 아니다.
- 기준 밖 지적 셋을 전부 받아 W-00000127 로 세웠다. 그중 하나는 급하다 — 새 규칙이 evonest
  에서 지금 이 순간 틀린 지시로 서 있다.

## Principles applied

- SSOT — 버전을 정하는 자리를 하나로 모았다. 그런데 그 원칙이 evonest 에서는 이미
  `pyproject.toml` 로 정해져 있었고, 새 규칙이 그것을 안 보고 여섯 플러그인 전부에 말을
  걸었다. 원칙을 세우면서 그 원칙이 이미 다르게 정해진 자리를 못 셌다.
- Fail Fast — 명령이 빈 절과 버전 불일치에서 멈춘다. 추측하고 넘어가지 않는다.
- Honesty — 산문에서 버전 단계를 읽어내지 않고 인자로 받는다. 리뷰어가 그것을 확인했다.

## Context that helped

- 리뷰어가 임시 사본에 실제 CHANGELOG·매니페스트를 복사해 돌려 0.54.4 → 0.55.0 을 눈으로
  확인했다. 두 번 연속 돌리면 멈춘다는 것도 그렇게 찾았다.

## Context that was missing

- **적용 자리를 셀 때 "이 규칙이 이미 다르게 정해진 곳"을 안 봤다.** 루트 `CLAUDE.md` 는 여섯
  플러그인에 말을 거는데, evonest 는 자기 `CLAUDE.md` 에서 버전 SSOT 를 이미 선언해 뒀다.
  적용 자리를 셀 때 코드·설정·문서·실패 경로는 셌지만 **"같은 주제를 이미 정해 둔 하위 규칙"**
  은 안 셌다.
- 카드 scope 에 `stage/skills/` 가 있었는데 어느 성공 기준도 그 안의 낡은 문장을 안 지목해서
  실행자가 못 봤다. scope 는 허가이지 지시가 아니다 — 고쳐야 할 것은 기준이 지목해야 한다.

## Next changes

  된다.
- 앞으로 규칙을 세울 때 하위 디렉터리의 `CLAUDE.md`·`AGENTS.md` 가 같은 주제를 이미 정했는지
  본다.
