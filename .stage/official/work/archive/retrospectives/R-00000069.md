# R-00000069 드라이버가 실행자에게 대상 작업 항목을 전달한다

## Work

드라이버가 실행자 프로세스를 띄울 때 대상 작업 항목을 환경 변수 세 개로 넘긴다:
`STAGE_WORK_ITEM`(항목 id), `STAGE_WORK_ITEM_PATH`(카드 절대 경로),
`STAGE_PROJECT_ROOT`(프로젝트 루트 절대 경로). 감독 모드(`--execute`)와 무인
모드(`--unattended`) 양쪽 실행 경로에 같은 방식으로 주입한다.

주입은 `drive.py` 의 실행자 호출 지점에서만 일어난다. 저장된 검증 명령과 리뷰 명령은 받지
않는다. 공용 실행 함수 `run_check` 에는 선택 인자 `env` 를 더해 호출자가 정하게 했고, 인자를
넘기지 않는 기존 호출자의 동작은 그대로다.

## Decision points

**환경 변수 대 명령 문자열 치환.** 실행자 명령은 `.stage/settings.json` 에 적힌 셸 문자열이다.
`{item}` 같은 자리표시자를 치환하는 방식은 명령 안에 중괄호가 들어 있을 때 조용히 망가진다.
환경 변수는 셸이 그대로 풀어 주고 이미 설정된 명령을 깨뜨리지 않는다. 환경 변수를 택했다.

**주입 위치.** `run_check` 안에서 무조건 주입하면 검증 명령과 리뷰 명령까지 값을 받는다.
그 둘은 대상 항목을 알 필요가 없다. 선택 인자로 두고 드라이버가 실행자에게만 넘긴다.

**넘기는 값의 범위.** 환경 변수는 자식 프로세스 전체가 물려받으므로 항목 식별에 필요한
최소한만 넣었다.

## Principles applied

**Fail Fast** — 이 결함은 드라이버를 실제로 돌려 보려던 준비 과정에서 드러났다. 코드가 완성돼
있고 독립 리뷰를 두 번 받았어도, 한 번도 실행하지 않은 경로는 검증된 것이 아니다.

**SoC** — 실행자에게 맥락을 넘기는 일과 검증·리뷰 명령을 돌리는 일은 다른 관심사다. 공용
함수에 조건을 넣는 대신 호출자가 정하게 했다.

**Honesty** — 위임받은 쪽이 코드만 고치고 멈췄을 때 버전·이력·사양 문서가 빠진 것을 그대로
지적해 마무리시켰다. 부분 완료를 완료로 넘기지 않았다.

## Context that helped

카드에 현재 코드의 문제 지점을 인용해 둔 것. 실행자 명령을 셸에 그대로 넘기는 자리와, 기존
테스트가 왜 이걸 못 잡았는지(실행자가 파일 하나 만들고 끝나는 고정 명령이라 항목을 알 필요가
없었다)를 카드가 이미 담고 있어서 위임받은 쪽이 바로 일을 시작했다.

카드의 **위험** 한 줄 — 무인 모드 경로를 빠뜨리기 쉽다고 적어 둔 것. 양쪽 모두 주입됐다.

## Context that was missing

**코덱스 위임이 죽는 두 번째 경로.** P-00000001 은 이 문제를 "이미 떠 있던 프로세스가 세션
시작 때 해석한 옛 경로를 붙들고 있다"로 기록하고 있다. 이번에는 다르게 죽었다. 위임을 걸기
직전 이 저장소의 브로커 프로세스가 하나도 없음을 확인했는데도 막혔다. 코덱스 마켓플레이스가
세션이 열리는 바로 그 순간 저장소를 다시 당기면서 플러그인 폴더가 갈렸고, 그 세션이 조금 전
해석해 둔 경로가 사라졌다. 즉 세션 시작과 동기화가 겹쳐서 나는 경합이다.

여기서 나오는 운영 규칙: **코덱스에 위임한 작업이 도는 중에는 push 하지 않는다.** 마켓플레이스가
GitHub 에서 당기므로 push 가 같은 동기화를 다시 일으킨다.

대응은 같다 — 그 저장소의 브로커만 내리고 다시 건다. 이번에도 그것으로 풀렸다.

**위임 카드에 산출물 목록을 빠뜨림.** 카드의 제약 항목에 버전 범프와 변경 이력을 적었는데도
위임받은 쪽은 코드만 고치고 멈췄다. 성공 기준 목록에 파일 단위로 못 박아 두는 편이 낫다.
