# R-00000388 메인 세션이 서브세션에 일을 맡기고 닫는 절차와 번호 묶음을 만든다

## Decision points

- **번호 묶음을 넘기는 카드의 frontmatter(`reserved_ids:`)에 남겼다.** 따로 파일을 두면 그 파일도 두 세션이 함께
  고치는 목록이 된다(DE-00000091). 카드는 메인 세션이 시작해서 push 하므로 다른 세션이 fetch 하면 묶음이 보인다.
- **`stage_record_ids.py` 가 517줄이 되어 묶음 함수를 `stage_id_blocks.py` 로 나눴다.**
- **메인 세션은 서브세션 브랜치를 `git merge --squash` 와 `git commit -C` 로 받는다.** 리뷰가 HEAD 커밋의 경로만 받는
  문제(O-00000058)를 로컬 전용 커밋 없이 넘는다. W-00000383 파일럿에서 그대로 동작했다.
- **파일럿으로 W-00000383 을 골랐다.** 작고, 고칠 경로가 이 카드와 겹치지 않고, 리눅스에서 확인할 수 있다.

## Context that was missing

- 이 카드 자신은 HEAD 가 코드 커밋이 아니어서(파일럿 커밋이 뒤에 쌓였다) 로컬 worktree 에서 닫았다. 메인 세션이 한
  브랜치에서 여러 카드를 차례로 닫으면 이 일이 되풀이된다. 카드마다 PR 을 따로 내면 생기지 않는다.

## Rule candidate

- 없다.
