# R-00000049 Plainly 언어 품질 규칙을 불변 영역에 두다

## Work

Plainly가 매 프롬프트에 붙이는 고정 문구에 언어 품질 규칙을 넣었다. 비영어 답변이 영어 어순·수동태를
그대로 옮긴 번역투로 나오고 용어가 불필요하게 어렵던 문제를 막는다. 플러그인 0.4.0으로 릴리즈했고
`plainly-v0.4.0` 태그를 푸시했다.

## Decision points

- 규칙을 스타일 본문(`styles/baseline.md`)에 둘 것인가, 훅 고정 문구에 둘 것인가. 외부 스타일 파일이
  baseline을 통째로 치환하므로 스타일 본문에 두면 이 저장소를 포함해 자체 스타일을 쓰는 모든
  프로젝트에서 규칙이 사라진다. 훅 고정 문구를 선택했다.
- 규칙이 답변 언어를 지정할 것인가. 지정하지 않기로 했다. 어떤 언어로 쓰든 그 언어답게 쓰라는
  품질 규칙이며, 언어 선택은 사용자와 스타일의 몫이다.
- 실행 창을 어디로 둘 것인가. `kind: fix`의 선언된 라우팅이 codex라서 구현을 Codex에 위임하고
  Claude는 문구 설계와 검증을 맡았다.

## Principles applied

- SSOT — 규칙의 소유 위치를 훅 고정 문구 한 곳으로 고정하고 스타일 본문에 중복 기술하지 않았다.
- MECE — 네 가지 스타일 해석 경로(기본값, `NOORY_STYLE_PROFILE`, 프로젝트 설정, `NOORY_STYLE_FILE`)를
  빠짐없이 회귀 테스트로 덮었다.
- Fail Fast — 규칙이 센티널 종료 뒤에 나타나는지까지 검사해, 누군가 규칙을 스타일 본문으로
  옮기면 테스트가 즉시 깨지도록 했다.

## Context that helped

`resolve_style`이 외부 스타일 파일을 만나면 baseline을 합치지 않고 그대로 반환한다는 사실. 이것이
규칙의 위치를 결정했다.

## Context that was missing

루트 `CLAUDE.md`의 "All documents ... must be written in English"에 `.stage/` 예외가 없다. 이 때문에
작업 중 Stage 문서를 영어로 바꾸는 잘못된 판단을 했고, 되돌렸다. 문구 보정이 필요하다.

## Next changes
