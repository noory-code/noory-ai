# R-00000003 Repo-wide documentation cleanup — register work before governed changes

## Work

Audited root docs plus the `evonest`, `stage`, `plainly`, and `flutter-cask` packages for
stale facts, SSOT duplication, evergreen violations, banned vague phrases, broken links, and
version/CHANGELOG drift; fixed each finding, bumping the touched package's version and
CHANGELOG and landing each package as its own commit. `rag` and `pencil_m3_flutter` were
audited and needed no changes.

## Decision points

Scoping which packages actually had findings versus which were already clean — decided by the
audit pass, not up front.

## Principles applied

- SSOT — collapsed duplicated statements to one canonical location and linked the rest.
- Honesty / evergreen — removed time-based and self-invalidating doc phrasing so the body
  states current truth only.

## Context that helped

Each package's `version` + `CHANGELOG.md` acted as a per-package completion checklist, making
"is this package done" a concrete check rather than a judgment.

## Context that was missing

The Stage harness did not yet exist when this work began: the work item was registered
retroactively after `.stage/` was initialized mid-task, and the first five commits landed
before governance was in place. So verification and this retrospective cover the whole work
only in hindsight, not by construction.

## Next changes

Initialize the Stage harness and register the work item *before* starting governed changes,
not mid-task — so the verification and retrospective gates cover the entire work item from its
first commit rather than its tail.

## Promotion decision

`promotion: not_applicable` — the work touches only docs, CHANGELOG, and version fields,
nothing under `.stage/official/`.
