# R-00000378 카드와 기록을 등록할 때 번호를 원격에 잡는다

## Work

DE-00000092 를 구현했다. `stage_record_ids.py` 의 `IdReserver` 가 원격의 `refs/stage-ids/*` 를 세고, 고른
번호를 `--force-with-lease=<ref>:` push 로 잡는다. `register_work.py` 와 `manage_roadmap.py` 가 같은 것을 쓴다.
원격이 없거나 닿지 못하거나 push 를 거절하면 예전처럼 번호를 고르고 한 줄 알린다. PR #88.

이 저장소의 클라우드 세션에서는 git 프록시가 `refs/stage-ids/` push 를 HTTP 403 으로 거절했다. 병렬이 가장
많은 곳에서 이 기능은 번호를 잡지 못하고 예전 규칙으로 떨어진다.

## Decision points

- **원격 확인을 구현보다 먼저 했다.** 결과에 따라 이름(태그 등)이 바뀔 수 있어서다. 403 이 나왔고, 프록시
  안내가 정책 거절을 다시 시도하거나 돌아가지 말라고 해서 다른 이름은 시험하지 않았다. 다른 이름을 시도하려던
  명령은 auto-mode 분류기도 거절했다. 결정은 바꾸지 않고, 떨어지는 경로가 확실히 동작하게 하는 쪽을 골랐다.
- **HEAD 가 아니라 빈 트리로 만든 커밋 하나를 push 한다.** HEAD 를 push 하면 아직 올리지 않은 브랜치 작업이
  원격에 올라간다.
- **마커 커밋에 무작위 nonce 를 넣었다.** 같은 초에 같은 번호를 잡으면 두 세션의 커밋이 바이트까지 같아져서
  두 번째 push 가 "up to date" 로 성공했다. 테스트가 잡았다.
- **push 실패를 경쟁에 진 것으로 보는 것은 원격에 그 ref 가 생겼을 때뿐이다.** 그 밖의 실패는 원격이 거절한
  것으로 보고 그 실행 동안 잡기를 끈다. 403 인 클라우드가 이 경로다.
- **`--id` 로 번호를 준 등록은 잡지 않는다.** 등록이 실패한 뒤 같은 번호로 다시 하면 자기가 잡은 번호에
  거절당한다.
- **원격이 없어도 한 줄을 출력한다.** DE 는 "지금과 똑같이" 라고 했고 카드는 "잡지 못했다고 출력한다" 라고
  했다. 번호는 같고 stdout 도 같으므로 stderr 한 줄은 카드를 따랐다.

## Principles applied

- Fail Fast: 번호가 겹칠 수 있는 상황을 등록하는 순간 stderr 로 알린다.
- Postel's Law: 네트워크가 없거나 거절돼도 등록은 막지 않는다.
- Honesty: 403 을 카드, PR, CHANGELOG, 운영 문서에 그대로 적었다. 기능이 클라우드에서 동작하지 않는다는 것을
  숨기지 않았다.

## Context that helped

- DE-00000092 의 "Where this applies" 표. 고칠 자리가 하나씩 적혀 있어서 빠뜨린 곳을 찾을 일이 없었다.
- 저장소의 subprocess 인코딩 가드 시험. 새 시험의 `errors="replace"` 누락을 잡았다.

## Context that was missing

- 클라우드 프록시가 세션 브랜치 밖의 ref push 를 막는다는 것. 결정을 내릴 때 알았다면 클라우드 세션용 대안을
  함께 정했을 것이다.
- 닫기 리뷰가 HEAD 커밋의 경로만 받는다(O-00000058). 코드 커밋이 둘이라 합친 커밋을 로컬에서 만들어 닫았다.

## Next changes

- 클라우드 세션의 번호 충돌은 그대로 남았다. 메인 세션이 서브 세션을 만들 때 번호 범위를 나눠 주는 방식을
  메인 세션에 제안했다.
- 쌓이는 `refs/stage-ids/` 를 언제 치울지 정하지 않았다.
- GitHub 자체가 `refs/stage-ids/` 를 받는지는 로컬 세션에서 확인해야 한다.
