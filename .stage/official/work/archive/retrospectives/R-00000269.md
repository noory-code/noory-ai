# R-00000269 닫기 전 리뷰의 기준별 판정을 카드에 적는다

## Work

W-00000269. 닫기 리뷰가 통과하면 `close_work.py` 가 판정 JSON 의 기준마다 판정과 까닭을 카드의
`## Verification` 리뷰 블록에 적는다. 두 리뷰 경로(`review: pending` 리뷰, autonomous 독립 리뷰)
모두에 적용된다. `stage/operations/review.md` 에 닫기가 카드에 적는 내용을 정리했다.
외부 결과: 카드를 보관한 뒤에도 리뷰가 기준마다 무엇을 근거로 통과시켰는지 카드에서 읽힌다.
내부 결과: `test_close_work.py` 60개가 통과하고, 고치기 전 `close_work.py` 로 되돌리면 새 시험
2개가 실패한다. 이 카드의 닫기가 새 기능을 처음 실제로 쓴다.

## Decision points

- 실행 자리: Claude Code 클라우드 세션이 사용자의 직접 지시에 따라 먼저 실행했다고 보고했다.
  venue 예외는 실행 뒤에 DE-00000076 으로 기록했다. 로컬 세션은 그 지시를 직접 보지 않았다.
- 표시 형식: 카드 Actions 가 비어 있어 실행자가 코드 블록 안의 `- PASS: <criterion>` 줄과 들여 쓴
  `Reason:` 줄을 골랐다. 표를 쓰지 않아 `|` 문자를 따로 처리할 필요가 없다.
- 닫기 방법: `close_work.py` 는 HEAD 커밋 하나만 리뷰하므로 소스 커밋 `40063650` 을 HEAD 로 둔
  임시 작업 공간에서 닫았다. `.stage/` 는 최신 기록으로, 리뷰 명령은 W-00000286 설정으로 덮었다.

## Principles applied

Honesty: 실행 뒤에 기록한 예외임을 결정 기록에 밝혔다. 실행자 보고의 "사용자 지시" 는 보고에서
온 말이라고 구분했다.
만든 쪽 ≠ 보는 쪽: 클라우드의 Claude 가 고치고 로컬의 Codex 가 닫기 리뷰를 했다.

## Context that helped

- 실행자가 고치기 전 코드에서 새 시험이 실패하는 것까지 확인해 보고했다. 로컬에서 다시 재 같은
  결과를 얻었다.

## Context that was missing

- 클라우드 세션에 간 카드는 본문이 빈 상태였다. 채운 카드(묶음 브랜치 `claude/stage-cloud-batch`)는
  다른 브랜치에 있어 실행자가 보지 못했다. 카드를 채운 브랜치와 실행이 일어난 브랜치가 갈렸다.
- venue 예외를 실행 전에 기록하지 못했다. 사용자가 클라우드 세션에 직접 지시한 경로는 로컬 기록
  절차를 거치지 않는다.
