# R-00000270 닫기 전 리뷰에 일반 검사와 따로 제한 시간을 준다

## Work

W-00000270. `close_work.py` 에 `--review-timeout`(기본 3600초)을 더해 두 리뷰 경로가 그 값을 쓰고,
검사는 `--timeout` 을 쓴다. 드라이버는 자기 `--timeout` 을 `--review-timeout` 으로 넘겨 이전과 같은
한도로 닫는다. `stage/operations/review.md` 에 두 제한 시간을 적었다.
외부 결과: 생각을 깊게 하는 리뷰가 검사용 900초에 걸려 닫기가 끊기지 않는다.
내부 결과: `test_close_work.py` 62개와 `test_drive.py` 95개가 통과하고, 고치기 전 코드로 되돌리면
새 시험 3개가 실패한다. 이 카드의 닫기가 새 인자를 처음 실제로 쓴다.

## Decision points

- 실행 자리: Claude Code 클라우드 세션이 사용자의 직접 지시에 따라 먼저 실행했다고 보고했다.
  venue 예외는 실행 뒤에 DE-00000077 로 기록했다.
- 기본값 3600초: 카드 Actions 가 비어 있어 실행자가 정했다. 측정한 값이 아니다.
- 범위 밖 변경: 드라이버가 `close_work` 를 `timeout + 60` 초에 끝내므로 `driver_lifecycle.py` 가
  리뷰 제한 시간을 넘기게 했다. 그러지 않으면 드라이버가 리뷰 도중 닫기를 끊는다. 실행자가 이
  넘음을 보고했다.

## Principles applied

Fail Fast: 드라이버의 바깥 제한 시간과 새 기본값이 부딪치는 자리를 실행자가 먼저 찾아 막았다.
Honesty: 기본값이 측정값이 아니라는 것과 범위 밖 변경을 카드와 결정에 적었다.
만든 쪽 ≠ 보는 쪽: 클라우드의 Claude 가 고치고 로컬의 Codex 가 닫기 리뷰를 했다.

## Context that helped

- W-00000269 가 먼저 닫혀 이 카드의 닫기 리뷰도 기준별 판정을 카드에 남긴다.

## Context that was missing

- 카드를 등록할 때 드라이버가 `close_work` 를 부르는 경로를 세지 않았다. 범위에
  `driver_lifecycle.py` 가 빠진 이유다.
- 클라우드 세션은 본문이 빈 카드를 받았다. 채운 카드는 다른 브랜치에 있었다(R-00000269 와 같음).

## Next changes

- 드라이버가 닫을 때도 긴 리뷰 시간을 쓰게 하려면 드라이버의 바깥 제한 시간이 검사와 리뷰를
  함께 셈해야 한다. 드라이버 설계를 바꾸는 일이라 따로 카드로 다룬다.
