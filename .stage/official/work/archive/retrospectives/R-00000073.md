# R-00000073 스킬이 자기 플러그인의 스크립트를 가리키는 방법

## Work

스킬 문서가 같은 플러그인 안의 스크립트를 실행하라고 안내할 때 쓸 경로 표기를 정했다
(DE-00000031). 스킬은 스크립트를 자기 디렉터리 기준의 상대 위치로 지목하고, 실행하는 쪽이
호스트가 알려준 스킬 디렉터리로 절대 경로를 만들어 부른다.

## Decision points

**기존 두 관행 중 하나를 고를 것인가, 셋째를 만들 것인가.** 둘 다 동작하지 않는다는 것을
확인하고 셋째를 택했다. `${CLAUDE_PLUGIN_ROOT}` 는 훅 명령에만 주입되므로 에이전트 셸에서
빈 문자열이고, 저장소 상대 경로는 Stage 소스를 직접 체크아웃한 곳에서만 맞다.

**어디까지 금지할 것인가.** `${CLAUDE_PLUGIN_ROOT}` 자체를 금지하지 않았다. 훅 명령
(`hooks.json`)에서는 실제로 주입되므로 계속 쓴다. 금지되는 것은 스킬 본문의 셸 예시에 쓰는
것이다.

## Principles applied

**Honesty** — 동작하지 않는 것을 동작하는 것처럼 적어 온 관행을 확인 없이 이어받지 않았다.
셸에서 직접 값을 찍어 보고 결정했다.

**SSOT** — 경로의 근거를 스킬 파일 자신의 위치 하나로 정했다. 호스트마다 다른 변수를 나열하면
근거가 여러 개가 된다.

## Context that helped

스킬을 부를 때마다 호스트가 맨 앞에 스킬 디렉터리를 알려준다는 사실. 이 세션에서 스킬을
여러 번 부르며 매번 그 줄을 봤기 때문에, 변수를 찾아 헤매지 않고 이미 있는 것을 쓸 수 있었다.

## Context that was missing

**Codex 호스트가 스킬 디렉터리를 어떤 형태로 알려주는지 확인하지 않았다.** Claude Code 에서만
확인했다. 다르면 스킬 본문의 표현을 두 경우 모두 성립하게 다듬어야 한다. 결정 본문의
`## Follow-up` 에 남겼다.

## Next changes

- 다른 스킬의 옛 표기를 이 결정에 맞춘다 — `stage-archive` 본문이 `${CLAUDE_PLUGIN_ROOT}` 를
  쓰고, `stage-work` 와 `stage-archive` 의 명령 예시가 저장소 상대 경로를 쓴다. 별도 카드.
