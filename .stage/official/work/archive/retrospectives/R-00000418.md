# R-00000418 닫는 길 두 문서가 서로를 막고 있었고, 첫 카드가 걸릴 때까지 아무도 몰랐다

## Decision points

- `review.md` 는 리뷰어가 직접 보지 못한 증거를 주장으로 보았고, `cloud-execution.md` 는 기계의 확인이 도착하면 닫기 리뷰가
  모든 기준을 판정한다고 했다. 둘을 합치면 기계 전용 기준을 가진 카드는 닫히지 않았다. W-00000407 의 닫기 리뷰가 두 기준을
  `unable` 로 반려해서 드러났다. 사용자가 2026-11-24 에 절차를 고치는 길을 골랐다("1").
- 작업 세션이 줄의 형식을 `- Checked` 와 `- User verdict` 둘로 고정했다. 자유로운 문단은 기록으로 치지 않는다. 그래서
  W-00000407 의 확인은 지휘 세션이 문단에서 줄로 옮겨 적어야 했다.
- `- Checked ... did not hold` 뒤의 `- User verdict ... held` 는 사용자의 판정이 정한다. 사용자가 2026-11-24 에 이것을 알고
  닫으라고 했다("닫으세요").
- method 는 새로 만들지 않고 `read` 를 쓴다. 그래서 닫기 줄의 `read` 수로는 기록된 확인에 기댄 기준이 몇 개인지 알 수 없다.
- 리뷰어는 아무도 돌리지 않은 확인을 적은 줄을 가려내지 못한다. 이 기준들의 관문은 줄을 누가 쓰느냐에 달려 있다.
  W-00000407 에서는 줄을 쓴 지휘 세션과 판정한 리뷰어가 같은 모델이었다. 사용자가 이것도 알고 닫으라고 했다.
- 범위 밖인 `stage/skills/stage-orchestrate/SKILL.md` 를 작업 세션이 고쳤다. 사용자의 답을 리뷰어가 읽는 자리에 적으라는
  문장이 없었기 때문이다.

## Context that was missing

- 닫기 절차를 적은 두 문서를 처음부터 끝까지 따라가 본 카드가 W-00000407 전에는 없었다. W-00000372 는 같은 종류였지만
  `review: not_required` 라 걸리지 않았다.
- 실제 리뷰어가 새 문장을 따르는지는 작업 세션이 돌려 보지 않았다. W-00000407 의 재리뷰 한 번이 유일한 관찰이다.
- 다른 프로젝트의 리뷰 명령에는 새 문장이 없다. 빠져도 audit 가 알리지 않는다.

## Rule candidate

- 닫는 절차를 바꾸거나 새 길을 적은 카드는, 그 길로 실제 카드 한 장을 닫아 본 뒤에 닫는다(R-00000404 의 후보와 같은 종류,
  두 번째 관찰).
