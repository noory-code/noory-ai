# R-00000315 시도 횟수를 되돌릴 때 멈춘 판의 작업을 정리한다

## Work

W-00000315. `--reset-attempts` 가 중단된 역할이 기록돼 있으면 그 역할의 venue 정리 명령(reaper)을 먼저 부르게 했다.
O-00000051 을 닫았다.
외부 결과: 드라이버를 멈추고 되돌린 뒤 다시 돌린 판이, 멈춘 판에서 살아남은 Codex 작업의 늦은 보고 때문에 깨지지 않는다.
내부 결과: 실행자·리뷰어·역할 없음 세 경우를 시험이 보고, 정리 명령이 되돌리기 전에 돈다는 것까지 확인한다.

## Decision points

- Ctrl-C 처리가 아니라 되돌리기에서 정리했다. 되돌리기는 어떤 식으로 멈췄든 문서가 권하는 다음 걸음이고, kill 된
  드라이버는 스스로 정리할 수 없다.
- 정리 명령이 없거나 실패해도 되돌리기는 막지 않았다. `reap_turn` 이 이미 경고를 남기고, 막으면 사람이 갈 길이 없다.

## Principles applied

만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- O-00000051 이 "멈출 때 reaper 를 부르는지, 되돌릴 때 늦은 보고를 어떻게 세는지"를 다음 확인 거리로 적어 두었다.
- 시도 상한에 걸렸을 때는 이미 reaper 를 부르고 있어 같은 함수를 쓰면 됐다.

## Context that was missing

- `--timeout` 이 되돌리기 시점에는 기본값이 없어(None) 정리 명령에 넘길 시간 제한을 따로 정해야 했다.
