# R-00000017 Unified work-card lifecycle implementation

## Work

Implemented DE-00000007: planned `W-*` cards in the backlog, `--backlog` capture, the
`start_work.py` mover enforcing scope and the venue/split contract at start, audit rework for
columns and legacy compatibility, schema v3 with B-family migration, bilingual template updates,
and this repository's own migration. Released as Stage 0.23.0.

## Decision points

- Reused DECISION-free structures wherever possible; the one code collision found (my first
  DECISION002 pick was already taken by the not-linked-back check) was renamed to DECISION003
  before release — the ordered link-pin test caught the overlap immediately.
- Narrowed the WORK007/SSOT001 boundary so duplicate detection still owns present+archive while
  a card appearing in two lifecycle columns is an SSOT error.
- Kept legacy `B-` rows recognized by the backlog index membership check so pre-v3 projects
  audit truthfully before migrating.

## Principles applied

- Fail Fast (mover refuses bad starts with exact resolutions), SSOT (one id counter across three
  columns), MECE (planned/open/final statuses partition by location), Completion (behavior,
  audit, templates, migration, self-migration, tests, release together).

## Context that helped

- The pin test (`test_audit_link_pin`) made every audit-surface change explicit and reviewable.
- The migration pattern from v2 (idempotent, dry-run, never delete unrecorded bodies) extended
  cleanly to the B conversion.

## Context that was missing

- Nothing recorded which audit codes were still free; finding-code allocation is implicit in the
  pin test only.

## What changes in later behavior

- New work enters as a planned card (`--backlog`) unless it starts immediately; starting is
  always `start_work.py`, never a hand move.
- Backlog grooming edits statuses in place; only the mover changes a card's column.

## Routing

- Everything lives in the released plugin and this repository's migrated `.stage/`; nothing
  promotes to `official/`.
