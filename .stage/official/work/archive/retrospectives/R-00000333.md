# R-00000333 stage 0.66.0 을 낸다

## Work

릴리스 명령 한 번으로 Stage 를 0.65.0 에서 0.66.0 으로 올렸다. 쌓여 있던 변경 기록 다섯 묶음에
버전 제목이 붙었고 두 매니페스트가 같은 값을 말한다. PR #31 로 main 에 합쳤다(`db8db3e9`).
사용자가 `/reload-plugins` 를 돌린 뒤 이 컴퓨터의 Claude Code 가 0.66.0 을 읽는 것을 확인했다.

## Decision points

- **부 버전을 올렸다.** 새 설정(`model_tiers`, `tier_routing`)과 새 훅(`SubagentStop`)이 생겼으므로
  고침이 아니라 기능이다.
- **팀원을 띄우지 않고 감독 세션이 직접 실행했다.** 이 프로젝트의 claude venue 절차는 팀원에게
  맡기라고 한다. 릴리스는 명령 한 번이고, 오래 돈 세션에서는 팀원 창이 뜨지 않은 적이 있어
  직접 했다. 절차에서 벗어난 것이라 사용자에게 알렸다.
- **설치 기록 파일 대신 실제로 읽는 버전으로 판정했다.** 설치 기록(`installed_plugins.json`)은
  여전히 0.64.0 을 말한다. 그러나 `claude plugin list` 는 0.66.0 을 이 저장소의 `stage` 폴더에서
  읽는다고 답하고, 같은 세션에서 훅의 동작도 새 버전으로 바뀌었다. DE-00000054 의 기준은 새
  버전이 실제로 불러와지는 것이므로 그 관측을 근거로 삼았다.

## Principles applied

- Honesty — 설치 기록이 0.66.0 을 말하지 않는다는 사실을 카드의 검증 절에 그대로 적었다.
  성공 기준의 문구("설치 기록에서 확인")와 실제 근거가 다르다는 것도 함께 적었다.
- Completion — 버전을 올리고 합친 데서 닫지 않고, 새 버전이 불러와지는 것을 본 뒤에 닫았다.
- Fail Fast — 릴리스를 올리기 전에 시험 두 묶음과 감사를 먼저 돌렸다.

## Context that helped

- 보관된 릴리스 카드 W-00000231 이 릴리스 카드의 범위와 성공 기준을 어떻게 적는지 보여 줬다.
- 같은 세션에서 릴리스 전에 받은 범위 넘음 보고가 비교 대상이 됐다. 스크래치 폴더에 변수 경로로
  쓰는 같은 모양의 명령이 갱신 전에는 보고됐고 갱신 뒤에는 보고되지 않았다.

## Context that was missing

- 이 컴퓨터의 마켓플레이스는 이 저장소 폴더를 가리키는 디렉터리 출처다. Claude Code 가 플러그인을
  캐시가 아니라 그 폴더에서 바로 읽는다는 것을 카드를 쓸 때 몰랐다. 그래서 성공 기준을 "설치
  기록에서 확인"이라고 적었는데, 그 파일은 갱신 뒤에도 바뀌지 않았다.
- 새 세션이 어느 쪽을 읽는지는 확인하지 않았다. 확인한 것은 `claude plugin list` 의 답과 이
  세션의 훅 동작이다.
- Codex 쪽 설치본은 확인하지 않았다. Codex 실행자가 지금 설정된 모델을 거절해 돌릴 수 없다.
