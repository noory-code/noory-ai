# R-00000360 훅 고침 브랜치에 main을 합쳐 PR #69의 충돌을 푼다

## Work

PR #69 는 PR #70 이 먼저 머지되면서 보관 목록의 같은 자리에서 충돌했다. 브랜치에 main 을 합쳐 보관 목록의
세 줄을 모두 남겼고, evonest 변경 기록에 두 개가 된 `## Unreleased` 절을 하나로 합쳤다.

## Decision points

- 머지 커밋을 만드는 방법: 카드를 등록해 만드는 안과 사용자가 터미널에서 직접 커밋하는 안이 있었다.
  사용자가 카드를 등록하는 안을 골랐다.
- 카드 번호: Windows 세션의 PR #71 이 W-00000359 를 쓰고 있어서 W-00000360 으로 등록했다. 등록하기 전에
  fetch 해서 알았다.
- 변경 기록: Git 은 두 `## Unreleased` 절을 충돌 없이 합쳤다. 충돌 표시가 없어도 결과를 읽어 보고 하나로 합쳤다.

## Principles applied

- SSOT: 변경 기록의 `## Unreleased` 절은 하나다. 릴리스 명령이 그 절 하나를 읽는다.
- Honesty: 관문이 커밋을 막은 것을 돌아가지 않고 사용자에게 알렸다.

## Context that helped

- R-00000358 에 적은 "등록하기 전에 fetch 한다" 가 번호가 세 번째로 겹치는 것을 막았다.

## Context that was missing

- 카드를 닫고 보관하기 전에 PR 이 main 과 충돌하는지 확인하지 않았다. 보관한 뒤에는 열린 카드가 없어서
  충돌을 푸는 머지 커밋을 관문이 막는다.
- 관문에는 머지 커밋을 따로 다루는 규칙이 없다. main 에서 이미 리뷰받고 들어온 파일도 열린 카드를 요구한다.

## Next changes

- 관문이 머지 커밋을 구분하지 못하는 것을 관찰 기록으로 남길지 사용자에게 묻는다.

## Rule candidate

- 카드를 닫기 전에 브랜치에 main 을 합쳐 충돌이 없는지 확인한다. 근거는 이 카드 한 번뿐이라 아직 규칙으로
  올리지 않는다.
