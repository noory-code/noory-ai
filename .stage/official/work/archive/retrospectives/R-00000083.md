# R-00000083 실행하는 쪽이 일을 못 했는데 성공으로 끝난다

## Work

드라이버가 실행하는 쪽의 종료 코드만 믿고 성공을 판정하던 것을, 실행 전후의 저장소 상태
비교로 바꿨다(DE-00000033). 아무것도 안 바뀐 시도는 감독·무인 모두 실패로 판정되고, 실패
메시지가 "이미 다 되어 있던 일" 의 정당한 길(`close_work.py` 수동 실행)을 알려준다. 무인
모드에는 같은 구멍이 실제로 있었다 — 빈 커밋을 깨끗한 무변경으로 받아 닫힘까지 갈 수 있었다.

## Decision points

- 갈래 셋 중 저장소 상태 비교를 골랐다(DE-00000033) — 출력 문자열 읽기는 표현이 바뀌면
  조용히 무력해지고, 실행하는 쪽의 자기 보고 계약은 자기 보고를 안 믿으려고 시작한 일과
  모순이며 반복 관찰 전의 새 계약이라 배제했다.
- 비교에서 검증 출력을 뺐다 — 시도마다 달라질 수 있는 값을 넣으면 "안 바뀌었는데 바뀐
  것처럼" 보이는 구멍이 된다. 기존 NO-PROGRESS 지문은 그대로 뒀다.
- 드라이버로 안 돌렸다 — 카드 하나를 돌리려면 껍데기 부모가 필요한데 그 오염을 없애려는
  W-00000082 가 아직 열려 있다. 벗어난 이유를 카드에 적었다.

## Principles applied

- **Fail Fast** — 조용히 통과하던 무변경 실행이 그 자리에서 실패로 드러난다.
- **Honesty** — 판정의 근거를 실행하는 쪽의 말이 아니라 관측 가능한 상태에 뒀다. 검증도
  Codex 의 보고를 믿지 않고 RED 를 저장소 밖 사본에서 직접 재현했다.
- **MECE** — 자동 통과(상태가 바뀜)와 수동 통과(사람이 close_work 로 닫음)가 겹치지 않고,
  정당한 무변경 경우가 빠지지도 않는다.
- **AHA** — 실행하는 쪽 자기 보고 계약(갈래 C)은 반복이 보이기 전에는 만들지 않는다.

## Context that helped

- W-00000081 을 막 닫은 참이라 위임-검증-리뷰 흐름이 그대로 재사용됐고, RED 재현 절차(저장소
  밖 사본)도 두 번째라 빨랐다.
- 사고 기록이 카드에 실행 로그째 남아 있어(막힌 채 종료 코드 0) 무엇을 재현해야 하는지
  분명했다.

## Context that was missing

- Codex 세션의 Stage 플러그인 캐시가 또 깨졌다(P-00000001 과 같은 뿌리, 이번에는
  `stage_guard.py` 누락). 구현은 됐지만 카드 기록·감사를 Codex 쪽에서 못 했다. 이 제안이
  열려 있는 동안은 위임 결과의 기록을 Claude 쪽에서 마무리하는 것으로 흡수한다.
