# R-00000356 evonest 가 Windows 한국어 로캘에서도 동작하고 테스트가 통과하게 고치기

## Work

한국어 Windows(cp949)에서 evonest 테스트를 실행하니 438개 가운데 199개만 통과했다. 원인을 찾아 보니
테스트만이 아니라 본체에도 버그가 세 군데 있었다. 텍스트 모드 `subprocess` 호출 12개에
`encoding="utf-8", errors="replace"` 를 줬고, `cli.py` 가 인코딩할 수 없는 글자를 만나도 죽지 않게
했고, `doc_updater.py` 가 상대 경로를 슬래시로 돌려주게 했다. 테스트는 파일을 UTF-8 로 읽고 쓰게
했다. 새 호출이 인코딩을 빠뜨리면 실패하는 테스트를 더했다. 고친 뒤 같은 기기에서 440개가 통과했다.

## Decision points

- 고칠 범위: 실패한 테스트만 통과시키지 않고, 테스트가 드러내지 못한 본체의 `subprocess` 호출
  12개도 고쳤다. 테스트는 `claude` 호출을 가짜로 바꾸므로 이 호출들은 실패로 나타나지 않았다.
  stage 에서 같은 모양의 호출이 실제로 출력을 잃었으므로(W-00000352) 같은 원인으로 봤다.
- `cli.py` 를 고치는 방법: 스트림 인코딩을 UTF-8 로 바꾸지 않고 오류 처리만 `replace` 로 바꿨다.
  인코딩을 바꾸면 cp949 콘솔이나 cp949 로 읽는 쪽에서 한글이 깨진다. 대신 em dash 는 `?` 로 나온다.
- 경로를 어디서 고칠지: `doc_updater.py` 는 본체를 고쳤다. 그 경로는 모델에 보내고 다시 받아 쓰는
  키라서 OS 마다 달라지면 안 된다. `add_proposal` 이 돌려주는 경로는 실제 파일 경로라서 본체는 두고,
  `/` 로 자르던 테스트를 고쳤다.
- 포매터: `ruff format` 을 전체에 실행하니 이 카드와 상관없는 파일 7개가 바뀌었다. 되돌리고 이
  카드가 바꾼 줄만 남겼다. 서식만 바뀐 100줄이 실제 변경을 가리기 때문이다.
- 실행 방식: 절차는 팀원을 띄우라고 하지만 Windows 에 tmux 가 없어 이 세션이 직접 고쳤다.
- 커밋 순서: 처음에 코드를 먼저, 카드를 나중에 커밋했다. 닫기 리뷰는 HEAD 커밋의 경로를 받으므로
  카드 커밋을 앞으로 옮겼다. 아직 push 하지 않은 브랜치였다.

## Principles applied

- Honesty: 고정된 Python 3.11 로 확인하지 못한 것, 실제 `claude -p` 를 부르지 않은 것, mypy 오류
  2개가 남아 있는 것을 카드에 적었다.
- Fail Fast: 새 테스트가 인코딩을 빠뜨린 호출의 파일과 줄을 짚으며 실패한다. 고치기 전 소스에서
  실패하는 것을 확인했다.
- SSOT: stage 의 인코딩 검사를 가져다 쓰지 못했다. 패키지가 서로 독립이라 evonest 에 같은 검사를
  따로 뒀다. 같은 검사가 두 곳에 있게 된 것은 저장소 구조에서 나온 중복이다.
- MECE: 텍스트 모드 호출을 전부 찾아 고쳤고, `claude_runner.py` 와 `tools/` 에는 해당 호출이 없는
  것을 확인했다.

## Context that helped

- `.stage/operations/verification.md` 의 "Windows 동작 확인" 규칙이 무엇을 남겨야 하는지 정해 줬다.
- R-00000354 와 stage 의 `test_subprocess_text_encoding.py` 가 원인과 검사 방법을 이미 보여 줬다.

## Context that was missing

- 이 앱 안에서는 `uv` 가 내려받은 Python 을 쓰지 못한다. `AppData\Roaming` 이 다른 폴더로 돌려져
  있어서 `uv` 가 만든 링크가 어긋나는 것으로 보인다. 원인은 확인하지 않았다.
  `UV_PYTHON=3.14 UV_PYTHON_PREFERENCE=only-system` 을 주면 시스템 Python 으로 실행된다.
- 이 기기는 ARM64 Windows 라서 rag 의 의존성 `kuzu` 가 설치되지 않는다. rag 는 테스트하지 못했다.
- evonest 의 CI 가 Windows 를 실행하는지, 실행한다면 어느 로캘인지 확인하지 않았다.
