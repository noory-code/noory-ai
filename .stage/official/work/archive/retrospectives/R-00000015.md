# R-00000015 Routing contract completion

## Work

Closed the review-found gaps in the B-00000001..3 releases: mixed kinds now carry a
machine-readable split contract, venue exceptions apply only through validated decision records
under one contract shared by the registration CLI and the audit, work cannot complete on open
decisions, and every English and Korean guidance surface states the real routing SSOT. Released
as Stage 0.22.0.

## Decision points

- Chose a reserved `split` routing value over semantic mixed-work detection — the review
  directive and Honesty both forbid guessing; `split` makes the project declare mixedness once,
  deterministically.
- Made the exception contract a shared function (`venue_exception_error`) instead of parallel
  CLI/audit logic, with the `work_item` back-link enforced only by the audit because the CLI
  cannot know the id before allocation.
- Upgraded VENUE003 to an error and added the DECISION002 completion gate — both fail fast on
  states the previous release merely narrated.
- Dogfooded immediately: W-00000015 itself is a `fix` carried in a Claude session, authorized by
  DE-00000006 with `authorizes: venue_exception`.

## Principles applied

- Fail Fast: refusals with exact resolutions replaced informational messages.
- SSOT: one routing owner (settings), one exception validation, one meaning owner (canon).
- MECE: routed / split / unrouted kinds partition the taxonomy; exceptions are the single escape
  hatch.
- Honesty: no semantic audit; stale "advisory" claims corrected rather than papered over.
- Completion: behavior, audit, templates (both languages), and tests changed together.

## Context that helped

- The review directive itself enumerated the gaps precisely, including the trap to avoid (fake
  semantic audits).
- The 12 red tests written first made the contract concrete before any implementation.

## Context that was missing

- W-00000012..14 closed while their decisions stayed `open` because nothing gated it — exactly
  the class of gap the new DECISION002 check now catches mechanically.

## What changes in later behavior

- Recording a decision now includes closing it (`decided`) before the depending work completes.
- Registering policy-exception work starts with the decision record, not with the item.
- Feature-kind work in this repository always begins as a design item plus an implementation
  item with `parent` lineage, or carries an explicit exception decision.
