# R-00000346 게이트가 변수로 쓴 cd 와 && 로 이어진 cd 를 따라가서 쓰기 대상을 읽는다

## Work

열린 카드가 없을 때 `S=밖폴더 && mkdir -p $S/sub && cd $S/sub && sed -i … f.md` 가 저장소 쓰기로
막히던 것을 고쳤다. 쓰기·지우기 대상을 셀 때 `cd`·`pushd`·`mkdir` 인자 앞의 변수를 풀고, `&&` 로만
이어진 줄에서는 `cd` 를 일어난 것으로 본다.

## Decision points

- **고치기 전에 계획을 다시 물었다.** 변수만 풀면 될 줄 알았는데, 문제를 다시 만들어 보니 `&&` 뒤의
  `cd` 를 늘 두 폴더로 보는 규칙 때문에 실제로 막혔던 명령은 여전히 막힌다는 것이 드러났다. 게이트를
  허락하는 쪽으로 더 바꾸는 일이라 사용자에게 두 방법을 보이고 정해 달라고 했다.
- **`.stage` 삭제 검사는 건드리지 않았다.** 새 `&&` 규칙은 선택으로 넣고, 쓰기·지우기 대상
  계산에서만 켰다. 지우기를 막는 검사는 계속 모든 가능한 폴더를 본다.
- **변수 정규식을 한 곳으로 옮겼다.** 대상 경로와 `cd` 인자가 같은 규칙으로 풀리게 했다.

## Principles applied

- Fail Fast — 고치기 전에 문제를 다시 만들어서 두 번째 원인을 찾았다.
- SSOT — 변수 정규식을 `stage_shell.py` 한 곳에 둔다.
- Honesty — 실제 세션 동작은 머지한 뒤에야 볼 수 있다고 적었다.

## Context that helped

- W-00000342 가 남긴 재현 방법. `shell_write_paths` 에 명령을 넣어 보면 원인이 바로 보인다.

## Context that was missing

- `_command_groups` 의 "조건부 `cd`" 규칙이 `&&` 와 `||` 를 같은 것으로 다룬다는 점이 문서에
  드러나 있지 않았다. 셸에서는 `&&` 뒤의 명령이 `cd` 가 성공했을 때만 돈다.
