# R-00000416 되돌리기는 닫기를 실패시키고, 저장소 밖 읽기는 알리기만 한다

## Decision points

- 리뷰어가 추적되는 파일을 고쳤다가 `git checkout` 이나 `git restore` 로 되돌리면 닫기가 그 리뷰를 실패시킨다. 내용이 같아도
  파일의 inode 와 시각이 달라진 것을 본다.
- git 이 무시하는 파일에 쓴 것과, 세션 기록 폴더나 GitHub 를 이름으로 든 명령은 실패시키지 않고 경고로 알리고 카드에 남긴다.
  무시되는 파일까지 실패시키면 캐시를 쓰는 모든 리뷰가 실패하고(두 시험 묶음과 audit 만 돌려도 `.pyc` 33개가 써진다), 글자
  대조로 실패시키면 프로젝트 안에서 `~/.claude` 를 찾기만 한 리뷰가 실패하기 때문이다.
- 저장소 밖 읽기를 막지는 않았다. 막으려면 리뷰어의 셸을 좁혀야 하는데 이 카드의 제외 항목이다. 리뷰어가 `gh` 대신 `curl` 로
  옮겨 간 기록이 있어 거부 규칙도 더하지 않았다.
- 위는 작업 세션이 정했고 지휘 세션이 사용자의 위임으로 받았다.
- DE-00000087 은 codex 가 없는 동안 권한, 닫기, 검증 절차를 바꾸는 카드를 사용자 확인 뒤에 닫으라고 한다. 이 카드와
  W-00000408, W-00000413 이 그런 카드다. 사용자가 2026-11-23 에 묻지 말고 진행하라고 한 위임으로 닫았고, 카드마다 확인을 따로
  받지는 않았다. O-00000062 에 적는다.

## Context that was missing

- 독립 리뷰 세션이 리뷰어의 셸 권한을 이번 묶음에서 가장 위험한 선택으로 보았다. 이 카드는 읽기를 드러나게 했을 뿐 막지 않았다.
  사용자의 Mac 에서는 `~/.claude/projects/` 에 모든 프로젝트의 대화가 있다.
- Windows 에서 돌려 본 것이 없다. 거기서는 `st_ctime` 이 만든 시각이다.
