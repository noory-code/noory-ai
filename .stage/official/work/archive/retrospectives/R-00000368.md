# R-00000368 닫기와 보관을 한 번에 하게 고친다

## Work

`close_work.py` 에 `--archive` 를 넣었다. 맨 위 카드를 닫으면 같은 명령이 카드와 회고를 보관한다. 기본 동작은
그대로다. 테스트 6개를 먼저 쓰고 고쳤다.

## Decision points

- 기본 동작으로 하지 않고 선택 사항으로 넣었다. 드라이버가 닫은 뒤에 `work/current/` 의 카드를 커밋하기 때문이다.
- 닫기는 성공하고 보관이 실패하면 0 이 아닌 값으로 끝낸다. 성공으로 끝내면 카드가 리뷰 대기 목록에 남은 것을
  모르고 지나간다.
- 다른 카드 아래에 있는 카드에는 확인 명령을 실행하기 전에 거절한다. 다 실행한 뒤에 거절하면 시간을 버린다.
- 승격이 `approved` 인 카드를 따로 막지 않았다. 닫기가 이미 그 상태를 거절한다.
- 보관 코드를 옮기지 않고 `archive_work.archive_one` 을 불렀다. 보관 규칙을 두 군데에 두지 않는다.

## Principles applied

- SSOT: 보관 규칙은 `archive_work.py` 한 곳에 있다.
- Fail Fast: 쓸 수 없는 조합을 확인 명령보다 먼저 거절한다.
- KISS: 드라이버 흐름은 고치지 않았다.

## Context that helped

- `land_run.py` 의 `allowed_lifecycle_paths` 가 드라이버가 닫힌 카드를 어디서 찾는지 보여 줬다.
- `test_archive_work.py` 가 보관에 필요한 폴더와 색인을 보여 줬다.

## Context that was missing

- 닫기와 보관이 왜 나뉘어 있는지 적은 문서가 없었다. 코드 다섯 군데를 읽고 알았다.
- 카드에 확인한 내용을 적은 커밋을 코드 커밋 뒤에 올렸다. 닫기 리뷰는 `HEAD` 커밋의 경로를 보므로 코드 커밋에
  맞춘 작업 폴더를 따로 만들어 닫았다. 카드에 적는 것은 닫는 커밋에 함께 넣으면 된다.

## Next changes

- 손으로 닫는 맨 위 카드는 `--archive` 로 닫는다.
- 드라이버가 닫는 카드도 한 번에 보관하려면 `land_run.py` 가 보관된 카드를 커밋하게 고쳐야 한다. 드라이버를
  다시 쓸 때 본다.

## Rule candidate

- 닫기 전에는 코드 커밋 뒤에 기록만 고친 커밋을 올리지 않는다. 2026-11-20 에도 같은 이유로 작업 폴더를 따로
  만들었다. 두 번째다. 닫기 리뷰가 볼 커밋을 `HEAD` 로 고정한 것이 원인이라, 규칙보다 그 자리를 고치는 것이
  낫다.
