# R-00000086 드라이버가 카드 하나를 직접 받게 한다

## Work

드라이버가 대상을 부모로만 받아 카드 하나를 돌리려면 껍데기 부모를 만들어야 했다. 이제
대상을 보고 판단한다 — 안 끝난 자식이 있으면 지금처럼 부모로 다루고, 없고 자신이 돌릴 수
있으면 자신을 돌린다. 감독·무인·dry run 이 같은 규칙을 쓰고 새 옵션은 없다. 도구의 호출
방법 때문에 없던 작업 단위가 기록에 생기던 오염이 사라졌다.

## Decision points

- "부모는 자식만 돌린다" 는 기존 보장을 어떻게 지키나 — 경계 테스트로 못 박았다. 안 끝난
  자식이 하나라도 있으면(돌릴 수 없는 자식이어도) 대상을 직접 돌리지 않는다. 이 테스트들은
  고치기 전 코드에서도 통과한다 — 새 기능이 아니라 기존 보장을 고정하는 테스트다.
- 이 카드 자체는 드라이버로 안 돌렸다 — 돌리려면 바로 이 카드가 없애려는 껍데기 부모를
  만들어야 했다. 마지막으로 손 위임을 쓴 카드가 된 셈이다.

## Principles applied

- **SSOT / 기록의 진실성** — 기록은 실제 일의 단위만 담는다. 도구 제약이 만들던 가짜 단위가
  원인이었고, 제약 쪽을 고쳤다.
- **MECE** — 대상의 두 경우(자식 있음/없음)가 겹치지 않고 빠지지 않는다. 자식이 있으면서
  말단일 수는 없다.
- **Honesty** — RED 를 실행자 보고와 별개로 저장소 밖 사본에서 재현했고, 경계 테스트가
  고치기 전 코드에서 통과하는 것까지 구분해 확인했다.

## Context that helped

- 카드의 `## Scope` 에 설계가 문장으로 확정돼 있어 위임 프롬프트가 그대로 옮겨 적는 수준이었다.
- 위임 전 캐시 확인 절차(P-00000001 에 기록)가 이번에는 한 번에 통했다.
