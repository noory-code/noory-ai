# R-00000376 PR 브랜치에서 CI 가 같은 테스트를 한 번만 실행하게 하기

## Work

워크플로 네 개의 `push` 조건을 `main` 브랜치로 한정했다. 그 한정이 빠지면 실패하는 테스트를 더했다.

## Decision points

- **`push` 를 없애지 않고 `main` 으로 한정했다.** 머지한 뒤의 `main` 도 한 번은 확인해야 한다. PR 브랜치가
  main 보다 뒤처진 채 머지되면 머지 결과는 PR 에서 확인한 트리와 다르다.
- **OS 와 Python 버전 조합은 그대로 두었다.** 사용자는 중복을 없애라고 했다. 조합을 줄이면 확인 범위가
  좁아져서 다른 결정이다.
- **테스트를 Stage 폴더에 두었다.** 워크플로를 지키는 테스트가 이미 거기 있다. 그래서 Stage 의 변경 기록에도
  한 줄이 들어갔다.

## Principles applied

- User intent: 사용자가 요청한 중복 제거만 했다.
- Honesty: 닫을 때 확인하지 못한 성공 기준과, PR 없는 브랜치에서 CI 가 실행되지 않게 된 것을 카드에 적었다.
- MECE: 테스트가 워크플로 파일을 모두 읽어서 빠지는 워크플로가 없다.

## Context that helped

- `gh pr checks --json workflow,event`. 검사를 워크플로와 실행 조건으로 세면 중복이 바로 보였다.

- 워크플로 테스트가 Stage 폴더에 있어서 저장소 전체의 CI 를 고쳐도 Stage 변경 기록에 적힌다.
