# R-00000419 후보를 적어 두는 것이 일감을 만들고 있었다

## Decision points

- 문턱의 내용은 사용자가 DE-00000102 에서 정했다. 이 카드는 그것을 문서와 브리핑에 옮겼다.
- 조건의 주인을 `operations/before.md` 의 "Follow-up candidates" 로 두었다. `after.md`, 지휘 스킬, `cloud-execution.md` 는
  한 문장으로 말하고 거기를 가리킨다.
- 세션 보고와 닫기 사이에 버린 수를 `Follow-up candidates discarded: <n>` 줄로 카드에 둔다. 후보의 내용은 적지 않는다.
  이 줄이 없으면 닫을 때 앞선 보고에서 버린 수를 더할 수 없다. 작업 세션이 정했고, 사용자가 그 세션에서 "추천대로"라고
  답했다고 작업 세션이 전했다. 지휘 세션은 그 말을 직접 듣지 않았다.
- 지휘 세션은 증거가 있는지만 본다. 재현 명령을 돌리거나 인용한 줄이 마일스톤 파일에 있는지 찾아보지 않는다. DE-00000102 가
  알고 고른 약점이다.
- 집계 줄은 지휘 세션이 손으로 적는다. 적었는지 보는 스크립트는 없다.
- 범위 밖인 `stage/scripts/started_cards.py` 의 설명 한 줄을 작업 세션이 고쳤다. DE-00000102 의 "Where this applies" 가 든
  자리다.

## Context that was missing

- 사용자가 토론 세션과 작업 세션의 대화에 직접 답했고, 지휘 세션은 그 답을 세션의 메시지로만 받았다. 같은 날 사용자가
  "왜 내가 하위 세션에 가서 답변을 줘야하지?"라고 물었다. 사용자의 말이 여러 세션에 흩어지면 지휘 세션이 무엇이 정해졌는지
  모른다.
- 문턱이 실제 후보를 얼마나 걸러 내는지는 쌓인 열세 건에 한 번 대 본 것이 전부다.
