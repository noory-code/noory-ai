# R-00000374 Windows 에서 리뷰어가 PowerShell 도구로도 테스트를 실행하게 하기

## Work

`claude_review_companion.py` 가 Windows 에서 리뷰어에게 `PowerShell(python3 -m unittest:*)` 규칙을 함께
허용하게 했다. 플랫폼마다 허용 목록이 무엇인지 확인하는 테스트를 더했다.

## Decision points

- **PowerShell 규칙은 Windows 에서만 붙인다.** macOS 와 Linux 의 Claude Code 에는 PowerShell 도구가 없다.
  없는 도구의 규칙을 넘기면 어떻게 되는지 확인하지 않았으므로 그쪽 허용 목록은 그대로 두었다.
- **감사 명령은 허용하지 않았다.** W-00000361 의 리뷰어는 감사 명령도 거절됐다고 했다. 그것은 Windows 문제가
  아니라 리뷰어가 `python3 -m unittest` 만 실행하게 한 설계다. 넓힐지는 이 카드에서 정하지 않았다.
- **원인을 단정하지 않았다.** W-00000361 의 리뷰어가 PowerShell 도구를 썼다는 기록은 없다. 거절되는 경우
  하나를 재현했고 그 경우를 고쳤다고만 적었다.

## Principles applied

- Honesty: 재현한 것과 확인하지 못한 것을 카드에 나눠 적었다.
- Fail Fast: 고치기 전에 실제 `claude` 로 규칙 세 가지를 비교해서 가정이 맞는지 먼저 봤다.
- MECE: 허용 목록을 플랫폼으로 나눴고 테스트가 세 플랫폼을 모두 확인한다.

## Context that helped

- `claude -p --output-format stream-json`. 리뷰어가 어느 도구를 불렀고 무엇이 거절됐는지 그대로 보였다.
- W-00000359 에서 판정 파일 쓰기 규칙을 고친 경험. 권한 규칙은 실제 `claude` 로 확인해야 한다는 것을
  알고 있었다.

## Context that was missing

- 작업 로그에는 리뷰어의 마지막 글만 남는다. 리뷰어가 어떤 도구를 불렀고 무엇이 거절됐는지 남지 않아서
  W-00000361 의 원인을 기록으로 확인할 수 없었다.

## Next changes

- 닫기 리뷰어의 모델인 opus 가 Windows 에서 어느 셸 도구를 고르는지 확인하지 않았다.
- 명령 뒤에 파이프를 붙이면 규칙에 맞지 않을 수 있다. 실행해 보지 않았다.

## Rule candidate

- 리뷰어에게 허용하는 규칙을 바꾸면 실제 `claude` 로 허용되는 경우와 거절되는 경우를 모두 실행해 본다.
  (2회차. 1회차는 W-00000359.)
