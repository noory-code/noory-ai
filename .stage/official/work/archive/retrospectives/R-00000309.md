# R-00000309 Claude 리뷰가 판정 파일 밖을 바꾸면 리뷰를 실패시킨다

## Work

W-00000309. 실제 `claude` 로 두 리뷰 경로를 재 보니, 리뷰어 자신의 쓰기는 권한 규칙이 막지만
`python3 -m unittest` 가 돌리는 시험 코드의 쓰기는 다 통과했다. 대역이 리뷰 앞뒤로 저장소를 비교해 판정 파일 밖이
바뀌면 판정을 지우고 경로를 알리며 3 으로 끝나게 했다. 프로젝트의 Claude 리뷰 명령도 같은 대역을 거친다.
외부 결과: 리뷰가 바꾼 트리를 같은 리뷰가 승인하는 일이 없다. 바뀐 경로가 리뷰 로그에 남는다.
내부 결과: scripts 전체 725개, hooks 393개가 통과하고, 실측 두 경로 모두 종료 코드 3 과 지워진 판정을 확인했다.
검사를 끄는 변이와 판정 파일 제외를 빼는 변이를 시험이 잡는다.

## Decision points

- 프로세스를 가두지 않고 앞뒤 스냅숏으로 잡았다. 샌드박스는 Stage 가 받치는 모든 호스트(Windows)에 없고, 리뷰어의
  직접 쓰기는 권한 규칙이 이미 막는다.
- 바뀐 파일을 되돌리지 않고 남겼다. 되돌리면 사람의 편집까지 지울 수 있다.
- 프로젝트 리뷰 명령이 대역을 거치게 해 권한과 검사를 한 곳에 두었다. 모델 고정은 명령 안의 환경 변수로 남겼다.

## Principles applied

Honesty: "리뷰어는 판정 파일만 쓴다"는 설명을 인자 검사가 아니라 실제 실행으로 확인하고, 틀린 부분을 고쳤다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.
이 카드가 고친 대역이 이 카드의 닫기 리뷰도 돌린다. 고친 검사가 그 리뷰에도 걸린다.

## Context that helped

- W-00000299 의 판정이 argv 검사의 한계와 재현 방향을 적어 두었다.
- 드라이버의 `repository_path_snapshot` 을 그대로 쓸 수 있었다. 무시 규칙과 `.stage/.runtime` 제외가 같다.

## Context that was missing

- 실측 첫 두 판은 시험 준비가 틀렸다. 카드와 로그를 프로젝트 밖에 두어 리뷰어가 못 읽었다. 리뷰 입력이 실제로
  어디 있는지를 시험 준비의 기준으로 먼저 적어 두었어야 했다.
- 이 세션의 앞선 닫기 리뷰들(W-00000305·306·307)은 이 검사 없이 돌았다. 리뷰어가 시험을 돌렸다면 그 시험이 쓴
  파일이 있었을 수 있지만, worktree 를 지워 지금은 확인할 수 없다. 그 카드들의 시험은 임시 폴더에만 쓴다.
