# R-00000268 보관할 때 카드 폴더의 기록 아닌 파일도 함께 옮긴다

## Work

W-00000268. `archive_one()` 이 카드 폴더를 보관할 때 `.md` 가 아닌 파일을 모든 깊이에서 같은
상대 위치로 바이트 그대로 옮긴다. 작업 기록은 지금처럼 `status: archived` 로 다시 쓴다.
외부 결과: 카드 폴더에 둔 증거 파일이 보관 뒤에도 남는다.
내부 결과: 새 시험 네 개를 더했고, 그중 이동 시험 두 개는 고치기 전 코드에서 실패한다. 인수 명령
24개와 scripts 전체 663개가 통과한다.

이 카드는 이 저장소에서 처음으로 Claude Code 클라우드 세션이 실행했다(DE-00000075). 고친 쪽은
클라우드의 Claude 이고, 범위 대조·시험·리뷰·닫기는 로컬에서 했다.

## Decision points

- 실행 자리: 정책상 codex 몫이지만 드라이버 명령이 이 컴퓨터의 경로를 불러 클라우드에서 돌지
  않는다. 카드 한 장에만 venue 예외를 세웠다(DE-00000075).
- 성공 기준 범위: 등록 직후 Claude 가 첫 기준을 "작업 기록이 아닌 모든 파일" 로 넓히면서 "작업
  기록이 아닌 `.md`" 를 넣었다. 클라우드 1회차가 그 전제가 틀렸다고 아무것도 바꾸지 않고
  보고했다. 카드 폴더의 `.md` 는 모두 작업 기록으로 읽히므로 감사와 보관이 막고, 말없이 사라지지
  않는다(`stage/hooks/stage_record_paths.py` 26행). 사용자가 클라우드 세션에서 그 종류를 빼는
  1안을 골랐고, 리뷰 전에 카드 기준을 그에 맞췄다.

## Principles applied

Fail Fast: 클라우드 실행자가 틀린 전제에서 일부만 고치지 않고 멈춰 보고했다.
Honesty: 클라우드 결과를 그대로 믿지 않았다. 범위 대조, 로컬 전체 시험, 고치기 전 코드로 되돌려
시험이 실패하는지 확인하는 일을 로컬에서 다시 했다.
만든 쪽 ≠ 보는 쪽: 클라우드의 Claude 가 고치고 로컬의 codex 가 판정했다.

## Context that helped

- 카드의 "카드가 틀렸다고 판단하면 아무것도 바꾸지 말고 이유만 보고한다" 조항이 클라우드에서도
  그대로 작동했다.
- 실행 보고를 커밋 메시지에 쓰게 한 덕분에 `.stage/.runtime/` 이 없는 클라우드 결과도 작업
  로그로 옮길 수 있었다.

## Context that was missing

- Claude 가 기준을 넓힐 때 넓힌 종류가 실제로 사라지는지 재현하지 않았다. 한 번 재현했으면
  `.md` 종류가 빠졌을 것이다.
- 클라우드 실행 계약에 보고 칸 이름만 적고 "칸마다 한 줄" 조건을 적지 않았다. 보고가 여러 줄로
  왔다. 닫기 도구는 형식을 검사하지 않아 막히지 않았지만, 드라이버 계약과 다르다.
- `close_work.py` 의 리뷰 대상은 HEAD 커밋 하나에서만 정해진다. 그래서 카드·회고 기록은 닫은
  뒤에 커밋해야 한다. 이 순서가 클라우드 계약에 없었다.
