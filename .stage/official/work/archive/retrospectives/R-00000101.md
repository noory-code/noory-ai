# R-00000101 드라이버 설명 문서를 계약 다섯 층에 맞춘다

## Work

`SCHEMA_V4.md` 의 무인 드라이버 절을 지금 동작에 맞췄다 — 공용 작업 로그, 실행자 주장과 드라이버
관찰의 대조, 실패가 로그에 남는 것, 리뷰 지적이 다음 바퀴로 흐르며 받는다/안 받는다/미룬다 를
근거와 함께 적는 것, 상한에 닿으면 커밋하지 않고 넘기는 것, 바퀴가 띄운 것을 거두는 것.
`stage-drive` 스킬이 가리키는 규칙 주인 목록에 계약을 넣었다.

## Decision points

- **이 카드가 필요했나.** 아니다. C1~C5 각 층이 자기가 무효화한 설명까지 범위에 넣었으면 문서가
  따로 밀리지 않았다. 카드 한 장이 생긴 것은 문서를 뒤로 미룬 대가다.

## Principles applied

- **SSOT** — 스킬이 "규칙은 여기 있다" 고 가리키는 문서가 실제와 달랐다. 가리키는 곳이 틀리면
  읽는 사람이 낡은 쪽을 진짜로 믿는다.
- **Honesty** — 문서가 코드보다 뒤처진 것을 그대로 두면 문서가 거짓말을 한다.

## Context that helped

W-00000097 리뷰어가 기준 밖 관찰로 짚었다. 기준 밖이라 그 카드를 막지 않았고, 사람이 판단해
별도로 처리했다 — DE-00000032 가 만든 처리 방식이 실제로 작동한 사례다.

## Context that was missing

각 층을 쪼갤 때 그 층이 무효화하는 설명 문서를 안 셌다.

## Next changes

계약이 적용되는 자리를 셀 때 **코드 호출 지점만 세지 말 것.** 설정, 설명 문서, 실패 경로도
같이 센다. 오늘 이 셋이 각각 따로 카드가 됐다 — 설정(claude 거두기), 문서(이 카드), 실패
경로(W-00000100·101). W-00000098 이 넣은 규칙을 이 방향으로 넓혀야 한다.
