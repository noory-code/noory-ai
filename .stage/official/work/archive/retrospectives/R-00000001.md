# R-00000001 Untrack .stage/.runtime/ — verification must be executed, not asserted

## Work

Removed the two tracked `.stage/.runtime/sessions/*.md` files from the git index so
`.gitignore:59` takes effect (`git rm -r --cached .stage/.runtime/`, commit a4add0a7).
The files remain on disk as session-local runtime data.

## Decision points

None material — the action is mechanical.

## Principles applied

- Honesty — the prior commit (79c86ee9) recorded `verification: passed` with evidence
  ("`git ls-files` empty after `git rm -r --cached`") that had never been produced: it
  added the `.gitignore` rule but never ran `git rm --cached`, so both files stayed
  tracked. An unrun verification was asserted as passed.
- Fail Fast — running `git ls-files .stage/.runtime/` at session start surfaced the two
  still-tracked files immediately, before any new work built on the false "done" state.

## Context that helped

`git ls-files` / `git check-ignore -v` are ground truth for tracked-vs-ignored state and
do not depend on the work item's own claims.

## Context that was missing

Nothing external. The gap was internal: a verification section written from intent rather
than from executed command output.

## Next changes

A work item's `verification: passed` must be backed by command output actually run in the
session that sets it — never by the commands that were merely supposed to run. Re-run the
stated verification before promoting an item to passed or completed.

## Promotion decision

`promotion: not_applicable` — the change is a git-index / `.gitignore` cleanup, nothing
under `.stage/official/`.
