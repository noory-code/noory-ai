# R-00000050 초기화가 기계 상태를 스스로 감추게 하다

## Work

Stage 초기화가 프로젝트 `.gitignore`에 `.stage/.runtime/`을 등록하도록 했다. 그동안은 사용자가
손으로 넣어야 했고, 빠뜨리면 세션 요약·승격 의도 같은 기계 상태가 커밋에 섞였다. 플러그인 0.38.0.

## Decision points

- `.stage/` 전체를 무시할 것인가, `.runtime/`만 무시할 것인가. Stage의 존재 이유가 이력을
  세션·기계 너머로 남기는 것이므로, 결정 기록과 회고는 추적하고 기계 상태만 무시하기로 했다.
- git 저장소가 아닌 디렉터리에서 `.gitignore`를 만들 것인가. 만들지 않기로 했다. 요청받지 않은
  파일을 남기지 않는다.
- 워크트리·서브모듈처럼 `.git`이 파일인 경우도 저장소로 볼 것인가. 본다.

## Principles applied

- SSOT — 무시 항목의 소유자를 초기화 스크립트 한 곳으로 정했다. 문서에 "직접 넣으세요"라고
  적어두는 방식은 사용자마다 상태가 갈라진다.
- Fail Fast — 바이트 단위 비교와 줄바꿈 없는 마지막 줄까지 테스트로 고정해, 기존 `.gitignore`를
  망가뜨리는 회귀가 즉시 드러나게 했다.
- MECE — 생성·덧붙임·중복·`.git` 파일·비 git·주석 줄까지 경우를 나누어 덮었다.

## Context that helped

`.stage/.runtime/`에 무엇이 들어가는지가 `stage_runtime.py`와 `stage_guard.py`에 흩어져 있어,
무시해도 되는 이유를 근거로 확인할 수 있었다.

## Context that was missing

`init_stage.py`에는 테스트 파일 자체가 없었다. 프로젝트 초기화는 모든 Stage 사용자가 가장 먼저
실행하는 경로인데도 회귀 검사가 없던 셈이다. 이번에 `test_init_stage.py`를 신설했다.

## Next changes

- Stage 초기화 시 뼈대 문서를 프로젝트 로케일로 생성하는지 확인한다. `.stage/` 안에 영어로 남은
  뼈대 파일이 약 53개 있고, 근본 원인이 초기화 템플릿이면 별도 항목으로 등록한다.
