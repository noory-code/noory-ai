# R-00000314 번호 도구가 제목 줄에만 번호가 있는 기록도 센다

## Work

W-00000314. 번호 도구가 frontmatter `id:` 줄만 세서, 제목 줄에만 번호가 있는 제안(P-)의 이미 쓴 번호를 빈 번호로
알리던 것을 고쳤다. O-00000056 을 닫았다.
외부 결과: 제안을 새로 쓸 때 보관된 제안과 번호가 부딪히지 않는다.
내부 결과: 작업 트리와 다른 브랜치 양쪽에서 제목 줄 번호를 센다. 모든 접두사를 파일 이름 최대 번호와 대조해 맞았다.

## Decision points

- 파일의 첫 제목만이 아니라 접두사로 시작하는 모든 1단계 제목을 센다. 더 세면 번호를 하나 건너뛸 뿐이고, 덜 세면 부딪힌다.
- 예전 제안에 frontmatter 를 덧붙이지 않고 `stage_records.py` 가 이미 받는 제목 줄 형식을 세게 했다.

## Principles applied

만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- 감사(SSOT001)가 중복 번호를 커밋 전에 잡아 버그가 드러났다.
- 모든 접두사를 파일 이름의 최대 번호와 대조하는 검사로, 틀린 것이 P 하나라는 것을 고치기 전에 확인했다.

## Context that was missing

- 도구를 만들 때 기록 형식이 둘(frontmatter, 제목 줄)이라는 것이 도구 쪽에 반영되지 않았다. 같은 사실을 읽는 코드가
  두 곳(`stage_records.py`, `stage_record_ids.py`)에 따로 있어서 한쪽만 알았다.

## Next changes
