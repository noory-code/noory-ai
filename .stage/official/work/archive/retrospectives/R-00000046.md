# R-00000046 자율 실행 드라이버 계약 umbrella 회고

## Work

Stage를 게이트/거버넌스 하네스에서 자율 실행 드라이버로 확장하는 계약을 설계·확정하고(DE-13~17, umbrella 소유), 구현을 다섯 자식으로 분해해 전부 shipping·검증·아카이브했다. umbrella로서 구현이 계약을 검증할 때까지 열려 있었고, supervised MVP(W-47)로 핵심 계약이 검증됐다.

다섯 통제 장치: W-43 종료 판정(acceptance) · W-44 독립 판정(venue 분리 + claude 자동 리뷰어) · W-45 집계(부모는 자식 전부 terminal 시만 완료) · W-46 에스컬레이션(escalate_work + 한계 config) · W-47 supervised 드라이버(drive.py). 각 자식은 자체 설계 결정(DE-18~23)을 가진다.

## Decision points

- DE-13 드라이버는 게이트와 분리된 별도 컴포넌트(게이트는 deny/allow만). DE-14 기계 판정 종료(acceptance). DE-15 parent 체인 집계. DE-16 독립 판정 필수. DE-17 에스컬레이션 1급 상태 + 폭주 상한. (자식 세부: DE-18 acceptance 스키마, DE-20 독립 판정 venue 분리, DE-21 집계 경계, DE-22 에스컬레이션 출구/한계, DE-23 드라이버 아키텍처+supervised 범위.)
- 실행 주체: 매 자식을 Codex가 구현(venue codex)하고, 독립 판정은 문맥 없는 `claude -p`가 수행 — DE-16을 이 작업 자체에 도그푸딩.

## Principles applied

- SSOT / MECE — 각 통제의 소유 위치를 단일화(acceptance·non_terminal_children·reviewers·limits·run state).
- SoC — 게이트 vs 드라이버, 출구 vs 루프 집행을 분리.
- Fail Fast / No partial completion — 상한·부재·막힘은 `blocked`, 가짜 완료 금지.
- Honesty — 실행자 오판을 증거로 정정; 미완 설계를 official로 승격하지 않음.
- AHA — 필요 전 추상화/스키마를 만들지 않음(런타임 상태는 드라이버에서).

## Context that helped

- 각 자식의 DE 계약이 구현을 결정적으로 만들었다.
- 기존 Stage 메커니즘(`--check`/run_check, review 리졸버, `parent`, `blocked`, 결정 기록)이 재사용 기반이었다.

## Context that was missing

- 백그라운드 Codex 완료를 이른 git status/idle 신호로 판정하다 두 번 오판 — 트리 안정화 폴링(긴 창) + 테스트 통과 확인으로 해결.
- 드라이버(DE-23)는 supervised MVP다. 전면 무인 루프·실물 executor 명령·자동 회고는 미완.

## Next changes
