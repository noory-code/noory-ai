# R-00000328 등급 표 설정을 읽어 등록하는 카드에 tier 를 적는다

## Work

공용 모듈 `stage/hooks/stage_model_tiers.py` 를 만들고, 등록(`register_work.py`)과 시작(`start_work.py`)이 카드에 `tier:` 를 적게 했다. v4 설정 템플릿에 claude 칸만 채운 네 등급을 실었고, `SCHEMA_V5.md` 에 계약을 적었다. 시험 20개를 더했다.

## Decision points

- Codex 실행기가 `gpt-6-astra` 를 ChatGPT 로그인에서 거부해서, 사용자 결정으로 `local-no-codex` 환경에서 Claude 가 실행했다.
- 카드 범위에 적은 `stage/templates/project-stage/settings.json` 은 init 이 쓰지 않는 옛 파일이었다. 실제 템플릿 `stage/templates/v4/project-stage/settings.jsonc` 를 고쳤고 경계 넘음으로 보고했다.
- 등급 설정이 틀리면 등록·시작은 거부하고(Fail Fast), 훅·드라이버 같은 실행 중 읽는 쪽은 등급이 없는 것으로 본다(호출을 깨뜨리지 않는다).
- 나중에 하려고 적어 두는 카드(planned)도 등록 때 등급을 적는다. 시작은 빈 등급만 채운다.

## Principles applied

SSOT(설정 읽기는 공용 모듈 하나), Fail Fast(잘못된 설정에서 등록 거부), Honesty(확인하지 않은 codex·agy 모델 이름을 템플릿에 넣지 않음), MECE(등록·시작·템플릿·문서가 각자 한 가지를 맡음).

## Context that helped

- `start_work.py` 의 `build_frontmatter` 가 모르는 키를 버린다는 것을 읽고 나서 시험을 썼다. 시험이 그 줄을 실제로 밟는지 그 줄을 지워서 확인했다(시험 2개가 깨졌다).

## Context that was missing

- 카드 범위를 쓸 때 init 이 어느 템플릿을 쓰는지 확인하지 않았다.
- 첫 닫기 때 scripts 시험 전체를 돌리지 않아, 템플릿 주석의 백틱을 금지하는 기존 시험이 깨진 것을 리뷰어가 먼저 찾았다. 다음 카드부터 닫기 검사에 hooks·scripts 시험 전체를 넣는다.
