# R-00000152 카드가 읽는 사람 몫을 자기가 안 지고 있었다

## Work

작업 카드를 쓰는 규칙 셋을 등록 절차에 넣었다. 제목은 할 일로 쓴다. 카드는 네 가지에 답한다 —
무엇을 하는가, 왜 지금인가, 무엇을 이루려는가, 언제 끝나는가. 뜻을 먼저 쓰고 번호는 뒤에 붙인다.

## Decision points

**제목 규칙을 뒤집었다.** 전 규칙은 "결과를 적고 단계를 적지 말라"였고, 나는 그것을 "끝난 상태로
쓰라"로 읽어 왔다. 사용자가 계획 카드를 열어 보고 "이게 일감인가요?"라고 물었을 때 방어할 말이
없었다. **일감의 제목은 할 일이다.** 결과는 목적 칸이 쥔다.

**규칙을 세 개로 늘린 이유.** 처음에는 제목만 고치려 했다. 사용자가 "일감이면 무엇을 왜 하는지,
어떤 목적인지, 종료 조건이 뭔지가 나와야 한다"고 짚었고, 그게 맞다. 제목은 증상이고 원인은 카드가
무엇을 담아야 하는지 아무 데도 안 적혀 있던 것이다. 세 번째(번호 말고 뜻)는 같은 대화에서 사용자가
내 카드 본문을 읽고 "이거 알아듣니?"라고 물어서 드러났다.

**과거 카드는 안 건드린다.** 보관된 카드 140여 장의 제목을 고치면 그것을 가리키는 회고와 결정의
인용이 어긋난다. 규칙은 앞으로 쓰는 카드부터다.

## Principles applied

- **Honesty** — 규칙을 잘못 읽어 온 것을 그대로 적었다. 전 규칙이 애매했다고 넘기지 않았다.
- **SSOT** — 카드의 어느 칸이 무엇을 쥐는지 표로 못 박았다. 칸은 있는데 무엇을 담는지 안 적혀 있어
  비어 있는 칸과 해당 없는 칸이 구분이 안 됐다.
- **documentation(본질 명명)** — 규칙마다 왜 그런지를 함께 적었다. 이유 없는 규칙은 급할 때 제일
  먼저 버려진다.

## Context that helped

- 사용자가 카드 파일을 직접 열어 본 것. 나는 항상 맥락을 들고 읽으므로 안 보이던 것이 그 순간
  드러났다. **읽는 사람이 없으면 읽기 문제는 안 보인다.**

## Context that was missing

- **같은 지적이 두 번째다.** 전에도 에픽 둘이 목적 칸을 비운 채 돌아 지적을 받았고, 그때는 그
  카드들만 채우고 규칙으로 안 올렸다. 한 번 더 겪고 나서야 규칙이 됐다.
- 규칙을 적었지만 **아무것도 그것을 강제하지 않는다.** 목적 칸이 빈 카드가 등록되는 것을 막는 검사는
  없다. 실행 검사 명령이 비면 드라이버가 거절하는 것이 유일한 자동 장치다.

## Next changes

- 목적과 끝나는 조건이 빈 카드를 검사가 거절할지 정한다. 지금은 규칙만 있고 장치가 없다. 규칙이
  또 안 지켜지면 그때 장치를 단다 — 문서로 안 되는 것이 확인된 뒤에 만든다.
- 앞으로 쓰는 카드가 규칙을 지키는지 다음 몇 장에서 본다.
