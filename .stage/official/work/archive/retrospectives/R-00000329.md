# R-00000329 드라이버가 카드 등급의 모델과 에포트를 실행기와 리뷰어에 넘긴다

## Work

드라이버가 카드 등급의 값을 `STAGE_MODEL`·`STAGE_EFFORT` 로 넘긴다. 실행기는 자기 venue 값을, 리뷰어와 `close_work.py` 의 닫기 리뷰는 리뷰어 venue 값을 받는다. 판마다 작업 기록에 `Model tier (JSON):` 한 줄이 남는다. 시험 11개를 더했다.

## Decision points

- 무인 경로의 리뷰는 `close_work.py` 를 거친다. 그래서 닫기 리뷰 환경도 고쳤다(범위 밖, 보고함). 이 덕분에 사람이 손으로 닫을 때도 같은 값이 넘어간다.
- `driver_venues` 가 `close_work` 를 가져오므로, 리뷰어 venue 를 고르는 함수를 `stage_paths.py` 로 옮겨 순환 import 를 피했다. 기존 호출부는 `driver_venues` 를 통해 그대로 쓴다.
- 부모 프로세스에서 물려받은 `STAGE_MODEL`·`STAGE_EFFORT` 는 버린다. 등급 없는 카드가 엉뚱한 값으로 돌지 않게 하려는 것이다.
- 명령이 변수를 읽는지(`command_uses_*_env`)를 기록한다. 명령에 모델을 박아 둔 프로젝트에서 감사가 "등급이 적용되지 않았다" 를 알릴 근거가 된다.

## Principles applied

SSOT(값은 공용 모듈 하나에서, 리뷰어 venue 판단도 한 함수), Fail Fast 대신 Postel's Law(등급 설정이 없거나 틀리면 실행 중에는 아무 값도 넘기지 않음), Honesty(무인 경로를 끝까지 돌려 보지는 않았다고 보고에 적음).

## Context that helped

- 기존 `test_drive.py` 의 가짜 실행기·리뷰어 틀 덕분에 드라이버를 끝까지 돌리는 시험을 짧게 썼다.
- W-00000328 에서 배운 대로 처음부터 hooks·scripts 시험 전체를 돌렸다.

## Context that was missing

- 무인 경로의 리뷰가 `close_work.py` 를 거친다는 것을 카드 범위에 반영하지 않았다.
