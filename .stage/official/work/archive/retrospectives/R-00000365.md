# R-00000365 다음에 할 일의 순서를 .stage 로 옮긴다

## Work

다음 카드 두 장을 `selected` 로 바꾸고, 개인 메모에만 있던 할 일을 계획 카드 세 장과 관찰 세 건으로 옮겼다.
개인 메모는 `.stage` 를 가리키는 안내로 줄였다.

## Decision points

- **새 자리를 만들지 않았다.** 순서는 계획 카드의 `status` 와 `priority` 가, 미룬 일은 관찰이 이미 맡고 있다.
  "다음 할 일" 문서를 따로 만들면 같은 사실의 둘째 자리가 된다.
- **일과 본 것을 갈랐다.** 사용자와 하기로 했거나 결정 기록이 미룬 것은 카드로, 내가 보고 적어 둔 것은
  관찰로 남겼다. 내가 본 것을 카드로 만들면 사용자가 정하지 않은 목적을 지어내게 된다.
- **찾은 고장을 이 카드에서 고치지 않았다.** 세션 시작 글의 목록이 나오지 않는 것은 훅 코드의 고장이다.
  이 카드는 기록만 고치는 계획 카드라서 유지 카드로 따로 등록했다.
- **새 카드의 상태는 `captured` 로 두었다.** `selected` 는 사용자와 순서를 정한 두 장에만 주었다.

## Principles applied

- SSOT: 다음 할 일의 자리를 저장소 하나로 했다. 개인 메모에는 안내만 남겼다.
- MECE: 메모에 있던 것을 일(카드), 본 것(관찰), 이 컴퓨터의 사정(다른 메모 파일)으로 나눴다.
- Honesty: 메모를 다 읽지 않고 옮겼다는 것과, 색인이 실린 세션으로 확인했다는 것을 카드에 적었다.
- Fail Fast: 상태를 바꾼 뒤 세션 시작 글을 직접 뽑아 보았고, 목록이 나오지 않는 것을 그때 찾았다.

## Context that helped

- `stage/operations/backlog.md` 의 상태 흐름. `selected` 가 "다음에 집을 일"이라는 뜻임을 알려 줬다.
- 세션 시작 훅을 명령으로 직접 실행할 수 있었다. 새 세션을 열지 않고 시작 글을 볼 수 있었다.

## Context that was missing

- 세션 시작 글의 "Selected backlog" 가 지금 구조에서 동작하지 않는다는 것. 테스트가 통과하고 있어서 아무도
  몰랐다. 테스트는 없어진 폴더 구조로 확인한다.
- 개인 메모가 200줄까지 자랐다는 것. 진행 기록을 한 줄씩 덧붙이는 방식이라 할 일과 지난 일이 섞여 있었다.

  세션 시작 글을 뽑아 보아서 고장을 찾았다. (1회차)
