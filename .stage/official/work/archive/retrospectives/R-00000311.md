# R-00000311 범위 넘음 알림에서 고치지 않은 경로를 뺀다

## Work

W-00000311. 범위 넘음 알림이 세션 transcript, `/dev/null`, 임시 폴더 파일, 펼치지 않은 `$TMPDIR/…` 를 넘은 경로로
내던 것을 고쳤다. O-00000050 을 닫았다.
외부 결과: 알림 한 줄이 뜨면 실제로 범위 밖 파일을 고친 것이다. 사람과 에이전트가 그 줄을 믿을 수 있다.
내부 결과: hooks 전체(397개)가 저장소 루트와 `/tmp` 아래 현재 폴더 양쪽에서, scripts 전체가 저장소 루트에서 통과한다.
고친 넷을 하나씩 되돌리는 변이를 시험이 모두 잡는다.

## Decision points

- 장치와 임시 폴더를 빼는 일은 알림에만 적용하고 `.stage` 게이트에는 적용하지 않았다. 게이트는 모든 대상을 본다.
- 작업 폴더 안 경로는 임시 폴더 안에 있어도 빼지 않는다. 시험 픽스처와 임시 폴더에서 도는 프로젝트가 그렇다.
- 홈 폴더 설정처럼 작업 폴더 밖이지만 실제 변경인 경로는 계속 알린다. 펼칠 수 없는 변수도 추측하지 않고 알린다.

## Principles applied

Honesty: 거짓 경고는 진짜 경고를 묻는다. 줄일 것은 거짓 경고이고, 진짜 넘음의 신호는 남겼다.
만든 쪽 ≠ 보는 쪽: 실행 맥락이 없는 별도 Claude 세션이 판정했다. 같은 모델 계열이라 교차 venue 판정은 아니다.

## Context that helped

- O-00000050 이 실제 호출 네 가지를 그대로 적어 두어 훅 함수에 바로 넣어 재현할 수 있었다.

## Context that was missing

- 관찰은 원인을 `mutation_targets` 로 짐작했지만, transcript 쪽 원인은 그 안의 `collect_explicit_paths` 가 페이로드
  전체를 훑는 데 있었다. 짐작은 방향만 맞았다.
- 처음 쓴 시험 하나가 이름과 반대로 검증하고 있었다(임시 폴더 안 경로를 "임시가 아님"으로 둠). 커밋 전에 고쳤다.
- 첫 닫기에서 hooks 시험 16개가 실패했다. `scratch_target` 이 상대 경로를 훅 프로세스의 현재 폴더 기준으로 풀어,
  `/tmp` 안 worktree 에서 돌면 모든 상대 경로가 임시 파일로 보였다. 저장소 루트에서만 시험을 돌려 놓쳤다. 두 번째
  시도에서 작업 폴더 기준으로 풀고, 현재 폴더를 옮겨 보는 시험을 더했다. 경로를 다루는 훅 변경은 현재 폴더를 바꿔서도
  시험해야 한다.
