# R-00000042 독립 판정 venue 분리 회고

## Work

자율 실행 드라이버의 세 번째 통제 장치 — 독립 판정 — 을 구현했다. `WorkItem`에 `venue` 파싱을 추가하고, `review.reviewers`(venue→명령) 해석기를 두어 자율 항목의 실행자와 다른 venue의 리뷰어를 유일하게 고르며(없거나 모호하면 fail-closed), `close_work`가 자율 항목 종료 시 이 반대-venue 리뷰를 강제한다(`BLOCK`/비영시 차단). 완료 게이트는 autonomous 항목에 `review: passed`를 요구한다. codex 실행 항목의 판정자로 `claude -p` 자동 리뷰어를 settings.json에 추가하고 실제 실행으로 검증했다. 실행은 Codex, 리뷰는 Claude(+문맥 없는 독립 `claude -p` 패스).

## Decision points

- DE-00000020: 판정자 venue ≠ 실행자 venue 강제 + claude 자동 리뷰어 신설. DE-00000016의 구현.
- claude 리뷰어의 실제 명령 형태를 settings 추가 시 실행 검증(허구 금지) — `claude -p`가 stdin diff를 읽어 `[P1]`/`APPROVED` 판정을 냄을 확인.

## Principles applied

- Honesty / No temporary passes — 실행자 자기검토를 구조적으로 차단(venue 분리).
- DIP — 판정 기준이 실행자에 종속되지 않음.
- Fail Fast — 독립 판정자 부재/모호 시 조용한 통과 대신 blocked.
- DRY — 기존 `run_check`·리뷰 래퍼(`BLOCK`/exit) 재사용.
- TDD — 신규 테스트 11개(파서 venue, 반대-venue 해석 실패/성공, 자율 강제, 비자율 불변) 통과.

## Context that helped

- DE-00000020 계약이 스키마·fail-closed 방침을 명확히 고정.
- 기존 `resolve_review_command` 패턴과 codex-companion 래퍼가 재사용 지점을 제공.

## Context that was missing

- `claude -p`의 stdin 동작은 사전 지식이 아니라 실제 실행으로 확인해야 했다.
