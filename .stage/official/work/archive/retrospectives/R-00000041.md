# R-00000041 acceptance 필드 구현 회고

## Work

자율 실행 드라이버의 첫 통제 장치 — 기계 판정 가능한 종료(acceptance) — 를 구현했다. work-item에 `autonomous`(bool)·`acceptance`(셸 명령 리스트) 필드를 추가하고, `register_work`/`start_work`가 autonomous 항목의 acceptance 누락을 거부하며, `close_work`가 item의 acceptance를 `--check`와 병합해 실행(전부 exit 0)한다. 템플릿·SCHEMA_V4.md·테스트 4종 포함. 실행은 Codex(venue codex), 독립 리뷰는 Claude가 수행.

## Decision points

- DE-00000018: acceptance 스키마 확정(셸 문자열 리스트, 명시 `autonomous` 플래그, `--check`와 통합).
- 실행 주체 오판·정정: 첫 git status를 Codex 완료 전에 확인해 "실행 실패"로 오판, venue 예외(DE-00000019)를 만들었다가, Codex 산출물이 실제로 반영된 것을 확인하고 예외를 되돌리고 venue를 codex로 복귀시켰다.

## Principles applied

- SSOT — 종료 조건의 소유 위치를 item의 `acceptance` 필드로 단일화.
- DRY — 기존 `run_check()` 실행 경로 재사용, 새 엔진 없음.
- Fail Fast — autonomous인데 acceptance가 없으면 등록/시작에서 거부.
- Honesty — 실행 실패 오판을 증거(작업 트리·테스트)로 정정.
- TDD — 파서·거부·병합·실패 케이스 테스트 존재, 훅 304 + scripts 264 통과.

## Context that helped

- DE-00000014/DE-00000018 계약이 스키마와 통합 방침을 명확히 고정.
- 기존 `--check`/`run_check()` 경로가 재사용 지점을 제공.

## Context that was missing

- 초기 grounding이 "acceptance 필드 없음"으로 오판 — 실제로는 계약 후 구현으로 채워졌다.
- 백그라운드 에이전트의 완료를 git status 조기 확인으로 판정 → Codex의 파일 쓰기 반영 전 상태를 보고 실패로 오인.
