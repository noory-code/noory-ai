# R-00000006 Encode lifecycle flows as skills; verify gate beliefs before acting on them

## Work

Added the `stage-work`, `stage-archive`, and `stage-handoff` skills and the
`archive_work.py` one-shot archiver; fixed a real hook bug (a shell redirection after
`git commit` read as a commit pathspec, causing false registration-gate denials); corrected the
false "two gates" learning in R-00000005; made "verification is executed, not asserted" a durable
`operations/verification.md` rule and added this repo's kind rows (audit now errors=0, warnings=0);
and clarified the SessionStart context line that had implied archiving needs a new work item.

## Decision points

- Whether to relax the archive "registration gate" the previous session reported. Reading
  `stage_paths.py` showed `.stage` is in `DEFAULT_EXCLUDED_PREFIXES`, so that gate never fires on
  `.stage/official/...` — there was nothing to relax. The fix was to encode the correct one-gate flow
  and correct the record, not to change enforcement.
- `archive_work.py` performs the moves directly (a trusted fast path) rather than only planting
  intents. Justified because it re-enforces the same invariants the promotion gate checks
  (terminal status, ref match, index row) and is tested and idempotent.

## Principles applied

- Honesty / Fail Fast — a reported "two gates" model was verified against the code and refuted
  before any work built on it; the false retrospective was corrected, not reflected.
- SSOT — one archive flow lives in `stage-archive`; `stage-retrospective` delegates to it; and no
  second work item is minted for work that already has one.
- KISS — a single validated command replaces a multi-step manual gate dance.

## Context that helped

`stage/hooks/stage_paths.py` (`DEFAULT_EXCLUDED_PREFIXES`) and a direct reproduction of the
`git_commit_pathspec_files` mis-parse settled both questions empirically instead of by assumption.

## Context that was missing

The operational knowledge for each lifecycle step existed only in hook source, so every session
re-derived it. That is the root cause these skills remove.

## Next changes

Use `git commit -F <file>` as a bare command (no shell redirection in the same invocation) until
the parser fix is confirmed live on the running hooks. As new Stage lifecycle steps recur, encode
them as skills rather than re-reading the hooks.

## Promotion decision

`promotion: not_applicable` — changes live in the `stage/` plugin package and present-flow records,
not this repo's `.stage/official/` canon.
