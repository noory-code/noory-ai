# R-00000019 Schema v4 topology registry

## Work

Implemented the dormant schema-v4 topology registry, official-zone path predicates, relocation
and lifecycle resolvers, stable DE plus legacy-D reference compatibility, family-local counters,
scan-root derivation, conformance ratchet, tests, and the Stage 0.24.0 release metadata.

External completion: W-00000019's requested C2 foundation is implemented without changing
schema-v3 consumer behavior. Internal completion: all public registry functions are exercised,
both full unittest suites pass, strict Stage audit is clean, manifests agree, and source checks
pass. Retrospective completion: the adoption constraint and measurement corrections are recorded
here and in DE-00000010.

## Decision points

- The card simultaneously required zero legacy topology literals and prohibited the consumer
  rewrites needed to reach zero. The repository owner approved a measured ratchet until the
  scheduled consumer-adoption cards (DE-00000010).
- Initial measurement covered hooks and scripts but omitted executable skill Python. Expanding
  the scan to all production Python corrected the baseline to 11 modules, 85 occurrences on 71
  source lines.
- `stage_topology.py` remains one cohesive registry despite exceeding 500 lines because splitting
  its declaration table from its resolvers would create two topology owners. Most lines are
  immutable data declarations rather than mixed responsibilities.

## Principles applied

- SSOT: v4 topology facts live in `stage_topology.py`; `stage_paths.py` owns only authorization
  containment, guarded by a parity test. DE-00000010 owns the temporary adoption exception.
- MECE: every declared family zone is resolvable, relocation destinations are bijective, and the
  conformance scan covers hooks, scripts, and executable skill Python.
- Fail Fast: ambiguous rejected-card locations, invalid decision-derived lifecycle, unknown scan
  purposes, new legacy consumers, and count increases all fail explicitly.
- AHA: C2 ships a dormant registry without prematurely rewriting consumers assigned to C4-C5
  and migration C7.
- Honesty: the initial 66-line measurement was corrected to 85 occurrences on 71 lines; no
  zero-literal completion was claimed early.
- Completion: external, internal, and retrospective perspectives were all verified before close.

## Context that helped

- `stage/docs/SCHEMA_V4.md`, DE-00000009, W-00000018, and its retrospective provided the frozen
  interface, official-zone amendment, and implementation sequence.
- Root `CLAUDE.md` supplied the Python, cross-platform, plugin-version, and verification rules.
- Existing hook and script tests established the import style and protected schema-v3 behavior.

## Context that was missing

- The design did not state how a zero-legacy-literal test could coexist with dormant v3 consumers.
  DE-00000010 now owns the incremental enforcement rule.
- The first measurement command scoped only hooks and scripts. Future production conformance
  scans must begin at the plugin root and exclude tests explicitly, rather than enumerate likely
  executable directories from memory.
