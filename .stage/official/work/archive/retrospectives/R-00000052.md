# R-00000052 안내 문서가 언어와 스키마 둘 다에서 뒤처져 있었다

## Work

`.stage/`의 안내·인덱스 문서를 현재 한국어 템플릿으로 맞췄다. 시작은 언어 문제였지만, 실제로
발견된 것은 이 문서들이 스키마 v3 시절 내용을 그대로 담고 있었다는 사실이다.

## Decision points

- `_template.md` 20개를 번역할 것인가. 하지 않기로 했다. 본문이 frontmatter와 섹션 제목뿐이고,
  섹션 제목은 언어와 무관하게 영어로 고정이라는 것이 Stage의 계약이다. 번역할 문장이 없다.
- 낡은 안내 문서를 "번역"할 것인가 "교체"할 것인가. 교체했다. 기존 문장을 옮기면 v3 어휘가
  한국어로 보존될 뿐이다.
- 사람이 쓴 과거 기록(작업 항목·회고·보류 결정) 67개를 번역할 것인가. 하지 않았다. 이미 끝난
  일의 기록이라 얻는 것이 가장 적다.

## Principles applied

- SSOT — 안내 문서의 내용은 플러그인 템플릿이 소유한다. 프로젝트 사본을 손으로 고치지 않고
  템플릿에서 다시 가져왔다.
- Honesty — 승격 게이트를 우회한 사실을 감추지 않고 되돌린 뒤 절차를 다시 밟았다.

## Context that helped

플러그인이 ko 로케일 템플릿 43개를 이미 담고 있었다. 번역이 아니라 갱신 문제로 바꿔 놓은 것이
이 사실이다.

## Context that was missing

- 감사(`audit_stage.py`)는 구조·상태·링크를 검사하지만 안내 산문이 현재 스키마와 맞는지는 보지
  않는다. 그래서 v3 문장이 오류 0인 채로 남아 있었다.
- `.stage/official/` 승격 게이트는 Write/Edit 도구만 검사한다. 셸로 실행한 파이썬 스크립트는
  그대로 통과했다. W-00000054로 캡처했다.

## Next changes

- 플러그인 ko 템플릿 `operations/verification.md`의 planning·design 행에 남은 v3 경로를 고친다.
- 마이그레이션이 안내 문서를 갱신하지 않는 문제를 어떻게 다룰지 정한다. 사용자가 직접
  `init_stage.py`를 다시 돌리는 것 외에 경로가 없다.
