# R-00000358 훅 명령이 Windows에서는 python을 부르게 고친다

## Work

python.org 에서 설치한 Windows 에는 `python3` 명령이 없다. 훅 명령 여섯 줄(Stage 다섯 줄, evonest 한 줄)이
`python3` 를 불러서, 그런 기기에서는 훅이 시작하지 못했고 Claude Code 는 도구 호출을 그대로 진행했다.
명령 앞에 `case "$OS" in Windows_NT) p=python;; *) p=python3;; esac; "$p" ` 를 붙여 Windows 에서는
`python` 을 부르게 했다. 명령이 이 형태를 벗어나면 실패하는 테스트를 두 패키지에 더했다. macOS 와
한국어 Windows(cp949) 양쪽에서 실제 세션의 훅이 인라인 코드를 거절하는 것을 확인했다.

## Decision points

- 고치는 방법: 명령 안에서 OS 를 보고 인터프리터를 고르는 안과, 훅이 실패하면 도구 호출을 막는
  설정(`onFailure: "block"`)을 넣는 안이 있었다. 사용자가 앞의 안만 골랐다. 뒤의 안은 넣지 않았다.
- Windows 를 구분하는 값: `uname` 을 부르지 않고 `OS=Windows_NT` 환경 변수를 봤다. 훅마다 프로세스를
  하나 더 띄우지 않는다.
- 확인하는 순서: 맥북에서 고치고 PR 을 열어 둔 채 Windows 세션이 실행해 본 뒤에 닫았다. 사용자가
  "Windows 확인 뒤 머지" 라고 했다.
- 카드 번호: Windows 세션과 번호가 두 번 겹쳤다(356, 357). 사용자가 "내 카드를 357로" 라고 해서 이
  카드 번호를 바꿨고, 두 번째도 같은 결정을 따라 358 로 바꿨다.
- 번호를 바꾸며 이미 push 한 커밋을 고쳐 쓰려던 명령은 거절됐다. 커밋을 더하는 쪽으로 바꿨다. 예전
  커밋 메시지에는 W-00000357 이 남아 있다.

## Principles applied

- Honesty: `python3` 를 설치한 적 없는 기기가 아니라 `PATH` 에서 뺀 기기에서 실행한 것, evonest 훅을
  실제 세션에서 실행하지 않은 것, Git Bash 가 없는 Windows 와 Codex 에서 실행하지 않은 것을 카드에 적었다.
  확인하지 않은 Codex 동작을 변경 기록에 썼다가 지웠다.
- Fail Fast: 테스트를 먼저 쓰고 실패를 본 뒤 고쳤다. 고친 줄을 되돌리면 테스트가 실패한다.
- SSOT: 훅 명령 규칙은 루트 `CLAUDE.md` 한 곳에 두고 `stage/hooks/README.md` 는 그 형태를 설명한다.
- MECE: 저장소의 `hooks.json` 두 개와 그 안의 명령 여섯 줄을 모두 고쳤다.

- Codex 가 Windows 에서 훅 명령을 어느 셸로 실행하는지 모른다. 구독이 끊겨 실행해 볼 수 없다.

## Rule candidate

- 두 세션이 같은 저장소에서 카드를 등록할 때는 등록하기 전에 fetch 하고, 등록한 뒤 바로 push 한다.

  알았다.
