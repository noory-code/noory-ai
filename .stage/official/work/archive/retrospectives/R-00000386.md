# R-00000386 실행자 모델이 사용량 한도에 걸리면 같은 venue의 다른 모델로 넘어가는 순서를 둔다

## Decision points

- **시작할 때 두 가지를 사용자가 골랐다.** 순서는 venue 마다 한도 묶음의 목록(`model_fallbacks`), 다시 실행은 시도 횟수에 세지
  않는다. 한도를 알아보는 문구(`usage_limit_patterns`)는 메인 세션이 정했다. 셋 모두 카드의 `## Progress` 에 적고 서브세션에
  넘겼다.
- **카드 한 장인데도 서브세션에 맡겼다.** DE-00000094 는 카드 한 장은 메인 세션이 하라고 한다. 그 기준의 근거는 서브세션이 같은
  문서를 처음부터 읽는 비용이다. 이번에는 메인 세션의 대화가 아주 길어서 메인 세션이 드라이버 코드를 새로 읽는 쪽이 더
  비쌌다. 서브세션 비용은 아래 Verification 에 있다.
- **서브세션이 올린 확인 거리 셋을 사용자가 2026-11-22 에 추천대로 받아들였다.** 모든 묶음이 막히면 드라이버만 멈추고 카드는
  막힘으로 바꾸지 않는다. agy 문구는 카드의 오류 한 건에서 왔고 다시나에서 실제로 맞춰 본다. 한도에 걸린 모델이 남긴 작업은
  다음 모델이 이어받는다.

- **메인 세션의 맥락이 클 때는 카드 한 장도 서브세션에 맡길 수 있다.** DE-00000094 의 "나눌지" 기준은 서브세션 쪽 비용만 본다.
  메인 세션 쪽 비용도 함께 보도록 고칠지 본다. (1회차 — 아직 규칙으로 올리지 않는다)
