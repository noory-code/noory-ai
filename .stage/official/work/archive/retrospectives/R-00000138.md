# R-00000138 정직성 규칙을 스타일 밖으로 옮긴 회고

## Work

plainly 의 정직성 규칙 두 문장(추측을 사실로 말하지 않는다, 확인 안 된 주장은 표시한다)이
스타일 경계 밖 고정 주입으로 올라갔다. `baseline.md` 에서는 빠져 한 응답에 두 번 실리지
않는다. plainly CHANGELOG 에 미출시 절이 처음 섰다 — 이 저장소의 새 릴리스 규칙을 plainly 가
받는 자리다. 매니페스트는 0.4.1 그대로.

한 바퀴에 통과(기준 여섯 전부 PASS).

## Decision points

- **찾은 방법이 이번 일의 핵이다.** 카드를 만들기 전에 실사용을 대조했다 — 이 저장소가 쓰는
  `.plainly/style.md` 25 줄과 `runtime.py` 의 외부 파일 갈래를 같이 읽고, 외부 파일이 baseline
  을 **안 붙인다**는 것을 코드에서 확인했다. 그래서 "오늘 하루 정직성 규칙 없이 돌았다"가
  추측이 아니라 사실이었다.
- **동작을 안 바꿨다.** 외부 파일이 baseline 을 대체하는 것은 스타일 저자에게 전권을 주는
  설계 선택이다. 정직성이 고정 주입으로 올라가면 위험이 사라지므로 대체 동작은 그대로 뒀다 —
  더 적게 고치고 같은 결과를 얻는다.
- 선례를 따랐다. 0.4.0 이 언어 규칙을 스타일에서 고정 주입으로 옮긴 판단과 같은 자리, 같은
  이유다. 새 구조를 만들지 않았다.

## Principles applied

- Honesty — 이 카드 자체가 그 원칙의 적용이다. 문체는 고르는 것이고 안 속이는 것은 아니다.
- SSOT — 규칙 하나가 한 자리에만 있다. baseline 과 고정 주입 양쪽에 두지 않았다.
- AHA — 새 계층(언어별 스타일 층 같은 것)을 만들지 않았다. 지금 있는 자리로 충분했다.

## Context that helped

- README 가 이미 "언어 규칙은 모든 내장·외부 스타일에 적용된다"고 선언해 둔 것. 그 문장이
  "스타일과 무관한 고정 규칙"이라는 자리가 이미 있음을 알려 줬고, 정직성이 왜 거기 없는지가
  바로 질문이 됐다.
- 결과를 즉시 눈으로 확인했다 — 다음 턴의 주입 문맥에 정직성 문장이 경계 밖에 붙어 왔다.

## Context that was missing

- 없음. 카드가 작고 경계가 분명했고, 기준이 실행 가능한 형태였다.
