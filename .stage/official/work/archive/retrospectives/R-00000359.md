# R-00000359 리뷰 명령을 셸 문법 없이 Python 스크립트로 실행하기

## Work

이 프로젝트의 리뷰 명령 여섯 개는 POSIX 셸 문법으로 리뷰어의 출력을 받아 작업 로그에 덧붙였다.
Windows 의 `cmd.exe` 는 그 문법을 실행하지 못해서, 리뷰가 필요한 카드를 Windows 에서 닫을 수 없었다.
`stage/scripts/run_review.py` 를 더해 그 일을 Python 으로 옮겼고, 설정의 리뷰 명령 여섯 개를 그
스크립트 호출로 바꿨다. Windows 에서 건너뛰던 테스트 두 개가 이제 실행된다.

## Decision points

- 처음에는 `close_work.py` 가 Windows 에서 Git 의 `sh` 를 찾아 명령을 넘기는 방법을 권했다. 사용자가
  "우리 파이썬만 쓰기로 했던 것 같다"며 멈추게 했다. 그 방법은 Stage 를 Git Bash 에 기대게 하고,
  `SCHEMA_V4.md` 가 정한 `cmd.exe` 실행과 `%VAR%` 문법의 Windows 설정을 깨뜨린다. 코드를 쓰기 전에
  멈췄다.
- 명령을 실행하는 쪽(`close_work.run_check`)은 고치지 않고 명령 문자열을 고쳤다. 플랫폼의 셸로 넘기는
  계약은 그대로 두고, 두 셸이 똑같이 읽는 문법만 쓰게 했다.
- `$STAGE_이름` 은 스크립트가 직접 펼친다. POSIX 셸은 넘기기 전에 이미 펼치고 `cmd.exe` 는 그대로
  두므로, 스크립트가 한 번 더 펼치면 양쪽에서 같은 값이 된다.
- 실행자 명령(`executors`)은 다루지 않았다. 닫기에 쓰이지 않는다.

## Principles applied

- SSOT: 설정 파일 하나가 모든 플랫폼에서 쓰인다. Windows 용 설정을 따로 두지 않았다.
- Fail Fast: 프로젝트의 리뷰 명령에 셸마다 다르게 읽히는 문법이 들어오면 테스트가 실패한다.
- Honesty: macOS 와 Linux 에서 실행하지 않았다는 것과, 닫을 때 받는 리뷰가 같은 모델의 리뷰라는
  것을 카드에 적었다.
- AHA: 실행자 명령까지 감싸는 일반 도구를 만들지 않고 리뷰 명령만 다뤘다.

## Context that helped

- 루트 `CLAUDE.md` 의 Cross-Platform 표와 `SCHEMA_V4.md` 의 플랫폼 셸 설명.
- 실제 `claude` 를 띄우는 검사(`LiveReviewerWriteProbeTest`). 테스트만으로는 알 수 없던, 리뷰어가
  `cmd.exe` 를 거쳐 끝까지 실행되는지를 이 검사로 확인했다.

## Context that was missing

- 설계를 권하기 전에 루트 `CLAUDE.md` 의 Cross-Platform 표를 다시 읽지 않았다. 읽었다면 `sh` 를
  권하지 않았을 것이다.
- 실제 리뷰어 검사는 Windows 에서 한 번도 실행된 적이 없어서, 검사 코드에 Windows 문제가 세 군데
  있다는 것을 아무도 몰랐다.

## Next changes

- 실행자 명령도 POSIX 문법이다. Windows 에서 드라이버를 쓰려면 같은 방식으로 바꿔야 한다. 지금은
  Windows 에 tmux 가 없어 드라이버를 쓰지 않으므로 카드로 등록하지 않았다.
- W-00000356 과 W-00000357 은 이 변경이 main 에 들어가면 Windows 에서 닫을 수 있다.

## Rule candidate

설계를 권하기 전에 루트 `CLAUDE.md` 의 Cross-Platform 표에 그 방법이 금지되어 있는지 확인한다.
이미 있는 규칙을 읽으라는 말이라 새 규칙으로 올리지 않는다.
