# DE-00000010 Baseline legacy topology literals until consumer adoption

## Question

How should C2 enforce the schema-v4 no-legacy-literal conformance rule while its scope also
requires all schema-v3 consumers to remain unchanged until C4-C5 and migration C7?

## Options

- Establish a measured C2 baseline: fail on any new production module containing a legacy
  topology literal or any increase above the verified per-module counts; allow counts to fall.
  C4-C5 and C7 reduce the baseline to zero as they adopt the registry.
- Expand C2 to rewrite all consumers immediately, absorbing C4-C5 and migration work from C7
  and changing the frozen dependency sequence.

## Principles applied

- SSOT: `stage_topology.py` owns v4 paths; the conformance baseline records only temporary v3
  consumer debt and must disappear as those consumers adopt the registry.
- MECE: the baseline enumerates every production Python module, including skill executables,
  outside the two topology owners; unlisted modules and count increases are both rejected.
- Fail Fast: new debt fails the test immediately instead of hiding behind a broad exemption.
- AHA: consumer behavior is not abstracted or rewritten before its scheduled implementation
  cards, while the measured repetition justifies the registry introduced by C2.
- Honesty and No silent substitution: C2 does not claim zero legacy literals while 85 verified
  occurrences on 71 source lines remain across 11 schema-v3 consumer modules.

## Chosen direction

Establish the measured baseline in C2. The repository owner approved this direction on
2026-07-13. The test permits only reductions from the verified per-module counts and requires
all new production Python modules to contain zero legacy topology literals.

## Reason

This preserves v3 runtime behavior and the C2-C9 dependency sequence while creating an
executable ratchet toward the final zero-literal rule. Rewriting consumers in C2 would violate
the card's explicit exclusions and duplicate work already assigned to later cards.

## Follow-up

- C4-C5 remove hook and command-consumer entries as each module adopts `stage_topology`.
- C7 removes the migration consumer entries and changes the conformance expectation to zero.
- W-00000019 retrospective must note that design-level zero-tolerance constraints need an
  explicit adoption phase when the same card requires legacy behavior to remain operational.
