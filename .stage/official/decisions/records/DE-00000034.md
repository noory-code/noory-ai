# DE-00000034 드라이버 한 바퀴의 역할 계약

## Question

드라이버가 한 바퀴를 돌 때 작업자·리뷰어·드라이버는 서로 무엇을 주고받는가. 무엇을 근거로
통과를 정하고, 언제 끝나고, 안 끝나면 어떻게 하는가.

지금까지 이 질문에 답한 문서가 없다. 사고가 날 때마다 그 자리에서 판단을 하나씩 만들어
넣었고(W-00000073, 77, 81, 83, 89, 90, 92, 94), 그 덧댐이 다음 사고를 불렀다.

## Options

### A. 지금 구조에 빈 인덱스 방어를 덧댄다

리뷰어에게 실행자 인덱스를 계속 물려주되, 인덱스가 비었는데 HEAD 에 파일이 있으면 리뷰
전에 막는다. W-00000094 의 원래 형태.

비용은 가장 싸다. 그러나 방어를 하나 더 얹는 것이고, 다음 오염 방식이 오면 또 카드가 는다.

### B. 드라이버가 리뷰 자료를 텍스트로 조립해 넘긴다

드라이버가 자기 환경에서 diff 를 떠서 리뷰어에게 stdin 으로 준다. 인덱스를 물려주지 않는다.

인덱스 문제는 사라진다. 그러나 리뷰어가 여전히 diff 텍스트만 본다. 이 리뷰는 PR 리뷰가
아니라 루프 중간 점검이고, 리뷰어는 저장소 안에서 돌아 파일을 직접 열 수 있다. 대용품을
계속 쓰는 선택이다. 또 리뷰 자료가 커질수록 입력 한계에 다시 닿는다.

### C. 카드마다 로그 파일 하나를 두고 그 경로를 양쪽에 넘긴다

드라이버가 카드마다 로그 파일을 만들고, 작업자와 리뷰어에게 그 **경로**를 넘긴다. 작업자는
거기에 한 일과 바뀐 파일을 쓰고, 리뷰어는 그것과 카드를 읽고 저장소 파일을 직접 열어 기준
마다 판정을 덧붙인다. 드라이버는 실행 전후를 자기 환경에서 관찰해 작업자의 진술과 대조하고,
왕복을 세고 끝을 정한다.

자료를 통째로 옮기지 않고 파일 하나를 같이 보게 한다. 인덱스를 물려줄 일이 없고, 도구
세션이 죽어도 기억이 남고, 사람이 나중에 그 파일만 열면 경위를 안다.

## Principles applied

- **SSOT** — 한 바퀴의 사실(한 일, 바뀐 것, 판정, 남은 것)이 로그 파일 하나를 소유 위치로
  갖는다. 지금은 실행자 출력, 리뷰어 출력, 카드, 사람의 기억에 흩어져 있고 대부분 버려진다.
- **MECE** — 역할 셋이 겹치지 않고, 주고받는 것이 빠짐없이 열거된다. 지금까지 덧댄 방어가
  각각 이 계약 안에서 어디로 가는지 아래 대조표가 덮는다.
- **Fail Fast** — 작업자의 진술과 드라이버의 관찰이 어긋나면 리뷰까지 가기 전에 끊는다.
- **AHA** — 새 추상화를 먼저 만들지 않는다. 로그 파일은 사고 열 건이 같은 결핍(바퀴 사이에
  정보가 안 흐른다)을 반복해 보인 뒤에 도입한다.
- **KISS** — 드라이버가 넘기는 것은 경로 셋(카드, 작업 위치, 로그)이다. 자료를 만들어
  나르지 않는다.
- **DIP** — 계약은 역할로만 쓴다. 도구 이름이 계약에 들어가면 도구마다 예외가 생긴다.
- **Honesty** — 밖에서 온 말은 안내이지 판정 근거가 아니다.

## Chosen direction

**C.** 아래를 계약으로 확정한다.

### 역할

| 역할 | 책임 |
|---|---|
| 작업자 | 카드를 받아 고친다. 커밋하지 않는다. 한 일과 바뀐 것을 로그에 쓴다. 리뷰 지적을 카드 목적에 대고 받을지 정하고, 그 판단과 근거를 로그에 쓴다. |
| 리뷰어 | 카드와 로그를 읽고 저장소 파일을 직접 열어, 카드의 성공 기준마다 판정을 로그에 쓴다. |
| 드라이버 | 로그를 만들고 경로를 넘긴다. 실행 전후를 자기 환경에서 관찰한다. 작업자 진술과 대조한다. 카드의 인수 검사를 직접 돌린다. 왕복을 세고 끝을 정한다. |

### 한 바퀴에 오가는 것

1. 드라이버 → 작업자: 카드 경로, 작업 위치, 로그 경로
2. 작업자 → 로그: 무엇을 왜 했나, 무엇이 바뀌었다는 주장, 리뷰해 달라는 요청
3. 드라이버: 실행 전후 저장소 관찰 → 바뀐 파일 목록. **작업자에게 넘긴 격리 인덱스가 아니라
   저장소 본래 상태를 자기 환경에서 본다.**
4. 드라이버: 작업자 주장과 관찰을 대조. 어긋나면 여기서 실패
5. 드라이버: 카드의 인수 검사를 직접 실행
6. 드라이버 → 리뷰어: 카드 경로, 로그 경로, 관찰한 바뀐 파일 목록
7. 리뷰어 → 로그: 기준마다 통과/실패와 근거. 기준 밖에서 본 것은 따로 표시
8. 드라이버: 기준이 전부 통과면 커밋하고 닫는다. 남았으면 다음 바퀴로, 남은 항목을 작업자에게
9. 작업자 → 로그: 지적마다 받는다 / 안 받는다 / 미룬다 + 근거. 받은 것은 고친다
10. 상한에 닿을 때까지 반복. 닿으면 커밋하지 않고 사람에게 올린다

### 계약이 적용되는 자리

역할은 셋이지만 각 역할이 실제로 도는 자리는 하나가 아니다. 계약은 아래 자리 **전부**에
같이 적용된다. 한 자리만 고치면 나머지가 옛 방식으로 남는다.

코드에서 센 결과다(`run_check` 호출 지점 전수).

| 역할 | 도는 자리 | 쓰는 설정 |
|---|---|---|
| 작업자 | 감독 모드 한 스텝 (`drive.py:1270`) | `executors` |
| 작업자 | 무인 모드 한 스텝 (`drive.py:1014`) | `executors` |
| 인수 검사 | 감독 모드 한 스텝 (`drive.py:1320`) | 카드의 `acceptance` |
| 인수 검사 | 카드를 닫을 때 (`close_work.py:314`) | `--check` 인자 |
| 리뷰어 | 감독 모드 한 스텝 (`drive.py:1339`) | `review.reviewers` |
| 리뷰어 | 무인 항목을 닫을 때 (`close_work.py:349`) | `review.reviewers` — **같은 명령** |
| 리뷰어 | 단계 리뷰로 닫을 때 (`close_work.py:372`) | `review.strengths` |

리뷰어가 도는 자리는 셋이고, 그중 둘이 같은 명령 문자열을 쓴다. 그래서 그 명령이 무엇을
받는지 바꾸면 부르는 쪽 **둘 다** 그것을 줘야 한다. 한쪽만 고치면 다른 쪽은 없는 것을 읽으러
간다.

무인 모드는 스텝 안에서 리뷰어를 부르지 않고 닫을 때 부른다. 닫기 리뷰가 계약 밖에 남으면
무인 모드는 계약을 하나도 못 받는다.

부르는 쪽이 리뷰어에게 파일 목록을 만들어 주는 방법은 자리마다 다르다 — 드라이버 스텝은
실행 전후를 비교하고, 닫기는 커밋이 끝난 뒤이므로 그 커밋이 담은 파일을 쓴다. 어느 쪽이든
**부르는 쪽이 자기 손으로 만든다**(규칙 1).

### 한 바퀴가 실패하면 무엇이 남는가

처음 이 계약을 쓸 때 성공하는 길만 봤다. 그래서 실패하는 길을 처음 밟자마자(W-00000097,
2026-07-27) 구멍이 셋 나왔다. 실패도 그 바퀴의 사실이므로 성공과 같은 자리에 같은 방식으로
남아야 한다.

실패할 수 있는 자리 (`drive.py` 에서 셈):

| 자리 | 위치 | 지금 남는가 |
|---|---|---|
| 실행자가 0 이 아닌 코드로 끝남 | 1060 | **아니오** — 실행자 출력이 버려진다 |
| 실행자가 저장소를 하나도 안 바꿈 | 1063 | 사유 한 줄만 |
| 실행자 진술이 드라이버 관찰과 어긋남 | 1079 | 사유 한 줄만 |
| 인수 검사 실패 | 1320 (감독) | 감독은 출력, 무인은 닫기 쪽 |
| 리뷰어 명령이 죽거나 차단 판정 | 1339 (감독) | 감독은 출력 |
| 상한에 닿아 사람에게 올림 | 1092 | **커밋이 막힌다** |

규칙 넷:

1. 실패한 시도의 산출물은 버린다 (지금 그렇게 한다).
2. **실패 이유와 그때의 실행자·리뷰어 출력은 공용 로그에 남는다.** 실행자가 "다 했다" 고
   적어 놓았는데 드라이버가 실패로 판정하는 경우가 실제로 있었다 — 판단이 갈렸는데 근거가
   사라지면 사람이 아무것도 못 한다.
3. **그 바퀴가 밖에 띄운 프로그램은 바퀴가 끝나면 거둔다.** 성공이든 실패든. 안 거두면
   다음 위임이 조용히 막힌다 (2026-07-27 에 실행자 여섯 개가 살아남아 저장소를 계속 썼다).
   밖에 띄우는 것이 없는 venue 는 그 사실을 설정에 밝힌다 — 예를 들어 명령을 동기로 부르고
   끝나면 같이 끝나는 도구는 거둘 것이 없다. 그것을 표현할 수 없으면 매번 경고가 나고, 그러면
   사람이 경고를 무시하게 되어 진짜 경고까지 묻힌다.
4. **실패를 기록하는 커밋은 반드시 성공한다.** 무시 대상 경로 때문에 막히면 안 된다.
   실패를 남기려다 실패하면 아무 흔적도 안 남는다.

### 불변 규칙

1. **밖으로 주는 것은 드라이버가 만든다.** 한 역할이 남긴 상태를 다른 역할에게 물려주지
   않는다.
2. **밖에서 온 말은 판정 근거가 아니다.** 종료 코드와 출력 텍스트는 안내다. 통과는 드라이버가
   직접 관찰한 사실로만 정한다.
3. **판정 잣대는 카드의 성공 기준뿐이다.** 기준 밖 관찰은 로그에 적기만 한다. 차단하지 않고,
   토론하지 않고, 자동으로 카드가 되지 않는다. 카드로 만들지는 사람이 정한다.
4. **계약은 역할로만 쓴다.** 도구 이름은 설정에만 있다.

## Reason

사고 열 건이 하나의 전제에서 나왔다 — 리뷰 자료를 `git diff` 로 만든다. diff 를 뜨려면
인덱스가 필요하고, 실행자가 만든 새 파일까지 보이게 하려니 실행자 인덱스를 물려주게 됐다.
그때부터 리뷰 결과가 실행자의 뒷정리에 좌우됐다.

이 프로젝트는 PR 을 쓰지 않고, 이 리뷰는 PR 리뷰도 아니다. 커밋 전 루프 중간 점검이고,
리뷰어는 저장소 안에서 돈다. 파일을 직접 열 수 있는데 대용품을 기본값으로 깔았다.

A 는 방어를 하나 더 얹는다. 다음 오염 방식이 오면 카드가 또 는다. B 는 인덱스 문제만
없애고 대용품은 유지하며, 자료가 커지면 입력 한계에 다시 닿는다. C 는 자료를 나르지 않고
같은 파일을 보게 해서, 오염될 중간물 자체를 없앤다.

C 는 덤으로 지금 빠져 있는 것을 채운다. 루프인데 바퀴 사이에 아무것도 안 흐른다 — 리뷰어가
무엇이 모자랐는지 말해도 드라이버는 통과/차단 단어만 보고 나머지를 버리고, 다음 바퀴 작업자는
카드만 다시 받는다. 로그가 그 통로가 된다.

## Follow-up

구현 카드 셋. 각각 그 자체로 돌아가는 상태를 남긴다.

- **C1** — 드라이버가 바뀐 파일 목록을 자기 환경에서 만들고, 리뷰어에게 diff 대신 그 목록과
  카드 경로를 준다. 리뷰어 쪽 인덱스 물려주기를 걷어낸다. 이것만으로 지금의 고장이 없어진다.
- **C2** — 로그 파일을 도입한다. 작업자가 쓰고, 드라이버가 진술과 관찰을 대조하고, 리뷰어가
  읽고 판정을 덧붙인다.
- **C3** — 왕복 루프. 남은 항목을 다음 바퀴 작업자에게 넘기고, 상한을 세고, 상한에 닿으면
  사람에게 올린다. (W-00000097)
- **C4** — 실패도 남는다. 실패 이유와 그때의 실행자·리뷰어 출력을 공용 로그에 남기고,
  사람에게 올리는 커밋이 무시 대상 경로 때문에 막히지 않게 한다. (W-00000100)
- **C5** — 밖에 띄운 것을 거둔다. 바퀴가 끝나면 그 바퀴가 띄운 실행자·리뷰어를 정리한다.
