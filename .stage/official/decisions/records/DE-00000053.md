# DE-00000053 층마다 카드가 무엇을 묻는가

## Question

일감의 크기는 셋이다 — 에픽, 스토리, 액션. DE-00000035 가 누가 누구 밑에 서는지는 정했지만
**각 층이 무엇을 물어야 하는지는 어디서도 안 정했다.** 지금은 그릇 파일이 그 답을 우연히 들고
있어서 아무도 대조하지 않는다.

## Options

### 목적의 길이

- 길이를 안 잰다. **안 고른다** — 지금 카드 목적이 열 줄을 넘고, 도구를 쓸 때마다 띄우기에는
  너무 길다.
- **한 문장으로 막는다. 고른다.** 사용자가 정했다.
- 글자 수까지 센다. **안 고른다** — 사용자가 거기까지는 안 하기로 정했다. 한 문장이라도 길게 쓸
  수 있지만 그건 사람이 읽어야 안다.

### 저장소 안의 한국어 그릇

- 살린다. 카드 만드는 명령이 언어 설정을 보게 한다. **안 고른다** — 기록의 칸 제목은 기계가 읽는
  이름이라 영어로 고정한다는 계약이 이미 있다. 한국어 칸 제목은 그 계약을 어긴다.
- **지운다. 고른다.** 지금 아무도 안 읽는다.

## Principles applied

- SSOT — 층마다 무엇을 묻는지가 이 결정 하나에 있다. 그릇 파일은 그것을 따른다.
- MECE — 층이 서로 다른 것을 묻는다. 겹치면 아래층이 위층 말을 되풀이하게 된다.
- Honesty — 있는데 아무도 안 읽는 파일을 남겨 두지 않는다.
- KISS — 목적 한 문장. 길게 쓸 자리는 다른 칸이다.

## Chosen direction

### 목적은 한 문장이다

층마다 하나씩, 한 문장을 넘지 못한다. 등록할 때 막는다.

**아래층은 위층 말을 되풀이하지 않는다.** 위가 무엇을 이루는지 말하면 아래는 그중 자기가 맡은
조각을 말한다.

2026-07-31 의 W-00000168 과 W-00000170 이 거의 같은 문장을 갖고 있었다 — 카드마다 혼자서도
읽히게 쓰다가 위층 말을 다시 적은 것이다. 한 문장으로 막으면 다시 적을 자리가 없다.

**글자 수는 안 센다.** 한 문장이라도 길게 쓸 수 있지만 기계가 못 잡는다. 사람이 읽어야 안다.

### 층마다 묻는 것

| | 에픽 | 스토리 | 액션 |
|---|---|---|---|
| 목적 (한 문장) | ✓ | ✓ | ✓ |
| 사용자 가치 | ✓ | ✓ | ✓ |
| 아래에 무엇이 있나 | 스토리 목록 | 액션 목록 | — |
| 무엇이 이 일을 낳았나 | — | — | ✓ |
| 무엇이 끝나야 시작하나 | — | — | ✓ |
| 범위 · 위험 · 성공 기준 | ✓ | ✓ | ✓ |
| 다음 행동 | ✓ | ✓ | ✓ |

에픽과 스토리는 자식을 나열하고, 액션은 대신 출처와 의존을 묻는다. 액션은 더 안 쪼개지므로
자식이 없고, 혼자 서지 못하므로 무엇에서 나왔고 무엇을 기다리는지가 필요하다.

### 시작한 카드도 같은 것을 묻는다

지금 일을 시작한 뒤 쓰는 그릇에는 **세 크기 모두 사용자 가치 칸이 없다.** 등록 절차는 네 가지를
요구하는데 그릇이 셋만 준다. 계획으로 잡아 둔 카드는 옮겨질 때 내용을 갖고 가서 안 걸리고,
바로 시작한 카드만 걸린다.

시작한 뒤 쓰는 그릇에 사용자 가치를 넣는다. 그 그릇이 더 갖는 것은 일이 굴러가며 채워지는 칸뿐이다
— 진행, 검증, 회고, 승격 결정, 관련 진실.

### 한국어 그릇을 지운다

`stage/templates/v4/locales/ko/work/` 아래 그릇 넷을 지운다.

- 카드를 만드는 명령은 영어 그릇만 읽는다(`register_work.py` 의 `_v4_template`). 확인했다.
- 한국어 그릇이 복사되는 자리는 프로젝트를 처음 만들 때뿐이다(`init_stage.py` 의 `LOCALE_ROOT`).
  복사된 뒤에는 아무도 안 읽는다.
- 기록의 칸 제목은 기계가 읽는 이름이라 언어와 상관없이 영어다. 이미 선 계약이다.
- 액션 그릇은 한국어판이 아예 없어서, 지금도 층마다 언어가 다르다.

`locales/ko/` 아래 다른 파일(설명 문서, 인덱스)은 그대로 둔다. 사람이 읽는 산문이고 칸 제목이
아니다.

## Where this applies

| 어디 | 무엇이 바뀌나 |
|---|---|
| `stage/templates/v4/project-stage/work/current/` 의 `_epic.md`·`_story.md`·`_template.md` | 사용자 가치 칸이 는다 |
| `stage/templates/v4/project-stage/work/planned/` 의 셋 | 위 표와 대조해 확인. 지금 맞는 것으로 보인다 |
| `stage/templates/v4/locales/ko/work/` 의 `planned/_epic.md`·`planned/_story.md`·`current/_epic.md`·`current/_story.md` | 지운다 |
| `stage/skills/stage-work/register_work.py` | 목적이 한 문장을 넘으면 거절한다 |
| `stage/skills/stage-work/SKILL.md` | 층마다 무엇을 묻는지, 목적은 한 문장 |
| `stage/docs/SCHEMA_V5.md` | 일감 계층의 계약이 사는 곳 |
| `stage/operations/documentation.md` | 목적 한 문장이 문서 규칙에 걸리는지 확인 |
| `stage/scripts/tests/` 와 `stage/skills/stage-work/` 의 시험 | 위를 고정 |
| `stage/CHANGELOG.md` | 플러그인 변경 규칙 |

**쓰기와 커밋을 따로 셌다** — 이 결정은 그릇 파일과 등록 명령만 바꾼다. 훅의 쓰기 검사도 커밋
검사도 안 건드린다. 목적이 한 문장인지는 등록할 때만 본다.

세었지만 안 바뀌는 자리 — **이미 만들어진 카드 165장.** 목적이 여러 문장인 것이 많다. 다시 쓰지
않는다. 새로 만드는 카드부터 적용한다.

## Reason

층마다 무엇을 묻는지가 곧 그 층이 무엇을 이루는 자리인지를 정한다. 지금은 그것이 파일에만 있고
계약에는 없어서, 그릇이 등록 절차와 어긋나도 아무도 모른다.

목적을 한 문장으로 막는 것은 짧게 쓰라는 뜻이 아니라 **아래층이 위층 말을 되풀이할 자리를
없애는 것**이다. 그리고 도구를 쓸 때마다 띄우려면 짧아야 한다.

## 이 규칙이 틀렸다는 것을 무엇으로 알게 되나

- 한 문장에 다 못 담아서 사람이 목적 칸을 비우거나 억지로 줄인 카드가 나온다.
- 한 문장인데 세 줄짜리 문장이 반복해서 나온다 — 그러면 문장 수가 잘못된 자다.
- 액션의 출처·의존 칸이 계속 비어 나온다 — 그러면 그 층에 그 질문이 안 맞는다.
