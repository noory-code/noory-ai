# DE-00000044 모델은 명령이 못 박고, 등급을 바꾸는 축은 안 만든다

## Question

드라이버는 venue 마다 고정된 명령 하나를 갖는다. 시도가 1에서 3으로 올라도 실행자와 리뷰어가 그대로
다. obra/superpowers 는 이 자리에 등급 축을 두고, 막힌 실행자를 한 등급 위 모델로 갈아 끼운다.
같은 축이 Stage 에도 필요한가.

그 물음을 열고 나서 **설정을 실제로 확인했다.** 지금 명령 어디에도 모델 지정이 없고, 두 CLI 의
기본값이 붙는다 — claude 는 `~/.claude/settings.json` 의 `opus[1m]`, codex 는 `~/.codex/config.toml`
의 `gpt-5.6-sol`(추론 강도 high). 둘 다 각 surface 의 최상급이다.

그래서 물음이 바뀐다. **올릴 자리가 없다.** 남은 진짜 물음은 이것이다: 모델이 명령 밖에 있어도
되는가.

## Options

### A. 등급 축을 만든다 (원래 후보)

프로젝트가 마지막 시도용 명령을 따로 선언한다. **지금 이 프로젝트에는 올릴 자리가 없으므로 선언할
내용이 없다.** 쓸 데 없는 장치를 먼저 만드는 길이다.

### B. 싼 등급을 아래에 붙인다

옮겨 쓰기 수준의 일에 싼 모델을 쓰고 마지막 시도에서 지금 등급으로 돌아온다. 값은 비용 절감인데,
**어느 카드가 싼 등급으로 되는지 가를 근거가 지금 없다.** superpowers 는 "계획에 코드가 다 적혀
있으면"을 기준으로 삼는데, Stage 카드는 코드를 안 담는다.

### C. 모델을 명령에 못 박고 축은 안 만든다

`claude -p --model opus[1m]`, 코덱스는 companion 이 받는 방식으로 `gpt-5.6-sol` 을 명시한다.
등급을 바꾸는 장치는 안 만든다.

## Principles applied

- **AHA** — 반복이 확인되기 전에 장치를 만들지 않는다. 등급을 올린 적도, 내린 적도 없다.
- **Honesty** — 지금 어떤 모델로 도는지 명령을 읽어서는 알 수 없다. 사람의 개인 설정을 따라가는
  값을 "우리가 정한 것"처럼 두면 안 된다.
- **SSOT** — 드라이버가 어떤 모델로 도는지의 소유 위치는 프로젝트 설정이어야 한다. 지금은
  실행하는 사람의 홈 디렉터리에 있다.
- **Fail Fast** — 개인 설정이 바뀌면 드라이버가 조용히 다른 모델로 돈다. 그 변화가 결과에 나타날
  때까지 아무도 모른다.

## Chosen direction

**C.**

### 1. 모델을 명령이 못 박는다

`executors` 와 `review.reviewers` 의 명령이 모델을 명시한다. 값은 지금 쓰는 것과 같다 — claude 쪽
`opus[1m]`, codex 쪽 `gpt-5.6-sol`. **동작은 안 바뀌고, 바뀌는 것은 그 값이 어디에 적혀 있느냐다.**

이유는 재현이다. 지금은 실행하는 사람이 자기 CLI 기본 모델을 바꾸면 드라이버가 다른 모델로 돌고,
작업 로그에도 그 사실이 안 남는다. 카드가 왜 막혔는지 나중에 되짚을 때 그 값이 없으면 원인을 못
가른다.

### 2. 등급을 바꾸는 축은 안 만든다

시도가 올라도 같은 명령을 쓴다. 지금 두 venue 다 각 surface 의 최상급이므로 올릴 자리가 없고,
내리는 쪽(B)은 어느 카드가 싼 등급으로 되는지 가를 근거가 없다.

**이것은 "필요 없다"가 아니라 "아직 근거가 없다"이다.** 근거가 생기는 조건을 아래 후속에 적는다.

### 3. 어느 모델로 돌았는지 작업 로그에 남긴다

명령에 모델이 박히면 로그에 남길 값도 생긴다. 카드가 막혔을 때 "이 등급이 못 푼 것인가"를 나중에
가르려면 이 기록이 먼저 쌓여야 한다.

## Where this applies

| 자리 | 무엇이 바뀌나 |
|---|---|
| `.stage/settings.json` `executors.claude` | 명령에 `opus[1m]` 을 명시한다 |
| `.stage/settings.json` `executors.codex` | companion 이 받는 방식으로 `gpt-5.6-sol` 을 명시한다 |
| `.stage/settings.json` `review.reviewers` 두 벌 | 같은 방식으로 명시한다 |
| `.stage/settings.json` `review.strengths` 네 벌 | 같은 방식으로 명시한다 |
| `stage/templates/v4/project-stage/settings.jsonc` | 새 프로젝트가 받는 기본값. **모델 이름을 템플릿에 박을지, 자리만 두고 주석으로 안내할지 구현이 정한다** — 템플릿에 박으면 그 모델이 사라질 때 새 프로젝트가 깨진다 |
| 작업 로그 | 어느 명령으로 돌았는지 남긴다 |
| `stage/docs/` 의 드라이버 절 | 모델이 명령에 있다는 것 |

바꿀 것이 **없다고 확정한** 자리:

| 자리 | 왜 그대로인가 |
|---|---|
| `stage/scripts/drive.py` 의 명령 고르는 로직 | 명령이 하나뿐이므로 고를 것이 없다. 등급 축을 안 만들었다 |
| `limits.max_attempts_per_item` | 시도 수는 안 바뀐다 |
| DE-00000017 에스컬레이션 | 등급 축이 없으므로 겹칠 것도 없다 |
| `review.strengths` 의 강도 구분 | 강도와 모델은 다른 축이다. 강도는 그대로 두고 모델만 명시한다 |

## Reason

A 는 쓸 데가 없는 장치를 먼저 만든다. 이 프로젝트의 두 venue 가 이미 최상급을 쓰므로 "한 등급 위"가
존재하지 않는다. 사용자가 그 둘을 계속 쓰기로 확인했다(2026-07-30).

B 는 값이 있지만 판정 근거가 없다. Stage 카드는 코드를 안 담으므로 "옮겨 쓰기 수준"을 카드에서
읽어낼 방법이 지금 없다.

C 가 남기는 것은 작지만 실재한다. 지금 드라이버가 어떤 모델로 도는지는 **실행하는 사람의 홈
디렉터리에** 적혀 있다. 그 값이 프로젝트 밖에 있는 한, 결과를 되짚을 때 그 변수를 고정할 수 없다.

## Follow-up

- 구현은 W-00000149 가 받는다. 범위가 크게 줄었다 — 등급 축이 아니라 명령에 모델을 적는 일이다.
  W-00000148(재리뷰 범위)과 같은 설정 항목을 건드리므로 한 바퀴에 같이 돌린다.
- **등급 축을 다시 여는 조건**: 어느 모델로 돌았는지 로그가 쌓인 뒤, 시도를 다 쓰고 막힌 카드
  중에서 "같은 등급이 세 번 같은 자리에서 막힌" 사례가 모이면 그때 연다. 그 전에는 추측이다.
