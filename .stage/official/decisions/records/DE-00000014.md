# DE-00000014 말단 종료 조건 스키마

## Question

말단(leaf) 작업 항목이 "완료됨"을 드라이버가 사람 개입 없이 판정하려면, 종료 조건을 어떤 형태로 선언해야 하는가? 현행 검증은 `close_work`가 실행하는 산문 기준과 호출자가 넘기는 `--check` 셸 명령(exit 0)뿐이며, Success criteria는 산문이라 결정적 판정 근거가 아니다.

## Options

- A. 현행 유지 — 산문 Success criteria + 임의 `--check`. 드라이버가 판정 근거를 신뢰하지 못한다.
- B. 구조화된 acceptance 필드 도입 — 항목에 기계 실행 가능한 검증 단계 목록을 필수 필드로 둔다. 통과 = 모든 단계 exit 0.
- C. 외부 테스트 스위트 참조만 — 항목이 특정 테스트 케이스 id를 가리킨다.

## Principles applied

- SSOT — 종료 조건의 단일 소유 위치는 항목의 acceptance 필드다.
- Fail Fast — 기계 판정이 불가한 종료 조건을 가진 자율 대상 항목은 등록 시점에 거부한다.
- TDD / F.I.R.S.T — 검증은 실행 가능하고 자기검증적이어야 한다.
- MECE — 통과와 실패는 배타적이고 전수적으로 갈린다.

## Chosen direction

B. 기존 `close_work --check` 실행 경로를 항목의 필수 구조 필드 `acceptance`(기계 실행 가능한 검증 단계 목록)로 승격한다.

- 자율 실행 대상 항목은 `acceptance` 없이는 등록 불가(Fail Fast).
- 통과 = 모든 `acceptance` 단계 exit 0.
- 산문 Success criteria는 사람용 설명으로 병존하되, 판정 근거는 아니다.
- 사람 판단이 불가피한 항목(디자인 취향 등)은 자율 대상이 아니라 승인 게이트 항목으로 분류한다.

## Reason

드라이버가 자율로 전진하려면 판정이 결정적이어야 한다. 산문(A)은 결정적이지 않고, 외부 참조만(C)은 항목이 자기완결적이지 않다. B는 이미 있는 `--check` 실행 경로를 재사용하므로 새 실행 엔진이 필요 없다(AHA). 이는 세 통제 장치 중 "종료(말단)"를 구현한다.

## Follow-up

- `acceptance` 필드의 정확한 스키마(단계 표현·타임아웃·실행 환경)는 구현 자식 항목에서 확정한다.
- 사람 판단 필수 항목의 분류 규칙(자율 대상 제외 조건)을 명문화한다.
