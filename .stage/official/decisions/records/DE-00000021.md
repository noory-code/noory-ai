# DE-00000021 상위 집계 롤업의 경계와 terminal 정의

## Question

DE-00000015의 상위 집계 롤업을 어떻게 구현하는가? 자식이 전부 terminal일 때 부모의 완료를 어떻게 다루며, "terminal"은 무엇이고, 드라이버(W-47) 부재 상태에서 W-45의 경계는 어디인가?

## Options

- A. 완료 게이트에 "부모는 비-terminal 자식이 있으면 완료 불가" 규칙 + 자식-terminal 질의 함수. 자동 전진(부모 close)은 드라이버(W-47) 몫.
- B. W-45가 자동 전진(부모 자동 close)까지 구현.
- C. 순수 파생 뷰만, 강제 없음.

## Principles applied

- SSOT — 부모의 완료 자격은 자식 집합의 상태에서 파생한다(별도 저장 없음).
- MECE — terminal 집합을 명확히 가른다.
- Fail Fast — 미완 자식이 있으면 부모 완료를 조기에 차단.
- AHA / SoC — 자동 전진은 드라이버(W-47)의 책임이므로 W-45와 분리.
- OCP — 기존 `parent`/archive의 열린-자식 제약을 파괴 없이 확장.

## Chosen direction

A. W-45는 집계 primitive(질의 + 완료 게이트)만 만든다.

- **자식-terminal 질의**: 부모의 모든 자식이 terminal이면 참. terminal = status ∈ {completed, archived, rejected}(`WORK_FINAL_STATUSES`) — open(active/review/blocked)도 planned(captured 등)도 아닌, 결판난 상태. `rejected`도 terminal로 포함(결판났으므로 부모를 막지 않는다).
- **부모 완료 게이트**: `parent`로 지목된 항목은 비-terminal 자식이 하나라도 있으면 완료/종료 불가(`item_completion_blockers`/`close_work`). 기존 archive_work의 "열린 자식" 제약을 완료 단계로 끌어올려 일관화한다(planned 자식도 부모를 막는다 → umbrella 패턴 형식화).
- **자동 전진**(부모 자동 close)은 드라이버(W-47)가 이 질의를 사용해 수행한다. W-45는 primitive만 제공한다.

## Reason

부모의 완료 자격은 자식 집합에서 파생하므로 별도 상태를 저장하지 않는다(SSOT). 자동 close는 드라이버의 책임이라 분리한다(AHA/SoC). terminal에 `rejected`를 포함해 결판난 자식이 부모를 막지 않게 한다(전진 목적). archive의 열린-자식 제약과 정합하되, 완료 단계로 승격해 planned 자식까지 포괄한다. 이는 세 통제 장치 중 "종료(상위 집계)"를 구현한다.

## Follow-up

- 부모 자신의 통합 acceptance(부모도 검증이 필요할 때)와의 결합 방식.
- 자동 전진 트리거의 정확한 형태(W-47에서 확정).
- `rejected` 자식이 있을 때 부모의 `terminal_disposition` 처리(수용 vs 부분 실패)는 W-47/후속에서.
