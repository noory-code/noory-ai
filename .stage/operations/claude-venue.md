# claude venue 실행

이 문서는 이 프로젝트에서 claude venue 카드가 실행되는 방식을 소유한다. 근거 결정:
DE-00000062.

## 감독 모드 — 세션 팀원이 실행한다

감독 세션이 claude venue 카드를 드라이버에 넘기지 않고, 팀원 에이전트를 띄워 카드를 준다.
팀원은 자기가 만든 워크트리에서 일한다.

절차:

1. 카드가 `work/current/` 에 있고 본문이 차 있는지 확인한다. 카드와 조상 카드가 팀원의 전체
   지시문이다.
2. **카드 등록을 먼저 커밋한다.** 새로 만든 워크트리는 본 체크아웃의 커밋 안 된 변경을 안
   가져오므로, 방금 등록하고 커밋하지 않은 카드는 팀원의 워크트리에 없다. 팀원이 카드를 못
   찾으면 본 체크아웃에서 커밋한 뒤 그 커밋을 가져오는 명령을 알려 준다.
3. **팀원을 띄운다.**
   - **Agent 도구 호출에 `isolation` 인자를 넣지 않는다.** 다른 값으로 두는 것이 아니라
     인자가 없어야 한다 — 호출문만 보면 지켰는지 확인된다.
   - 관측(2026-08-06·07, 각 한 번): `isolation: "worktree"` 로 띄운 실행은 tmux 창을 안
     잡고 배경 기록으로 돌아왔고, 그 인자 없이 띄운 실행은 창을 잡았다. 창을 안 잡으면
     사람이 tmux 창에서 실행을 볼 수 없다. `isolation` 의 다른 값과, 창을 잡은 실행이 함께
     달고 있던 이름 인자는 따로 갈라 재지 않았다.
   - 팀원에게 이름을 준다 — 그 이름으로 팀원을 부른다.
   - 격리는 팀원이 스스로 만든다. 지시문의 첫 걸음으로 본 체크아웃에서
     `git worktree add <워크트리 경로> -b <팀원 브랜치> HEAD` 를 돌리고 그 경로 안에서만
     일하게 한다. 명령마다 그 경로를 넘기게 하고 — 감독 세션과 팀원 세션 둘 다 명령 사이에
     작업 디렉터리가 본 체크아웃으로 되돌아갔다(2026-08-07 관측) — 파일을 바꾸기 전에
     `git branch --show-current` 로 브랜치를 확인하게 한다.
4. **띄운 직후 팀원이 실제로 떴는지 본다.** 띄우는 도구는 창이 죽어도 성공을 낸다. 몇 분 뒤
   `git worktree list` 에 팀원 워크트리가 없으면 창부터 확인한다 —
   `tmux list-panes -a -F "#{pane_id} #{pane_dead} #{pane_start_command}"` 로 죽은 창과 그
   시작 명령을 본다. 시작 명령이 부르는 실행 파일이 사라졌으면(O-00000043) 세션을 다시
   시작하는 것 말고 이 세션에서 할 수 있는 것이 없다.
5. 드라이버 실행자와 같은 계약 문구를 그대로 준다 — 커밋 금지, 공유 로그
   (`.stage/.runtime/driver/logs/<카드>.md`)에 `### Executor report` 형식의 실행 보고, 범위
   경계 넘음 보고, 카드 frontmatter `promotion` 최종 선택 기록.
6. 계약에 더하는 한 줄: **막히거나 갈림길이면 일을 지어내지 말고 감독에게 묻는다.**
7. 팀원이 끝나면 감독이 인수 검사를 돌리고, codex 판정을 받는다(만든 쪽 ≠ 보는 쪽).
8. 판정이 반려하면 실패한 기준마다 수용·기각·보류를 이유와 함께 정해 팀원에게 돌려보낸다.
   기준 자체가 도달 불가로 드러나면 바퀴를 더 돌리지 말고 그 한계를 카드의 `## Verification`
   에 적고 닫는다.
9. 통과하면 감독이 워크트리 커밋 → 병합 → 회고 → 닫기 → 보관을 잇는다. **워크트리를 치우기
   전에 작업 로그를 본 저장소로 옮긴다** — `.stage/.runtime/` 은 커밋 대상이 아니라 워크트리와
   함께 사라진다.

**보고에서 무엇을 빼라고 시키지 않는다.** 하니스 준비(워크트리 만들기 등)도 저장소를
바꿨으면 변경 목록에 적게 하고, 카드 작업과는 `Decisions made:` 안에서 갈라 적게 한다. 빼서
가리면 실행자 주장과 실제가 어긋나고, 그 어긋남을 잡는 것이 이 계약의 목적이다.

### 3번 걸음에서 팀원 모델을 고른다

모델을 정하지 않고 팀원을 띄우면 부모 세션 모델을 그대로 물려받는다. 그대로 두면 문구 하나
다듬는 `documentation` 카드에도 가장 무거운 모델이 붙는다. 고르는 근거는 카드의 `kind` 다 —
`venue_routing`(`settings.json`)이 이미 같은 신호로 venue 를 가르므로 새 축을 만들지 않고
같은 신호를 쓴다.

| kind | 모델 | 근거 |
|---|---|---|
| `design` | opus | 되돌리기 어려운 구조 판단이 나오는 자리 |
| `planning` | opus | 결정 레코드(DE-\*)를 만들거나 바꾸는 자리 — 이 kind 로 등록된 실제 카드 대부분이 `decision_refs`/`promotes` 로 결정 레코드를 문다 |
| `documentation` | sonnet | W-00000232(문서 카드)가 여러 차례의 실행 라운드와 독립된 리뷰 2회를 거쳤고, 반려마다 측정이 끝나는 지점과 주장이 시작하는 지점을 가르는 판단이었다 — 이 카드 자신도 중간 tier 로 돈 반례다 |
| `release` | sonnet | 검증 기준(`operations/verification.md`)이 통과를 "새 버전이 실제로 불러와지는 것이 관측됨"으로 정의하고 "버전만 올라간 상태는 통과가 아니다"(DE-00000054)라고 명시한다 — 불러와짐을 관측하는 것은 릴리스 명령을 실행하는 것을 넘는 판단이다 |
| `feature` | 해당 없음 | `split` 은 등록 시점에 설계/구현 자식으로 갈라지므로(용어집 Venue 절) leaf 카드가 `feature` kind 로 팀원에게 오지 않는다 |
| `development` / `fix` / `qa` / `ops` / `chore` | 해당 없음 | codex venue 로 가므로 claude 팀원이 맡지 않는다 |

**이 표는 판정자의 모델을 정하지 않는다.** `review.reviewers.codex`(`settings.json`)가 kind 와
무관하게 이미 고정돼 있다. 이 값을 바꾸려는 사람은 먼저 독립 리뷰가 실제로 무엇을 반려해
왔는지부터 읽는다 — 그 기록은 `.stage/.runtime/driver/logs/` 아래 실행 로그와, 최근 닫힌
카드의 `## Verification` 절에 있다.

이 표는 실측이 아니라 기본값이다. 어긋나는 사례가 나오면 그때 고친다.

팀 기능이 없는 세션에서는 사람 창 넘김(stage-handoff)으로 돌아간다.

## 무인 모드 — codex 전용

무인 실행은 codex venue 카드만 받는다. 팀은 세션 없이 돌지 않고, 비대화형 `claude -p` 는
명령 실행 권한이 없다(측정: W-00000220). 무인 claude venue 수요가 생기면 허용 목록 방식을
그때 결정한다.

## 판정자 경로는 별개다

`review.reviewers.claude`(codex 카드의 판정자로 도는 `claude -p`)는 읽기·쓰기만으로 돌아
이 문서의 범위 밖이다.
