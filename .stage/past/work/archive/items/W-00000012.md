# W-00000012 Separate Stage core operations from project policy

## Purpose

Make the Stage plugin the single owner of common operational rules while project-local `.stage/`
files own only project-specific policy, overrides, and runtime records, so projects can upgrade
Stage without carrying duplicated common policy or losing project-specific criteria.

## Scope

- Record the ownership boundary between plugin-owned core operations and project-owned policy as
  a working decision before implementation.
- Move common lifecycle, artifact, hook, review, retrospective, portability, documentation, and
  output defaults to one plugin-owned location.
- Define a minimal project policy surface for work-kind verification criteria, venues, governance
  exclusions, and explicit overrides.
- Update initialization, audit, context injection, skills, templates, documentation, and tests to
  the new ownership model.
- Provide a migration path for existing `.stage/operations/` directories that preserves
  project-specific policy, and migrate this repository's `.stage/`.
- Bump the Stage plugin version in both manifests and record the change in the changelog.

## Success criteria

- A fresh Stage initialization does not copy identical common operational rules into the consuming
  project; project-local policy contains only declared project values or explicit overrides.
- Existing project-specific verification kinds survive migration without manual reconstruction.
- The audit detects unsupported policy versions, malformed overrides, and unresolved ownership
  drift.
- Hooks, scripts, skills, and documentation resolve effective rules from one common owner plus
  project overrides.
- This repository's `venue` values and `kind -> venue` routing have one declared project owner.
- `python3 -m unittest discover -s stage/hooks/tests -q` and
  `python3 -m unittest discover -s stage/scripts/tests -q` pass.
- The migrated repository passes `audit_stage.py` with zero errors and zero warnings.

## Progress

- DE-00000002 recorded the ownership boundary before implementation.
- Eleven common docs moved to plugin-owned `stage/operations/`; initialization copies only the
  project policy surface (`operations/verification.md` kind table).
- `settings.json` gained `operations_overrides`; `STAGE_SCHEMA_VERSION` bumped to 2; hooks stay
  version-agnostic.
- The audit gained OPS001–OPS004 ownership-drift checks (v2-gated) and a plugin-catalog fallback
  (CATALOG002).
- `scripts/migrate_stage.py` migrates existing projects idempotently and never deletes content
  that differs from the plugin copy; `--dry-run` supported.
- Skills (`stage-init`, `stage-work`, `stage-decision`, `stage-retrospective`), README, and
  templates updated to the new contract.
- This repository's `.stage/` migrated: 10 identical copies deleted, the stale pre-venue
  `artifacts.md` removed, `verification.md` rewritten preserving all nine kind criteria,
  `schema_version` stamped 2.
- Stage plugin released as 0.19.0 (both manifests + changelog).
