# R-00000005 Archiving completed work — one gate, and literal paths

## Work

Moved W-00000001..W-00000004 from `present/work/` to `past/work/archive/`: each item copied to
`archive/items/` with `status: archived`, its retrospective copied to `archive/retrospectives/`,
and a row added to `archive/index.md` recording the `completed` final status. Removed the present
copies and cleared them from `review.md`.

## Decision points

Archiving needs exactly ONE gate: a pending per-path **archive intent**. There is no separate
registration gate on archive writes. Verified in `stage/hooks/stage_paths.py`:
`DEFAULT_EXCLUDED_PREFIXES = (".stage", ".git", ".discuss")`, so `is_source_path` returns False for
every `.stage/...` target and `source_registration_blocker` returns empty — the registration and
commit gates never fire on `.stage/` paths.

W-00000005 was created on the mistaken belief that archiving required a fresh open work item. It
did not. Archiving is record keeping authorized by the archive intent, which already names the
completed item being archived; no new work item is needed.

## Principles applied

- SSOT — `archive/index.md`'s `Final status` cell preserves the terminal state (`completed`) that
  the `archived` status overwrites on the item itself; and archiving must not mint a second work
  item for work that already has one, which would duplicate the record.
- Honesty / Fail Fast — the first draft of this retrospective asserted a two-gate model that was
  never verified against the code; reading `stage_paths.py` refuted it.

## Context that helped

`stage/scripts/audit_stage.py` confirmed archive consistency (index rows, moved retrospectives,
status rule) with errors=0. `stage/hooks/stage_runtime.py` documents the per-item archive intent
and the path/ref matching the gate enforces.

## Context that was missing

A shell command cannot use variables for the target paths — the hook parses the raw command text,
so `$VAR/W-...` reaches the gate unexpanded and matches no intent. Write `past/` targets with
literal paths.

## Next changes

To archive completed items: create one archive intent per item covering its `items/<id>.md`,
`retrospectives/<ref>.md`, and the shared `index.md`, then perform the moves with LITERAL paths.
No work-item registration is required. This flow is now encoded in the `stage-archive` skill so it
is executed, not re-derived.

## Promotion decision

`promotion: not_applicable` — archiving is record keeping, not a promotion of new `past/` canon.
