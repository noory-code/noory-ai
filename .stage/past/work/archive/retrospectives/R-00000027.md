# R-00000027 commit gate ignores shell redirections in git add

## Work

git_add_paths_from_command now breaks at the first shell redirection (reusing
stage_git._is_shell_redirection), so `git add path 2>/dev/null` no longer yields the
redirection as a phantom pathspec. Diagnosed by claude (parser run on both reported
commands), implemented by codex under the cross-venue delegation contract, reviewed and
committed by claude (ab0f0d20, 0.25.2).

## Decision points

- Two reported symptoms; only the redirection leak is a hook defect. The nested-double-quote
  case was verified to match bash exactly and left untouched — weakening the gate to swallow
  it would let genuinely-committed pathspecs through.
- Reused the existing redirection predicate rather than copying the regex (SSOT).

## Principles applied

- Honesty / Fail Fast: the card scope was narrowed to the verified bug before any code changed;
  the non-bug was recorded, not silently "fixed".
- SSOT: one _is_shell_redirection definition serves both the add and commit-pathspec scanners.

## Context that helped

- Running the parser on the exact failing commands turned a two-symptom report into a
  one-line fix with a clear boundary.

## Context that was missing

- None.

## Next changes

- Operational: keep using `git commit -F <file>` for messages with quotes or shell
  metacharacters (the nested-quote case is user-side, not a gate defect).
