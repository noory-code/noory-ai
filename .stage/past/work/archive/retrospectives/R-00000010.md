# R-00000010 Configurable review — strength bound to a command, not a label; review-before-commit caught two fail-open holes

## Work

Added a `review` block to `.stage/settings.json`: per-stage strength (design/implementation/
promotion) where each strength maps to a project-defined, verdict-emitting command. `close_work.py`
runs the implementation-stage review at close and refuses to complete on a failing/`BLOCK:` verdict.
The audit reports an unusable config as `REVIEW001`; the resolver is one owning definition shared by
close_work and the audit.

## Decision points

- The user wanted a strength SETTING. The first honest instinct (a strength label) was refuted by
  the design red-team as theater — a label the tooling can't run. Resolution: the strength is a
  named level the PROJECT binds to a real command (like `venue` binds nothing and the project
  declares it). So the label stays configurable AND is bound to execution.
- Enforcement lives in `close_work`, not a hook: Stage hooks have a 10s timeout and can't run an LLM
  review. This means hand-completing an item bypasses review — the same limit as `verification`;
  documented rather than hidden.

## Principles applied

- Honesty / Fail Fast — three adversarial reviews (one design, two code) before landing. The code
  review caught two fail-OPEN holes a green test suite hid: a `BLOCK:` verdict clipped out of the
  evidence before it was scanned, and a non-string stage value silently coerced to `off`. Both now
  fail toward blocking.
- SSOT — `REVIEW_STRENGTHS`/`REVIEW_STAGES`/`resolve_review_command` have one home in `stage_paths`,
  reused by close_work and the audit.
- Fail-closed — a configured-on stage with a missing/typo'd command blocks the close; it never
  silently skips the review.

## Context that helped

The codex stop-review-gate (a shipped "run a review, block on BLOCK:, fail closed on every anomaly")
was the reference for the verdict convention and the fail-closed posture.

## Context that was missing

Nothing external. The open edge is that review, like verification, is only enforced through the
script; a hook-level enforcement would need a non-invasive design (the Stop-hook audit attempt in
W-7 showed the invasive version breaks the hook contract).

## Next changes

If review must be enforced even on hand-completion, design a non-invasive check that a non-`off`
stage recorded review evidence — separate work, not a hook subprocess.

## Promotion decision

`promotion: not_applicable` — changes live in the `stage/` plugin package.
