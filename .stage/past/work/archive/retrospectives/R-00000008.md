# R-00000008 Review before build caught a blocker; enum gate closes the not_required bug at write time

## Work

Added `register_work.py` and `close_work.py` (each inside its owning skill) and a PreToolUse
enum-validity gate that blocks a work-item write whose status/verification/retrospective/promotion
value is invalid. The gate and the audit now share one owning definition of the valid sets.

## Decision points

- Design was red-teamed BEFORE coding. That review changed the plan: it found a blocker
  (close_work would set `status: completed` without a final `promotion`, manufacturing an
  audit-failing, commit-blocking item) and flipped "enforce integrity" from a Stop-hook audit
  subprocess (rejected as invasive) to a narrow PreToolUse enum block reusing the existing
  hierarchy projection.
- The implementation was red-teamed BEFORE commit. That review found a real BLOCKER: check output
  was spliced into a regex REPLACEMENT template, so any passing check printing a backslash (a
  Windows path, a printed regex) crashed `close_work` and left the item permanently un-closable.
  Fixed with a replacement function; regression-tested with backslash/`\1` output.

## Principles applied

- Fail Fast / Honesty — two adversarial reviews before landing caught a design blocker and a code
  blocker that the passing test suite did not. Review is not optional after a design.
- SSOT — one owning definition of the enum value sets (`stage_work.py`), imported by both the gate
  and the audit, so a write the gate allows is exactly one the audit accepts.
- Honest scope — `close_work` verifies the checks RAN and records their evidence; it does not judge
  whether the checks are sufficient for the kind. Claimed no more than that.

## Context that helped

The existing hierarchy-projection machinery (`projected_file_text`) made the enum gate a small,
non-invasive block instead of a new subsystem — the earlier Stop-hook attempt broke a contract test,
this reuses shipping code.

## Context that was missing

Nothing external. The gap the whole item closes is that lifecycle bookkeeping and field validity
lived only in hook/audit code and were re-derived (and mistyped) by hand each time.

## Next changes

Index-row membership in the scripts is eventually-consistent (read-modify-write); it self-heals via
the audit + a reconciling re-run. If concurrent-window index races prove common, add a lock.

## Promotion decision

`promotion: not_applicable` — changes live in the `stage/` plugin package.
