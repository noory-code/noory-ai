# DE-00000068 담을 경로 중 아직 없는 것이 있을 때

## Question

드라이버가 한 바퀴의 결과를 담을 때, 카드가 선언한 경로 중 **아직 만들어지지 않은 것**이
있으면 `git add` 가 통째로 실패한다. 그래서 카드를 옳게 거절한 실행이 커밋 실패로 판정된다.

**없는 경로를 어떻게 다루고, 그 처리가 기록에 어떻게 남는가.**

## Options

1. **없는 경로를 빼고 나머지를 담는다.** 뺀 것은 실행 기록에 적는다. (선택)
2. **경로마다 따로 담고 실패한 것은 넘어간다.** 결과는 1번과 같은데, 없어서 실패한 것과 다른
   이유로 실패한 것이 안 갈린다.
3. **거절을 담기보다 먼저 읽는다.** 실행자가 카드만 고쳤으면 담기를 아예 안 부른다.
4. **안 바꾼다** — 카드가 아직 없는 파일을 `scope` 에 안 적게 한다.

## Principles applied

- **Fail Fast** — 없는 경로를 뺐다는 것이 조용하면 안 된다. 실행 기록에 남겨 사람이 본다.
- **Honesty** — 이 결정이 상속받은 관측의 선택지 목록은 낡았다. 낡은 것을 낡았다고 적고
  실제로 남은 질문만 답한다.
- **AHA** — 실측에 없는 모양을 위해 미리 넓히지 않는다. 같은 고장이 걸릴 다른 자리가 있는지
  세고, 없으면 없다고 적는다.
- **SSOT** — 담을 경로의 소유자는 카드의 `scope` 하나다. 이 결정은 그 목록을 거르기만 하고
  새 목록을 만들지 않는다.

## Chosen direction

**1번.** 담기 직전에 목록을 거른다 — **디스크에 있거나, 그 경로 표현이 추적 중인 파일 하나라도
가리키면 남긴다.** 둘 다 아니면 뺀다. 뺀 경로는 실행 기록에 이름으로 적는다.

거른 뒤에는 `git add -A` 로 담는다.

### 왜 파일 존재만으로 거르면 안 되나

**실측으로 확인했다.** 선언한 디렉터리의 파일이 전부 지워진 실행을 만들어 돌렸다.

| 거르는 방법 | 담긴 것 |
|---|---|
| 디스크에 있는가만 본다 | **아무것도 안 담긴다 — 삭제를 잃는다** |
| 디스크에 있거나 그 경로가 추적 중인 파일을 가리키는가 | `D doomed/x.py` — 삭제가 담긴다 |

이유는 `git ls-files -- doomed/` 가 `doomed/x.py` 를 내지 `doomed/` 를 안 내기 때문이다.
그래서 판정은 "그 문자열이 추적 목록에 있는가"가 아니라 **"그 경로 표현이 추적 중인 파일을
하나라도 가리키는가"** 여야 한다. 앞쪽으로 쓰면 디렉터리 항목이 전부 빠진다.

### 왜 없는 것은 빼면서 남는 것은 거절하나

DE-00000066 은 반대로 정했다 — 허용 목록 **밖**의 경로가 이미 스테이지에 올라 있으면 조용히
빼지 말고 거절하라고. 방향이 반대인데 근거는 하나다.

**모르는 것이 무엇이냐가 다르다.** 목록 밖이 올라와 있으면 그것이 어떻게 거기 왔는지를
하니스가 모른다 — 카드의 자격을 타고 들어가면 안 되는 것이 들어갈 수 있으므로 거절이 맞다.
목록 안이 없는 것은 반대다. **없다는 사실 자체가 답이다** — 실행자가 안 만들었고, 안 만든
정당한 이유가 있다(카드가 틀렸다고 판단한 경우). 담을 것이 없는 것을 담으라고 할 수 없다.

한쪽은 **알 수 없어서** 멈추고, 다른 쪽은 **알기 때문에** 지나간다.

### 실측 — 무엇이 이미 고쳐져 있고 무엇이 남았나

O-00000034 는 방아쇠 둘과 고칠 길 셋을 적었다. **셋 중 둘은 이미 해소됐다.** 코드를 열어
확인했다.

| 관측이 적은 것 | 지금 |
|---|---|
| 첫 방아쇠 — 카드만 바뀌어 담을 것이 없다 | **고쳐짐.** `stage/scripts/driver_git.py:93-95` 가 카드 파일을 목록에 넣고, `:103` 이 "담을 것 없음"을 성공으로 읽는다 |
| 길 1 — 담을 목록에 카드 파일을 늘 넣는다 | **이미 그렇다.** 위와 같은 자리 |
| 길 2 — 담을 것 없음을 거절로 읽는다 | **이미 그렇다.** `driver_supervised.py:381`, `driver_unattended.py:418` 의 `executor_changed_only_work_card` |
| 길 3 — 계약에서 `promotion` 쓰기를 뺀다 | 필요 없어졌다. 첫 방아쇠가 풀려서다 |
| 둘째 방아쇠 — 선언한 경로가 아직 없다 | **살아 있다.** 이 결정이 답하는 자리 |

**그래서 관측이 적어 둔 선택지 셋은 이 질문의 답이 아니다.** 셋 다 첫 방아쇠를 겨눈 것이고
그 방아쇠는 이미 안 당겨진다.

### 순서 문제는 따라온다 — 따로 고치지 않는다

무인 루프는 이 순서로 돈다.

```
418  executor_rejected 를 판정한다        ← 이미 옳게 판정한다
527  commit_item 을 부른다                 ← 여기서 add 가 통째로 실패한다
528  실패하면 "commit failed" 로 올린다     ← 거절이 하니스 오류로 덮인다
536  if executor_rejected: ...             ← 여기까지 못 온다
```

거절 판정은 이미 옳다. 못 쓰이는 이유는 그 앞 걸음이 실패해서다. **거르기가 들어가면 527 이
성공하고 536 이 제대로 돈다** — 순서를 바꿀 필요가 없다. 3번(거절을 담기보다 먼저 읽기)을
버리는 이유가 이것이다. 3번은 거절한 실행만 고치고, 카드가 아직 없는 파일을 선언한 채 다른
일은 한 실행은 그대로 밟는다.

### 2번과 4번을 버린 이유

**2번(경로마다 따로 담기)** 은 결과가 같다 — 실측에서 담긴 것이 1번과 한 글자도 안 다르다.
버리는 이유는 갈라지지 않는다는 것이다. 경로 하나가 권한이나 다른 이유로 실패해도 "없어서
넘어감"과 같은 자리에 떨어진다. 1번은 왜 뺐는지를 알고 빼므로 그것을 기록에 적을 수 있다.

**4번(안 바꾼다)** 은 "새로 만들 파일을 `scope` 에 적지 마라"는 뜻인데, 그러면 그 파일이
카드의 선언 범위 밖이 되어 담기지 않는다. 만들라고 시킨 파일을 담을 수 없게 된다.

### 같은 고장이 걸릴 다른 자리 — 세었고, 없다

| 자리 | 담는 방법 | 걸리나 |
|---|---|---|
| `stage/scripts/driver_git.py:96` `commit_item` | 카드의 `scope` + 카드 파일을 `git add --` | **걸린다.** 이 결정이 고치는 자리 |
| `stage/scripts/land_run.py:362` | diff 에서 뽑은 목록에 `git add -A --` | 안 걸린다. 목록이 diff 에서 나와 못 맞는 경로가 안 생긴다 |
| `stage/scripts/driver_git.py:146` `commit_lifecycle` | `git add --update -- .stage` | 안 걸린다. 항상 있는 디렉터리 하나다 |

|---|---|
| `stage/scripts/driver_git.py:93-95` | 담을 목록을 만드는 자리 — 거르기가 들어갈 곳 |

## Reason

담기가 통째로 실패하는 것은 git 의 동작이고 우리가 못 바꾼다 — `git add -- a b` 는 `b` 가
없으면 `a` 도 안 담는다. 실측했다. 그러니 목록을 넘기기 전에 우리가 고르는 수밖에 없다.

**무엇을 고를지는 이미 정해져 있다.** 카드의 `scope` 가 담을 것의 소유자이고, 이 결정은 그
목록에서 담을 수 없는 것만 뺀다. 새 목록을 만들지 않고, 목록을 넓히지도 않는다.

**뺀 것을 적는 이유는 O-00000020 이다.** 만든 쪽이 조용히 목록을 줄이면 무엇이 안 담겼는지가
아무 데도 안 남는다. 여기서는 하니스가 줄이므로 하니스가 적는다.

이 결정이 무는 값 하나: **거른 뒤에도 실행자가 카드만 고친 실행은 카드 파일 하나짜리 커밋을
남긴다.** 그것이 옳다 — 거절도 기록이고, 그 커밋이 `driver_unattended.py:536` 의 거절 처리가
읽는 근거다.

## Follow-up

- 이 결정을 구현하는 카드가 뒤에 온다. 시험이 네 모양을 덮어야 한다 — 없는 파일, 없는
  디렉터리, 통째로 지워진 디렉터리(삭제가 담기는지), 그리고 뺀 경로가 실행 기록에 적히는지.
- **거절한 실행이 시도를 안 태우는지는 구현 뒤에 실측한다.** 지금은 담기가 먼저 실패해서 그
  뒤를 못 봤다. O-00000034 는 그 실측이 나온 뒤에 닫는다.
