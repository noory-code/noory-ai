# DE-00000104 규칙 후보는 두 번 보면 묻지 않고 규칙이 되고, 한 번 본 것은 사람이 잡은 것만 사용자가 판정한다

## Question

`.stage/state/rule-candidates.md` 에 후보 39건이 있고 14건이 `proposed: promote` 다. 사용자 판정을 받은 것은 0건이다.
14건 가운데 12건은 "하니스 밖에서 잡혔다"는 한 번의 관찰로 올리자는 제안이 됐다. `rule-promotion.md` 는 올릴지는 사용자가
정한다고 한다. 다섯 가지를 묻는다.

1. 문턱 아래의 후보(`proposed: hold`)는 어떻게 두는가?
2. 승격 문턱을 바꾸는가?
3. 누가 `proposed: promote` 줄을 규칙으로 만드는가?
4. 새 문턱을 지금 목록에 적용하는가?
5. 한 번 봤는데 누가 잡았는지 적히지 않은 후보는 어떻게 하는가?

DE-00000102 는 후속 작업 후보의 문턱을 정했고 규칙 후보는 이 결정으로 미뤘다.

## Options

| 질문 | 선택지 |
|---|---|
| 1 | A 목록에서 뺀다 / B 지금대로 둔다 / C 목록에는 두고 세션 색인에는 `proposed: promote` 줄만 싣는다 |
| 2 | 1 두 시험을 그대로 둔다 / 2 두 번 본 것만 올린다 / 3 둘째 시험을 좁힌다. 한 번으로 올리는 것은 사람이 잡았거나 병합·릴리스 뒤에 드러난 것만이고, 닫기 리뷰어나 CI 가 잡은 것은 `hold` 다 |
| 3 | 1 모으는 세션이 돌 때 사용자가 표 하나로 한 번에 판정한다 / 2 두 번 본 것은 자동, 한 번 본 것만 사용자에게 표로 보인다 / 3 전부 자동 |
| 4 | 가 지금 적용한다 / 나 다음에 모을 때부터 |
| 5 | 올림 후보로 둔다 / 회고가 사람이나 병합 뒤의 발견을 들 때까지 `hold` |

## Principles applied

- User intent: 다섯 질문 모두 사용자가 골랐다.
- AHA: 한 번 본 것으로 규칙을 만드는 길을 좁힌다.
- Honesty: 확인할 수 없는 표시("하니스 밖에서 잡혔다")만으로는 그 표시에 기대는 문턱을 넘기지 않는다.
- KISS: 두 번 본 것은 회고를 열면 누구나 확인할 수 있어 판정할 것이 없다.

## Chosen direction

사용자가 2026-11-25 에 토론 세션 session_018VXR6SH4PsfzwA6PTiZW3a 의 대화에서 골랐다. 지휘 세션은 그 세션의 보고로 받았고,
사용자가 같은 날 지휘 세션에서 추천이 그대로 선다고 확인했다("네", "추천대로").

|---|---|---|
| 1 | C. 목록에는 두고 세션 색인에는 `proposed: promote` 줄만 싣는다 | "추천대로" |

## Reason

지금 문턱은 한 번 본 것 대부분을 올리자는 제안으로 만들고, 그 제안은 사용자의 판정을 기다리며 쌓였다. 두 번 본 것을
자동으로 올리면 판정할 것이 없는 줄에서 사용자를 뺀다. 한 번 본 것에서 닫기 리뷰어와 CI 를 빼는 까닭은, 그것들이 잡았다면
하니스가 제 일을 한 것이기 때문이다.

알고 고른 약점:

- 두 번 본 것의 자동 승격은 Claude 가 자기 증거로 자기 규칙을 쓰는 것이다. 서로 다른 두 행동을 같은 것으로 잘못 묶으면 한
  번짜리가 규칙이 된다. 묶는 것도 Claude 가 한다.
- 지금 적용하면 규칙이 한꺼번에 여섯 개 는다. 장치를 줄이는 M-00000006 과 반대 방향이다.
- 올린 규칙을 빼는 방법은 정하지 않았다.

이 결정이 틀렸다고 볼 일: 자동으로 올라간 규칙 가운데 회고 둘이 실제로는 다른 행동을 말한 것이 나온다. 또는 `hold` 로 내린
한 번짜리와 같은 실수가 다시 사람에게 잡힌다.
