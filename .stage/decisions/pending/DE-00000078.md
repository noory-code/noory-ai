# DE-00000078 실행 보고를 카드에 남기는 고치기는 Claude Code 클라우드 세션에서 실행한다

## Question

W-00000287 은 `kind: fix` 라 정책상 codex 몫이다. 사용자는 이 카드를 만든 클라우드 세션에서
"자율 실행하시죠"라고 지시했다. 이 세션에는 codex 드라이버가 없다(드라이버 명령이 이 컴퓨터에만
있는 경로를 부른다). **이 카드를 어느 자리에서 실행하는가.**

## Options

1. **로컬 codex 드라이버에 넘긴다** — 정책 그대로다. 사용자 지시와 어긋나고 클라우드 실행 시험
   표본이 늘지 않는다.
2. **이 클라우드 세션이 실행하고, 판정·회고·닫기는 로컬에서 한다** — DE-00000075 와 같은
   모양의 예외를 한 장 더 세운다. (선택)

## Principles applied

- **User intent** — 사용자가 이 세션에서 바로 실행하라고 지시했다.
- **만든 쪽 ≠ 보는 쪽** — 카드에 `review: pending` 을 걸어, 닫을 때 로컬의 codex 리뷰가
  판정한다.
- **Honesty** — 클라우드 세션에는 Stage 훅과 `.stage/.runtime/` 이 없다. 범위 대조와 실행 보고
  이관은 로컬에서 다시 한다.

## Chosen direction

**2번.** W-00000287 은 Claude Code 클라우드 세션이 `claude/w268-cloud` 브랜치에서 실행한다. 이
결정은 W-00000287 한 장만 허가한다. 실행 계약은 DE-00000075 의 세 변경(세션 브랜치에 커밋·push,
`### Executor report` 는 커밋 메시지 본문, 범위 대조는 로컬)을 그대로 쓴다.

## Where this applies

| 자리 | 무엇을 하는가 |
|---|---|
| W-00000287 카드 `venue` · `decision_refs` | `claude` 와 이 결정을 가리킨다 |
| `.stage/work/active.md` W-00000287 행 | Venue 칸을 `claude` 로 둔다 |
| 로컬 마무리 | 범위 대조, 인수 명령과 scripts 전체 시험, codex 판정, 회고, 닫기 |

`settings.json` 의 `venue_routing` 은 바뀌지 않는다. 카드가 보관될 때 이 결정도 함께 소진된다.

## Reason

DE-00000075 의 시험 결과를 본 뒤 정책을 다시 보기로 했고, 그 판단에는 표본이 더 필요하다. 이 카드는
그 표본을 하나 더한다.

## 이 규칙이 틀렸다는 것을 무엇으로 알게 되나

로컬 codex 판정이 이 카드의 클라우드 결과를 반려하거나, 로컬에서 다시 하는 검사가 클라우드에서
놓친 것을 잡으면 이 경로의 비용이 이득보다 크다. 그때는 1번으로 돌아간다.

## Follow-up

- W-00000269·W-00000270 은 이 세션이 `claude/w268-cloud` 에서 사용자 지시로 먼저 구현했다.
  W-00000269 는 이 브랜치에서 DE-00000076 으로 닫혔다. W-00000270 의 예외(DE-00000077)와 채워진
  Actions 는 `claude/stage-cloud-batch` 에 있다. 두 브랜치를 합칠 때 어느 구현을 남길지 로컬에서 정한다.
- 처음에는 이 결정과 카드를 DE-00000076·W-00000286 으로 적었다. 두 번호가 다른 브랜치에서 이미
  쓰인 것을 push 전에 확인하고 DE-00000078·W-00000287 로 바꿨다.
- 클라우드 실행을 정책으로 둘지는 "venue 가 누가와 어디서를 한 칸에 담는다"는 논점과 함께 정한다.
