# DE-00000020 독립 판정의 venue 분리와 claude 자동 리뷰어

## Question

DE-00000016의 독립 판정을 자율 항목에 어떻게 강제하되 "실행자=판정자"를 피하는가? 현재 유일한 리뷰 명령은 codex-companion(Codex 검토)뿐이라, codex 실행 항목을 codex가 검토하면 독립성이 깨진다.

## Options

- A. 판정자 venue ≠ 실행자 venue를 강제하고, venue별 리뷰어 명령을 둔다(claude 자동 리뷰 신설). codex 실행 항목 → claude 리뷰.
- B. 독립 판정자를 자동 구축하지 않고, 없으면 수동 에스컬레이션.
- C. DE-16을 유지하되 codex 자기검토를 허용(독립성 포기).

## Principles applied

- Honesty / No temporary passes — 실행자의 자기검토는 통과 위조다.
- DIP — 판정 기준이 실행자에 종속되면 안 된다.
- Safe completion > Speed — 안전한 완성이 속도보다 우선.
- Fail Fast — 독립 판정자가 없으면 조용히 통과시키지 않고 blocked.
- AHA — 지금은 claude/codex 2-venue만 다룬다.

## Chosen direction

A. 판정자 venue를 실행자와 분리하고 claude 자동 리뷰어를 신설한다.

- 자율(`autonomous: true`) 항목은 종료 시 독립 판정이 필수다. 판정자 venue ≠ item.venue.
- config에 `review.reviewers` 맵(venue → 명령)을 둔다. 자율 항목의 필수 리뷰 = `reviewers[item.venue와 다른 venue]`. 2-venue 기준 유일하게 결정된다. 해당 반대-venue 리뷰어가 미구성이면 auto-complete 불가 → `blocked`(에스컬레이션, DE-00000017 재사용).
- claude 리뷰어 = `claude -p` 헤드리스(설치 확인: `/Users/woogis/.local/bin/claude`, `-p/--print`). diff만 보는 문맥 없는 독립 세션이며 `[P1]`/`BLOCK` 시 차단(codex-companion 미러). 정확한 명령 형태는 settings.json에 추가할 때 실제 실행으로 검증한다.
- 기존 opt-in per-stage review(`strengths`/`stages`)는 비자율 항목용으로 그대로 유지(하위 호환).

## Reason

codex가 codex를 검토하면 통과 위조 위험이 있어 DE-16의 목적이 무력화된다. venue 분리로 진짜 독립을 확보한다. 판정자 부재 시 조용한 통과 대신 `blocked`로 되돌린다(Honesty/Fail Fast). 지금은 claude/codex 2-venue뿐이라 "다른 venue" 선택이 유일하게 결정된다(AHA; N-venue 일반화는 후속). 오케스트레이터(대화 중인 claude)는 맥락·편향이 있으므로 판정은 별도 `claude -p` 세션이 수행한다.

## Follow-up

- claude 리뷰어 명령의 정확한 형태(diff 전달 방식·타임아웃)는 settings.json 추가 시 실행 검증.
- N>2 venue일 때의 판정자 선택 규칙.
- claude 리뷰의 비용/시간을 관측한 뒤 strength(경량/심층) 조정.
