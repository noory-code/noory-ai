# DE-00000085 Distill 카드만 기존 제품 리뷰와 재검사로 닫습니다

## Question

제품 코드가 novel-ai에 있는데 noory-ai의 HEAD만 검토하는 닫기 리뷰로 W-00000274를 다시 검토해야 할까요?

## Options

- noory-ai HEAD의 문서 변경을 제품 리뷰로 받습니다. 실제 제품 변경을 검토하지 못합니다.
- 제품 커밋의 동일성과 기존 독립 리뷰를 확인하고 검사를 다시 실행합니다. 사용자 승인에 따라 이 카드만 닫기 리뷰를 생략합니다.

## Principles applied

Honesty: 다른 저장소의 문서 리뷰를 제품 리뷰라고 부르지 않습니다. SSOT: 제품 소스와 검사 결과는 novel-ai에서 확인합니다. Completion: 독립 리뷰와 네 가지 검사를 근거로 종료합니다. User intent: 사용자가 이 카드의 리뷰 생략을 승인했습니다.

## Chosen direction

두 번째 방안을 택합니다. W-00000274만 `review: not_required`로 닫습니다. 실행 venue와 다른 카드의 리뷰 정책은 바꾸지 않습니다.

2026-11-01에 원래 커밋 `77c2f9bd`와 배포 커밋 `bcc44303`의 patch-id가 모두 `5a582eb413b51e572e3a5d6b0b05eef3a4e4b71e`임을 확인했습니다. novel-ai를 fetch한 뒤 `git merge-base --is-ancestor bcc44303 origin/main`이 종료 코드 0을 반환했습니다.

기존 독립 리뷰는 `.stage/research/llm-work/integration/evidence/2026-10-06-reviews/distill-claude-review-round2.json`이며 `approved: true`입니다. 이번에 새 제품 리뷰를 실행했다고 주장하지 않습니다. 제품 worktree에서 pytest 379개, mypy 소스 파일 40개, ruff와 format 파일 71개 검사가 통과했습니다. 닫기 도구도 같은 검사 네 개를 직접 실행합니다.

| `stage/scripts/audit_stage.py` | 완료 상태와 결정 연결을 검사합니다. 코드·규칙은 바꾸지 않습니다. |

## Reason

닫기 도구가 검토하는 HEAD에는 제품 구현이 없습니다. 같은 제품 patch와 이미 승인된 독립 리뷰를 연결해야 실제 검토 범위를 정확히 설명할 수 있습니다. 이 결정은 한 카드의 종료 절차만 다루므로 공식 정책으로 승격하지 않고 `deferred`로 남깁니다.

반증 조건: patch-id가 다르거나 배포 커밋이 origin/main에 없거나 독립 리뷰가 승인되지 않았거나 네 가지 검사 중 하나라도 실패하면 이 근거로 닫지 않습니다.

## Follow-up

사용자가 승인한 일회성 예외이므로 대안 실행 실험은 적용하지 않습니다. 기존 리뷰의 비차단 지적 여섯 개는 카드에 한계로 남기며 이번 종료 작업에서 제품을 수정하거나 새 작업을 등록하지 않습니다.
