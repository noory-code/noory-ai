# DE-00000087 codex 가 없는 동안 권한·닫기·검증 절차를 바꾸는 카드는 사용자 확인 뒤에 닫는다

## Question

W-00000299 는 클라우드에서 닫힌 카드 5장을 로컬 codex 로 다시 판정해 1장(W-00000295)을 반려했다.
같은 모델의 리뷰가 "인자가 맞게 넘어간다"를 "다른 파일을 쓸 수 없다"의 증거로 받아들인 사례였고,
권한 제한이나 닫기·검증 절차를 바꾸는 카드에 다른 모델 계열의 검토를 더하라고 권고했다.
DE-00000086 으로 codex 가 없는 기간이 시작됐으므로 그 검토를 맡을 다른 모델 계열이 없다.
**그 종류의 카드를 이 기간에 무엇이 다시 보는가.**

## Options

1. **아무것도 더하지 않는다** — 실제로 뚫렸던 종류를 같은 조건으로 계속 닫는다.
2. **환경을 붙인 모든 카드에 사용자 확인을 건다** — 빠짐은 없지만 문구 수정 카드까지 사람을
   기다린다. 확인이 일상이 되면 읽지 않고 통과시키게 된다.
3. **관문 자체를 바꾸는 카드에만 사용자 확인을 건다** — 대상을 바뀐 경로로 정한다. (선택)

## Principles applied

- **User intent** — 사용자가 조건을 더하라고 지시했다(2026-11-14).
- **만든 쪽 ≠ 보는 쪽** — 관문을 고치는 카드를 그 관문과 같은 모델이 판정하면, 관문이 약해지는
  변경을 관문 스스로 통과시킨다. 그 자리에만 다른 눈을 둔다.
- **MECE** — 대상을 판단이 아니라 경로 목록으로 정해 카드마다 해석이 갈리지 않게 한다.
- **Honesty** — 이 규칙은 도구가 강제하지 않는다는 것을 적는다.

## Chosen direction

**3번.**

대상은 아래 두 조건을 모두 만족하는 카드다.

- 카드의 `environment:` 가 `cloud` 또는 `local-no-codex` 다.
- 카드가 바꾼 경로(실행 보고의 `Changed paths (JSON)`)에 아래 가운데 하나가 있다.

| 경로 | 무엇의 관문인가 |
|---|---|
| `stage/hooks/` | 쓰기·등록·커밋 게이트 |
| `stage/scripts/claude_review_companion.py`, `stage/scripts/codex_companion.py` | 리뷰어의 권한 |
| `stage/skills/stage-retrospective/close_work.py` | 닫기 판정 |
| `stage/scripts/audit_stage.py` | 감사 규칙 |
| `stage/scripts/drive.py`, `stage/scripts/driver_*.py` | 드라이버의 실행·리뷰 순서 |
| `.stage/settings.json`, `stage/templates/v4/project-stage/settings.jsonc` | 실행기·리뷰 명령·라우팅 |
| `.stage/operations/`, `stage/operations/` | 닫기·검증·리뷰 절차 문서 |

대상 카드는 다음 순서로 닫는다.

1. 감독이 인수 검사와 닫기 리뷰 판정까지 받는다. 닫기 명령의 마지막 실행은 아직 하지 않는다 —
   리뷰가 통과한 닫기 워크트리의 결과를 본 가지로 옮기지 않고 둔다.
2. 감독이 사용자에게 세 가지를 보여 준다: 바뀐 경로와 한 줄씩의 요약, 기준별 리뷰 판정,
   리뷰어가 직접 실행하지 못하고 기록이나 코드 읽기로 판정한 기준.
3. 사용자가 확인하면 카드의 `## Verification` 에 `사용자 확인 — <날짜>` 한 줄과 사용자가 본 것을
   적는다. 그 뒤에 닫힌 카드를 본 가지로 옮기고 커밋한다.
4. 사용자가 반려하면 그 이유를 실패한 기준으로 다뤄 실행자에게 돌려보낸다.

이 규칙은 도구가 강제하지 않는다. `close_work.py` 는 사용자 확인 줄을 읽지 않는다.

## Where this applies

| 종류 | 자리 | 무엇을 하는가 |
|---|---|---|
| 문서 | `.stage/operations/claude-venue.md` | 대상 경로와 닫는 순서를 적는다 — 이 결정이 바꾸는 유일한 자리 |
| 게이트 | `close_work.py` | 바뀌지 않는다. 사용자 확인 여부를 모른다 |
| 감사 규칙 | `audit_stage.py` | 바뀌지 않는다. 확인 줄이 없는 대상 카드를 잡지 못한다 |
| 실패 경로 | 감독이 대상임을 놓침 | 카드가 확인 없이 닫힌다. 남는 흔적은 `## Verification` 에 확인 줄이 없다는 것뿐이다 |
| 실패 경로 | 사용자가 오래 답하지 않음 | 카드가 `active` 로 남고 그 변경은 본 가지에 커밋돼 있되 닫히지 않은 상태다 |

코드 호출 자리는 없다. 이 결정은 감독 세션의 절차만 바꾼다.

## Reason

반려된 한 장은 리뷰어의 권한을 좁히는 카드였다. 관문을 고치는 변경은 틀렸을 때 그 뒤의 모든
카드가 약해진 관문을 지나므로 비용이 다른 카드보다 크고, 같은 모델이 놓치기 쉬운 자리라는 것이
이미 한 번 관측됐다. 표본이 5장뿐이라 "이 종류만 위험하다"고 말할 근거는 되지 못한다. 확인된
자리부터 막는 것이다.

돌려 보지 않았다. 선택지들은 같은 입력에서 다른 출력을 내는 것이 아니라 사람이 언제 개입하는지가
다르다.

## 이 결정이 틀렸다는 것을 무엇으로 알게 되나

- 대상 카드가 사용자 확인 줄 없이 닫힌 것이 한 번이라도 발견되면, 절차만으로는 지켜지지 않는다는
  뜻이다. 그때는 감사 규칙으로 강제한다.
- 대상이 아닌 카드에서 같은 모델의 리뷰가 통과시킨 결함이 거듭 나오면 경로 목록이 좁다는 뜻이다.
  DE-00000086 의 반증 조건과 같은 관측이며, 그때는 2번으로 넓힌다.

## Follow-up

- codex 구독을 되살리면 이 조건을 W-00000299 의 원래 권고(다른 모델 계열의 검토)로 바꿀지 정한다.
- 감사 규칙으로 강제할지는 위 첫 번째 관측이 나오면 정한다. 구현하지 않았다.
