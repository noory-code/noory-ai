# DE-00000086 codex 가 없는 로컬 세션을 별도 환경으로 선언해 Claude 가 실행하게 한다

## Question

사용자가 codex 구독을 당분간 유지하지 않는다(2026-11-14). `venue_routing` 은 development·fix·qa·
ops·chore 를 codex 로 보내고 `review.strengths` 의 모든 명령도 codex 를 부른다. DE-00000082 는
클라우드 세션에서만 이 라우팅을 벗어나게 했으므로, 로컬 세션에서는 codex 로 라우팅되는 카드를
시작할 수도 닫을 수도 없다. **codex 가 없는 기간에 로컬 카드를 누가 실행하고, 그 사실을 어디에
남길 것인가.**

## Options

1. **`venue_routing` 과 `review.strengths` 를 전부 claude 로 바꾼다** — 카드마다 붙일 것이 없다.
   대신 설정이 "원래 codex 가 하던 일"이라는 사실을 잃고, 닫기 리뷰가 같은 모델의 리뷰였다는
   표시를 아무것도 강제하지 않는다. 구독을 되살리면 되돌리는 결정이 다시 필요하다.
2. **`environment_venues` 에 로컬 환경을 하나 더 선언한다** — 라우팅과 리뷰 명령은 그대로 두고,
   카드가 `environment:` 로 "codex 없는 로컬에서 Claude 가 대신 실행했다"를 남긴다. DE-00000082 의
   세 조건(선언된 환경, 그 환경의 venue, `review: pending`)이 그대로 걸린다. (선택)
3. **카드마다 venue 예외 결정을 세운다** — DE-00000082 가 같은 예외 일곱 장을 보고 버린 방식이다.

## Principles applied

- **User intent** — 사용자가 2번을 골랐다(2026-11-14).
- **Honesty** — venue 는 실제로 실행한 쪽을, environment 는 codex 가 없었다는 사정을 말한다.
  임시 상태가 임시로 기록된다.
- **SSOT** — "codex 가 원래 맡는 종류"는 `venue_routing` 한 곳에 남는다. 1번은 그 사실을 지운다.
- **만든 쪽 ≠ 보는 쪽** — 환경 정책이 `review: pending` 을 강제하므로 리뷰 없이 닫히는 카드가
  생기지 않는다. 다만 보는 쪽이 같은 모델 계열이라는 약점은 그대로 남는다(아래 Reason).

## Chosen direction

**2번.**

- `.stage/settings.json` 의 `environment_venues` 에 `"local-no-codex": "claude"` 를 더한다.
  `venue_routing`, `executors`, `review` 는 고치지 않는다.
- codex 가 없는 로컬 세션에서 codex 로 라우팅되는 종류의 카드는
  `--environment local-no-codex --review` 로 등록하거나 시작한다.
- 닫기 리뷰는 설정을 고치지 않고 Claude 대역으로 돌린다
  (`STAGE_CODEX_COMPANION=stage/scripts/claude_review_companion.py`). 절차는 클라우드와 같으며
  `stage/operations/cloud-execution.md` 의 Close 3·4단계가 소유한다. 카드의 `## Verification` 에
  같은 모델의 리뷰였다고 적는다.
- 클라우드 세션은 지금처럼 `cloud` 를 쓴다. 두 환경은 "어디서"가 다르므로 합치지 않는다.
- codex 구독을 되살리면 새 카드에 이 환경을 쓰지 않는다. 선언은 이 환경으로 닫힌 카드가 모두
  보관된 뒤에 지운다.

### 새 환경 이름 하나로 기존 판정이 그대로 걸린다

실제 `.stage/` 사본에 선언 한 줄을 더하고 공유 판정 함수
`stage_work.environment_venue_error` 를 돌린 결과(2026-11-14, 코드 변경 없음):

| 입력 (environment, venue, review) | 결과 |
|---|---|
| 선언 전 `local-no-codex`, claude, pending | 거절 — 선언되지 않은 환경 |
| `local-no-codex`, claude, pending | 허용 |
| `local-no-codex`, claude, not_required | 거절 — 독립 닫기 리뷰가 필요하다 |
| `local-no-codex`, codex, pending | 거절 — 이 환경의 venue 는 claude 다 |
| `cloud`, claude, pending | 허용 (기존 동작 유지) |

`load_environment_venues` 는 환경 이름을 고정하지 않고 설정의 키를 그대로 읽는다. 그래서 2번은
설정 한 줄이고, 플러그인 코드는 바뀌지 않는다. 1번은 돌려 보지 않았다 — 두 방향은 한 번의
실행에서 다른 결과를 내는 것이 아니라 카드에 무엇이 남는지가 다르다.

## Where this applies

| 종류 | 자리 | 무엇을 하는가 |
|---|---|---|
| 설정 | `.stage/settings.json` `environment_venues` | 새 환경을 선언한다 — 이 결정이 바꾸는 유일한 자리 |
| 코드 | `stage/hooks/stage_paths.py` `load_environment_venues` | 선언을 읽는다. 바뀌지 않는다 |
| 코드 | `stage/hooks/stage_work.py` `environment_venue_error` | 세 조건을 판정한다. 바뀌지 않는다 |
| 코드 | `stage/skills/stage-work/register_work.py`, `stage/scripts/start_work.py` | `--environment` 를 받는다. 바뀌지 않는다 |
| 감사 규칙 | `stage/scripts/audit_stage.py` VENUE006 | 열린 카드가 조건을 어기면 낸다. 바뀌지 않는다 |
| 게이트 | 닫기 (`close_work.py`), 드라이버 (`drive.py`) | 리뷰 명령이 `codex_companion.py` 를 부르고, 그 스크립트가 `STAGE_CODEX_COMPANION` 을 읽는다. 닫기와 드라이버가 같은 명령 문자열을 쓰므로 두 호출자 모두 이 변수를 받아야 한다 |
| 설정 | `preflights.codex`, `reapers.codex` | 실행 venue 가 claude 이면 돌지 않는다 |
| 문서 | `.stage/operations/claude-venue.md` | codex 없는 로컬 세션의 시작·닫기 명령을 적는다 |
| 문서 | `stage/operations/cloud-execution.md` | 절차의 소유자. "venue 가 없는 실행 환경" 일반을 이미 다루므로 고치지 않는다 |
| 실패 경로 | `--environment` 를 빠뜨림 | venue claude 이면 등록·시작이 라우팅 불일치로 거절한다. venue codex 로 등록되면 실행기가 없어 실행 단계에서 멈춘다 |
| 실패 경로 | `STAGE_CODEX_COMPANION` 을 빠뜨림 | 리뷰 명령이 codex 를 찾지 못해 0 이 아닌 값으로 끝나고 닫기가 막힌다(fail closed) |

## Reason

라우팅은 "이 종류는 다른 모델이 만든다"는 설계 의도이고, codex 가 없는 것은 사정이다. 사정
때문에 의도를 지우면 구독을 되살릴 때 무엇을 되돌려야 하는지도 함께 사라진다. 환경 선언은
의도를 남긴 채 사정만 기록하고, 이미 있는 판정이 독립 닫기 리뷰를 강제한다.

이 결정이 잃는 것도 적는다. DE-00000082 는 클라우드 결과를 "나중의 로컬 codex 확인"으로 다시 볼
수 있다는 것을 안전망으로 삼았다. codex 가 없는 동안 그 안전망은 없다. 실행도 리뷰도 같은 모델
계열이므로, 둘이 함께 놓치는 결함은 결정적 검사(acceptance 명령)와 사람의 확인만이 잡는다.

그 안전망이 실제로 잡은 것이 있다. W-00000299 가 클라우드에서 닫힌 카드 5장을 로컬 codex 로 다시
판정해 1장(W-00000295)을 반려했다. 같은 모델의 리뷰가 인자 확인을 실제 쓰기 제한의 증거로
받아들인 사례였고, W-00000299 는 권한 제한이나 닫기·검증 절차를 바꾸는 카드에 다른 모델 계열의
검토를 더하라고 권고했다. 그 권고는 아직 판단되지 않았고, 이 기간에는 다른 모델 계열이 없다.

## 이 결정이 틀렸다는 것을 무엇으로 알게 되나

이 환경으로 닫힌 카드에서, 닫기 리뷰가 통과시킨 결함을 사람이나 나중의 사용이 거듭 찾아내면
같은 모델의 리뷰가 관문 구실을 못 한다는 뜻이다. 그때는 이 환경의 카드에 사람의 확인을 닫기
조건으로 더한다. codex 를 되살린 뒤 표본 재검토(W-00000299 방식)가 이 환경의 카드를 자주
반려해도 같다.

## Follow-up

- 열려 있는 codex venue 카드(W-00000271, W-00000281, W-00000282)를 환경을 붙여 다시 시작할지
  카드마다 정한다. W-00000271 은 문장이 자연스러운지를 다른 모델이 보는 것이 목적의 일부였다.
- codex 구독을 되살리면 이 환경으로 닫힌 카드를 표본 재검토할지 정한다.
- 권한 제한이나 닫기·검증 절차를 바꾸는 카드는 codex 가 없는 동안 사람의 확인을 닫기 조건으로
  둘지 정한다(W-00000299 의 권고가 가리킨 종류다). → DE-00000087 이 정했다.
