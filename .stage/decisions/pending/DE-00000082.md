# DE-00000082 실행 환경을 venue 와 다른 칸으로 두고 클라우드 실행을 정책으로 허용한다

## Question

`venue` 한 칸이 "누가 실행하는가"(모델)와 "어디서 실행하는가"(로컬 훅·codex 가 있는 자리인지)를 함께
담는다. 클라우드 세션에는 codex 가 없어 `kind -> venue` 라우팅이 codex 를 고른 카드를 Claude 가
실행했고, 2026-10-31 하루에 카드마다 같은 모양의 venue 예외 결정 일곱 장(DE-00000075~081)을 세웠다.
**클라우드 실행을 카드마다의 예외로 둘 것인가, 정책으로 둘 것인가.** 사용자는 정책으로 만들라고
지시했다.

## Options

1. **카드마다 예외를 세운다(지금)** — 결정 기록이 같은 문장을 반복하고, 실행 전에 세우는 것을 잊으면
   실행 뒤에 소급해 세운다(DE-00000076·077).
2. **`cloud` 를 새 venue 값으로 둔다** — venue 가 다시 "누가"와 "어디서"를 섞는다. 클라우드에서
   실행한 모델(Claude)을 기록하지 못하고, 교차 venue 리뷰 규칙이 `cloud` 의 반대편을 정할 수 없다.
3. **실행 환경을 카드의 별도 칸 `environment` 로 두고, 환경마다 실행하는 venue 를 설정에서 선언한다**
   — venue 는 실제로 실행한 쪽으로 남고, 환경은 따로 남는다. (선택)

## Principles applied

- **User intent** — 사용자가 클라우드 실행을 정책으로 만들라고 지시했다.
- **SoC** — 한 칸에 한 책임만 둔다. venue 는 누가, environment 는 어디서.
- **SSOT** — 클라우드 실행 계약을 결정 일곱 장에 복제하지 않고 `stage/operations/cloud-execution.md`
  한 곳이 소유한다.
- **Honesty** — venue 는 실제로 실행한 쪽을 말한다. 같은 모델 계열의 닫기 리뷰는 교차 venue 리뷰가
  아니라는 것을 카드에 적는다.
- **만든 쪽 ≠ 보는 쪽** — 정책으로 허용하는 대신 독립 닫기 리뷰(`review: pending`)를 조건으로 건다.

## Chosen direction

**3번.**

- 카드 frontmatter 에 선택 칸 `environment` 를 둔다. 없으면 로컬이다.
- `settings.json` 의 `environment_venues` 가 환경마다 그 환경에서 실행하는 venue 를 선언한다. 이
  프로젝트는 `{"cloud": "claude"}` 다.
- `environment` 가 선언된 환경을 가리키고, `venue` 가 그 환경의 venue 와 같고, `review` 가 `pending`
  또는 `passed` 이면, `venue_routing` 과 달라도 예외 결정 없이 허용한다. 등록·시작 도구와 감사가 같은
  조건을 쓴다.
- 섞인 종류(`split`)를 나누라는 규칙은 환경과 상관없이 그대로 둔다. 그 규칙은 "누가"가 아니라 설계와
  구현을 나누는 규칙이다.
- 실행·이관·닫기 절차는 `stage/operations/cloud-execution.md` 가 소유한다.

## Where this applies

| 종류 | 자리 | 무엇을 하는가 |
|---|---|---|
| 코드 | `stage/hooks/stage_paths.py` | `environment_venues` 를 읽는다 |
| 코드 | `stage/hooks/stage_work.py` | 환경 정책 허용 조건을 판정한다(공유) |
| 코드 | `stage/skills/stage-work/register_work.py`, `stage/scripts/start_work.py` | `--environment` 를 받고 조건이 맞으면 예외 없이 등록·시작한다 |
| 감사 규칙 | `stage/scripts/audit_stage.py` | 조건이 맞으면 VENUE003 을 내지 않고, `environment` 가 조건을 어기면 VENUE006 을 낸다 |
| 설정 | `.stage/settings.json`, `stage/templates/v4/project-stage/settings.jsonc` | `environment_venues` |
| 문서 | `stage/operations/cloud-execution.md`, `stage/docs/SCHEMA_V4.md` | 실행 계약과 칸 정의 |
| 실패 경로 | 위 세 도구 | 선언되지 않은 환경, venue 불일치, 리뷰 미요구를 이유와 함께 거절한다 |
| 게이트 | 닫기 | 바뀌지 않는다. `review: pending` 카드는 리뷰 판정 없이 닫히지 않는다 |

## Reason

같은 예외를 일곱 번 세운 것은 예외가 아니라 정책이라는 뜻이다. 일곱 장 모두 같은 조건(클라우드,
Claude 실행, 독립 닫기 리뷰, 로컬 또는 worktree 에서 닫기)을 반복했고, 그 카드들의 닫기 리뷰가 모두
통과했다.

## 이 규칙이 틀렸다는 것을 무엇으로 알게 되나

클라우드에서 실행한 카드의 닫기 리뷰나 나중의 로컬 codex 확인이 클라우드 결과를 자주 반려하면, 같은
모델 계열의 리뷰가 실행자의 사각지대를 함께 놓친다는 뜻이다. 그때는 클라우드 카드의 닫기 리뷰를
로컬 codex 로 되돌리는 조건을 더한다.

## Follow-up

- 클라우드에서 실행한 카드를 로컬 codex 로 표본 검사할지 정한다.
- 결정이 정착되면 `official/canon` 으로 승격한다.
