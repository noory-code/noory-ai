# DE-00000102 후속 작업 후보는 지금 깨져 있거나 열린 마일스톤의 완료 기준 한 줄을 지목할 때만 카드가 된다

## Question

카드를 닫을 때마다 후속 작업 후보가 넷에서 여섯 건씩 나온다. 2026-11-23 에 닫은 여덟 장에서 서른 건이 넘었고 사용자가 "한도
끝도 없이 일이 생긴다"고 했다(O-00000061). 그날의 리뷰 세션은 사용자가 문턱을 정하기 전에는 지휘 세션이 후보에서 목적을
유추해 카드를 만들지 말라고 했다(O-00000062). 네 가지를 묻는다.

1. 카드가 되지 못한 후보는 어떻게 되는가?
2. 무엇이 문턱을 넘는가?
3. 누가 판정하고 사용자는 무엇을 보는가?
4. 이미 쌓인 후보(O-00000061 의 아홉 건, W-00000418 의 네 건)는 어떻게 하는가?

규칙 후보(회고의 `## Rule candidate`)의 문턱은 이 결정이 다루지 않는다. 토론 세션이 사용자와 이어서 정한다.

## Options

| 질문 | 선택지 |
|---|---|
| 1 | A 기록하지 않고 버린다. 진짜 문제면 다시 나타난다 / B 목록에 한 줄로 두고 나온 횟수를 센다 / C 열린 마일스톤에 닿는 것만 둔다 |
| 2 | 1 지금 깨져 있다(명령이 실패하거나, 결과가 틀리거나, 문서대로 하면 막힌다. 재현할 수 있다) / 2 열린 마일스톤에 닿는다 / 3 1 또는 2 / 4 닫을 때 사용자가 고른 것만 |
| 3 | 가 작업 세션이 후보마다 증거를 붙이고 없으면 지휘 세션이 버린다. 사용자는 등록된 카드만 본다 / 나 가 에 더해 닫을 때 "등록 몇, 버림 몇" 한 줄 / 다 가 에 더해 통과한 후보를 등록 전에 사용자가 확인한다 |
| 4 | 가 지금 문턱을 대서 통과한 것만 등록하고 나머지는 버린다 / 나 새 후보부터 적용한다 / 다 문턱을 대지 않고 전부 버린다 |

## Principles applied

- User intent: 네 질문 모두 사용자가 골랐다.
- AHA: 한 번 나온 후보로 일감이나 절차를 만들지 않는다. 진짜 문제는 다시 나타난다.
- KISS: 버린 후보의 목록을 두지 않는다(B 를 고르지 않았다).
- Fail Fast: 지금 깨진 것은 문턱을 넘는다.

## Chosen direction

사용자가 2026-11-25 에 골랐다. 질문 1 에서 3 은 토론 세션 session_018VXR6SH4PsfzwA6PTiZW3a 에서, 질문 4 와 둘째 조건의
읽기는 지휘 세션 session_018VXR6NxmjDnZJNGb3TZWco 의 질문에 답해서 골랐다.

| 질문 | 고른 것 | 사용자의 말 |
|---|---|---|
| 1 | A. 문턱을 넘지 못한 후보는 기록하지 않고 버린다 | "A 가 좋습니다." |
| 2 | 3. 지금 깨져 있거나, 열린 마일스톤에 닿으면 카드다 | "3으로 합시다." |
| 2 의 둘째 조건 | 열린 마일스톤의 완료 기준 한 줄을 지목해야 한다. 목적 문장에 닿는 것으로는 모자란다 | "네, 좁혀 읽기" |
| 3 | 나. 후보를 낸 쪽이 증거(재현 명령, 또는 완료 기준 한 줄의 인용)를 붙이고, 없으면 지휘 세션이 버리고, 닫을 때 집계 한 줄을 남긴다 | "네 추천대로" |
| 4 | 가. 쌓인 후보에 지금 문턱을 댄다 | "소급한다" |

문턱을 넘은 후보는 목적과 성공 기준을 들고 온다. 깨진 것은 "재현 명령이 통과한다"가 성공 기준이고, 마일스톤 것은 지목한
완료 기준이 목적이다. 그래서 지휘 세션은 후속 카드마다 목적을 사용자에게 묻지 않는다.

DE-00000093 은 "다음 할 일이 카드로 가지 않고 사라진다"를 자기가 틀렸다고 볼 일로 적었다. 이 결정은 문턱을 넘지 못한
후보가 사라지는 것을 의도한다. 그 문장은 "문턱을 넘은 다음 할 일이 카드로 가지 않고 사라진다"로 읽는다. 사용자가
2026-11-25 에 이렇게 좁히는 것을 받아들였다("추천대로 해주세요").

| 이미 되어 있음 | 3 | 버리지도 등록하지도 않는다 |

## Reason

후보를 모두 적어 두면 적힌 것이 일감으로 읽힌다. O-00000061 과 보관된 카드의 `Follow-up candidate:` 줄이 그렇게 쌓였다.
후보를 낸 쪽에 증거를 낼 책임을 두면 지휘 세션은 증거가 있는지만 센다. 집계 한 줄은 문턱이 너무 높거나 낮은지를 나중에
숫자로 보게 해 준다.

알고 고른 약점:

- 판정하는 쪽도 같은 모델이다. 재현 명령이 진짜 고장을 보여 주는지까지는 보지 않는다.
- 해 보지 않은 길은 깨진 것으로 치지 않는다. 에픽을 닫는 길은 실제 에픽을 닫을 때 처음 확인된다.
- 버린 후보는 세기만 하고 적지 않으므로, 문턱이 잘못 버린 것을 나중에 찾을 수 없다.

이 결정이 틀렸다고 볼 일: 버려진 후보와 같은 문제가 뒤에 사고로 나타나고, 그 후보가 붙일 수 있었던 증거가 그때도 없었다.
또는 닫을 때의 집계에서 등록이 버림보다 계속 많다.

선택지를 실제로 돌려 본 것은 쌓인 후보 열세 건에 문턱을 댄 것 하나다(위 표). 선택지 1 만 쓴 경우와 3 을 쓴 경우는 이
열세 건에서 결과가 같았다. 마일스톤 조건으로만 통과한 후보가 없었다.
