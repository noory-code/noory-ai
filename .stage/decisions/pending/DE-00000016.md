# DE-00000016 독립 판정 필수화

## Question

자율 실행 항목의 검증을, 일한 주체가 스스로 판정하게 둘 것인가, 독립된 판정 주체를 필수화할 것인가? 현행은 기본 자기검증(`close_work`가 `--check` 실행)이며, opt-in `review` 훅(codex-companion review, `[P1]`/`BLOCK` 시 차단)만 독립 검증을 제공한다.

## Options

- A. 자기검증 유지 — 드라이버가 실행 주체의 판정을 그대로 신뢰한다.
- B. 자율 항목에 독립 판정 필수 — 기존 `review` 훅을 자율 대상 항목의 종료 게이트로 강제한다.
- C. 항목마다 선택.

## Principles applied

- Honesty / No temporary passes — 자기 채점은 통과를 위조할 구조적 유인이 있다.
- Fail Fast — 실행자와 다른 축의 실패를 조기에 노출한다.
- Safe completion > Speed(우선순위) — 안전 완성이 속도보다 우선이다.
- DIP — 판정 기준이 실행자에 종속되어서는 안 된다.

## Chosen direction

B. 자율 실행 대상 항목은 독립 판정을 필수로 한다.

- 기존 `review` 메커니즘(실행 venue와 다른 주체; 예: 구현=codex면 검토=claude)을 자율 항목의 종료 필수 게이트로 승격한다.
- `acceptance` 셸 검증이 통과해도, 독립 판정자가 `BLOCK`하면 종료가 아니다 → 재시도 또는 에스컬레이션.

## Reason

자율 루프에서 실행자의 자기검증은 "통과했다"를 위조할 유인이 있다(세 통제 장치의 핵심). 독립 판정은 `acceptance`(기계)와는 다른 축의 실패 — 요구 오해, 범위 이탈 — 를 잡는다. 안전 완성이 속도보다 우선이므로 필수화가 맞다. 이미 있는 `review` 훅을 재사용한다(AHA).

## Follow-up

- 독립 판정자 부재(codex-companion 미가용) 시 폴백: 자율 불가 → 사람 대기.
- 판정자 다양성(단일 판정자 vs 다관점) 결정.
- `acceptance` 통과 후에만 판정을 호출할지, 병행할지 결정.
