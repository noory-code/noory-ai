# DE-00000092 두 세션이 같은 기록 번호를 고르지 않게 하는 방법

## Question

두 세션이 서로의 브랜치를 받아 오지 않은 채 카드나 기록을 등록할 때, 같은 번호를 고르지 않게 하려면 어떻게
하는가?

지금은 `stage_record_ids.py` 가 이 체크아웃과 이미 받아 온 브랜치만 세고 네트워크에는 가지 않는다. 그래서
`.stage/operations/parallel-sessions.md` 가 등록하기 전에 `git fetch` 를 하고 등록한 뒤 바로 push 하라고 정한다.
이 규칙이 있는 동안에도 번호가 겹쳤다(R-00000358 에서 두 번).

## Options

| 선택지 | 내용 | 약한 점 |
|---|---|---|
| 지금 규칙을 둔다 | 등록하기 전에 fetch 하고 등록한 뒤 바로 push 한다. | 한 번 잊으면 겹친다. 겹친 것은 push 가 거절되거나 사람이 알려 줘야 안다. |
| 등록할 때 번호를 원격에 잡는다 | 번호마다 원격에 ref 를 하나 만든다. 이미 있으면 다음 번호로 넘어간다. | 등록할 때 네트워크가 있어야 한다. |
| 겹친 뒤에 고친다 | PR 에서 CI 가 겹친 번호를 잡고, 도구로 번호를 바꾼다. | 카드, 회고, 링크, 커밋 메시지에 적힌 번호를 모두 다시 써야 한다. |

## Principles applied

- Fail Fast — 번호가 겹치는 것을 등록하는 순간에 막는다.
- SSOT — 어떤 번호가 쓰였는지는 원격 한 곳이 답한다. 체크아웃마다 다르게 세지 않는다.
- Postel's Law — 네트워크가 없을 때도 등록은 된다. 다만 번호를 잡지 못했다고 알린다.

## Chosen direction

등록할 때 번호를 원격에 잡는다.

- 번호를 고르면 `refs/stage-ids/<번호>` 를 원격에 만든다. 이미 있으면 거절되고, 다음 번호로 다시 시도한다.
- 원격에 닿지 못하면 지금처럼 이 체크아웃과 받아 온 브랜치만 세어 번호를 고르고, 번호를 원격에 잡지 못했다고
  출력한다.
- 원격이 없는 프로젝트는 지금과 똑같이 동작한다.

### 받아 오지 않은 두 번째 세션이 같은 번호를 잡으려 하면 거절된다

빈 원격 저장소 하나와 클론 두 개로 실행했다. 두 클론은 서로의 커밋을 받아 오지 않았다.

| 순서 | 명령 | 결과 |
|---|---|---|
| A 가 번호를 잡는다 | `git push --force-with-lease=refs/stage-ids/W-00000374: origin HEAD:refs/stage-ids/W-00000374` | 성공했다. |
| B 가 같은 번호를 잡는다 | 같은 명령 | `! [rejected] (stale info)` 로 거절됐다. |
| B 가 조건 없이 push 한다 | `git push origin HEAD:refs/stage-ids/W-00000374` | 빨리 감기가 아니라서 거절됐다. |

원격에는 A 가 만든 ref 하나만 남았다. `refs/stage-ids/` 는 `refs/heads/` 밖에 있어서 보통의 clone 과 fetch 가 받아
오지 않는다.

지금 규칙을 두는 쪽은 이미 실행된 결과가 있다. R-00000358 의 카드 한 장에서 번호가 두 번 겹쳤다.

## Where this applies

| 종류 | 자리 | 이 결정으로 바뀌는 것 |
|---|---|---|
| 코드 | `stage/scripts/stage_record_ids.py` | 다음 번호를 말해 줄 때 원격에 잡는 선택지를 더한다. 원격의 `refs/stage-ids/` 도 센다. |
| 코드 | `stage/skills/stage-work/register_work.py` (5줄) | 카드 번호를 고른 뒤 원격에 잡는다. 거절되면 다음 번호로 넘어간다. |
| 코드 | `stage/skills/stage-roadmap/manage_roadmap.py` (184줄 근처) | 마일스톤과 테마 번호를 고르는 자리다. 같은 방식을 쓴다. |
| 코드 | `stage/skills/stage-retrospective/close_work.py`, `stage/scripts/driver_lifecycle.py` | 회고 번호는 카드 번호에서 얻는다. 카드 번호가 겹치지 않으면 회고 번호도 겹치지 않는다. 바뀌지 않는다. |
| 코드 | `stage/scripts/drive.py`, `driver_unattended.py`, `driver_worktree.py` | 번호를 고르지 않고 예약된 회고 번호를 넘겨받는다. 바뀌지 않는다. |
| 코드 | 손으로 번호를 받는 기록 (DE, O, Q, P, A, K) | `stage_record_ids.py` 를 실행해서 번호를 받는다. 같은 명령이 번호를 잡는다. |
| 설정 | 없음 | 원격의 이름은 git 설정에서 읽는다. Stage 설정에 새 키를 두지 않는다. |
| 문서 | `.stage/operations/parallel-sessions.md` | "등록하기 전에 fetch, 등록한 뒤 바로 push" 를 네트워크가 없을 때의 규칙으로 고친다. |
| 문서 | `stage/skills/stage-decision/SKILL.md`, `stage/operations/cloud-execution.md`, `stage/docs/BLUEPRINT.md` | `stage_record_ids.py` 가 네트워크에 가지 않는다고 적은 곳을 고친다. |
| 실패 경로 | 원격에 닿지 못한다 | 받아 온 브랜치만 세어 번호를 고르고, 잡지 못했다고 출력한다. 등록은 막지 않는다. |
| 실패 경로 | push 권한이 없다 | 원격에 닿지 못한 것과 같이 다룬다. |
| 실패 경로 | 번호를 잡았는데 등록이 실패한다 | 잡힌 번호는 쓰이지 않은 채 남는다. 번호가 하나 비는 것은 받아들인다. |
| 관문 | 없음 | 번호를 고르는 것을 막거나 허락하는 관문이 없다. |
| 점검 규칙 | `stage/scripts/audit_stage.py` 의 번호 중복 검사 | 한 체크아웃 안에서 겹친 번호를 잡는다. 그대로 둔다. |

## Reason

번호가 겹치는 까닭은 두 세션이 서로 다른 것을 보고 세기 때문이다. 순서를 지키라는 규칙은 사람이나 세션이
기억해야 지켜지고, 잊은 것을 알려 주는 것이 없다. 원격에 ref 를 만드는 것은 git 이 한 번에 한 쪽만 성공하게
해 주므로 기억에 기대지 않는다.

이 결정이 틀렸다고 볼 일: 번호를 원격에 잡았는데도 두 브랜치에서 같은 번호가 나온다. 또는 등록할 때마다
원격을 기다리는 시간이 길어서 세션이 번호 잡기를 끄고 일한다.

## Follow-up

- GitHub 이 `refs/stage-ids/` 같은 이름의 ref 를 받아 주는지는 확인하지 않았다. 시험은 로컬의 빈 저장소로 했다.
  구현 카드가 이 저장소의 원격으로 확인하고, 안 되면 받아 주는 이름(예: 태그)으로 바꾼다.
- 잡아 둔 ref 가 쌓인다. 치울지, 언제 치울지는 정하지 않았다.
- 겹친 뒤에 번호를 바꾸는 도구는 실행해 보지 않았다.
