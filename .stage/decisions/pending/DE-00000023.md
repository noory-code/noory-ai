# DE-00000023 자율 실행 드라이버 아키텍처와 안전 경계

## Question

자율 실행 드라이버(W-47)의 루프 구조, 실행자 구동 방식, 런타임 상태, 무진전 감지, 안전 경계를 어떻게 정하는가? 이 드라이버는 네 primitive — acceptance(DE-14) · 독립 판정(DE-16/20) · 집계(DE-15/21) · escalate/한계(DE-17/22) — 를 엮어 사람이 승인한 분해를 자율 실행한다.

## Options

실행자 구동(가장 위험한 축):
- A. `executors` config(venue → 명령). 드라이버가 `executors[item.venue]`로 항목 작업을 생성(codex headless / claude -p). reviewers 패턴 미러.
- B. 드라이버는 라이프사이클만 오케스트레이션, 실행은 외부(사람/별도 프로세스).
- C. 드라이버가 codex-rescue 브리지를 직접 호출.

## Principles applied

- SoC / DIP — 실행자를 config로 추상화, venue 아키텍처와 일관.
- Honesty / No partial completion — 실패·상한은 `blocked`, 절대 가짜 완료 아님.
- Fail Fast — 실행자·한계 부재/막힘 시 조용히 통과하지 않고 escalate/중단.
- SSOT / AHA — 런타임 상태는 `.runtime/`로 분리(커밋 churn 방지).
- 우선순위: Truthfulness > User intent > Project essence > Safe completion > Durability > Simplicity > Speed.

## Chosen direction

A. config 기반 실행자 + 안전 불변식이 박힌 루프.

- **실행자**: `executors` config(venue → 명령), reviewers와 대칭. 드라이버는 항목 venue에 맞는 executor로 작업을 생성한다. executor 부재 → 해당 항목 실행 불가 → escalate(fail-closed).
- **루프**: 대상 부모(umbrella/target)를 받아 — 준비된(비-terminal · 의존 충족 · acceptance 보유) 말단 자식을 우선순위 순 선택 → executor 실행 → acceptance 검증 → 통과 시 독립 판정 → 통과 시 close(verification passed) + 부모 집계 전진 → 실패 시 재시도(항목당 시도 상한) / 무진전·상한 시 escalate. 부모가 terminal 되거나 전역 상한·blocked까지 반복.
- **런타임 상태**: `.runtime/driver/<run>.json`(untracked) — iteration 수, 시작 시각, 항목별 시도 카운트·마지막 지문.
- **무진전 감지**: 지문 = hash(git diff + acceptance 출력). 연속 시도에서 동일 → 무진전 → escalate.
- **한계 집행**: `load_limits_config`를 읽되 **반환 error를 반드시 검사**한다(absent/malformed가 둘 다 `None`이므로 — 독립 리뷰 지적). 항목당 시도 상한 초과 → escalate; 전역 iteration/벽시계 초과 → 런 종료(백스톱) + 핸드오프.
- **안전 불변식**: (1) 드라이버는 승인된 분해(대상 부모의 기존 자식) 안에서만 동작 — 새 항목 생성·새 분해 승인·official 승격을 하지 않는다(사람 게이트 보존, DE-13). (2) 모든 변이는 게이트된 경로(`start_work`/`close_work`/`escalate_work` 또는 게이트 통과 쓰기)로. (3) 실패·상한 = `blocked`, 가짜 완료 금지. (4) official 승격은 사람 몫(미검증 진리 금지).

## Reason

executor config는 reviewers와 대칭이라 venue 아키텍처를 일관되게 확장한다(SoC/DIP). 런타임 상태를 `.runtime/`로 분리해 커밋 churn을 없앤다(AHA). 안전 불변식이 자율의 핵심 — 드라이버가 사람 승인 게이트를 넘지 않고, 막히면 정직하게 `blocked`로 되돌린다(Honesty/Fail Fast/No partial completion). 우선순위상 Safe completion이 Speed보다 우선하므로 상한·escalate를 강제한다. 이는 세 통제 장치를 하나의 루프로 통합한다.

## Follow-up
