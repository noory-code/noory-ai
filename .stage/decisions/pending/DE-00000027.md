# DE-00000027 무인 부모 aggregation-close의 검증 계약

## Question

무인 루프가 부모(중간 노드/umbrella)를 자동 close할 때, 부모는 acceptance도 독립 코드-리뷰도 없이 완료된다(Codex 리뷰 P1 #3). 부모의 검증은 무엇으로 하는가?

## Options

- A. 부모에도 독립 코드-리뷰를 강제한다.
- B. 부모의 검증 = audit(전체 `.stage` 일관성) + close_work의 집계 게이트(모든 자식 terminal). 별도 코드-리뷰는 부과하지 않는다.
- C. 부모 auto-close를 아예 하지 않는다(사람만).

## Principles applied

- Honesty / No silent pass — 부모 검증 방식을 명시적 계약으로 못 박는다(침묵의 공백 제거).
- AHA / KISS — 부모는 코드 산출물이 없으므로 코드-리뷰는 무의미하다.
- MECE — 코드-리뷰(자식) vs 집계-검증(부모)을 분리한다.

## Chosen direction

B. 부모 aggregation-close의 검증은 **audit + close_work의 집계 게이트**다.

- 부모(umbrella/중간 노드)는 자기 코드를 생산하지 않는다 — 그 자식들이 각각 이미 독립 리뷰를 거쳤다(DE-16/20).
- 따라서 부모에 코드 독립-리뷰를 부과하지 않는다(리뷰할 diff가 없다). 대신 `drive.py`의 부모 close는 `audit_stage.py`(전체 `.stage` 일관성)를 `--check`로 실행하고, close_work의 집계 게이트가 "모든 자식 terminal"을 강제한다. 둘 다 통과해야 부모가 close된다.

## Reason

Codex 리뷰는 부모가 "mandatory independent review 없이 완료"됨을 P1로 지적했다. 근본 원인은 불변식이 부모/자식을 구분하지 않은 것. 부모는 코드가 없으므로 코드-리뷰는 성립하지 않으며, 자식은 이미 리뷰됐다. audit + 집계 게이트를 부모의 명시적 검증 계약으로 삼아 침묵의 공백을 없앤다.

## Follow-up

- SCHEMA_V4.md의 무인 루프 문서에 부모 검증 계약을 명시한다.
