# DE-00000094 메인 세션이 서브세션에 일을 맡길 때 서브세션은 만들기만 하고 닫기는 메인 세션이 한다

## Question

메인 세션이 여러 클라우드 서브세션에 카드를 나눠 맡길 때, 번호, 맡은 카드, 보고, 닫기와 리뷰를 누가 어떻게 하는가?

2026-11-21 에 메인 세션이 서브세션 셋에 W-00000377, W-00000378, W-00000380 을 맡겼다. 그때 겪은 일은 W-00000385 의
`## User value` 에 있다. 이 절차는 Stage 문서에 없었고 메인 세션의 프롬프트에만 있었다.

## Options

| 선택지 | 내용 | 약한 점 |
|---|---|---|
| 서브세션이 끝까지 | 서브세션이 카드를 시작하고 구현하고 직접 닫고 리뷰를 부르고 PR 을 연다. 메인 세션은 머지만 한다. 2026-11-21 에 한 방식이다. | 실행한 쪽이 자기 기록을 쓰고, 리뷰에 넘길 경로(합친 커밋)를 자기가 정한다. `stage-handoff` 의 위임 계약과 맞지 않는다. |
| 서브세션은 만들기만, 닫기는 메인 세션 | 메인 세션이 카드를 시작해 두고 서브세션을 띄운다. 서브세션은 구현하고 자기 브랜치에 커밋하고 push 하고 보고한다. 메인 세션이 그 브랜치를 받아 검사를 다시 돌리고 리뷰를 불러 닫고 머지한다. | 메인 세션의 일과 맥락이 는다. 닫기가 메인 세션 한 곳에 몰린다. |

## Principles applied

- SoC — 만드는 쪽과 기록·판정을 맡는 쪽을 나눈다. `stage-handoff` 의 위임 계약("a record must not be written by the agent whose work it attests to")과 같다.
- SSOT — 어떤 카드를 누가 맡았는지와 어떤 번호를 누가 쓰는지는 메인 세션이 push 한 기록 한 곳이 답한다.
- Fail Fast — 다른 브랜치에서 이미 시작됐거나 끝난 카드를 다시 시작하려 하면 그 자리에서 막는다.
- KISS — 번호는 네트워크 없이, 메인 세션이 나눠 준 묶음으로 고른다.

## Chosen direction

서브세션은 만들기만 하고 닫기는 메인 세션이 한다. 사용자가 2026-11-22 에 골랐다("추천대로 갑시다").

두 선택지에 모두 들어가던 것은 그대로 정한다.

- **카드는 메인 세션이 시작한다.** 서브세션을 띄우기 전에 메인 세션이 `start_work.py` 로 카드를 시작하고 push 한다.
  서브세션은 새 카드를 등록하지 않는다. 후속 작업은 보고에 적고, 메인 세션이 등록한다.
- **번호 묶음.** 서브세션이 결정·관측 같은 기록을 만들어야 하면, 메인 세션이 띄우기 전에 그 접두사의 번호 묶음을
  나눠 주고 그 묶음을 push 한 기록에 남긴다. 다른 세션이 fetch 한 뒤 `stage_record_ids.py` 로 번호를 고를 때 그 묶음을
  쓰인 번호로 센다. 서브세션은 받은 묶음 안에서만 번호를 쓴다.
- **맡은 카드 표시.** `start_work.py` 는 같은 카드가 받아 온 다른 브랜치에서 이미 `active` 이거나 보관되어 있으면
  시작하지 않고 그 브랜치를 알려 준다(W-00000367 을 두 세션이 한 일).
- **보고 형식.** 서브세션은 구현을 마치면 메인 세션에 정해진 항목으로 보고한다: 브랜치와 커밋, 바뀐 경로, 실행한 검사와
  결과, 내린 결정, 범위를 넘은 곳, 사용자 확인이 필요한 것, 후속 작업 후보. 실행 보고(`### Executor report`)는
  커밋 본문에 쓴다(`operations/cloud-execution.md`).
- **닫기는 메인 세션.** 메인 세션이 서브세션 브랜치를 받아 검사를 직접 다시 돌리고, 바뀐 경로 전체를 리뷰에 넘겨
  닫고 보관한 뒤 머지한다. 서브세션은 카드의 `status`, `verification`, `review`, `retrospective` 를 고치지 않는다.
- **나눌지 말지.** 고칠 경로가 서로 겹치지 않는 카드가 둘 이상일 때만 서브세션으로 나눈다. 카드 하나나 경로가 겹치는
  카드들은 메인 세션이 차례로 한다. 서브세션마다 같은 문서를 처음부터 읽는 비용이 든다(2026-11-21 서브세션 셋이 약
  32 달러).

반대 관점: 두 선택지 모두 리뷰어는 같은 모델이다. 메인 세션이 닫는다고 모델이 달라지지는 않으므로 얻는 독립성은
"실행한 쪽이 리뷰에 넘길 것을 정하지 않는다"에 그친다. 병렬이 더 중요해지면 이 결정을 다시 본다.

| 점검 규칙 | 없음 | 정하지 않는다. 구현 카드가 필요하면 정한다. |

## Reason

2026-11-21 의 서브세션 셋은 일을 마쳤지만, 번호를 막고, 보고를 받고, 머지 순서를 정하고, 닫는 방법을 알려 주는 일을
메인 세션이 프롬프트로 손으로 했다. 그 손일을 Stage 의 절차와 도구로 옮긴다. 닫기를 메인 세션이 하면 Stage 가 이미
가진 위임 계약을 바꾸지 않아도 된다.

이 결정이 틀렸다고 볼 일: 메인 세션이 닫기를 기다리는 서브세션 PR 이 쌓여서 병렬의 이득이 사라진다. 또는 메인 세션의
맥락이 넘쳐 압축되면서 서브세션의 보고를 잃는다.
