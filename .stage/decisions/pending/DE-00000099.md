# DE-00000099 오케스트레이터가 지휘하고 세션은 역할마다 나눈다

## Question

M-00000006 의 (라)에서 Stage 의 작업 세션을 어떻게 운영하는가? 누가 사용자의 확인을 받고, 누가 일을 정리하고, 일은 어떤 단위로
어느 세션에 맡기고, 누가 판정하고 닫는가?

근거와 사용자 발언은 W-00000402 의 `## User value` 에 있다. 2026-11-21~23 메인 세션 하나가 약 88.7 달러(맥락 84만 토큰)를 썼고 같은 기간
서브세션 16개 남짓의 합은 약 55 달러였다. 사용자와의 긴 탐구와 지휘를 한 맥락에 쌓은 것이 주된 까닭이다.

## Options

| 선택지 | 내용 |
|---|---|
| 오래 가는 메인 하나 | 메인 세션이 대화, 지휘, 정리, 닫기를 다 한다(2026-11-21~23 의 방식). |
| 역할마다 세션 | 오케스트레이터가 확인과 정리와 닫기를 맡고, 토론, 계획, 작업, 검증은 따로 세션을 둔다. |
| 지휘자 없음 | 세션마다 다음 카드를 스스로 집는다(C 컴파일러 글). 사용자 결정을 모아 묻는 자리가 없다. |

## Principles applied

- SoC — 확인과 지휘, 긴 탐구, 목표 설계, 만들기, 판정을 서로 다른 세션이 맡는다.
- SSOT — 세션 사이 결론은 결정 기록과 카드로 남기고, 진행 상태는 플랫폼의 세션 목록이 답한다.
- KISS — 따로 지휘 상태 파일을 만들지 않고, 오케스트레이터는 처음에는 짧은 스킬 하나로 시작한다.

## Chosen direction

역할마다 세션을 둔다. 사용자가 2026-11-23 에 낸 구조이고 아래를 함께 정했다.

| 세션 | 하는 일 |
|---|---|
| 오케스트레이터 | 여러 세션이 사용자의 확인을 받는 곳. 작업 정리(흩어진 이슈를 모으고 묶고 순서를 정함), 세션 띄우기, 진행 상황 챙기기, 카드를 닫고 머지하기. 흩어진 기록을 읽는 일은 서브에이전트에 맡기고 요약만 받는다. |
| 토론 세션 | 작업과 별개로 추가 작업이나 방향 전환을 사용자와 길게 이야기하는 곳. 결론은 결정 기록과 카드로 남기고 오케스트레이터는 기록을 읽는다. |
| 계획 세션 | 목표를 분명히 하는 설계. 무엇을 이룰지를 정하고 어떻게 할지는 정하지 않는다. |
| 작업 세션 | 에픽 하나. 그 아래 스토리는 작업 세션 안의 서브에이전트가 한다. |
| 검증 세션 | 판정만 한다. 닫기와 머지는 오케스트레이터가 한다. 변경이 생겼을 때 전체를 보는 쪽이 오케스트레이터라서다. |

- 작업 정리에 사용자와의 대화가 필요하면 정리 세션을 따로 둘 수 있다.
- 세션을 만들 때마다 시작 비용이 든다. 오래 걸리거나 대화가 길어지는 일, 깨끗한 맥락이 필요한 판정은 세션을 만들고, 짧게 끝나는
  일은 서브에이전트로 한다.
- 오케스트레이터의 맥락이 차면 그 세션을 아카이브하고 새 오케스트레이터가 기록에서 이어받는다. git 의 기록과 세션의 대화 원본은 남는다.
- 진행 중인 세션과 답을 기다리는 확인은 오케스트레이터가 플랫폼의 하위 세션 목록(`list_sessions`)으로 챙긴다. 따로 파일을 두지 않는다.
  기기에서 도는 세션도 클라우드 세션과 같이 본다.
- 오케스트레이터는 `stage-orchestrate` 스킬로 만든다. 다른 세션은 스킬 대신 첫 메시지(브리핑)로 역할을 받는다.
- 일감을 만들 때 상세한 실행 방식은 설계하지 않고 뒤로 미룬다(M-00000006 범위).

이 결정이 DE-00000094 를 바꾸는 점: 닫기는 여전히 메인 세션(오케스트레이터)이 하지만, 일의 단위가 카드 하나에서 에픽 하나로 커지고 그 안은
서브에이전트가 한다. DE-00000094 의 "나눌지" 기준(서브세션 쪽 비용만 봄)은 위의 시작 비용 기준으로 바뀐다.

반대 관점: 사람이 창을 오가는 비용(토론 세션과 오케스트레이터)이 모델 비용 절감보다 클 수 있다. 같은 모델의 검증 세션이 얻는 독립성은
깨끗한 맥락과 직접 실행하는 권한에서 오며 모델이 달라지지는 않는다.

## Where this applies

| 종류 | 자리 | 이 결정으로 바뀌는 것 |
|---|---|---|
| 절차 | 새 `stage/skills/stage-orchestrate/SKILL.md` | 오케스트레이터의 일. 짧게 두고 자세한 것은 기존 문서를 가리킨다. |
| 절차 | `stage/skills/stage-handoff/SKILL.md` 의 "Hand cards to cloud sub-sessions" | 새 스킬로 옮기고 겹치지 않게 한다. |
| 절차 | `stage/skills/stage-drive/SKILL.md` | 번호 순서로 실행하는 기계와 판단하는 오케스트레이터의 경계를 적는다. |
| 코드 | `stage/scripts/subsession_brief.py` | 작업 세션(에픽)과 검증 세션의 브리핑을 낸다. |
| 구현 카드 | 계획된 카드로 등록한다 | 위를 만든다. |

## Reason

2026-11-21~23 의 메인 세션은 대화와 지휘를 한 맥락에 쌓아 가장 비싼 자리가 되었다. Stage 는 장기 기억과 결정 기록을 이미 가지고 있어
세션이 끝나도 역할을 이어받을 수 있다. 역할을 나누면 오케스트레이터는 짧은 확인과 지휘만 쌓고, 긴 탐구는 토론 세션이 맡는다.

이 결정이 틀렸다고 볼 일: 새 오케스트레이터가 기록만으로 역할을 이어받지 못해 사용자가 같은 것을 다시 설명해야 한다. 또는 세션 시작 비용의
합이 2026-11-21~23 의 메인 세션 비용보다 커진다.
