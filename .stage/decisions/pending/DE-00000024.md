# DE-00000024 무인 드라이버 루프의 안전 경계

## Question

supervised `drive.py`를 무인 루프로 확장할 때 — auto-commit 대상, 자동 close/retrospective, executor 실물 명령, 한계 필수화, 안전 경계를 어떻게 정하는가?

## Options

auto-commit 대상(가장 위험한 축):
- A. 격리 브랜치 — 무인 런은 전용 브랜치에서 항목별 커밋, 사람이 리뷰·머지.
- B. main 직접 커밋.
- C. 커밋 안 함 — 다중 항목 불가(close는 클린 트리 필요).

## Principles applied

- Safe completion > Speed — 자율 커밋의 blast radius를 가둔다.
- Honesty / No partial completion — 실패·상한 = `blocked`, 가짜 완료 금지.
- Fail Fast — 무인 루프의 자동 정지 보장(한계 필수).
- SoC — 루프 제어 · 커밋 · close · escalate 책임 분리.

## Chosen direction

A + 안전 불변식.

- **auto-commit → 격리 브랜치**: 무인 런은 전용 브랜치(예: `stage/driver/<run>`)를 만들어 항목별 커밋한다. main 직접 커밋 금지. 사람이 런 종료 후 브랜치를 리뷰·머지한다.
- **한계 필수화**: 무인 모드는 `limits` config가 필수다(absent → 실행 거부). supervised와 달리 사람이 cap이 아니므로 무한 자율 루프를 금한다. 전역 iteration·벽시계 = 하드 백스톱, 항목당 시도 상한 = escalate 트리거.
- **자동 close + retrospective**: `close_work`가 retrospective를 요구하므로, 무인 close는 드라이버가 **기계 생성 retrospective**(템플릿 + 항목 verification evidence, `driver-generated` 표식)를 써서 close한다. 반성적 회고는 사람이 브랜치 머지 시 검토한다.
- **executor 실물 명령**: `executors` config에 codex/claude headless 실물 명령을 **검증 후** 넣는다(codex headless 호출 검증 포함). 부재 → fail-closed escalate.
- **루프**: `drive.py --unattended <parent>` — 준비된 말단 자식 선택 → executor 실행 → acceptance → 독립 판정 → 통과 시 브랜치 커밋 + close + 부모 집계 전진 → 실패 시 재시도(시도 상한)/무진전 → 상한·막힘 시 escalate(`blocked`). 부모 terminal 또는 전역 상한까지 반복.
- **안전 불변식**(DE-13/23 계승): 승인된 분해 안에서만; 모든 변이는 게이트된 경로로; 실패·상한 = `blocked`; official 승격·새 분해 승인 안 함; 사람 승인 게이트 안 넘음; **격리 브랜치**에서만 작동.

## Reason

격리 브랜치가 자율 커밋의 blast radius를 가둔다 — 오작동해도 main은 무사하고 사람이 머지에서 최종 판정한다(Safe completion). 한계 필수화는 무인 루프의 유일한 자동 정지 보장이다(Fail Fast). 기계 회고는 Completion 원칙의 최소 충족이며 사람 머지 검토로 보완한다(Honesty). 이 ship이 자율 실행을 실제로 완성한다.

## Follow-up

- 빌드/시연 제약: 현재 준비된 실제 작업 항목이 없어(전부 아카이브), 무인 루프는 fake executor 테스트로 로직 검증 + toy 항목으로 소규모 실증.
- codex headless 명령 형태 검증.
- 기계 회고 템플릿·브랜치 네이밍·머지 프로토콜 세부.
