# DE-00000079 codex 컴패니언 경로를 찾아 쓰는 고치기는 Claude Code 클라우드 세션에서 실행한다

## Question

W-00000289 는 `kind: fix` 라 정책상 codex 몫이다. 사용자는 이 클라우드 세션에서 "여기서는 코덱스가
하는 일을 니가 해야 한다"고 지시했고, 이 카드를 다음 일로 승인했다. **이 카드를 어느 자리에서
실행하는가.**

## Options

1. **로컬 codex 드라이버에 넘긴다** — 사용자 지시와 어긋난다. 게다가 고칠 대상이 바로 그 드라이버
   명령의 경로다.
2. **이 클라우드 세션이 실행한다** — DE-00000078 과 같은 모양의 예외를 한 장 더 세운다. (선택)

## Principles applied

- **User intent** — 사용자가 이 세션이 codex 몫까지 하라고 지시했다.
- **만든 쪽 ≠ 보는 쪽** — 카드에 `review: pending` 을 건다. 닫기 리뷰는 실행 맥락이 없는 별도
  세션이 한다.
- **Honesty** — 클라우드 세션에는 Stage 훅과 `.stage/.runtime/` 이 없고 codex 도 없다. 고친 명령이
  실제 codex 플러그인으로 도는지는 로컬에서만 확인할 수 있다.

## Chosen direction

**2번.** W-00000289 는 Claude Code 클라우드 세션이 `claude/w268-cloud` 브랜치에서 실행한다. 이 결정은
W-00000289 한 장만 허가한다. 실행 계약은 DE-00000075 의 세 변경(세션 브랜치에 커밋·push,
`### Executor report` 는 커밋 메시지 본문, 범위 대조는 닫기 전에)을 그대로 쓴다.

## Where this applies

| 자리 | 무엇을 하는가 |
|---|---|
| W-00000289 카드 `venue` · `decision_refs` | `claude` 와 이 결정을 가리킨다 |
| `.stage/work/active.md` W-00000289 행 | Venue 칸을 `claude` 로 둔다 |
| 로컬 확인 | 고친 codex 명령이 로컬에 설치된 codex 플러그인으로 실제로 도는지 본다 |

`settings.json` 의 `venue_routing` 은 바뀌지 않는다. 카드가 보관될 때 이 결정도 함께 소진된다.

## Reason

고칠 대상이 로컬 codex 드라이버 명령 자체라, 고치기 전에는 그 드라이버로 이 카드를 돌릴 수 없는
환경(클라우드, 다른 컴퓨터, 플러그인 버전이 바뀐 로컬)이 있다.

## 이 규칙이 틀렸다는 것을 무엇으로 알게 되나

로컬에서 고친 codex 명령이 돌지 않거나, 닫기 리뷰가 클라우드에서 놓친 것을 잡으면 이 경로의 비용이
이득보다 크다.

## Follow-up

- 카드마다 예외를 세우는 일이 오늘만 다섯 번째다(DE-00000075~079). 클라우드 실행을 정책으로 둘지는
  "venue 가 누가와 어디서를 한 칸에 담는다"는 논점과 함께 정한다.
