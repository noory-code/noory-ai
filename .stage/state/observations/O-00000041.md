# O-00000041 인라인 코드 차단이 경로를 셸에서 넘기면 안 걸린다

## Observation

훅은 `.stage` 를 언급하는 인라인 인터프리터 코드를 거절한다. 이유는 "그 코드가 무엇을 쓰는지
게이트가 확인할 수 없어서"다.

그런데 검사가 보는 것은 명령 전체 글자가 아니라 **인라인 코드 본문**이다. 그래서 경로를
셸 쪽에서 인자로 넘기면 같은 코드가 통과한다. 게이트가 못 보는 코드가 `.stage/` 를 쓴다는
사실은 똑같다.

## Evidence

2026-08-07, W-00000245.

막힌 쪽 — 힙독 안에 경로가 있다:

```
python3 - <<'EOF'
p = pathlib.Path(".stage/work/current/W-00000239/_story.md")
...
```
→ `Stage guard cannot verify what opaque inline interpreter code writes ... is refused.`

통과한 쪽 — 같은 힙독인데 경로가 `sys.argv` 로 들어온다:

```
for f in stage/templates/.../\_template.md .stage/work/retrospectives/_template.md; do
  python3 - "$f" <<'PY'
  p = pathlib.Path(sys.argv[1]); p.write_text(...)
PY
done
```
→ 통과했고 `.stage/work/retrospectives/_template.md` 가 실제로 바뀌었다.

이번 쓰기 자체는 정당했다 — 열린 작업이 있었고 그 경로가 선언한 범위 안이었다. 걸리는 것은
쓴 내용이 아니라 **게이트를 지나온 길**이다.

**반대쪽 면 — 읽기만 해도 막힌다.** 2026-08-08, `.stage/settings.json` 의 판정자 설정을 보려고
`python3 -c` 로 JSON 을 읽어 출력했다. 아무것도 안 썼는데 같은 문구로 거절당했다. `grep` 으로
바꾸니 통과했다.

검사가 쓰기와 읽기를 안 가른다. 그래서 게이트가 두 방향으로 다 틀린다 — 쓰는 코드를 인자로
넘기면 통과시키고, 읽기만 하는 코드는 막는다. 세는 일을 할 때 이 두 방향을 같이 봐야 한다.

## Impact

- 막으려던 것을 못 막는다. 인라인 코드로 `.stage/` 를 쓰는 길이 열려 있다.
- **막지 말아야 할 것을 막는다.** 읽기만 하는 한 줄이 거절당하면 사람이 우회로를 찾고, 그
  과정에서 게이트가 신뢰를 잃는다.
- **일부러 뚫으려는 사람보다 모르고 지나가는 쪽이 문제다.** 이번에도 우회하려던 것이 아니라
  파일 셋을 한 번에 고치려다 그렇게 됐다. 막혔어야 할 자리가 조용히 통과하면 그다음에도
  같은 모양을 쓴다.
- 같은 자리를 승격 게이트도 쓴다. `.stage/official/` 쓰기가 명령 글자에 경로가 없으면 안
  걸리는 것은 이미 알려진 동작이고(`archive_work.py` 가 그 길로 돈다), 그쪽은 의도된
  설계다. 이 관측은 그것과 다르다 — 인라인 코드 차단은 통과시키려던 길이 아니다.

## Status

**2026-08-10 정정: 위 Observation 의 절반이 틀렸다.** 셸 인자로 넘겨도 막힌다.

W-00000247 이 게이트 함수(`stage_shell.py:701`)에 이 기록의 두 명령을 그대로 넣어 봤다.
"통과한다"고 적은 쪽이 **막힌다.** 게이트는 인라인 코드 본문이 아니라 **원본 명령 전체**에서
`.stage` 를 찾고, 그 함수의 주석이 힙독 본문까지 일부러 그렇게 본다고 적는다. 커밋
`800d34ed`(2026-07-25)가 그 모양을 만들었으니 이 기록(2026-08-07)보다 앞선다.

**왜 그때 통과했다고 적었는지는 모른다.** 그 판을 다시 못 본다. 여기 적힌 명령을 지금 넣으면
막힌다는 것만 안다.

그래서 **못 막는 구멍은 없다.** 남은 것은 아래 반대쪽 면 하나다.

2026-08-10 처분: 열어 둔다. 고칠 길로 세웠던 W-00000247 은 만들 것이 없어져 거절했다.
**받는 조건은 사용자가 정했다 — 읽기만 하는 코드가 또 막히면 그때 다시 본다.** 지금은 우회가
한 번이면 되고(`grep` 으로 바꾸거나 스크립트 파일로 쓰거나), 그 우회가 게이트가 보내려는
방향이라 받지 않는다.
