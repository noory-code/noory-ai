# O-00000053 리뷰어가 사용량 한도로 돌지 못해도 드라이버가 시도 한 번으로 센다

**닫힘 — W-00000306 가 고쳤다.** `infrastructure_failure()` 가 서비스의 사용량 한도 메시지(session/usage limit,
429, `rate_limit_error`)를 인프라 실패로 알아봐, 판정 파일 없이 끝난 리뷰와 한도로 끝난 실행이 시도를 쓰지 않는다.
`--resume` 이 리뷰어 역할만 다시 돌리게 하는 일과 종료 이유를 구조화해 받는 일은 하지 않았다.

## Observation

감독 모드에서 리뷰 명령(`claude -p`)이 사용량 한도로 바로 끝나 판정 파일을 쓰지 못하면, 드라이버는 이를 인프라 실패가 아니라 리뷰 실패로 보고 시도 한 번을 쓴다. 인프라 실패를 가르는 `infrastructure_failure`(`stage/scripts/driver_review.py:266`)는 "timed out", "command not found", "[exit 126]", "[exit 127]", "terminated by signal", "killed by signal"만 알아본다. 사용량 한도 메시지("You've hit your session limit", HTTP 429, `rate_limit`)는 목록에 없다. 그래서 `retryable_review_infrastructure_failure`가 거짓을 돌려주고, 실행자가 이미 끝낸 판까지 실패한 시도로 남는다.

## Evidence

2026-10-15 다시나 W-00000034 2판.

- Codex 실행과 수락 시험은 끝났고, Claude 리뷰는 "You've hit your session limit · resets 5:10pm"으로 판정 파일 없이 끝났다.
- 드라이버 출력은 "Outcome: review verdict file is missing"이었고 "infrastructure failure did not spend an attempt" 문구가 없었다. 다음 미리보기는 "Attempt: 3/3"이었다.
- `--resume`은 "no interrupted driver role is recorded"로 거부됐다. 남은 마지막 시도는 실행부터 다시 하므로 2판 결과를 살릴 길이 없었고, Claude가 1판 리뷰어의 실험을 다시 돌려 확인하고 닫았다(다시나 R-00000034).

## Impact

시도 상한이 3이라, 한도에 한 번 걸리면 남은 기회가 하나 준다. 한도는 Claude를 많이 쓴 날 리뷰 단계에서 생기기 쉽다. 한 번 더 걸리면 실행 결과가 좋아도 카드가 막힌다.

## Status

닫힘. W-00000306 에서 사용량 한도 표지를 인프라 실패에 더했다.

## Next action

`infrastructure_failure`에 사용량 한도·429 표시를 더할지, 그리고 판정 파일 없이 끝난 리뷰를 실행 없이 다시 돌리는 길(`--resume`이 리뷰어 역할을 기록하게)이 필요한지 정하는 카드를 만든다. 고칠 때는 표시 문자열을 늘리는 대신 리뷰 명령의 종료 이유를 구조화해 받을 수 있는지 먼저 본다(다시나 verification.md의 "지키려는 성질을 직접 재라").
