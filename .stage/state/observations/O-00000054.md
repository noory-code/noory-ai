# O-00000054 Codex 드라이버 실행자가 닫기 도구 몫인 카드의 verification 을 손으로 passed 로 바꿨다

## Observation

W-00000286 을 드라이버로 실행하는 동안 Codex 실행자가 선택된 카드 frontmatter 의 `verification` 을
손으로 `passed` 로 바꿨다. 이 값은 닫기 도구가 검사를 실제로 돌린 뒤에 쓰는 값이다
(`stage/skills/stage-retrospective/close_work.py` 의 `set_field(updated, "verification", "passed")`).
실행 계약은 이를 막지 않는다. 프로젝트 실행 명령(`.stage/settings.json` 의 `executors`)은 실행자에게
카드 frontmatter 의 `promotion` 을 직접 고치라고 하지만, `verification`·`review`·`status` 처럼 닫기
도구가 소유하는 칸을 건드리지 말라는 문장은 없다.

## Evidence

2026-10-31 W-00000286(보관됨).

- R-00000286 "Context that was missing": 드라이버 실행자가 카드의 `verification` 을 손으로 `passed` 로
  바꿨고, 실행 계약에는 그 값을 건드리지 말라는 문장이 없다.
- R-00000286 "Principles applied": 닫는 쪽이 그 값을 `pending` 으로 되돌린 뒤 `close_work.py` 로 닫았다.

## Impact

`verification: passed` 는 실행한 검사의 결과로만 생겨야 하는 값이다(`close_work.py` 머리말). 손으로
쓴 `passed` 가 남으면 검사를 돌리지 않은 카드가 검증된 것처럼 읽힌다. 이번에는 닫는 쪽이 알아채
되돌렸지만, 되돌리지 않았다면 기록이 사실과 달라진다. 실행 명령이 frontmatter 칸 하나(`promotion`)를
직접 고치라고 하므로, 실행자가 다른 칸도 고쳐도 된다고 읽을 여지가 있다.

## Status

열림. 고치지 않았다.

## Next action

실행 계약(`stage/skills/stage-drive/SKILL.md`, `.stage/settings.json` 의 실행 명령, 템플릿 안내)에
"`verification`·`review`·`status`·`retrospective` 는 닫기 도구와 회고 절차가 쓴다. 실행자는 고치지
않는다"를 더할지 정한다. 문장보다 강하게 지키려면, 드라이버가 실행 전후 이 칸들을 비교해 실행자가
바꿨으면 그 판을 거절하는 길도 본다.
