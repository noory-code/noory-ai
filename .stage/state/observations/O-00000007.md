# O-00000007 사람이 카드를 바꾼 뒤 드라이버를 다시 돌릴 안전한 방법이 없다

## Observation

시도 상한에 닿으면 드라이버는 사람에게 올린다. 사람이 판단해 카드를 바꾸고 다시 돌리는 것이
계약이 예정한 흐름이다.

그런데 그때 쓸 명령이 없다. 시도 기록은 `.stage/.runtime/driver/<id>.json` 에 있고, 사람이 그
파일을 직접 고쳐야 한다. 그리고 세 자리를 다 맞춰야 한다 — 시도 수, 지문, 실행 시작 시각.
하나라도 형태가 틀리면 실행 전에 막힌다.

## Evidence

W-00000107. DE-00000036 으로 카드를 넓힌 뒤 다시 걸면서 두 번 밟았다.

- `last_fingerprint` 를 통째로 지웠더니 `run state last_fingerprint must be a string` 으로 막혔다.
  빈 문자열로 넣어야 했다.
- `started_at_unix` 를 첫 실행 시각 그대로 뒀더니 `global wall-clock limit exceeded before
  execution` 으로 막혔다. 시간 총량을 그 시각부터 재기 때문이다.

둘 다 실행에 들어가지도 못했다. 세 번째에 세 자리를 다 맞춰서야 돌았다.

## Impact

- 사람이 개입한 뒤 재개하는 경로가 매번 손으로 JSON 을 고치는 일이 된다.
- 형태 검사가 앞에서 막아 주는 것은 다행이지만, 무엇을 맞춰야 하는지는 코드를 읽어야 안다.
- 상한을 되돌린 사실이 어디에도 안 남는다. 사람이 왜 되돌렸는지가 기록되지 않는다.

## Status

**닫힘 (2026-07-30, W-00000131).** 되돌리기가 `--reason` 을 필수로 받는 드라이버 명령이 됐다.
세 자리를 명령이 맞추고, 도는 실행에는 거절하며, 누가 왜 되돌렸는지 카드의 공유 작업 로그에
남는다.
