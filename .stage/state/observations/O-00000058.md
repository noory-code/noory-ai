# O-00000058 닫기 리뷰는 맨 위 커밋이 고친 파일만 본다

## Observation

`close_work.py` 는 리뷰어에게 넘길 파일 목록을 `HEAD` 커밋에서 가져온다. 코드 커밋 뒤에 카드 기록만 고친
커밋을 하나 더 올리면 리뷰어는 `.stage` 파일만 받는다. 코드를 보지 않고 판정하게 된다.

## Evidence

- `stage/skills/stage-retrospective/close_work.py` 787~800줄: `HEAD` 커밋의 경로를 나열한다.
- W-00000368 을 닫을 때 기록만 고친 커밋을 먼저 올렸다. 코드 커밋에 맞춘 작업 폴더를 따로 만들어 거기서
  닫고 결과를 옮겼다(R-00000368).
- 앞서 W-00000352 와 W-00000353 을 닫을 때도 같은 이유로 작업 폴더를 따로 만들었다.

## Impact

지금은 카드 기록과 회고를 커밋하지 않은 채 닫고, 닫는 커밋에 함께 넣는 것으로 피한다. 이 순서를 모르는
세션은 리뷰가 코드를 보지 않았다는 것을 알아차리지 못할 수 있다. 판정은 통과로 나오기 때문이다.

## Status

열림. 피하는 방법이 있어서 급하지 않다.

## Next action

리뷰가 볼 커밋을 닫는 명령에서 고를 수 있게 할지 정한다. 관문 코드를 고치는 일이라 카드로 등록해서 한다.
