# O-00000050 파일을 바꾸지 않는 경로도 범위를 넘은 경로로 잡힌다

## Observation

Stage 훅이 범위를 넘은 경로를 고를 때, 실제로 고치지 않은 경로도 넘은 경로로 잡는다.
W-00000283 뒤로 사용자 화면에는 넘은 경로 한 줄만 남으므로, 잘못 잡힌 한 줄이 그대로 눈에 띈다.

## Evidence

2026-10-11 이 저장소의 Claude Code 세션에서 본 것:

- `stage/operations/hooks.md`를 고친 Edit 호출에서, 넘은 경로가
  `/Users/woogis/.claude/projects/-Users-woogis-Workspace-repo-noory-ai/<세션 id>.jsonl`로 나왔다.
  이 파일은 세션 transcript이고 Edit 대상이 아니다.
- `cp ... "$TMPDIR/sg_new.py"`를 쓰는 Bash 호출에서 넘은 경로가 `$TMPDIR/sg_new.py`로 나왔다.
  저장소 밖 임시 파일이고 변수가 펼쳐지지 않은 채로 찍혔다.
- W-00000283의 독립 리뷰 세션도 비슷한 두 경우를 보고했다. 하나는 `/dev/null`로 출력을 버리는
  Bash 호출이고, 다른 하나는 Write 호출의 transcript `.jsonl` 경로다.

원인은 확인하지 않았다. 훅이 호출 입력에서 대상 경로를 뽑는 쪽(`mutation_targets`)으로 짐작한다.

## Impact

넘지 않은 호출에도 경고 한 줄이 뜨면, 사람과 에이전트가 진짜 넘음을 가려내기 어려워진다.
막는 동작에는 영향이 없다. 범위 넘음은 알리기만 하고 막지 않는다.

## Status

open — 재현만 했고 원인은 보지 않았다.

## Next action

Edit 호출 하나와 `/dev/null`·`$TMPDIR`를 쓰는 Bash 호출 하나를 훅에 직접 넣어 어떤 경로가 뽑히는지 본다.
그 결과로 고칠 카드를 등록할지 정한다.
