# O-00000011 에이전트 세션 안에서 손으로 돌린 인수 검사는 가짜 실패를 보인다

## Observation

훅을 띄우는 테스트 스위트는 `CLAUDE_PROJECT_DIR`·`PROJECT_ROOT` 가 실려 있으면 깨진다 —
가드가 그 변수를 payload 의 cwd 보다 먼저 읽어, 테스트의 임시 픽스처가 아니라 변수가 가리키는
저장소를 판정하기 때문이다. 드라이버는 인수 검사 환경에서 두 변수를 걷어내므로(W-00000134)
드라이버 경유는 깨끗하다.

그런데 **에이전트 세션(claude/codex) 안에서 사람이나 에이전트가 스위트를 손으로 돌리면** 그
세션 자체가 변수를 갖고 있어 가짜 실패가 난다 — 이 저장소에서는 스크립트 스위트 8개.

## Evidence

W-00000131 리뷰(2026-07-30). 실행자와 리뷰어가 각자 세션 안에서 스위트를 돌려 8개 실패를
봤고, 리뷰어가 격리 재현으로 원인을 확정했다 — 드라이버의 검사 환경(`check_environment()`)과
같게 변수를 걷고 돌리면 480개 전부 통과.

## Impact

- 세션 안에서 검증하는 실행자·리뷰어·사람이 매번 같은 가짜 실패를 만나 원인 조사에 시간을
  쓴다. 이번 리뷰에서도 실제로 그랬다.
- 가짜 실패를 "원래 깨지는 것"으로 학습하면 진짜 실패를 무시하게 된다.

## Status

기록됨. 고치는 방향 둘 — 테스트 헬퍼가 훅을 띄울 때 두 변수를 스스로 걷거나(테스트가
hermetic 을 자기 손으로 지킴), 세션 쪽 지침이 걷고 돌리라고 안내하거나. 앞쪽이 원인 자리다.

## Next action

`stage/hooks/tests`·`stage/scripts/tests` 의 훅 스폰 헬퍼를 다음에 만지는 카드가 헬퍼에서
두 변수를 걷는다. 그 전까지는 세션 안 검증 시 변수를 걷고 돌린다.
