# O-00000001 리뷰 계약이 닿아야 하는 자리의 전수 지도

## Observation

리뷰 계약(DE-00000032 — 리뷰어는 카드를 읽고 성공 기준에 대고 판정한다)이 실제로 닿아야
하는 자리를 전수 열거했다. 하나씩 발견될 때마다 카드를 더하는 대신, 발견 시점에 그 종류
전체를 훑어 열거를 닫았다(`operations/discovery.md`).

리뷰 명령이 **실행되는 자리는 셋뿐**이다. 나머지 등장(감사, 등록기, 게이트 훅)은 설정을
검증만 하고 실행하지 않는다.

| 실행 자리 | 카드 경로 env | 계약 도달 |
|---|---|---|
| 감독 드라이버의 독립 리뷰 (`drive.py`) | 있음 | W-00000085 로 완료 |
| `close_work.py` 독립 리뷰 (자율 카드·무인 모드 경로) | 없음 | W-00000091 |
| `close_work.py` 단계별 리뷰 | 없음 | W-00000091 |

리뷰 **명령 문구**는: claude 리뷰어·red-team 강도에 계약 문구 있음, codex 리뷰어·standard
강도에 없음(기본 `review` 하위 명령은 지시문 자리가 없고 `adversarial-review` 는 받는다) —
W-00000087. **판정 처리**는 전 명령이 fail-open 이었다(오류 출력에 [P1] 이 없으면 통과) —
W-00000089. 리뷰어 입력이 비정상적으로 커진 미해명 사고 하나 — W-00000090 (첫 가설인 세션
환경 변수 상속은 재현 실패로 반증됨).

## Evidence

- 실행 자리 열거: `resolve_independent_review_command` / `resolve_review_command` 의 호출처
  전수 확인 (2026-07-26). 실행은 `drive.py:1150`, `close_work.py:329`, `close_work.py:357`.
- fail-open 실사고: W-00000088 드라이버 첫 실전 가동 — 리뷰어가 입력 초과로 죽었는데 통과
  처리됨 (그 카드 Verification).

## Impact

이 네 카드(W-00000087, 89, 90, 91)가 남은 구멍 전부를 겹침 없이 덮는다. W-00000090 조사에서
새 사실이 나오지 않는 한 이 묶음은 더 자라지 않는다.
