# O-00000046 빈 번호를 잡는 방식이 worktree 를 갈라 놓으면 안 통한다

## Observation

번호를 잡을 때 쓰는 방식은 **가장 큰 번호 + 1 로 시작해 파일을 `x` 모드로 열고, 이미 있으면
다음 번호로 넘어가는** 것이다. `x` 모드는 파일이 이미 있으면 실패하므로, 같은 디렉터리를 보는
두 프로세스는 절대 같은 번호를 못 가져간다.

**worktree 를 갈라 놓으면 이 성질이 사라진다.** worktree 마다 `.stage/` 를 따로 들고 있어서
같은 이름의 파일이 서로 다른 파일이다. 둘 다 만들기에 성공하고, 합칠 때 부딪힌다.

카드 번호와 회고 번호가 같은 약점을 갖는다.

**번호를 세는 한 어디서 잡아도 마찬가지다.** 잡는 시점을 닫기에서 카드 등록으로 옮겨도 안
풀린다 — 등록 역시 자기 사본만 세기 때문이다. 사본 둘에서 각각 등록해 보니 둘 다 같은 번호를
받았다.

## Evidence

2026-08-11, W-00000258 을 실행자에게 넘겼더니 이 이유로 카드를 거부했다. 감독이 코드를 열어
확인한 것은 다음 넷이다.

| 확인한 것 | 자리 |
|---|---|
| 회고 번호를 잡는 유일한 자리 | `stage/scripts/driver_lifecycle.py:52` `write_driver_retrospective` |
| 그것을 부르는 유일한 곳 | `stage/scripts/driver_unattended.py:607`, `:975` — 무인 실행뿐이다 |
| 카드 번호를 잡는 자리 | `stage/skills/stage-work/register_work.py:180-198` — 같은 `x` 모드 방식 |
| 무인 드라이버를 병렬로 돌리는 길 | `stage/scripts/drive_parallel.py:109` `--unattended` |

손으로 닫는 쪽(`stage/skills/stage-retrospective/close_work.py`)은 번호를 안 잡는다. 사람이
정한 번호를 받아 이미 쓰인 번호인지만 본다(`:700-708`).

**아직 안 잰 것:** 무인 드라이버 둘을 실제로 동시에 돌린 적이 있는지 확인하지 않았다. 부딪힌
판도 아직 없다.

## Impact

- 부딪히려면 **무인 드라이버가 둘 이상 동시에** 돌아야 한다. 감독이 붙어 도는 실행은 카드를
  안 닫으므로 회고 번호를 아예 안 잡는다.
- 부딪혀도 조용하지 않다. 합칠 때 같은 파일 이름 둘이 부딪히거나, 감사가 회고 주인이 다르다고
  잡는다.
- 카드 번호는 지금까지 메인 체크아웃에서만 등록해 왔다. 병렬 worktree 안에서 카드를 새로
  등록하면 같은 자리를 밟는다.

## Status

열어 둔다. W-00000259 가 고치는 중이다.

**답은 번호를 어디서 잡느냐가 아니라 세는 것을 그만두는 것이다.** 회고 번호를 카드 번호에서
그냥 만들면 세지 않으니 사본이 갈려도 겹칠 수 없다. 그러려면 모든 카드의 자리가 비어 있어야
하는데, 앞으로 등록될 카드를 막고 있던 회고는 둘뿐이었다(R-00000259, R-00000260). 둘을
R-00000251 과 R-00000248 로 옮겼고, 이제 다음 카드 번호 이상에 앉은 회고가 없다.

번호가 자기 카드와 안 맞는 회고 170장은 그대로 둔다. 앞으로의 카드를 안 막는다 — 카드 번호는
올라가기만 하므로 이미 지나간 번호를 다시 쓰지 않는다.

## Next action

`W-00000259` 가 번호를 세는 코드를 걷어내고, 자리가 차 있으면 조용히 다른 번호를 쓰는 대신
멈추게 한다. 그 카드가 닫히면 이 기록도 닫는다.
