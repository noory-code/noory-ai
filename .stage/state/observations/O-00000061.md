# O-00000061 지휘를 넘기는 시점에 카드가 되지 않은 후속 작업 후보가 남아 있다

## Observation

2026-11-23 에 메인 세션(session_018VXR6Pgir7NPX45jvBQqYs)이 지휘를 session_018VXR6RJwybKUJRATYqvEuM 에 넘겼다.
그때까지 여러 카드의 보고에서 나온 후속 작업 후보가 카드로 등록되지 않고 메인 세션의 대화에만 있었다.
다음 지휘자가 묶고 순서를 정하도록 여기에 적는다. 목적과 성공 기준은 정하지 않았다.

## Evidence

W-00000404 에서 나온 것(보관된 카드의 `## Progress` 에도 있다):

- `close_work.py` 가 검증 세션의 판정을 받아들이게 한다. 사용자가 W-00000401 에서 정하기로 했다. 그때까지
  검증 세션은 에픽에만 띄우고 스토리는 닫기 리뷰만 받는다.
- 토론 세션과 계획 세션의 브리핑을 생성한다.
- 에픽을 닫는 길(스토리별 cherry-pick)을 실제 에픽으로 해 본다.
- 몇 번 쓴 뒤 `stage-orchestrate` 스킬(235줄)에서 줄일 수 있는 지시를 찾는다.
- 세 번째 판의 인수인계와 다른 세션의 태그를 떼는 일(`set_session_tags`)은 해 본 적이 없다.

그 전 카드들에서 나온 것:

- CI 에서 `release_plugin.py --check-released --since 0.67.0` 을 돌린다(`fetch-depth: 0` 이 필요하다).
- 쓰인 번호를 세는 코드를 한 곳으로 모은다(`used_numbers`).
- SessionStart 가 내보내는 글의 크기에 상한을 둔다.
- 작업 로그의 원본 기록이 커밋되지 않는다.
- `model_fallbacks` 를 선언했는데 명령에 `$STAGE_MODEL` 이 없으면 audit 가 경고한다.
- Dasina 프로젝트 설정에 agy 의 `model_fallbacks` 를 넣는다.

규칙 후보:

- 인코딩 계약을 건드리는 수정은 계약 시험을 먼저 돌린다(한 번 관찰).
- 사용자에게는 질문 하나에 답 하나, 큰 그림부터(두 번 관찰, 올릴 수 있다).
- 다른 세션이 따르는 절차 문서는 그 문서만 받은 세션이 한 번 해 본 뒤에 닫는다(R-00000404, 한 번 관찰).

2026-11-23 지휘 세션 session_018VXR6RJwybKUJRATYqvEuM 이 W-00000403 을 시작부터 병합까지 끌고 가며 본 것:

W-00000403 에서 나온 것(보관된 카드의 `## Progress` 에도 있다. 두 건은 W-00000405 로 묶었다):

- `mechanisms.md` 의 B11 행에 Dasina 사고 출처(R-00000028, R-00000031)를 적는다.
- 빼기 전 기준선을 Mac 의 `.stage/.runtime/driver/logs/` 에서 센다(사용자의 기계가 필요하다).
- 뺀 문장을 자기 설정에 복사해 둔 다른 프로젝트(Dasina)의 실행자 설정은 이번 결정(남긴다)과 이미 같다. 할 일이 없는지 확인만 한다.

`stage-orchestrate` 스킬 세 번째 판이 말하지 않은 것:

- 열린 작업 세션이 없으면 이전 지휘자를 찾는 셋째 규칙(`stage-main-session:<id>`)이 걸리지 않는다. 그 태그를 가진 행이 새 지휘자 자신뿐이고 자기 행은 버리기 때문이다.
- `started_cards.py` 는 열린 관측을 내지 않는다. 후속 후보가 이 관측에 있다는 것은 메시지로만 전해졌다.
- 계획 카드의 순서(사용자가 정한 "W-00000403 먼저")가 기록에 없었다.
- 지휘자가 다른 세션의 자식이면 안 된다는 조건이 없다. 부모 세션을 보관하면 자식에 무슨 일이 생기는지 모른다.
- 사용자가 지휘를 넘겼다는 말이 이전 지휘자의 메시지로만 왔다. 새 지휘자는 자기 대화에서 사용자에게 확인받은 뒤에 움직였다. 스킬은 이 확인을 요구하지 않는다.
- 카드를 시작하기 전에 성공 기준을 지금 흐름에서 채울 수 있는지 보라는 말이 없다(R-00000403).
- 작업 세션이 닫기 리뷰가 도는 동안 커밋을 더 보냈다. 지휘 세션은 리뷰를 멈추고 다시 squash 했다. 스킬과 `cloud-execution.md` 는 "리뷰를 시작한다, 더 커밋하지 말라"를 작업 세션에 알리라고 하지 않는다.
- `cloud-execution.md` 의 닫기 절차는 회고를 쓴 뒤 카드의 `retrospective: completed` 와 `retrospective_ref` 를 채우라고 말하지 않는다. 채우지 않으면 `close_work.py` 가 리뷰 전에 멈춘다.
- 카드에 저장된 검사와 같은 명령을 `--check` 로 넘기면 닫기 기록에 같은 검사가 두 번 적힌다.
- `register_work.py` 는 클라우드 세션에서 번호를 원격에 잡지 못한다(`refs/stage-ids/` 푸시 거부). 스킬의 "Organize work" 는 이 경우를 말하지 않는다.
- squash 커밋의 제목이 작업 세션의 마지막 커밋 제목이 된다(`git commit -C FETCH_HEAD`). W-00000403 의 squash 는 제목이 "record why the derived default timeout stays" 인데 내용은 카드 전체의 변경이다.

사용자의 답을 기다리는 것(어느 카드에도 속하지 않는다):

- 이전 지휘 세션 "Main session"(session_018VXR6Pgir7NPX45jvBQqYs)을 보관하는가? 사용자가 카드 한 장을 병합까지 끌고 간 뒤 다시 보기로 했고, 그 조건은 W-00000403 으로 채워졌다.
- 병합된 원격 브랜치 `claude/conduct-w403`, `claude/w403-drop-execution-instructions`, `claude/conduct-register-load-card` 를 지우는가?


## Impact

W-00000372(릴리스, 사용자의 Mac 과 Windows 확인이 필요하다)이다.
