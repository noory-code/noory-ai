# Q-00000001 드라이버 리뷰어의 입력이 왜 340만 토큰이 됐나

**이 질문은 답이 나왔다(2026-07-26).** 판정하는 쪽에 주는 임시 인덱스가 비어 있어
`git diff HEAD~1` 이 저장소 전 파일을 삭제로 읽었다 — 9MB 다. 아래 `## Status` 에 근거가 있고,
남은 미지와 수정은 W-00000094 가 이었다.

**세션 화면은 이 질문을 아직 열린 것으로 센다.** 질문 서랍에 있는 것은 다 열린 것으로 세기
때문이다(`stage_context.py`). 그 자리는 W-00000197 이 맡는다.

## Question

2026-07-26, W-00000088 드라이버 스텝의 리뷰어(`claude -p`)가 "요청 약 342만 토큰, 그중
대화만 약 216만 토큰" 오류로 죽었다. 그 시점의 diff 는 34KB(약 1만 토큰)뿐이었다. 나머지
약 8MB 는 어디서 왔나?

실측으로 반증된 가설 (W-00000090, 2026-07-26):

- 세션 환경 변수 상속 — 사고 당시와 같은 조합(`GIT_INDEX_FILE` 임시 인덱스,
  `STAGE_WORK_ITEM_PATH`, 세션 식별 변수 전부)으로 소형 호출을 재현해도 정상 동작한다.
- 리뷰어 환경의 diff 팽창 — 임시 인덱스 아래 `git diff HEAD~1` 은 14KB다.
- codex 실행자가 남긴 큰 미추적 파일 — 저장소 안 1MB 이상 파일은 전부 gitignore 상태라
  intent-to-add 대상이 아니다.

남은 단서: 오류 문구의 대화 크기(약 216만 토큰)가 당시 이 Claude 세션 기록 크기와 자릿수가
같고, `CODEX_COMPANION_TRANSCRIPT_PATH` 가 그 기록 파일을 가리키고 있었다. 재현은 안 됐다.

## Decision needed

재발했을 때 원인을 잡을 계측 — **일부는 이미 설치됨 (2026-07-26)**: claude 리뷰 명령이
stdin 을 `.stage/.runtime/last-review-stdin.bin` 으로 `tee` 한다. 재발하면 그 파일 크기가
"stdin 이 컸나, 다른 데서 컸나" 를 즉답한다. stdin 이 작았다면 남는 용의자는 `claude -p`
호출 자체가 붙이는 문맥이므로, 그 호출의 환경 전체를 보존해 비교한다. 원인이 잡히면 fix
카드로 잇는다.

## Status

**answered (2026-07-26)** — 설치한 계측이 같은 날 두 번째 발생(W-00000093 드라이버 스텝)에서
원인을 잡았다. 리뷰어 stdin 은 9,016,382 바이트였고, 내용은 저장소 962개 파일의 diff, 그중
956개가 "deleted file mode" — **리뷰어용 임시 인덱스가 사실상 비어 있어 `git diff HEAD~1` 이
전 파일 삭제로 읽은 것**이다. 대화 216만 토큰 ≈ 9MB 로 첫 사고와도 일치한다. 환경 변수
가설이 재현되지 않던 이유도 설명된다 — 문제는 환경이 아니라 인덱스 내용이었다.

남은 미지 하나(무엇이 codex 실행자 스텝에서 인덱스를 비우는가)와 수정은 W-00000094 가
잇는다. 이 질문은 답변으로 닫는다.
