# 현재 상태

이 문서는 현재 프로젝트 관측의 인덱스를 소유한다.

관측 본문은 `observations/`에 있다.

## 현재 관측

- [O-00000002](observations/O-00000002.md) — 사람에게 넘기는 커밋이 카드 범위 안의 `.stage`
  파일을 함께 담는다. 지금은 해가 없어 받지 않는다.
- [O-00000013](observations/O-00000013.md) — 드라이버가 도는 동안 사람이 같은 체크아웃을 만지면
  그 변경이 실행자 몫으로 섞여 성공한 실행이 실패로 판정된다. 우회는 있고 아직 안 받았다.
- [O-00000015](observations/O-00000015.md) — `.stage/` 기록을 고치는 카드를 드라이버에 넘기면
  실행자가 목적 게이트에 한 번 막힌다. 다시 시도하는지 실패로 보고하는지 아직 안 봤다.
- [O-00000020](observations/O-00000020.md) — 만든 쪽이 카드의 파일 목록을 스스로 넓히면 넘었다는
  기록이 카드에서 사라진다. 보고에만 남는다.
- [O-00000021](observations/O-00000021.md) — 도구 없이 말로 물으면 아무 게이트도 안 걸린다.
  목적을 안 보고 사람에게 판단을 떠넘겨도 아무 데도 안 남는다.
- [O-00000024](observations/O-00000024.md) — 판정하는 쪽이 실행하는 쪽보다 값을 더 쓴다
  (72 바퀴 실측: 출력 2.9배, 입력 1.3배). 판정을 어디에 맡길지의 기준.
- [O-00000025](observations/O-00000025.md) — 승격했다는 말을 감사가 검사할 수 없다. 새 기록을
  만드는 승격은 잡히고, 기존 공식 문서를 고치는 승격은 못 잡는다.
- [O-00000028](observations/O-00000028.md) — 병렬 worktree 실행 환경. 클로드 몫은 답이 나왔다
  (워크트리 문제가 아니라 실행자가 어디서든 명령 권한이 없음). 코덱스 설정과 기준점 문제가 남았다.
- [O-00000034](observations/O-00000034.md) — 카드를 거절하고 계약대로 `promotion` 만 쓴 실행자를
  드라이버가 커밋 실패로 막는다. 담는 목록에 카드 파일이 없어서다.
- [O-00000035](observations/O-00000035.md) — 무인 결과를 병합할 때 열린 작업이 없어 커밋 게이트가
  막는다. 하니스가 시킨 다음 걸음을 하니스가 막고, 충돌이 없으면 조용히 지나간다.
- [O-00000036](observations/O-00000036.md) — 마일스톤 완료 기준을 여러 개 주면 마지막 하나만
  남고 나머지는 말없이 사라진다. M-00000003 에서 셋 중 둘을 잃었다가 닫기 직전에 되살렸다.
- [O-00000037](observations/O-00000037.md) — 코덱스 캐시를 되잡는 완화책이 0.60.0 에서는 세 번
  돌려도 안 통했다. **다음 세션의 코덱스 실행이 사전 점검에서 막힌다.**
- [O-00000038](observations/O-00000038.md) — 쉬고 있는 팀원이 쌓인 메시지를 안 집고, "할 일
  없음" 알림이 실제 작업보다 먼저 온다. 감독이 한 번 더 보내야 움직인다.
- [O-00000039](observations/O-00000039.md) — 0.60.0 릴리스를 기준이 "통과가 아니다"라고 하는
  상태에서 통과로 닫았다. 카드의 성공 기준이 기준 문서보다 느슨했다.
