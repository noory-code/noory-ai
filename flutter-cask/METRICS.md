# 스킬 효과성 메트릭

## 개요

Flutter Cask는 34개의 스킬을 제공하지만, 어떤 스킬이 실제로 가치를 제공하는지 측정할 수 있는 메트릭이 필요합니다. 이 문서는 스킬 효과성을 평가하고 투자 결정을 내리기 위한 메트릭 프레임워크를 정의합니다.

## 측정 목표

1. **우선순위 결정**: 패키지 업데이트 시 어떤 스킬을 먼저 업데이트할지
2. **확장 방향**: 어떤 카테고리를 확장할지 (Firebase? Testing? 새 카테고리?)
3. **유지보수 ROI**: 사용률이 낮은 스킬의 유지보수 비용 대비 가치

## 메트릭 프레임워크

### 1차 메트릭 (현재 수집 가능)

#### GitHub 기반 메트릭

- **이슈/피드백 빈도**: 각 스킬별 언급 횟수
  - Issue Template을 통한 구조화된 피드백
  - 자연어 이슈에서 스킬 이름 추출

- **스킬 요청 빈도**: 새 스킬 요청 시 언급되는 카테고리/패키지

- **문서 조회 패턴**: GitHub Analytics를 통한 스킬 디렉토리 방문 수

#### 커뮤니티 참여 메트릭

- **Repository Stars/Forks**: 전체 프로젝트 관심도
- **Issue/PR 참여도**: 커뮤니티 활성화 수준
- **외부 언급**: 블로그, SNS에서의 언급 (수동 추적)

### 2차 메트릭 (플랫폼 지원 필요)

Claude Code 플랫폼이 지원할 경우:

- **스킬 호출 횟수**: 각 스킬이 실제로 트리거된 횟수
- **트리거 패턴 매칭**: 어떤 키워드가 가장 많이 사용되는지
- **세션당 사용 깊이**: Quick Reference만 보는지, 전체 가이드를 보는지
- **오류율**: 스킬 로딩/실행 실패율

### 간접 메트릭

- **패키지 pub.dev 통계**: 각 패키지의 인기도 (Likes, Pub Points, Popularity)
- **패키지 업데이트 빈도**: Breaking changes 발생 가능성
- **커뮤니티 질문 빈도**: Stack Overflow, Reddit 등에서의 질문 수

## 데이터 수집 방법

### 1단계: 경량 피드백 시스템 (현재 구현)

- `.github/ISSUE_TEMPLATE/skill-usage-feedback.md`: 사용자가 어떤 스킬을 사용했는지 보고
- `.github/ISSUE_TEMPLATE/skill-request.md`: 새 스킬 요청 및 기존 스킬 개선 제안
- Issue labels를 통한 자동 분류: `feedback`, `usage-metrics`, `skill-request`

### 2단계: 분기별 수동 분석

- GitHub Issues 분석 스크립트 작성 (Python/Node.js)
- 스킬별 언급 횟수 집계
- pub.dev API를 통한 패키지 통계 수집
- 분기별 리포트 생성

### 3단계: 플랫폼 통합 (장기)

Claude Code 플랫폼에 사용 통계 API 요청:
- 익명화된 스킬 호출 횟수
- 트리거 키워드 통계
- 오류/성공률

## 의사결정 기준

### 우선순위 높음 (집중 투자)

- 피드백 빈도 상위 20%
- pub.dev Popularity Score > 90
- Breaking changes 발생 시 24시간 내 업데이트

### 우선순위 중간 (정기 유지보수)

- 피드백 빈도 중간 50%
- pub.dev Popularity Score 70-90
- Breaking changes 발생 시 1주일 내 업데이트

### 우선순위 낮음 (재평가 대상)

- 피드백 없음 또는 최하위 30%
- pub.dev Popularity Score < 70
- 분기별 리뷰 후 유지/제거 결정

### 새 스킬 추가 기준

- 3건 이상의 독립적인 요청
- pub.dev Popularity Score > 85
- 기존 카테고리와 시너지 또는 새 카테고리 정당성

진행 중인 작업 항목은 이 문서가 아니라 GitHub Issues에서 추적합니다.

## 참고

이 메트릭 프레임워크는 데이터 기반 의사결정을 위한 시작점입니다. 실제 데이터 수집 후 메트릭을 조정하고 개선해야 합니다.
