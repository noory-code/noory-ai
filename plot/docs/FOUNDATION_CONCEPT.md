## Plot 작동 전제

Plot 은 **AI 로 동작**한다. 사용자와 AI 가 대화하며 **함께 캔버스에 그림을
그린다** — 다이어그램 기반의 기획서를 공동 작성하는 도구. 아래 개념들은
그 협업에서 AI 가 묻고/도출하고/갱신하는 대상이다.

## 3종 개념 + 시간축

| 개념 | 한 줄 | 시간 지향 | 입출력 |
|---|---|---|---|
| **미션** | 존재의 뿌리. 탄생의 이유. *왜 존재하는가.* | 과거/뿌리 | **입력** (인터뷰) |
| **코어밸류** | 현재의 노력. *지금 어떻게 결정하는가.* | 현재/노력 | **입력** (인터뷰) |
| **아이덴티티** | 쌓여가는 지향. *어떤 존재이고 싶은가.* | 미래/지향 | **출력** (AI 도출·갱신) |

```
미션(과거/뿌리) ──▶ 코어밸류(현재/노력) ──▶ 아이덴티티(미래/지향)
   입력                입력                    출력(파생)
```

> **시간축 주의:** 이건 *개념의 시간 지향*(뿌리→노력→지향)이지, 로드맵·
> 스프린트 같은 *시간 기반 기능*이 아니다. Plot 은 공간 기반을 유지한다
> ([[feedback_plot_space_vs_time]]). 충돌 없음.

### 미션 — 존재의 뿌리
왜 존재하는가. 탄생의 이유. **입력**(미션 인터뷰로 받는다).
- BANAS: **Be all · New all.** "나의 일상을 함께 만드는 사람들의 공동체."

### 코어밸류 — 현재의 노력
지금 무엇을 어떻게 결정하는가. **입력**(코어밸류 인터뷰).
- BANAS: **관용과 지지.** 뉴비 환영, 실수에 너그럽고, 노력을 응원한다.
- (감사 메모: node-format 에서 본 "판단 기준"이 바로 이것 — *지금 어떻게
  결정하는가*. core_value 의 본질이 의사결정 기준임을 개념이 확인.)

### 아이덴티티 — 쌓여가는 지향  ★ 핵심
어떤 존재이고 싶은가. **선언이 아니라 행동의 반복으로 만들어진다.**
- **출력값이다, 입력값이 아니다.** 초기엔 AI 에이전트가 미션+코어밸류를
  보고 도출하고, 이후 행동/설계가 쌓이며 계속 업데이트된다.
- **이게 Plot 이 다른 기획 툴과 다른 이유.** 다른 툴은 아이덴티티를 사람이
  적어 넣지만, Plot 은 AI 가 도출·진화시킨다.

> **핵심 인사이트: 아이덴티티는 입력값이 아니라 출력값이다.**

## 액터 구조 (BANAS 예)

역할이 **고정되지 않는다** — 누구나 팬이 되고 누구나 히어로가 된다.

| 액터 | 정의 |
|---|---|
| **바나 (BANA)** | 모든 유저 통칭 |
| **팬** | 히어로를 좋아하는 사람 |
| **히어로** | 전문가. 히어로끼리는 동료 |
| **써드파티** | 주류도매상·광고주 등. 커뮤니티 안의 접근형 참여 |

**관계 유형**
- 히어로 ↔ 팬 (나의 히어로 / 나의 팬)
- 히어로 ↔ 히어로 (동료)
- 히어로 ↔ 써드파티 (접근형 — 눈팅)

## Plot 에 녹이는 흐름

1. **미션 인터뷰** → 미션(입력)
2. **코어밸류 인터뷰** → 코어밸류(입력)
3. **아이덴티티 에이전트 도출** → 아이덴티티(출력), 이후 계속 업데이트
4. **액터 설계** — 역할 전환 가능한 구조
5. 이 컨텍스트를 참조해 **이후 서비스 기획 전반에 활용**

## 노드 데이터 형식에 주는 함의 (node-format 감사로 연결)

- **미션·코어밸류 = 입력** → 인터뷰로 받는 산문. label + 단일 prose 로
  충분 (감사 결론과 일치).
- **아이덴티티 = 출력** → "어느 필드를 사람이 채우나"가 핵심 질문이 아니다.
  *AI 가 도출·누적*하는 것이라:
  - **provenance**(어느 미션/코어밸류/행동에서 도출됐나)와
    **evolution**(언제 갱신됐나)이 입력 필드보다 중요한 구조 후보.
  - 14개 flat 노드 = 누적된 출력의 단면 — "catch-all"이라 깐 이질성도
    *도출된 관찰의 누적*으로 보면 자연스러울 수 있음 (재검토 필요).
- → identity node-format 의 열린 결정(①body ②facet ③catch-all)을 **"출력값"
  관점에서 다시 본다.**
