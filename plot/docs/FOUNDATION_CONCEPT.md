## Plot 작동 전제

Plot 은 **AI 로 동작**한다. 사용자와 AI 가 대화하며 **함께 캔버스에 그림을
그린다** — 다이어그램 기반의 기획서를 공동 작성하는 도구. 아래 개념들은
그 협업에서 AI 가 묻고/도출하고/갱신하는 대상이다.

> **채우는 방식 = 캔버스에 붙은 AI 대화창(인터뷰).** (방향, 2026-06-06.)
> 사용자가 폼 필드에 타이핑하는 게 아니라, AI 가 **인터뷰하듯 질문**하며
> 대화로 노드 내용을 채워간다. 따라서 각 kind 의 **인터뷰 질문 세트**가
> 핵심 산출물이다 — 지금은 노드 body 의 정적 프롬프트(유도)로, 나중엔 AI
> 챗이 같은 질문을 던지는 형태로 재사용. (AI 챗 창 자체는 미구현 — 큰 별도
> 기능. 질문 세트만 먼저 정의 가능.) 관련: project_plot_pencil_dev_direction.

### 미션 — 존재의 뿌리  (정의 보강: D-2026-06-16-K)
**미션 = 이 서비스가 세상·사람들에게 일으키려는 근본 변화 (존재의 뿌리).**
이윤 너머의 대담한 목적 — *Massive Transformative Purpose*(Exponential Organizations)에 대응.

**미션의 진짜 시험 = 지속가능한가?** 두 엔진:
- **(a) 계속 생기는 문제를 푸는가** — 안 마르는 수요. *Jobs-to-be-Done*(Christensen:
  사람은 제품이 아니라 "할 일"을 고용한다).
- **(b) 세상에 없던 가치인가** — 쉽게 대체 안 됨. *Value Innovation / Blue Ocean*(Kim·
  Mauborgne) = PHILOSOPHY "이전에 없던 가치".

**성공 상태 = 혁신이 일상이 된다** — 확산의 끝은 혁신이 문화에 흡수되어 평범해지는 것.
*Diffusion of Innovations*(Rogers).

**미션 인터뷰 = 2단계 (발견 → 거르기)** (= 토론 코치 mission판, D-2026-06-16-H/L):
- **발견:** ① 만들고 싶은 서비스가 누구의 무엇을 바꾸나? ② 그게 없으면 세상은 뭐가
  아쉽나? ③ 왜 하필 당신이·지금인가? → 근본 변화(후보)
- **거르기(지속가능성):** ① 이 문제는 계속 생기나? ② 지금 세상에 없는 가치인가?
  ③ 일상이 되면 세상은 어떻게 달라지나?

- BANAS: **Be all · New all.** "나의 일상을 함께 만드는 사람들의 공동체."

> 형식: 선언 1칸 + 본문(D-2026-06-16-J). 위 인터뷰 질문 세트는 **스킬/MCP 프롬프트로
> 패키징 예정**(ROADMAP 🅿) — `H`의 "적극적 토론 코치"의 실제 구현물.

### 코어밸류 — 현재의 노력  (정의 보강: D-2026-06-16-L)
**core_value = 결정이 갈릴 때 이기는 가치 = "지금 어떻게 결정하는가"의 기준.**
미래 지향(identity)이 아니라, 지금 실제로 작동하는 의사결정 우선순위.

**인터뷰 = 2단계 (발견 먼저 → 거르기):**

**1단계 — 발견 (서비스에서 후보를 캔다).** 가치를 허공에서 묻지 않고
*만들고 싶은 서비스가 강제할 결정*에서 끌어낸다.
1. 이 서비스에서 자주 부딪힐 결정은? (속도 vs 완성도 / 초보 vs 전문가 / 무료 vs 유료 …)
2. 그 갈림길에서 본능적으로 어디로 기우나? → 후보 가치
3. 경쟁자는 당연시하는데 나는 거부하고 싶은 것은? → 차별적 후보

**2단계 — 거르기 (후보가 진짜 코어인지).**
1. **트레이드오프를 만드나?** — 아무것과도 안 부딪히면 결정 못 하는 장식. *(Schwartz 1992)*
2. **불리해져도 지키나?** — 비용 0이면 코어가 아닌 "기본기(permission-to-play)". *(Collins&Porras / Lencioni)*
3. **적은 게 아니라 사는가?** — espoused ≠ shared. *(Bourne&Jenkins 2013)*

- BANAS: **관용과 지지.** 뉴비 환영, 실수에 너그럽고, 노력을 응원한다.
  (검증: 정예주의·엄격한 품질을 양보 → 트레이드오프 O, 불리해도 지킴 O. 통과.)
- (감사 메모: node-format 의 "판단 기준"이 바로 이것 — *지금 어떻게 결정하는가*.)

> 형식: **이름(label) + 본문(body)** (D-2026-06-16-M). 겹치던 `definition` 칸 제거 →
> 본문 흡수. 본문엔 의미 + **그 가치가 만드는 트레이드오프**(택하는 것/양보하는 것).

### 아이덴티티 — 쌓여가는 지향  ★ 핵심  (정의 보강: D-2026-06-16-N)
**identity = 서비스의 일관된 실행·표현 기준(액션 룰) — 보이스·디자인·태도를
"우리는 이렇게 한다"로 정한 것.** 그 룰들이 쌓여 서비스의 성격이 된다.

- **가치 충돌 판단이 *아님*.** core_value = *무엇을 택하나*(충돌 시 tie-breaker);
  identity = *어떻게 보이나·말하나*(항상 적용되는 일관 기준). 예: "디자인은
  원색·맛있어 보이게". 둘이 부딪히면 core_value가 상위 판단. (서비스디테일
  `rule` kind = per-service 운영정책 — 또 다름.)
- **출력값이다, 입력값이 아니다.** AI가 미션+core_value(+쌓인 행동)를 보고
  도출하고, 행동/설계가 쌓이며 갱신된다. 다른 툴은 사람이 적고, Plot은 AI가
  도출·진화시킨다 — Plot의 차별점.
- **선언이 아니라 행동의 반복으로 만들어진다** — 학술: 정체성은 being이 아니라
  *doing*으로 enact된다 (identity-as-practice; Oliver&Vough 2020, Brown 2022).
  표현 형태 = 브랜드 보이스 Do/Don't 룰 (Aaker 1997 5차원은 그 *요약*). 유동·진화가
  정상 (Gioia 2000, adaptive instability).

> **핵심 인사이트: 아이덴티티 = 항상 적용되는 일관 실행·표현 룰의 누적(출력값).**

> 형식: **이름(label) + 액션 룰 리스트** (D-2026-06-16-O). `description` 제거.
> **AI 도출 = 토론으로** — AI가 mission+core_value 보고 *초안 룰 제안* → 사용자와
> 다듬어 *확정*. **silent 자동생성 아님.** status(derived→confirmed)·provenance(자동)·
> evolution은 **AI 도출 흐름(ROADMAP 5.7)과 함께** 도입 — 지금은 inert라 뺌.

## 액터 구조 (BANAS 예)

역할이 **고정되지 않는다** — 누구나 팬이 되고 누구나 히어로가 된다.

| 액터 | 정의 |
|---|---|
| **바나 (BANA)** | 모든 유저 통칭 |
| **팬** | 히어로를 좋아하는 사람 |
| **히어로** | 전문가. 히어로끼리는 동료 |
| **써드파티** | 주류도매상·광고주 등. 커뮤니티 안의 접근형 참여 |

**관계 유형**
- 히어로 ↔ 팬 (나의 히어로 / 나의 팬)
- 히어로 ↔ 히어로 (동료)
- 히어로 ↔ 써드파티 (접근형 — 눈팅)

## Plot 에 녹이는 흐름

1. **미션 인터뷰** → 미션(입력)
2. **코어밸류 인터뷰** → 코어밸류(입력)
3. **아이덴티티 에이전트 도출** → 아이덴티티(출력), 이후 계속 업데이트
4. **액터 설계** — 역할 전환 가능한 구조
5. 이 컨텍스트를 참조해 **이후 서비스 기획 전반에 활용**

## ★ 서비스 기획의 토대 — 3종 전부 적용 (사용자 강조 2026-06-06)

미션·코어밸류·아이덴티티는 정의하고 잠드는 게 아니다. **세 가지 전부가
서비스 기획의 토대로 쓰여야 한다 — 모든 서비스는 이 셋을 기반으로
기획한다.** (사용자: "미션과 코어밸류, 아이덴티티가 다 쓰여야 한다는 거에요.
이를 기반으로 서비스 기획해야 한다는 겁니다.")

- **미션** — 이 서비스가 *왜/무엇을 위해* 존재하는가에 답해야 한다 (mission_ref).
- **코어밸류** — 서비스 설계의 모든 결정에서 *우선 가치*로 작동한다 (value_ref).
- **아이덴티티** — 서비스의 보이스·디자인·태도가 *정체성과 일관*되어야 한다
  (identity_ref).
- 이 적용이 ServiceDetail 의 **foundation-injection(발동)** 엣지로 가시화되고,
  산출물(Q6)의 **체현**으로 표현된다. → 파운데이션은 *흐름 전반의 렌즈*.

## 노드 데이터 형식에 주는 함의 (node-format 감사로 연결)

- **미션·코어밸류 = 입력** → 인터뷰로 받는 산문. label + 단일 prose 로
  충분 (감사 결론과 일치).
- **아이덴티티 = 출력** → "어느 필드를 사람이 채우나"가 핵심 질문이 아니다.
  *AI 가 도출·누적*하는 것이라:
  - **provenance**(어느 미션/코어밸류/행동에서 도출됐나)와
    **evolution**(언제 갱신됐나)이 입력 필드보다 중요한 구조 후보.
  - 14개 flat 노드 = 누적된 출력의 단면 — "catch-all"이라 깐 이질성도
    *도출된 관찰의 누적*으로 보면 자연스러울 수 있음 (재검토 필요).
- → identity node-format 의 열린 결정(①body ②facet ③catch-all)을 **"출력값"
  관점에서 다시 본다.**
