# Output

This document owns the rules for user-visible responses.

## Rules

- Lead with the conclusion in the first sentence; keep a status explanation to one paragraph.
- Do not use analogies.
- Make conclusions and questions explicit (state the question or the decision, not just context).
- When presenting options, list 2–3 and give each one time, cost, and risk.
- State uncertainty explicitly: name what is unverified and how you would verify it.
- When a response asks the user to choose or decide something, or is a turn in a discussion with
  the user (R-00000371, R-00000402):
  - Open with the big picture in one or two sentences: what is being decided overall, and where
    this question sits in it.
  - Ask one question that one answer settles. Hold every other open question until the user has
    answered this one, then ask them one at a time.
  - Use at most one table: the one that holds this question's options, listed as the options rule
    above says.
  - Put reasons and opposing views in their own sentences or in that table, never inside the
    question sentence.
  - Both times the user said they could not follow, the response had laid out several issues at
    once: reasons and an opposing view packed into one question sentence, then a long, abstract
    explanation.
